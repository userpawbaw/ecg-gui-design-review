# 레퍼런스 마이닝 3차 — 눈에 보이는 와우에서 제작 방식까지

2026-10-03 · 실제 브라우저 관찰 + 공개 소스 + 제작자 설명 · **선택 효과 분석, 원본 전체 재현 검증 전**

이번 추가 조사 대상은 **현재 Lusion과 My Little Storybook**, 심화 대상은 **Editorial New와 Igloo**다. ‘많은 유명 사이트’보다 A/B의 빈칸과 C의 새로운 중심 효과를 채울 만한 구간을 골랐다. 이 보고서의 사이트별 카드에는 ① 정확히 어디를 볼지 ② 무엇이 눈을 붙잡는지 ③ 물체·글자·깊이 ④ 입력/구현 방식 ⑤ ECG 번안 ⑥ 아직 모르는 것을 남긴다. 수상 태그나 기술 추정만으로 라이브 효과를 봤다고 처리하지 않는다.

## 0. 증거를 읽는 법

- **[관찰]** 이번 브라우저에 실제 표시된 화면·버튼·캔버스·계산된 글자 스타일. 캡처는 하단의 상태 지도에 대응한다.
- **[코드]** 해당 사이트가 현재 공개 제공하는 HTML/CSS/JS에서 확인한 값. 번들에 있는 함수/플러그인이 특정 장면에서 반드시 실행된다는 뜻은 아니다.
- **[제작자]** 제작자가 공개한 기술 설명. 이번 브라우저에서 재현하지 못한 구간은 이 태그만 쓴다.
- **[번안/제안]** ECG용 구도와 시험 파라미터. 원본 측정값과 구분한다.

촬영은 정지 캡처와 단계별 입력이다. 시간 길이·fps·중복 프레임 비율을 갖춘 연속 녹화는 이번에 확보하지 않았다. 캡처 간격을 easing 수치로 역산하지 않는다. 화면은 주로 1280×720, Editorial 초기 캡처는 1085×884다. 1920×1080으로 Editorial을 다시 연 구간은 정상 본문을 확보하지 못해 **품질 근거에서 제외**했다. 실제 구현 전에는 선택 효과 전체의 6–12 프레임, 정지/단발/역방향 입력 영상과 소품 좌표를 추가한다.

### EN-E1: 기록물과 제목이 함께 주연이 되는 회전

**눈을 붙잡는 이유:** 화면을 빈칸과 작은 본문으로 채우지 않고, 얇은 serif의 매우 큰 획이 공간을 지배한다. 신문이라는 이미 알고 있는 물체와 글자의 회전이 읽기 행위로 이어져 장식 운동에 그치지 않는다. **이 평면 회전의 인상과, B의 실제 옆면/틈 진입은 다르다.**

**구도/토큰 [관찰]:** 흰 바탕, 검은 글자, 중앙의 매우 큰 제목. 초기 1085px 폭에서 큰 제목 계산 크기 약 160.58px/굵기 200, 작은 메뉴 14px. 글자는 Editorial New. 정확한 색상 hex와 모든 자간/행간은 이번에 측정하지 않았다.

**입력/메커니즘 [코드]:** 신문에 CSS `rotate(360 × progress)`를 적용하는 **화면 평면 회전**. 읽은 app.js에 rotateY/rotateX/perspective 또는 WebGL 신문 근거는 없다. Locomotive Scroll의 smooth 설정과 모듈 구조가 확인된다. 제작진도 on-scroll, folding, parallax, sticky, 가변 폰트를 설명한다. 이 설명으로 종이 3D 안쪽에 카메라가 들어간다고 결론 내릴 수 없다.

|---|---|---|
| 회전 | progress 0→1에 CSS 회전 0→360° | 공개 app.js |
| 스크롤 | smooth=true | 공개 초기화 코드 |

**재료/용량:** 공개 app.js 65,964B, vendors.js 19,239B, main.css 68,715B. 받은 파일 본문 길이이며 압축 전송량/페이지 총량은 아니다. 글꼴 파일의 해상도 개념은 해당 없고 정확한 용량은 미확인. 원본의 신문 이미지·종이 면 자산을 복제하지 않았다.

**ECG 번안:** B0에서 큰 `심전도 잡음 제거`와 ECG 기록을 함께 주역으로 둔다. 회전과 확대가 기록을 읽는 자리로 이어지는 원리는 차용한다. **입체 아코디언 종이, 이면, 틈 속 인체, 카메라 진입은 독자 확장**으로 분류한다.

**우리 구현 경로:** 기존 프로젝트의 한 Lenis 입력→GSAP 씬 진행률→Three.js 종이 mesh 힌지 회전. 원본의 2D 재현은 DOM으로 별도 대조 가능하다. 종이 변형은 Blender에서 적은 본으로 접힘을 준비하거나 hinge별 그룹 변환. 얇은 이면, 접힘 그림자, 종이 결, 전경 가림을 먼저 시험한다.

**수용 기준/위험:** EN 원본과 비교할 것은 큰 글자+기록물의 위계와 회전 후 읽기 연결. B1–B3의 깊이와 카메라는 **독자 확장 검사**다. ‘원본에도 옆면이 있었다’는 조건으로 평가하지 않는다. 종이가 플라스틱 판/단일 이미지로 보이면 물성 TUNE. **재현 상태 none.**

### EN-E2: 굵기 변화도 글자의 움직임이다

원본 소스의 가변 굵기를 이용하면 단순 fade 외에 스크롤이 단어의 무게를 바꾸는 연출이 가능하다. B에서 `기록`은 얇게, `심전도`가 정면으로 도착할 때 굵고 선명하게 만들 수 있다. **한국어 글꼴은 별도 조달해야 하며 원본 영문 폰트를 그대로 한글에 적용할 수는 없다.** [번안] 큰 글자 70–84px / 보조 16–20px, 굵기 이동은 박동마다 번쩍이게 하지 않고 장면 도착에 한 번만 적용한다. 아직 글꼴의 축 지원/라이선스/실제 한글 가독성은 미확인이다.

### LU-E1: 여러 3D 조형의 접촉·가림·반사가 만든 밀도

**눈을 붙잡는 이유 [관찰+해석]:** 한 오브젝트가 떠 있는 빈 배경이 아니다. 둥근 십자/연결 조형이 겹치고 서로 가리며, 곡면의 밝은 띠와 깊은 골 그림자가 반복된다. 가까운 면은 크게, 뒤쪽 면은 부분적으로 보여 정지 화면부터 두께가 읽힌다. 코발트·백색·검은 공간의 제한된 대비가 복잡한 덩어리를 하나의 이미지로 묶는다.

**구도/토큰 [관찰]:** 1280×720에서 그림 패널 대략 x64,y185,w1152,h484. 큰 그림보다 앞에 한 줄/두 줄 소개, 첫 문장 약 32px Aeonik/400. 하단에서는 아주 큰 제목이 그림을 대신해 들어온다. 한 화면의 모든 정보가 같은 크기로 경쟁하지 않는다. 화면 밖 프로젝트 메뉴까지 포함한 전체 토큰은 미측정.

**ECG 번안:** C의 첫 화면에서 파형을 두께 있는 리본 조형으로 만들고, 몇 겹의 흐트러진 입력과 처리실의 링을 겹쳐 **신호가 화면을 채우는 구도**를 만든다. 원본 십자 조형을 그대로 의료 의미로 우기지 않고 곡면의 빛/겹침/밀도만 신호에 옮긴다. 이것은 독자 모델 제작이다.

**수용 기준:** 렌더 정면/측면에서 앞·뒤 리본이 구별되고, 검은 면이 단순 텅 빈 공간처럼 보이지 않음. 눈을 가늘게 떠도 주제 제목/주 리본/심장으로 시선 순서가 유지. 과한 반사로 신호 선이 하얀 덩어리가 되면 TUNE. 재현 상태 none.

### LU-E2: 비스듬한 큰 화면이 글자와 서로 다른 깊이를 가진다

**와우:** 직사각형 이미지가 작은 카드로 정렬되지 않고 큰 입체 화면으로 기울어 있다. 내용과 베젤/면의 방향이 분리돼 그림이 오브젝트가 된다. 옆의 문구도 큰 면적을 가져 화면과 동등한 시각적 역할을 한다 [관찰]. 이 구간의 연속 회전 입력/경로는 미측정이다.

## 3. My Little Storybook — 같은 세계 안에서 카메라가 이야기한다

**주소/제작:** [My Little Storybook](https://exp-my-little-storybook.lusion.co/) · Lusion 실험. 사이트 자체 설명에서 새 가족의 강 건너기, 스타일화한 자연을 실험했다고 밝힌다.

**보는 경로:** ENTER → 첫 장면의 NEXT → 다시 NEXT. 이번 관찰은 이 3개의 3D 장면이다. 버튼으로 진행하는 사례를 스크롤 UX로 그대로 복제한 것으로 쓰지 않는다.

실제 캡처 ID: `BK-03-scene.jpg` — 첫 장면 — 전경과 개울, 인물, 대사 면의 깊이 차이. 원본 사이트 화면은 저장소 밖 사용자용 보고서에만 수록.

실제 캡처 ID: `BK-04-next-scene.jpg` — 다음 장면 — 같은 물체를 다른 카메라 구도로 관찰. 원본 사이트 화면은 저장소 밖 사용자용 보고서에만 수록.

### BK-E1: 물체를 바꾸지 않고 시선을 이동한다

**눈을 붙잡는 이유:** 풀·개울·돌·새가 같은 세계에 있다. 다음 장면에서 더 가까운/높은 시점으로 바뀌어 같은 요소를 다시 발견한다. 전경 풀의 흐림과 화면 가장자리의 가림이 카메라 위치 변화를 먼저 알려 준다. 별개 이미지가 교체되는 것보다 인물의 공간이 기억에 남는다 [관찰+해석].

**구도/타이포:** 1280×720 중앙 3D 무대, 대사는 위쪽의 밝은 작은 면, NEXT는 아래 중앙. 새가 장면의 초점이고 전경은 일부 흐리다. ENTER/제목의 글꼴 Halant 확인, 대사 전체 크기·색과 카메라 좌표/FOV는 미측정.

**기술/입력:** 공개 JS에서 Three.js r122, GSAP 3.11.5, CustomEase 3.6.1 문자열 확인. NEXT 클릭에 장면/구도가 변화한 것은 관찰됨. 번들에 ScrollTrigger가 있지만 그것만으로 원본 진행이 스크롤이라고 결론 내리지 않는다. 카메라 보간이 어떤 곡선인지, DOF 처리의 정확한 pass는 미확인.

**재료:** 받아 본 JS 1,090,695B. bird.png, baby_bird.jpg, grass.jpg, frog.png, dust-texture.jpg 같은 텍스처 이름 확인. 해상도·각 용량·모델 포맷은 미확인. `.bind`를 `.bin` 자산으로 잘못 잡는 검색 결과는 버렸다. 원본에 물리적 팝업 책/종이 hinge를 봤다고 적지 않는다.

**ECG 번안:** A/B/C 모두 세 잡음 원인을 같은 사람·장치 공간에서 발견한다. PLI는 플러그 가까이, BW는 옆 흉곽, EMG는 손+전완 구도로 이동. 원인 소품은 다음 원경에도 그대로 있다. 레퍼런스의 NEXT 문법은 **우리의 스크롤 진행+계속 살아 있는 시간 재생**으로 번안한다.

**우리 경로 [제안]:** 모든 장의 소품 좌표를 먼저 하나의 scene graph로 고정. GSAP에서 카메라 position/target을 보간하고 전경 object 가림으로 전환을 검토. 대사는 HTML로 분리해 핵심 원인을 가리지 않는 화면 자리로 이동. 예비 영상은 회색 무대만으로 먼저 제작, 이후 DOF/빛/재질을 적용.

**수용 기준:** 동일 플러그·컴퓨터·인체가 카메라를 돌려도 같은 위치에 있음. 글자가 원인을 먼저 가리거나 깊이 흐림이 전극을 지우면 TUNE. 역방향 스크롤에서도 경로가 이어짐. 폴백은 정지 3장+짧은 설명으로 세계의 위치 관계를 유지. 원본 reduced-motion/모바일 분기는 미확인. 재현 상태 none.

### BK-E2: 대사를 ‘빈칸 라벨’로 두지 않는다

작은 밝은 면과 캐릭터가 같은 무대에 함께 놓여 대사의 위치에 의도가 보인다 [관찰]. ECG에서는 AC 표시를 플러그 근처 작은 보드로, 기법 이름을 출력 직전의 별도 면으로 놓을 수 있다. 긴 기법 설명이 아니라 **원인→입력→디지털 처리→출력**의 순서에서 필요한 한 줄만 등장시키는 규칙으로 옮긴다. 실제 최선 기법의 이름은 해당 데이터/평가 조건을 확인한 뒤 넣는다.

## 4. Igloo — 공간 이동과 입자 재형성을 분리해 분석

**주소:** [Igloo](https://www.igloo.inc/) · [제작자 사례 설명](https://www.awwwards.com/igloo-inc-case-study.html).

**보는 경로:** 로드 후 얼음집 → 휠 입력으로 공간 접근/변화 → 빛나는 동심 링과 중앙 입자 형태. 입자의 여러 모델 사이 재형성은 제작자 글의 **Interactive Particles**를 함께 확인한다. 이번 라이브에서는 그 푸터 hover 모델 전환을 직접 재현하지 못했다.

실제 캡처 ID: `IG-01-start.jpg` — Igloo 첫 공간 — 반투명 블록, 내부 빛과 넓은 풍경. 원본 사이트 화면은 저장소 밖 사용자용 보고서에만 수록.

실제 캡처 ID: `IG-06-sequence.jpg` — 이번에 실제 관찰한 동심 링과 중앙 입자 형태. 원본 사이트 화면은 저장소 밖 사용자용 보고서에만 수록.

### IG-E1: 큰 공간에서 밝은 중심으로 시선을 모은다

**끌리는 이유 [관찰+해석]:** 첫 화면에서 투명 블록의 쪼개짐과 내부 광원이 눈을 끈다. 화면 가장자리의 차가운 풍경보다 중앙의 빛이 강하다. 이후 동심 링을 위에서 내려다보는 구도가 들어와, 공간 전체와 입자 중심 사이의 크기 차이가 커진다. 본문 설명보다 카메라/형태가 먼저 공간 변화를 알려 준다.

**토큰/입력:** 1280×720, 흰 IGLOO 로고 왼쪽 위, 작고 촘촘한 고정폭 느낌의 문구 오른쪽 위, 차가운 회색/청색과 밝은 중심. UI가 대부분 WebGL이므로 정확한 폰트/px를 DOM으로 확정하지 못했다. body 높이는 720px였고 별도 일반 스크롤 컨테이너는 확인되지 않았다. 휠 입력 후 canvas 장면이 변한다. 원본의 진행률/휠 누적/감쇠 수치는 미확인.

**기술/재료 [제작자]:** Three.js·Svelte·GSAP·Vite와 Houdini/Blender 제작, 실시간 셰이더, 얼음 성장과 전환 후처리의 사용을 제작자가 설명한다. 이번 공개 entry는 16,546B이고 App3D를 별도 import한다. 그 파일은403으로 소스 미확보, 정확한 버전·셰이더·총페이로드는 확인하지 못했다.

**번안:** C의 처리실 바깥 곡면 링→중앙 디지털 배열 접근. 얼음/극지 풍경 자체는 ECG와 인과가 없으므로 기본안에서 옮기지 않는다. 밝은 중심과 깊은 바깥면의 대비, 큰 공간에서 세부 중심으로 들어가는 시각 문법을 쓴다.

### IG-E2: 입자가 다른 목표 형상으로 모인다 — 제작자 근거

**이번 근거 한계:** 아래의 입자 모델 전환은 직접 본 푸터 결과가 아니라 **제작자 설명에 근거**한다. `IG-07-volume.jpg`도 실제는 얼음집으로 돌아온 상태이며, 다른 입자 모델을 본 캡처로 쓰지 않는다.

**제작 방식:** 제작자는 푸터에서 모델 hover에 따라 입자 형태가 바뀌는 시뮬레이션, VDB 형상의 브라우저용 압축 export, 이동 속도와 연계된 색/빛을 설명한다. 카메라 동선을 greybox 예비 영상으로 먼저 공유하고 브라우저에서 shader/재료를 반복 튜닝했다. **정확한 particle count·보간 시간·export 포맷 스펙은 공개 글에서 확보하지 못했다.** [제작자]

**왜 C에 적합한가 [번안]:** 입력 파형을 단순 폭발로 없애는 대신 **무질서한 표본→정렬된 디지털 처리 공간→다른 형상인 출력**으로 재형성시킨다. ‘디지털 처리로 바뀐다’는 프로젝트 의미가 입자 target과 이동 방향에 붙는다. 원본은 브랜드 조형의 shape switching, 우리의 입력/출력 형상과 처리 격자는 독자 확장이다.

**구현 경로 [제안]:** 첫 시험은 20k 정도의 GPU Points/instanced 조각, 입력·중간 배열·출력 target을 미리 계산. WebGL2 ping-pong texture 또는 target buffer 보간으로 이동, 속도에 따라 국소 발광. 가까운 핵심 조각은 면/두께를, 먼 입자는 점으로 처리. 잡음층은 붉은/앰버 방향으로 빠지고 청록 출력은 결합한다. 수치는 **우리 시험 시작값**이며 원본값 아님. Houdini VDB 경로를 쓸지는 실제 조달 후 별도 선택.

**타임라인 [제안]:** 풀림→배열→재결합 3구간의 시작/중간/도착을 먼저 고정하고, 카메라 입력 p와 계속 흐르는 박동 t를 분리. p가 멈추면 전환 단계는 유지하되 그 단계의 표본/빛/심장 운동은 살아 있다. 임의의 가짜 SNR 상승 숫자로 진행률을 보여 주지 않는다.

**수용 기준:** 잡음이 제거된 출력이라는 방향이 읽히고, 역스크롤에서 같은 표본 조형이 되돌아감. 폭발만 보이거나 입자가 안개처럼 모두 뭉개지면 색이 아니라 target 밀도·속도·카메라를 수정. GPU 실패는 사전 렌더 설명 영상/정지 상태+단순 전환으로, 이후 비교 패널은 별도의 정확한 renderer로 인계. 재현 상태 none.

## 6. 다음에 보완할 조사와 판정

**지금 완료한 범위:** 위 선택 효과의 실제 화면, 끌리는 이유, 확인된 스택과 수치, ECG 번안, 구현 경로를 기록했다. 전체 사이트의 재현용 분석 완료와 동일하지 않다. 특히 원본 easing/ticker/모델 용량/모바일 및 reduced-motion 분기/목표 PC 성능은 미확인이다.

**제작 직전 순서:** 후보와 효과 선택 → 같은 입력 경로의 연속 녹화 → 선택 효과 6–12 프레임의 좌표/화각/색·글자 비율 → 필요한 자산의 포맷/크기/조달 가능성 → 한 효과 품질 시험 → 자체 Q/C 판정 → 사용자 피드백. 아직 미확인인 효과는 ‘원본과 같은 수준 verified’로 표시하지 않는다.

**이번 분류:** Editorial 3D 틈 진입 귀속은 철회, 2D 회전/글자 위계는 KEEP. Lusion 물성/큰 화면, Storybook 같은 세계 카메라는 번안 후보 KEEP. Igloo의 입자 전환은 제작자 근거를 가진 후보이며 **라이브 해당 구간 관찰 TUNE**. 이 분류는 사이트의 수상/전체 품질 판정이 아니라 우리 증거와 차용 범위의 판정이다.
