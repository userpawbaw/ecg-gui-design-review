# 40. 화면 글 교정 — 현재 GUI(`prototype/v2`) 적용 기록

> **이 문서의 자리** — `docs/39_ui_copy_style.md`(사용자 제공 화면 문안 규칙 U1~U8)를 이 저장소의 현재 GUI에 적용한 대응표다.
> 결정과 근거: D-160. 규칙 원천인 `95_academic_style.md` · `check_academic_style.py`는 원본 저장소에 있고 이 저장소에는 없다.
> 그래서 이번 교정은 39의 규칙표와 아래 §1의 차용 규칙으로 사람이 판정했다. 검사기를 돌린 결과가 아니다.

## 0. 2차 반영 (2026-11-08 사용자 피드백, D-160 보완)

- 영문 눈썹 글(OBSERVE · COMPARE · UNDERSTAND, SAME INPUT · SHARED TIME, METHOD EXPLORER)은 **되살렸다**. 아래 §3.1의 「표어 삭제」 행은 이 2차로 대체됐다.
- 화면의 서술 문장은 **「-입니다/-합니다」**로 끝낸다(「…오차이다」 → 「…오차입니다」). 라벨 · 버튼 · 상태값은 명사구 그대로. 아래 표의 「-이다/-한다」 교정안은 모두 이 규칙으로 바꿔 반영했다.
- 상태 그림은 2차 체계로 다시 그렸다(§2 갱신).

## 2. 그림 체계 (`prototype/v2/src/Glyph.tsx`, 2차)

11종. 1차(정사각 32 격자 · 몸체 그라데이션 판)는 사용자 비교 피드백으로 대체됐다. 2차 규칙:
- **주어 + 상태**: 모든 그림에 심전도 파형(청록 #5fd6c2, 신호)이 들어가고, 상태는 실물 실루엣(플러그 · 보드 · 계기 · 그래프 축, 회청 #8fa9a2)과 상태색 한 점(호박 · 산호 · 모래)으로.
- **좌 → 우 흐름**: 80 × 32(2.5 : 1). 「브리지 연결 없음」은 D-157 그림(파형 → 끊긴 점선 → 플러그 → 위로 휘는 전선) 구도를 그대로 잇는다.
- **획은 화면 픽셀 고정**(non-scaling-stroke): 칩 1.6 px, 큰 패널 2.4 px. 양감은 큰 패널에서 파형에만 은은한 번짐.

### 3.2 기법 설명 (`methods.json`)

이름은 39 §3.3의 정식 명칭을 따르고(Bandpass + Notch → 대역통과 · 노치 필터, Adaptive SWT → SWT 적응 임계값 처리, Residual U-Net → 잔차 학습 U-Net, Oracle wavelet → 오라클 웨이블릿 …), 원리 · 한계는 「-합니다」 안내체를 「-이다/-한다」로, 영문 혼용(denoiser, threshold, detail, checkpoint)을 우리말로 바꿨다.
한계 문장은 방어가 아니라 기법의 조건이므로 남겼다(「학습 자료 범위 밖의 장비 · 리듬 · 잡음에서는 성능이 달라진다」). 「같은 성능을 보장하지 않습니다」 같은 부정형만 긍정형으로 바꿨다.

### 3.4 실시간 측정

39 §3.2 · §3.3 · §3.4의 교정안을 그대로 반영하고, 상태는 그림 칩으로 바꿨다.
- 상태 막대: [linked] 연결됨 · [retry] 연결 끊김 · 재연결 중 · [cut] 보드 연결 끊김 · 출처 칩 [live] 보드 입력 / [stored] 저장 신호 재생 · --replay.
- 경고: 「⚠ 못 따라간다」 「⚠ 선이 뭉쳐 온다」 → [overload] 실시간 처리 한계 초과 · [jitter] 수신 간격 불규칙(칩, 툴팁에 기준값).
- 지표: 처리 지연 · 경과 시간 · 샘플 손실 · 전극 분리(lead-off)만 표시. 프레임 오류 · 재동기화 · 처리 누락 블록 · 실시간 계수(RTF) · 최대 수신 간격은 「진단 정보」 접힘.
- 출처 툴팁 「출처는 브리지 실행 방식을 따릅니다 — … 받은 신호는 기록하지 않습니다.」 → 삭제(출처 칩이 대신한다).
- 범례: 내부 코드 없이 정식 명칭만(39 §3.3).
