## 2. 산출물의 역할을 분리하는 방법

이 파일은 **순서와 상태의 색인**이다. A는 v2에 남기고 B·C는 각각 별도 씬 문서에서 수정한다. 시스템 v3는 모든 후보에 공통으로 적용하는 규칙만, 마이닝 보고서는 실제 레퍼런스의 관찰/기술/재료만 담는다. 예를 들어 `B2 틈이 너무 좁다`는 B 문서를 수정하고, `레퍼런스에 없는 효과를 원본에서 본 것처럼 서술했다`는 시스템과 해당 REF 카드를 수정한다. 하나의 수정이 두 파트에 영향을 줄 때는 작업 ID를 상호 링크하며 완료 상태를 각각 갱신한다.

**이미지 생성 상태:** 사용자 지시대로 보류. 이번에는 새 목업을 생성하지 않았다. 참고 사이트의 실제 화면 캡처는 분석 근거로만 저장했다.

3. **AB-TUNE / B-01 / B-02 보완 — 초안 완료:** A/B 수정 항목을 각각 작성. B를 원본 재현과 독자 확장으로 분해해 상세 프레임을 작성. A는 v2 + A-T 수정 명세로 검토.

5. **A/B/C 공동 검토 — 다음:** 사용자가 각 안의 유지/수정/보류 사항을 알려 주면 해당 문서만 수정. **제작 순서**와 각 안의 재사용 가능 부분을 확정.
6. **최종 시나리오 피드백 → 목업:** 선택한 안의 핵심 프레임 4장과 연결 장면을 생성하고 구도·빛·물성·주제 전달을 검토. 목업 수정도 안별 기록.
7. **구도와 전환 예비 동영상:** 정지 목업만으로 알 수 없는 카메라/가림/형태 변화를 회색 재질의 짧은 프리비즈로 확인. 해당 씬의 와우와 인과가 살아 있는지 판정.
8. **핵심 효과 구현 → 사용자 피드백 → 확장:** 아래 §4 순서를 선택 안의 씬마다 반복. 원격 제품 구현은 A/B/C 순서 결정 후의 단계.

레퍼런스 조사에서 단순 소개글로만 확보한 후보를 ‘완료’로 만들지 않는다. 이번 보고서의 완료는 **명시한 분석 구간**의 관찰·기술 분리와 ECG 번안까지다. 원본 효과의 모든 입력/시점과 전체 페이지의 완전 재현 검증은 이후 제작 카드의 별도 작업이다.
