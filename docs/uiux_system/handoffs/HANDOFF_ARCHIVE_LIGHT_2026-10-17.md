### 2.2 사용자에게 마지막으로 물은 것(답 대기)

1. **(a) 웅덩이 하나**(천창 x 1.7–3.5, y 2.45–3.88, 잎은 가장자리만) / **(b) 조각 유지**(D-084 천창, 잎이 가로지름).
2. **사다리 L1 / L2**. AI 권장은 L2다.
   - L1: 위 끝을 해치 뒤 모서리로 옮긴다. 그림자 6–7 px로 거의 개선되지 않는다.
   - L2: 뒷벽 레일 4.3 m에 기댄다. 그림자 2.0–2.4 px로 선명하다. 단, 사다리가 해치 안으로 오르지 않아 오르는 사람·해치 연출과 충돌할 수 있다.
3. **30° / 45°**: 평면에서 사다리가 뒷벽 면과 이루는 각도. `LAD_YAW` = 90 − 각도.
4. **칸 아랫면 재질 ×0.35(`UNDERSIDE_K=0.35`) 채택 여부**. AI 권장은 채택이다.
   - 아랫면/윗면 밝기 비가 0.60 → 0.27로 내려가고 나머지는 그대로다.
   - 앞턱(`SHELF_LIP`)은 앞면이 빛을 받아 밝은 띠가 되어 기각했다.

사용자가 함께 고민한 내용 `[대화]`:
- "해치 빛줄기가 왼쪽으로 떨어지는 것 자체는 오히려 r8보다 다채롭게 만드는 요소일 것 같은데, 책장 칸 아랫면이 더 어둡게 나오지 않는다는 문제가 이것에 영향을 받는지 고민되네. 후자만 개선할 수 있는지 방법을 탐색해볼까."
  - 답(측정): 해치 빛은 바로 아래 칸이 해를 받는 곳에서만 아랫면을 밝힌다. 가운데·오른쪽 아랫면 빛의 78–84 %는 주광 스폿이 칸 바닥에서 튄 빛이다. 그래서 해치 빛은 그대로 두고 아랫면만 고칠 수 있다.
- 사다리: "좀 더 벽쪽으로 붙여볼까? 또는 … 올라갈수록 벽에 붙게". L1과 L2가 이 두 안이다.

### 2.3 알려진 남은 문제

- 2.8 m 화면에서 주광 스폿이 지배해 잎 그림자가 약하다. 가중치 조정만으로 고칠 수 있다(`light-group-mix.py`로 바로 확인).
- 옮긴 사다리에 대해 오르는 사람 자세 검사를 하지 않았다(`pose-check-v3.py`). 가로대 접촉 오차 25 mm, 가로대 충돌 14.5 mm는 D-084 이전부터 있던 값이다.
- plain_range 42–48: 레퍼런스(45–54) 아래쪽 끝이다. 진한 색 비율 1.7–2.3 %(레퍼런스 5–6 %)이 부족하다.
- 웹 굽기, 웹 톤매핑, V1 카메라 웹 이식은 시작하지 않았다.
- 광원 그룹 EXR·.blend 원본은 저장소에 없다. 커밋된 것은 JPG와 측정값뿐이다. 가중치를 다시 섞으려면 §4.3 명령으로 해당 변형을 다시 렌더한다(빌드 1회 + 화면당 약 6분).

## 4. 작업 환경 재현

### 4.1 Python + Blender(bpy)
```
python3.11 -m venv ~/bpyenv
~/bpyenv/bin/pip install bpy==4.5.3 numpy==1.26.4 OpenEXR==3.5.2 pillow==12.3.0 scipy==1.17.1
```
(이 세션의 실제 버전: bpy 4.5.3 LTS, Python 3.11.17. Cycles CPU, 4코어 기준 1280×720 64샘플 한 장 약 6분.)

### 4.2 에셋(Poly Haven, CC0, gitignored `assets/source/`)
```
~/bpyenv/bin/python scripts/assets/fetch-polyhaven-sources.py .
```
md5를 파일마다 확인한다. `vintage_wooden_drawer_01`은 재게시되어 sha256 DIFF가 정상이다. 새 다운로드는 사용자 허가를 받는다. 이번 세션은 Poly Haven과 bpy 다운로드를 허가받았다.

### 4.3 렌더 명령

- B2 변형 하나, 광원 그룹 EXR 포함:
  ```
  LIGHTGROUPS=1 SHOTS_JSON='{"p2_z28":[[0,-0.8,2.8],[0,4.7,2.8],32],"p3_z20":[[0,-0.8,2.0],[0,4.7,2.0],32]}' \
  B2_FOLIAGE=branch [B2_EDGE=1 HOLES=1.7,3.5,2.45,3.88] LAD_MODE=wall|hatch_back|hatch LAD_YAW=60|45 [UNDERSIDE_K=0.35] \
  ~/bpyenv/bin/python scripts/blender/build_archive.py --intro2 --art r6 --dress --palette pastel --look h5 --b2 \
    --preview OUTDIR --samples 64 --res 1280x720 [--save OUT.blend] [--shots p3_z20]
  ```
- 가중치 섞기. 광원 세기를 바꾼 것과 같다(검증됨). 다시 렌더할 필요가 없다.
  ```
  ~/bpyenv/bin/python scripts/assets/light-group-mix.py OUTDIR/p3_z20_r2_off_r6_pastel_dress_lg0001.exr OUT.png key=0.5 sun=0.6 sky=4 rest=1 expo=0.3
  ```
- 측정:
  - `scripts/assets/frame-tone-stats.py`: L*, plain_range, sharpC 등. **plain_range는 같은 렌더 해상도끼리만 비교한다.**
  - `scripts/blender/shadow-sharpness-map.py`: 그림자 쌍별 반그림자 px, 가림 거리, 그늘 층위.
  - `scripts/blender/underside-light-sources.py`: 칸 아랫면 빛의 광원별 출처.
  - `scripts/assets/light-group-shares.py`, `light-group-sweep.py`: 구역 비율, 가중치 탐색.
- 렌더 중에 빌더를 고치려면, 빌더 사본으로 렌더한다(O-010).
  - 이 세션에서는 저장소 최상위 항목을 심볼릭 링크로 묶은 트리에 `scripts/blender/build_archive.py` 사본을 두었다. `ROOT`가 스크립트 위치 기준이기 때문이다.
  - 사본을 만든 뒤에 빌더를 고쳤다면 사본을 다시 복사한다. 이번 세션에서 낡은 사본으로 한 번 헛렌더했다.

### 4.4 레퍼런스 자료
레퍼런스 사이트 파일(glb, KTX2, js)과 녹화는 저장소에 없다. 이전 세션 임시 폴더에만 있었고 지금은 사라졌다. 다시 필요하면 사용자 허가를 받고 세션 임시 폴더에 받는다. 시트에는 "analysis only, not an asset"을 표시한다. 깨끗한 레퍼런스 지표는 `verification/r1-archive-ref-site-anatomy-20261016/README.md`에 있다.
