## 6. 효과 카드

### EFX-002-01 베이크 조명 3D 방 + 포인터 시선 회전

**선정 이유**: 사용자 지목("고개를 왼쪽 오른쪽으로 약간씩 돌리듯이 새로운 부분이 나타나는거야"), wow 포인트.
**지각**: 따뜻한 햇빛이 드는 방이 사진처럼 보인다. 마우스를 좌우로 움직이면 고개를 살짝 돌린 것처럼 방의 가장자리가 조금 더 보이고, 멈추면 부드럽게 따라와 멈춘다. 창밖 구름과 공기 중 먼지가 천천히 움직인다.
**입력 모델**: 포인터(시선 회전) + 시간(구름·먼지).
**판별 근거**: 사용자 가설은 "이미지를 일부 로딩하고 이동에 따라 추가 로딩"이었다 `[대화]`. 소스 확인 결과 **이미지가 아니라 실시간 3D 장면**이고, 포인터가 카메라를 회전시킨다. 장면은 처음에 모두 로드된다(추가 로딩 없음). `rX.onPointerMove`에서 목표 회전을 정하고 매 틱 지수 보간한다 `[코드]`.
**구현 메커니즘**:
```
카메라 계층: modelCamera(glb 안의 "camera" 오브젝트 위치·회전·fov 복사)
             └ mouseMoveCamera(포인터 회전 전용)
                 └ camera(스크롤로 이동, EFX-002-02)
onPointerMove(x, y ∈ [−1, 1]):
  targetRotX = deg(y × 0.2),  targetRotY = deg(−x × 0.75)
onTick(dt):  k = 1 − exp(−2 × dt);  rot = lerp(rot, target, k)   // 프레임률 독립 지수 보간
장면: scene_v9.glb(Draco) 메시마다 이름으로 베이크 텍스처 매칭
      → 조명 계산 없는 텍스처 재질(+ 선택적 hash blur) = 조명·그림자가 텍스처에 구워져 있음
생동감: 구름 인스턴스 25개(평면, 이동 0.5·변형 1), 먼지 파티클 2,000개(느린 변위·변형), 배경 그라데이션 평면
```
**파라미터**:
| 이름 | 값 | 출처 |
|---|---|---|
| 회전 폭 | 상하 ±0.2°, 좌우 ±0.75° | `[코드]` |
| 보간 계수 | `1 − exp(−2·dt)` → 시간상수 약 0.5 s(dt를 초로 가정) | `[코드]` `[추론]` |
| 카메라 fov | 기본 22.9°, glb 카메라 값으로 덮어씀 | `[코드]` |
| 입장 연출 | 카메라 x +5 → 0, 2 s, expo.out | `[코드]` |
| 구름 | 25개, 범위 19×13×20, 틴트 #F7EFE4 | `[코드]` |
| 먼지 | 2,000개, 변위 z −8.2, 속도 0.04, 크기 0.7(모바일 0.49) | `[코드]` |
**타임라인**: 로더 뒤 카메라 입장(2 s) → 이후 포인터에 따라 상시 반응. 스크롤 카메라(EFX-002-02)와 독립된 계층이라 동시에 적용된다.
**에셋**: `scene_v9.glb` 142 KB(Draco 지오메트리만), **베이크 텍스처 7장 KTX2 4096 px**: TexFleur 481 KB, TexProps 590 KB, TexMobilier 1.24 MB, TexTableaux 1.21 MB, TexBibli 723 KB, TexFloor 1.53 MB, TexWalls 572 KB(+ TexDecor 937 KB). 꽃 모델 `flower_v2.glb` 197 KB. 제작: Blender 등에서 모델링 → 조명 베이크 → glTF + KTX2 `[추론]`.
**성능 기법**: 조명을 텍스처에 구워 실시간 조명 계산이 없다(가벼운데 사진 같음). GPU 압축 텍스처(KTX2/Basis). 메인 씬은 header 또는 webgl 섹션이 화면에 있을 때만 렌더(`_updateHomeAboutGroupsScrollActive`). 초기 셰이더 사전 워밍업(`beginInitialShaderPrewarm`).
**접근성·폴백**: `prefers-reduced-motion` 처리 없음(번들 전체에서 0회) `[코드]`. 모바일은 `pathMobile` 에셋 분기와 줌 0.67.
**근거**: 카메라 계층·회전 수치 `[코드]`, 사용자 가설의 정정 `[대화]` `[코드]`, 텍스처 크기 `[런타임]`, 제작 도구 `[추론]`.
**재현 요구사항**: **베이크 조명 3D 장면**이 핵심 재료다 — Blender에서 모델링·조명·베이크 후 glTF(Draco) + KTX2로 내보내야 한다(Blender 작업 또는 외주 필요, 난이도 상). 코드는 카메라 3단 계층 + 지수 보간으로 간단(난이도 하).
**수용 기준**: (1) 포인터를 화면 끝으로 옮기면 좌우 약 0.75° 회전. (2) 포인터를 멈춘 뒤 약 1.5 s 안에 목표 각도의 95 %에 도달, 계단 없음. (3) 추가 네트워크 요청 없이 반응.
**ECG 번안**: 실험실·측정 장비가 놓인 "연구 공간"을 베이크 조명 3D로 만들고, 관람객 시선(포인터·터치)에 따라 미세하게 둘러보게 할 수 있다. 전시 키오스크에서는 포인터 대신 느린 자동 시선 이동을 기본값으로 둔다. 장면 속 화면에 파형을 띄운다면 canonical 데이터로 렌더한 텍스처만 쓴다.
**재현 상태**: `spike` — `prototype/spikes/attic` (베이크 조명 방 + 포인터 시선 ±0.75°/±0.2°, 2026-09-25 헤드리스 캡처; 실제 GPU 미검증) · 연구실 코너 v3도 같은 계열

### EFX-002-02 스크롤로 카메라가 내려가며 다가가기 (header)

**선정 이유**: 사용자 지목("아예 스크롤에 따라 시점이 아래로 내려가네. 좀 더 가까워지기도 하고. wow 포인트인 것 같아"), wow 포인트.
**지각**: 스크롤을 내리면 사진이 위로 밀리는 게 아니라 **카메라가 방 안에서 아래로 내려가며 앞으로 다가간다.** 가까운 사다리와 먼 창틀의 겹침이 달라져 입체가 느껴진다. 스크롤을 멈추면 부드럽게 멈춘다.
**입력 모델**: 스크롤 위치.
**판별 근거**: 소스 — `setScrollHeaderPositions(animatedScroll, headerRect, range, rotRange, offset, rotOffset)`이 매 렌더(`RENDER` 이벤트) 카메라 위치를 `−clamp(scroll / headerHeight × range, 0, range) − offset`으로 직접 설정. 위치 함수이므로 되돌리면 역으로 복원된다 `[코드]`. 녹화 22–26 s `[영상]`.
**구현 메커니즘**:
```
p = clamp(lenis.animatedScroll / headerHeight, 0, 1)      // Lenis lerp 0.085가 부드러움 담당
camera.position = −p × (0, 2.4, 4) − offset(0, 0, 0)      // 아래로 2.4, 앞으로 4 (glb 단위)
camera.rotation = −p × rotRange(0, 0, 0) − rotOffset
DOM 헤더 문구는 별도로 opacity·transform 페이드
```
3D 카메라를 실제로 이동시키므로 **원근 시차(가까운 물체일수록 많이 움직임)와 가림이 자연히 생긴다.** 사진 스크롤과 다른 핵심이 이것이다.
**파라미터**:
| 이름 | 값 | 출처 |
|---|---|---|
| 이동 범위 | y 2.4, z 4 (header 전체 높이에 걸쳐) | `[코드]` |
| 회전 범위 | 0 | `[코드]` |
| 스크롤 스무딩 | Lenis lerp 0.085(데스크톱), 모바일 1(즉시) | `[코드]` |
| 모바일 범위 배율 | `mobileScrollRangeScale`(About 0.55) | `[코드]` |
**타임라인**: header 영역을 스크롤하는 동안 선형(clamp). ScrollTrigger·scrub 없이 Lenis의 보간만으로 부드럽다.
**에셋**: EFX-002-01과 같은 장면.
**성능 기법**: 카메라 변환만 바꾸므로 추가 비용 없음.
**접근성·폴백**: reduced-motion 처리 없음 `[코드]`.
**근거**: 공식·수치 `[코드]`, 관찰 `[영상]` `[대화]`.
**재현 요구사항**: 3D 장면(EFX-002-01) + 스크롤 값 → 카메라 위치 선형 매핑 함수 하나. 난이도 하(코드) / 상(장면 제작).

### EFX-002-04 WebGL 드래그 갤러리 — 관성·스냅·드래그 힘으로 휘는 평면

**선정 이유**: 사용자 지목("부드러운 드래그 가속 반응"), 재사용 메커니즘.
**지각**: 사진 줄을 잡아끌면 손을 따라 약간 늦게 부드럽게 움직이고, 빠르게 끌면 가장자리 사진이 뒤로 물러나듯 휜다. 놓으면 관성으로 조금 더 가다가 가장 가까운 사진에 부드럽게 맞춰 선다. 끝이 없이 반복된다.
**입력 모델**: 포인터(드래그) + 시간(관성·스냅).
**판별 근거**: 소스 — DOM에서 미디어 크기를 측정해 WebGL 평면으로 복제하고(`addMedias`), 드래그 델타를 매 프레임 물리 루프(`onRender`)에 넣는다 `[코드]`. 녹화 1:01–1:11, 1:59–2:13 `[영상]`.
**구현 메커니즘**:
```
pointerdown → pointer capture, lenis.stop()(가로 드래그 판정 시)
pointermove → delta.x = 이전 x − 현재 x
매 프레임(u = dt × 60):
  currentDrag += delta.x × dragMultiplier(3)
  delta *= deltaDecay(0.9)                             // 놓은 뒤 관성
  rawForce = lerp(rawForce, |delta.x|, 1 − exp(−0.42·u))
  dragForce = clamp(rawForce × 400, 0, 600)
  smoothForce = lerp(smoothForce, dragForce, 1 − exp(−0.065·u))
  드래그 중 또는 smoothForce ≥ 42:
     smoothDrag = lerp(smoothDrag, currentDrag, 1 − exp(−0.068·u))   // 손보다 늦게 따라옴
  아니면(힘이 약해짐): 가장 가까운 칸으로 스냅
     smoothDrag = lerp(smoothDrag, index × width, 1 − exp(−0.055·u))
  각 평면 x = i × width − smoothDrag, 전체 길이로 wrap(무한 반복)
정점 셰이더: dist = smoothstep(0, 5.5, |화면 x|)
            z −= dist × uDragForce × 1.5              // 빨리 끌수록 가장자리가 뒤로 물러남
```

|---|---|---|---|

| deltaDecay(관성) | 0.9 / frame | 0.9 | `[코드]` |
| dragFollowLerp | 0.068 | 0.14 | `[코드]` |
| snapThreshold / snapLerp | 42 / 0.055 | 42 / 0.14 | `[코드]` |
| dragForce 계수 / 상한 | ×400 / 600 | 같음 | `[코드]` |

### EFX-002-05 틀 안에서 사진이 움직이는 시차 — 수평 드래그·수직 스크롤

### EFX-002-06 마우스 유체 왜곡 (GPU 유체 시뮬레이션)

### EFX-002-07 3D 벌 커서 동반자

**선정 이유**: wow 포인트(사이트 개성), 참고용.
**지각**: 작은 3D 벌이 커서 근처를 날아다니고, 클릭하면 말풍선으로 농담을 건넨다. 스크롤하면 스크롤 방향·속도에 반응한다.

**파라미터**:

**접근성·폴백**: 장식 요소. 대화 문구가 스크린리더에 노출되는지 미확인.

## 10. 열린 질문

- 벌 비행 경로·말풍선 로직, hero 제목 교체 타이밍은 해석하지 않았다.
- 포인터 회전 보간의 `dt` 단위(초/밀리초)를 코드에서 확정하지 못했다(시간상수 0.5 s는 초 단위 가정). → 로컬 세션에서 `?orbit` 없이 콘솔로 확인하거나, 규칙 녹화에서 정지 반응을 측정.
- 베이크에 쓴 도구(Blender Cycles 추정)와 텍스처 UV 배치(아틀라스 여부)는 KTX2를 풀어 봐야 알 수 있다 — 저작권상 저장소에는 넣지 않고 분석만 가능.
- 실제 GPU에서의 fps·GPU 메모리(4096 KTX2 × 8장 이상)는 측정하지 못했다.
- WebGL 미지원 시 폴백 화면이 있는지 확인하지 않았다.
