## 5. 검토 결과 — 보완·추가·수정할 점

### 5.1 보완 (발상은 유지, 방법을 강화)
1. **구도는 프롬프트가 아니라 키프레임으로 고정한다.** 글만으로는 매번 다른 구도가 나와 반복 비용이 커진다. 첫/끝 프레임 이미지(우리 Blender·three 블록아웃 렌더)를 조건으로 주고, 가능하면 회색 블록아웃 카메라 이동 영상을 video-to-video 가이드로 준다. 입고 QA가 첫/끝 프레임 일치를 SSIM으로 검사한다.
2. **"가감속"은 두 층이다.** 스크롤 관성(Lenis)은 손의 입력을 부드럽게 할 뿐, 영상 자체가 느렸다 빨라지면 같은 스크롤에 화면이 다르게 움직인다. 입고 QA가 광류로 속도 곡선을 재고 remap 표를 만들어 "같은 스크롤 = 같은 화면 이동"으로 맞춘다(시험 CV 0.605 → 0.11). 단 느린 구간에서 생긴 중복 프레임은 remap으로 없어지지 않으므로 브리프에서 일정 속도를 요구한다.
3. **정지했을 때 영상은 멈춘다.** 레퍼런스의 wow는 대개 멈췄을 때도 살아 있다(REF-003 소나). 두 방식을 시험해 쓰임새를 나눴다 — §10.

### 5.2 마우스 시선(고개 돌림) — 시험 후 정정

> **정정됨(2026-09-26)**: 첫 판은 "REF-002의 고개 돌림은 실시간 3D라서 가능했고, 평면 영상에서는 가려진 부분이 없어 한계"라고 적었다. 사용자가 "영상을 그렇게 만들어 달라고 하면 가능하지?"라고 반박했고, 우리 다락방 장면으로 진짜 렌더와 흉내를 비교하자 **REF-002의 경우는 첫 판이 틀렸다**(F-019).

REF-002의 고개 돌림은 **제자리 회전**(좌우 ±0.75°)이다. 제자리 회전은 물리적으로 시차를 만들지 않는다 — 가려진 물체가 드러나는 것이 아니라 **화면 가장자리가 새로 들어올 뿐**이다. 그래서 여백(overscan)을 두고 찍은 영상을 옮기면 거의 정확히 같아진다.

| 방식 (다락방, 화면 1280×720) | 진짜 렌더와의 평균 오차(0–255) | 구조 유사도(SSIM, 흐림 σ2) |
|---|---|---|
| 회전 +0.75°, 아무것도 안 함 | 18.4 | 0.749 |
| 회전 +0.75°, **overscan 이동 19.6 px** | **4.6** | **0.972** |
| 좌우 이동 0.12, 아무것도 안 함 | 23.7 | 0.710 |
| 좌우 이동 0.12, 평면 이동(최적 −52 px) | 5.8 | 0.956 |
| 좌우 이동 0.12, 실제 깊이로 변형 | 5.9 | 0.945 |
| 좌우 이동 0.30, 평면 이동(최적 −128 px) | 9.5 | 0.903 |
| 좌우 이동 0.30, 실제 깊이로 변형 | 10.6 | 0.874 |
| 중간 시점 0.06, **좌·우 변형 영상 50 % 섞기** | 16.3 | 0.784 |
| 중간 시점 0.06, 평면 이동 −26 px | 4.6 | 0.975 |

해석:
- **작은 회전(REF-002형)**: 영상 + 여백 이동으로 충분하다. 브리프에 "주 피사체 둘레 6 % 이상 여백"을 요구하면 된다.
- **머리를 옆으로 움직이는 이동(진짜 시차)**: 이 장면처럼 깊이 차가 작으면 평면 이동이 깊이 변형만큼 좋다. 깊이 변형은 가까운 물체 경계에서 늘어짐이 생겨 오히려 약간 나빴다. 깊이 차가 큰 장면(앞 물체와 먼 배경)에서만 깊이 맵이 이득을 볼 것이다 `[추론]`.
- **"시점이 다른 영상 여러 개를 만들어 마우스로 섞기"**: 두 겹 잔상이 생긴다(사다리·소품이 이중으로 보임). 영상 사이의 중간 시점은 섞기로 만들 수 없다. 여러 번 생성한 AI 영상은 서로 일관성도 없어 더 나빠진다.
- 사용자 제안 "시점이 내려가듯 찍은 영상"은 **스크롤 축**(하강)에 맞다. 마우스 축은 여백 이동이 담당한다 — 두 축을 영상 하나로 만들려면 시점 격자 전체가 필요하고, 그건 비싸고 잔상 문제가 있다. 진짜 시차가 핵심이면 V0에서 실시간 3D(또는 영상에서 3D를 복원하는 Gaussian Splatting — 미시험)로 보낸다.

### 5.3 추가
4. **V0 적합성 판정**(§2) — 모든 구간을 영상으로 만들지 않는다.
5. **입고 QA 자동화 + 사람 확인 분리** — 자동 검사는 컷·깜빡임·속도·해상도만 본다. AI 특유의 형태 녹아내림·가짜 글자는 12장 시트로 사람이 본다. 피드백 문장이 자동 생성되어 도구에 바로 넣을 수 있다.
6. **피드백 반복 상한** — 3회 안에 PASS/TUNE가 안 되면 대안 경로로 전환. 무한 재생성이 가장 큰 숨은 비용이다.
7. **출처·약관 기록** — 도구·요금제·약관(상업/비상업, 소유권)·프롬프트·입력 이미지를 registry 출처에 남긴다. 비영리 학술 전시라도 도구 약관이 전시 사용을 막을 수 있다.
8. **메모리·용량 설계** — 프레임 시퀀스는 압축 12–13 MB(720p 240장)로 가볍지만, 전부 디코딩하면 약 885 MB(4K ≈ 3.5 GB)다. 디코딩 창 방식으로 해결(F-018). 대안인 all-intra 영상 + `currentTime`/WebCodecs는 미시험.
9. **해상도 계획** — 생성 도구 출력은 흔히 720p–1080p다. 4K 전시 화면이면 업스케일을 V4에서 선명도로 검사한다.

**용량·메모리 실측(다락방 같은 장면)**: 받는 용량은 3D 장면 15.4 MB(모델 14.9 MB + 조명 이미지 3장) 대 영상 48장 3.0 MB(720p WebP)로 **짧은 영상이 가볍다.** 메모리는 영상이 720p 한 장당 3.7 MB로 디코딩 창 73장이면 약 270 MB — 3D는 GPU 텍스처 메모리를 아직 재지 않았다. "3D가 더 가볍다"는 메모리·긴 구간에서 맞을 가능성이 크고, 받는 용량은 짧은 구간이면 영상이 이긴다 `[테스트]` `[추론]`.

**판단**: 고정 경로 + 유기적 사실감 구간의 **첫 시안**은 AI 영상이 가장 싸다 `[추론]`. 정확한 구도·반복 수정·상호작용이 필요할수록 Blender/실시간 3D가 싸진다. 가장 유리한 조합은 **Blender 블록아웃(구도·카메라) → AI 영상(질감·빛) → 이 플레이어(디테일)**다. 실제 생성 도구의 비용·품질은 아직 측정하지 않았다 — 사용자 시험으로 확인한다.

## 10. 스크롤을 멈추면 영상도 멈춘다 — 두 방식의 판정 (D-026)

사용자 제안 두 가지를 구현해 시험했다(§6.2).

| | 1. 영상 위 살아 있는 층 (`?live=1`) | 2. 멈춰도 천천히 재생, 스크롤로 가속 (`?idle=play`) |
|---|---|---|
| 타당한 곳 | **모든 고정 경로 영상**(하강·전진·팬) | **반복 가능한 움직임**: 회전하는 물체, 흐르는 구름·물, 제자리 루프 — REF-001 moto 지구처럼 "위치"가 아니라 "회전량"이 스크롤과 연결되는 경우 |
| 안 맞는 곳 | 없음(단, 아래 주의) | **카메라 경로 영상**: 정지 중에도 카메라가 앞으로 가서 스크롤 위치와 어긋나고, 구간이 끝나기 전에 영상이 끝난다(시험: 스크롤 25 지점에서 영상 47/47 도달). 거꾸로 스크롤해도 되돌아가지 않는다 |
| 새로 생기는 문제 | ① **영상에 구워진 같은 요소가 멈춘 채 남는다** — 먼지를 코드로 얹을 거면 브리프에 "먼지·입자·흔들리는 빛 없이"를 요구. ② 층이 영상의 빛·원근과 맞아야 함 — 이 구현은 **영상 밝기로 먼지 밝기를 정해** 빛줄기 안에서만 반짝이게 했다. ③ 매 프레임 셰이더 비용(전체 화면 1패스, 먼지 3층) — 실제 GPU 미측정. ④ reduced-motion에서 끔 | ① **반복 이음매**가 보이면 튄다 — 입고 QA에 `loop_seam` 검사 추가(첫·끝 프레임 차이 ≤ 한 걸음의 2배). ② 스크롤 위치에 묶인 DOM 문구·섹션 전환과 영상이 어긋남 — 문구를 영상 위치가 아니라 스크롤에 묶어야 함. ③ "얼마나 스크롤했나"를 영상으로 알 수 없게 됨(REF-003 경로처럼 진행을 보여 주는 구간엔 부적합) |
| 권장 | 기본값 | 반복 영상에만, 1번과 함께 |

**조합 규칙**: 카메라 경로 구간 = 스크롤 위치 재생 + 1번. 반복 대상(지구·물체 회전) = 2번 + 필요 시 1번. 둘 다 아닌 긴 정지 화면이면 브리프에서 **별도 반복 클립**(같은 끝 장면의 3–6초 무한 반복)을 요청해 끝 지점에서 교차 전환한다.

**레퍼런스 사진(캡처)을 넣는 득실**
- 득: 글로 설명하기 어려운 색·빛·재질 분위기를 한 장으로 전달, 생성 반복 횟수를 줄일 가능성 `[추론]`.

## 12. 깊이 추정 맵이란

**이미 만든 영상에서 나중에 깊이를 뽑는 것**이다. 영상의 각 프레임을 깊이 추정 모델(이번 시험: Depth Anything V2 Small, Apache-2.0)에 넣으면 "각 픽셀이 카메라에서 얼마나 먼가"를 흑백 이미지로 추정해 준다(가까울수록 밝게). 플레이어는 마우스를 움직일 때 가까운 픽셀을 더 많이 옮겨 2.5D 시차를 만든다.

- 생성 **입력**으로 쓰는 깊이와는 다르다: 일부 생성 도구(video-to-video + 깊이 조건)는 우리 Blender 블록아웃의 **실제 깊이 패스**를 구조 가이드로 받는다 — 이건 구도를 고정하는 용도이고, 이 절의 깊이 맵은 완성 영상에 시차를 주는 용도다.
- 시험 결과(§6.2): 형태는 잘 맞지만(상관 0.905) **프레임마다 떨린다** — 그대로 시차에 쓰면 화면이 출렁인다. 시간 평균으로 절반 줄이면 경계가 흐려진다. 이번 장면처럼 깊이 차가 작으면 평면 이동이 같은 품질이라(§5.2) **기본값은 깊이 없이 overscan 이동**, 깊이 차가 큰 장면에서만 시간 일관성 모델을 시험한 뒤 쓴다.
