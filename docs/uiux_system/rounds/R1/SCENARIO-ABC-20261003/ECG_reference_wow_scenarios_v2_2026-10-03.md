## 1. 이번 수정에서 바로잡은 것

이전 [시나리오 v1](ECG_intro_story_scenario_review_2026-10-03.md)의 A(기록지 인쇄실)와 B(한 박동의 관측실)는 ECG의 뜻을 설명하는 데 집중했다. 그러나 **원본 레퍼런스에서 실제로 강렬했던 구체적 순간을 얼마나 옮길지**, 그 순간을 **어떤 구도로 목업에 넣을지**가 약했다. 특히 B는 레퍼런스의 명확한 시각적 기준보다 새 은유에 의존한다. 이 버전은 우선순위를 `원본 와우의 핵심 장면 → ECG와의 인과 → 프레임 구도 → 데이터 정합성`으로 정한다. v1의 두 안은 비교 후보로 남기되, 이번 목업의 기본안으로 자동 승격시키지 않는다.

사용자 피드백에 맞춰 **현재 Story는 전면 재제작 대상**으로 본다. [저장소 통합 계획](https://github.com/userpawbaw/ecg-gui-design-review/blob/claude/r1-autopilot-recommended/docs/uiux_system/rounds/R1/PLAN-R1-INTRO-STORY-V2.md)은 현재 인체·서고와 전원, 기저선, 근육의 P5 재구성을 다룬다. 아래 A안은 그 장소와 선택된 H5 인체를 **시나리오 재료**로 사용하지만, 현재 Story 화면의 행성, 정지 그래프, 코드식 기법 표기나 카메라 배치를 계승하는 제안은 아니다. 파형 엔진은 데이터가 검증된 부분만 계승한다.

### 관람객이 알아야 하는 이야기

첫 1초: **심전도 잡음 제거**. 다음: 심장에서 나온 박동이 실제 기록에는 잡음과 함께 나타난다. 이어서: 같은 기록을 처리하면 박동의 형태를 더 잘 읽을 수 있다. 그다음 세 장: 전원 간섭, 호흡에 따른 기저선 변동, 근육 활동이 각각 **어디서 생겼는지**와 **파형에서 어떻게 보이는지**를 보여 준다. 마지막으로 방법 비교 화면에 도착한다. 초반에는 기법 코드와 순위 결론을 말하지 않는다.

## 3. 목업 제작에 공통으로 적용할 화면 규격

기준 캔버스는 **1920 × 1080, 16:9**. 아래 모든 좌표는 왼쪽 위 원점, 픽셀 단위다. 주요 피사체의 `중심(x,y) / 화면 높이 또는 폭`을 적었고, 목업에서는 이 구도를 먼저 재현한다. 화면을 세로로 캡처할 때는 스크롤 상태를 `S0–S8`처럼 **각기 독립된 완성 프레임**으로 뽑는다. 스마트폰 구성은 별도 설계가 필요하며 이 구도를 무리하게 축소하지 않는다.

공통 파형 무대: Story 판독 구간에서 왼쪽 43% (`x=0–825`)는 **잡음 원인·사람·심장**, 오른쪽 57% (`x=825–1920`)는 **실제 저장 파형**. 그래프 영역 `x=930–1805, y=365–755`, 캡션은 그래프 바깥. 축과 얇은 격자는 남긴다. 실제 신호에 원근 왜곡을 넣지 않는다. 그래프의 노란 입력은 초록 출력에 비해 과도하게 밝지 않도록 같은 지각 밝기 범위를 목표로 한다. 도입부의 저장된 0 dB 혼합 입력, 이후 세 잡음의 저장 장면은 구분하여 표기한다.

카메라 움직임은 시각화용 제안값이다. `스크롤 p`는 각 행에서의 0–1 위치이고 **초 단위 재생 시간이 아니다**. 사용자 스크롤이 멈춰도 자전·호흡·심장·파형 등 독립 시간 요소는 계속 재생된다. `p`가 되돌아가면 카메라와 입력/출력 혼합 상태가 되돌아간다. 심장과 R 피크는 같은 저장 표본 인덱스를 참조한다.

## 4. A안 — 궤도에서 한 기록으로 내려오는 카메라

### A의 한 줄 논리

거대한 역광 지구가 관람객을 멈추게 한다. 카메라는 **그 지구 안의 특정 기록 보관 장소**로 끊김 없이 내려가고, 서고의 한 사람에게 연결된 전극을 따라 심장과 심전도 파형에 도착한다. 따라서 지구는 무관한 장식이 아니라 카메라 이동의 출발점이다. 이 설명이 목업만 보고도 읽히지 않으면 A안은 실패다.

**화면 질감:** 첫 3장면은 Moto의 차가운 검정·푸른 대기광을 가능한 한 충실히. 구름과 지붕을 통과한 뒤 광색이 따뜻한 앰버/아이보리로 변하면서 서고로 들어간다. 어두운 그림자 안에도 대륙 지형, 구름 두께, 서가의 깊이 정보가 남아야 한다. `Earth→room`을 순간 모핑하지 않는다.

### A의 Story: 같은 서고에서 원인을 찾아가는 새 3장

각 장 시작은 A8의 심장·파형에서 **뒤로 돌리**해 같은 인체와 서고를 다시 찾는다. 파형은 잠시 사라지며, 그 장의 원인이 작동한 뒤 오른쪽 판독면으로 돌아온다. `잡음 장 → 입력 → 출력`에서 원인과 파형이 한 장면에 같이 보이는 **정지 구간**을 둔다. 실제 저장 입력과 출력의 시간축은 동일하다. 연출 소품은 잡음의 **설명**이고 측정 현장의 촬영으로 주장하지 않는다.

| 아이디어 | 출처 | 한 프레임에서 보이는 사건 | 지켜야 하는 신호 규칙 / 검증 |
|---|---|---|---|
| **R 피크와 심장 한 시계** | 사용자 핵심 요구, 기존 구현은 대체로 만족 | 왼쪽 심장이 수축하기 시작하는 프레임과 오른쪽 R 피크의 sweep head가 지나가는 프레임이 일치. 스크롤을 멈춰도 계속 반복. | R 표본 인덱스 하나에서 심장 수축, 새 선, 모니터 표식을 구동. 독립 타이머 세 개를 각각 맞추는 방식 금지. 역스크롤 후에도 위상 점프 확인. |
| **sweep의 두 가장자리** | 사용자 기존 2.2.1v 피드백 | 새 선이 태어나는 쪽은 짧은 형광 헤드와 잔광, 오래된 선이 사라지는 오른쪽은 **국소적으로 부드러운 페이드**. 중앙 몸통은 읽기 좋은 명도. | 파형 좌표값은 바꾸지 않고 알파/광량만 변화. 첫 시안의 과밝은 노란 입력을 초록 출력과 균형 맞춤. 캡처 3프레임에서 선의 시작/몸통/소멸 밝기를 확인. |
| **한 박동씩 출력이 자리를 차지함** | 사용자 모니터 4박동 아이디어 + 확장 | 첫 R 뒤 1/4, 두 번째 뒤 2/4, 세 번째 뒤 3/4, 네 번째 뒤 전 구간의 청록 출력이 같은 시간 좌표에서 올라온다. 헤드가 마지막 칸을 통과할 때 작은 공간 광이 정리된다. | 입력/출력은 저장된 서로 다른 파형. 진폭을 중간값으로 변형하지 않고 **불투명도만 교차**. 4분할은 시각적 진행 표시이지 실제 알고리즘 처리 단계라 설명하지 않음. |
| **잡음 특징을 공간에 투사** | 신규 제안 | 전원: 전선이 닿은 컴퓨터에서 얇고 주기적인 빛 물결. 기저선: 방의 수평선이 아주 느리게 호흡. 근육: 손의 긴장 때만 국소 빛/미세 진동. 그래프는 흔들리지 않음. | 공간효과는 설명용. 입력 파형과 위상·시점이 어긋나지 않게 실제 저장 데이터의 관련 포락에서 구동. `60 Hz`를 초당 2–3회 물결 애니메이션으로 물리적 재현인 듯 쓰지 않음. |
| **파형을 여는 그래프 공간** | 사용자 격자·글자 피드백 + 확장 | 원인을 본 뒤 카메라가 멈추면 얇은 축/격자가 전경에 정착하고, 그래프 바깥에 큰 제목 면이 먼저 와서 선을 읽을 공간을 남긴다. | 파형 구역은 정면 평면. 작은 칸/큰 칸의 실제 시간·mV 대응 보존. 제목 시차가 R 피크를 가리지 않는지 확인. |
| **박동 이후 짧은 반응광** | 신규 제안 | R 피크가 지나간 뒤 심장 가장자리와 전극선의 빛이 1박보다 짧게 수그러든다. **심장 자체가 데이터보다 먼저 튀지 않는다.** | 수축 시작은 R 인덱스, 반응광은 같은 사건의 감쇠만. 광원효과가 피크 위치에 대해 지연으로 읽히지 않는지 60 fps 촬영 확인. |

독자 아이디어의 핵심은 **장면이 커져도 실제 파형을 훼손하지 않는 스펙터클**이다. 파형을 왜곡하는 파티클 폭발, 잡음이 지워지는 척하면서 R 피크 형태도 바꾸는 보간, ECG 그래프를 3D 투시로 눕히는 효과는 제외한다. 방법 이름은 전원/기저선/근육의 원인과 결과를 충분히 본 뒤에만 작은 정보층이나 Lab의 비교 패널에서 보여 준다.

## 7. 결과를 보고 스스로 수정하는 검토 장치

### 7.1 씬 카드의 필수 칸

목업용 각 씬 카드에는 `원본 레퍼런스 프레임/URL`, `우리 프레임 1920×1080`, `스크롤 p`, `독립 재생 시간 t`, `카메라 위치·시야각`, `피사체 중심·크기`, `글자 위치·크기`, `주목 순서`, `실제 데이터 구간/장식 구간`, `다음 씬으로 이어지는 물체·빛·선`을 넣는다. 한 칸이라도 비면 이미지 생성 지시문으로 넘기지 않는다. 레퍼런스의 wow를 쓴 씬은 두 이미지를 **같은 크기로 나란히** 놓고 검토한다.

### 7.2 두 축의 독립 평가

| 축 | 질문 | 실패 시 수정 |
|---|---|
| **품질 Q** | 원본에서 시선을 붙잡은 정확한 물성·빛·입체감·카메라 운동이 우리 프레임에서도 보이는가? Moto라면 대륙/남극 입체와 역광이 보이는가? Editorial New라면 종이의 회전/접힘 두께가 보이는가? | `TUNE`: 에셋 해상도, bump/roughness, 후처리, 조명, 렌더 경로부터 수정. 단순 색보정으로 입체 부족을 덮지 않는다. |
| **개연성 C** | 관람객이 글 없이도 `왜 이 물체가 다음 물체로 가는가`를 말할 수 있는가? A에서는 지구→목표 지점→고창→한 사람→심장→ECG가 한 경로인가? | `TUNE`: 중간 거리/목표 표식을 추가. 그래도 이어지지 않으면 `REJECT`하고 B처럼 직접적인 기록 매개로 교체. |
| **전달 E** | 첫 화면에서 ECG 디노이징을 알아차리는가? Story 각 장에서 원인과 파형을 연결하는가? | 제목, 관찰 시간, 원인·파형 동시 구도를 다시 설계. |
| **정합 D** | 같은 저장 표본·시간축에서 심장/R/입력/출력이 맞는가? 장식이 측정 결과처럼 보이지 않는가? | 하나라도 어긋나면 장면 채택 보류. 시각 품질 점수로 상쇄 불가. |

매 평가에는 `KEEP / TUNE / REJECT`와 **수정 지시 한 문장**을 붙인다. 예: `A3–A4: Q=KEEP, C=TUNE — 구름 뒤 고창 표식이 사라져 장소 연결이 끊긴다. 목표점을 960,540에 유지하고 지붕을 2프레임 일찍 노출.` 품질 Q와 개연성 C를 별개로 기록해야 예쁜데 의미 없는 장면을 걸러낼 수 있다. 목업 검토 시에는 사용자와 함께 프레임 4개(A0/A3/A5/A7, 또는 B0/B2/B3/B5)를 먼저 본 뒤 전체 시퀀스로 확장한다.

### 7.3 제작 전 내부 게이트

1. **정지 쌍:** 핵심 와우 프레임을 레퍼런스와 같은 비율로 나란히 비교. 피사체 크기·빛 방향·재질 정보가 부족하면 시나리오 문구가 아니라 시각 에셋부터 수정.
2. **인과 쌍:** 각 전환의 전·후 프레임에서 공통 목표점/선/물체를 형광 표시 없이 찾아낼 수 있어야 함. 찾지 못하면 설명문 추가가 아니라 전환 재설계.
3. **정지 스크롤 검사:** 스크롤을 멈춰도 심장·파형·원인 연출이 각자의 시간 규칙대로 살고, R 시계는 하나여야 함.
4. **데이터 판독:** 2.5초 창의 축, 격자, 입력/출력 동일 좌표, 노란/초록 명도, sweep 소멸 가장자리, R 동기, 역스크롤 복원 확인.
5. **Story 전면 재제작 검사:** 세 잡음 각각에 원인 발견 전경, 원인+심장+실제 파형 정지 구간, 출력 전환, 다음 장으로 카메라 왕복이 존재해야 함. 기존 Story의 저품질 지구/정지 파형을 기준으로 합격시키지 않음.

**현재 자체 판정:** A는 Moto 와우를 가장 직접적으로 보존할 잠재력이 크지만 Q와 C 모두 위험하다. B는 C가 강하고 제작 범위가 작지만 Q가 약해지기 쉽다. 둘 다 아직 `TUNE`이며 `KEEP`/최종 선택은 아니다. 이전 v1 A는 B의 출발 재료로만, v1 B 관측실은 정확한 레퍼런스 와우와 연결하는 근거가 약해 이번 우선 목업 대상에서 제외한다.

## 8. 원래 피드백과의 구체성 대조

| 원래 피드백이 이미 구체적이었던 지점 | 이 문서의 보강 | 남은 결정 |
|---|---|---|
| 지구 회전·역광 → 사람 윤곽·심장 → 파형 | A0–A8에 **중간 스케일 3장면**, 목표 좌표, 카메라 각도, 피사체 크기, 글자 면을 추가. `지구→사람` 모핑을 폐기하고 실제 장소를 통과하는 카메라 경로로 설명. | A의 지구가 ECG 맥락에서 충분히 납득되는지 목업 반응으로 판정. |
| 심장과 저장 R 피크 동기, 스크롤 멈춰도 재생 | 스크롤 p와 시간 t를 분리, A7/A8과 독자 아이디어에 단일 표본 시계 기재. | 프레임 단위 구현 검증은 목업 후 제작 단계. |
| sweep 소멸 fade, 새 선 형광 잔광, 0 dB 입력 명도, 격자 | 파형 독자 아이디어 표와 데이터 판독 게이트에 각각 명시. | 실제 밝기/잔광 길이는 나란히 본 시안에서 확정. |
| 전원 콘센트·컴퓨터·AC 표시·물결, 호흡, 손 쥠 | A Story에서 세 장 모두 **원인 발견 구도 → 왼쪽 원인/오른쪽 신호 → 처리 전환**으로 기술. B에서도 세 탭의 구도를 적음. | 원인 소품의 최종 조형과 각 장의 재생 속도. |
| 레퍼런스의 wow를 살리면서 이미지 생성 가능한 시나리오 | 원본 와우 사건을 표로 분리하고, A/B 각 씬에 1920×1080 위치·크기·렌즈·빛·텍스트·동작을 적음. | 사용자의 시나리오 피드백과 최종 선택 후 목업 생성. |

**결론:** 원래 피드백은 사건 순서와 동기 조건에서 이미 제작 브리프 수준이었다. 이 버전은 빠져 있던 **공간 좌표, 화면 점유율, 카메라 경로, 레퍼런스 와우와 의미 사이의 연결 검증**을 채운다. 이미지 생성에 쓸 핵심 정지 프레임은 정의되었지만, 세부 자산 확정과 A/B 선택은 아직 열려 있다. 따라서 목업은 사용자의 새 시나리오 검토와 최종 피드백 이후에 만든다.
