# 독립 GUI 확정 설계 · S2

작성: 2026-09-08. 원본 코드 기준: `5eb27946087faca3c6e70b3925e2ba132b2ee680`.
이 문서와 `independent/`는 이전 GUI 파일 재열람 전에 작성한다. 동결 후 수정은 `prototype/`에만 반영한다.

## 1. 프로그램이 증명해야 하는 것

**같은 입력에서 잡음이 줄어드는 정도와 신호가 달라지는 정도를 함께 관찰하고, 그 장면이 전체 실험에서도 성립하는지 확인한다.** 실제 장비에서는 참조 파형이 없으므로 취득 품질과 처리 상태를 별도로 판단한다.

주 사용자는 발표자·개발 팀원이고, 관람객은 발표 모드로 핵심 비교를 경험한다. 첫 화면에서 논문 전체를 읽거나 질환을 분류하게 하지 않는다. 시각적 우선순위는 파형 → 조작 조건 → 선택 방법과 근거 → 상세 출처다.

성공 과업:

1. 30초 안에 같은 입력·같은 시간·같은 진폭축의 FE 기준선과 선택 출력 차이를 설명한다.
2. 방법을 바꾸어도 record, noise, SNR, 선택 구간이 유지됨을 확인한다.
3. 더 높은 scaled SNR을 보고 strict SNR과 α를 확인하여 진폭 보정 효과를 구별한다.
4. 한 장면의 차이를 전체 EXP-A 결과와 혼동하지 않는다.
5. 데이터가 오지 않는 계측 화면을 보고 LIVE라고 오해하지 않는다.

30초는 설계 목표이며 사용자 실험 결과가 아니다.

## 2. 정보 구조 결정과 대안

| 대안 | 장점 | 약점 | 판단 |
|---|---|---|---|
| 질문마다 독립 페이지 | 명확한 설명, 고정 시연 순서 | 선택 조건이 복제되고 이동하며 기억해야 함 | 체험 안내에는 유용하나 작업 공간의 기본 구조로 채택하지 않음 |
| 하나의 큰 대시보드 | 모든 수치 동시 확인 | 국소·전체·실시간 근거를 섞기 쉬움 | 제외 |
| 작업 공간 3개 + 같은 상태의 상세 보기 | 데이터 성격과 사용 과업을 분리하고 조건을 유지 | 범위 표시와 복귀 규칙이 필요 | 채택 |

선택 구조:

- **실험실**: 사전 계산한 파형을 조건별로 비교. 선택 구간 상세는 같은 화면 하단에 연결한다.
- **전체 근거**: EXP-A의 record 단위 결과를 검토. 실험실의 EXP-G 저장 장면과 별도 결과임을 명시한다.
- **계측**: 참조가 없는 실제 스트림의 상태를 점검. 연결되지 않은 프로토타입에는 저장 파형도 자동 삽입하지 않는다.
- **발표 모드**: 실험실 상태를 그대로 유지하며 설명 영역을 줄이는 표현 방식. 별도의 데이터 세트나 숨은 최고 성능 장면을 만들지 않는다.
- **출처·계산 규약**: 다이얼로그. 현재 파형 출처, 시간, 선택 편향, 양자화, 재현 상태를 확인한다.

새 화면은 기존 화면의 결함뿐 아니라 다른 질문·다른 데이터 계약·독립 작업 수명 때문에 추가할 수 있다. 이번에 전체 근거와 계측을 분리한 이유가 그것이다. 방법 설명과 구간 확대는 질문과 입력이 같으므로 패널로 남긴다.

## 3. 레이아웃과 시각 문법

기준 1440×960, 최소 검토 1024px 데스크톱. 760px 이하에서는 열을 세로로 쌓고 문서 전체가 스크롤되게 한다. 고정 높이로 내용을 잘라내지 않는다.

| 영역 | 기준 배치 | 설계 의도 |
|---|---|---|
| 전역 헤더 | 72px 내외, 로고·작업 공간·출처 버튼 | 어디에 있는지, 어떤 데이터인지 항상 인식 |
| 화면 제목 | 짧은 질문과 한 문장 설명 | 핵심 성과를 기능명보다 먼저 이해 |
| 조건 바 | 데이터 축·잡음·SNR·record 표시 | 조작 원인과 입력 정체성 연결 |
| 파형 영역 | 남은 폭 약 72%, 어두운 배경 | 데이터에 첫 시선, 동일 시간축의 세 행 |
| 방법 영역 | 약 28%, 최소 260px | 방법 탐색, 선택, 원리·한계 |
| 구간 상세 | 파형 아래 전폭 | 전체 문맥에서 고른 시간 범위 확대 |
| 상태 메시지 | 원인 가까이, 완료는 별도 status | 조작 확인, 오류와 정상 완료 분리 |

배경은 밝은 중성색, 본문은 진한 청회색. 파형 패널은 짙은 남색이다. 입력은 주황, 선택 출력은 청록, 참조는 옅은 보라 점선, FE는 회청색. 선택색과 정상 상태를 같은 의미로 취급하지 않는다. 색마다 텍스트·선 모양·위치가 동반된다. 둥근 카드는 작업 경계를 표현하는 곳에만 사용한다.

타이포그래피: 제목 28–32px, 본문 15–16px, 보조 12–13px. 핵심 수치는 tabular numerals. 유료 웹폰트/CDN 없이 시스템 폰트를 사용한다. 기본 버튼 높이는 38px 이상; 작은 보조 버튼도 28px 이상과 간격을 확보한다.

## 5. 상태 보존과 오류

중앙 상태: workspace, axis, noise, snr, method, selection(start,length), amplitude, view(trace/residual), playback, presentation, provenanceOpen.

- 방법 변경: 입력·시간·진폭 유지. 출력/설명/지표만 교체.
- 조건 변경: method·time·amplitude 유지. source/record 변경은 안내. 없는 조합은 명시적 unavailable.
- 작업 공간 이동: 실험실 상태 유지, 재생 정지. 복귀 시 자동 재생하지 않음.
- popup 닫기: 이전 트리거에 focus 복귀. Escape와 닫기 버튼 지원.
- 잘못된 시간: 경계 범위로 보정하고 사용자에게 알림. NaN·역전 구간·0길이 계산 금지.
- 데이터 손상/누락: 오류 패널, 재시도. 이전 지표를 새 조건의 결과처럼 남기지 않음.
- 향후 비동기 inference: runId별 결과, 새 요청 뒤 늦게 온 이전 결과 폐기. loading 중 입력/완료 결과 scope 분리.

## 7. 접근성과 읽기

버튼/선택에 native semantics, 항상 보이는 label, `aria-pressed`, 키보드 focus ring을 쓴다. hover 전용 필수 정보 없음. 시간 선택에 숫자·단계 이동이 있어 단일 포인터와 키보드 모두 가능하다. 파형 SVG에는 title/desc, 동일한 수치를 담는 표/요약이 동반된다.

동적 메시지는 `role=status` 한 곳으로 전달하되 매 프레임 읽지 않는다. 데이터 오류는 `role=alert`. 줄바꿈·200% 확대에서 핵심 조작을 숨기지 않는다. 모션 축소 설정 존중. WCAG 최소 목표 크기와 대비를 점검하되 자동 검사만으로 접근성 전체 적합을 선언하지 않는다.

## 8. 실제 제작 범위와 후속 연결

독립안: 오프라인 실행, 저장 실제 output, 2축·4잡음·6 SNR, 7방법+identity, 동일 축 비교, 시간 선택, residual, 재계산 지표, 전체 실험 표, 명확한 계측 빈 상태, 출처 확인.

최종안에서 반드시 다시 판단할 항목: 기존 GUI의 좋은 비교 흐름·전시 복귀·다중 비교 방식을 수용할지, 시연 프레임 누락, 실제 exporter/bridge와의 경계, 팀 디버깅 식별 체계.

범위 밖 검증: 모델 재학습/재추론, 실제 AFE 연결, 임상 적합, Windows 전용 브라우저·GPU·스크린리더 실기. 이들은 화면 제작 완료와 별개의 gate다.
