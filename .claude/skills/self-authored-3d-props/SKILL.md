# 자체 제작 3D 소품 — 제작과 검수

기원: 2026-10-18 사용자 요청. 초기 서고의 컴퓨터·프린터 등은 외부 에셋보다 자체 제작 형태를 충분히 검수하지 않은 문제가 컸다(F-108). 기존 리뷰 §5·§7과 외부 MIT 스킬 2종의 hard-surface/asset-QA 작업 흐름, Polycount 업계 위키의 베벨·노멀·베이크 트레이드오프, Blender 공식 문서를 조사해 프로젝트에 맞게 종합했다(`references/sources.md`). 외부 스킬 코드/본문은 복사하지 않았다. 외부 스킬은 Blender 5.2 기반이고 여기의 bpy는 4.5.3이므로 해당 스크립트를 그대로 실행하지 않는다. **모든 수치는 이 서고의 출발 목표이며 보편적인 합격값이 아니다.**

작업 전 `docs/playbook/README.md`에서 맞는 카드(P-006 등), `docs/uiux_system/24_ASSET_RESEARCH_STAGE.md` §1.1, 서고 리뷰 §5·§7을 읽는다. 스킬은 `.claude/skills/`용이며 다른 환경에서도 아래 절차를 그대로 따른다. Story 소유 파일·소품, r8/D-084 기본값은 확인 없이 바꾸지 않는다. 디자인 갈림길이면 먼저 D를 기록하고 다른 원격 브랜치의 번호를 확인한다.

## 1. 제작 브리프와 형상

1. 대상의 역할, 실제 또는 설계 치수(m), 놓이는 높이·주변 물체·카메라 거리/FOV를 적는다. 실측 자료가 없으면 **가정** 표시. 프린터/CRT/ECG 모니터를 단지 `box()` 하나로 대신하지 않는다.
2. 사진·제조사 치수도·자체 스케치 2–3개에서 **형태 특징만** 추출한다. 링크와 관찰점을 기록한다. 레퍼런스 사이트의 이미지/코드/모델을 저장소로 복사하지 않는다. ECG 장비 화면에 합성 파형을 실제 데이터처럼 넣지 않는다.
3. 먼저 회색 점토(clay)로 큰 덩어리, 밑면/발, 틀, 패널, 화면·트레이·손잡이의 **진짜 깊이 차**를 만든다. 사용자가 볼 시점에서 3/4 실루엣을 확인한다. 작은 장식으로 큰 비례 문제를 가리지 않는다.
4. 파라미터에 이름·단위를 붙인다. 크기 변경 시 베벨 폭·인셋·UV 물리 크기도 따라 계산한다. 뷰 변환 전후 크기를 확인해 nonuniform scale로 베벨 폭이 왜곡되지 않게 한다.

## 2. 엣지·법선·표면

1. 목표 화면에서 빛을 받아야 하는 보이는 바깥 모서리에 실제 베벨 후보를 둔다. 모든 미세 엣지를 무조건 세분화하지 않는다. Polycount는 베벨이 실루엣/하이라이트를 개선하지만 긴 얇은 삼각형과 정점 비용을 늘린다고 설명한다. subpixel 엣지는 법선/베이크와 비교한다. 서고 출발 범위: 판재 3–5 mm, 소품 2–4 mm, 책 1.5–3 mm; 2 segment + Weighted Normal을 시작값으로 시험한다. 베벨 폭은 국소 두께의 절반 미만으로 하고 겹침·역전·광택 줄무늬를 검사한다. 평면 음영이 흔들리면 실제 면 평탄성·smooth shading·sharp edge·modifier 순서를 먼저 확인한다. Weighted Normal은 깨진 비평면 형상을 고치는 도구가 아니다.
2. Boolean 컷이 필요한 장비라면 컷터를 실제 표면 너머로 통과시키고, 컷 후 베벨·법선 순서로 평가한다. 베벨이 일부에서 갑자기 줄거나 평면 음영이 흔들리면 컷터의 너무 좁은 벽·겹침·비균일 스케일을 먼저 본다. Blender 5.2 스킬의 수치/자동 코드는 bpy 4.5.3에서 검증 전이므로 이 저장소에 그대로 도입하지 않는다.
3. 서랍 틀/안쪽 판, 화면 테두리/유리, 프린터 상판/출구, ECG 기기 몸체/디스플레이를 실제 기하 단차로 분리한다. 서고 리뷰의 첫 인셋 목표는 5–10 mm. `z-fighting`이나 빛샘 없는지 옆·역광에서 확인한다.
4. 단색/낮은 대비의 미세 결을 기본으로 두고 책은 물체별 명도 차로 구분한다. 먼지·마모·과한 노이즈를 자동 추가하지 않는다. 재질 원본(알베도·노멀·거칠기), UV 물리 스케일, 베이크, 압축을 각각 비교한다. Poly Haven 출처만으로 품질 합격을 선언하지 않는다.
5. 웹용 굽기 전 UV 여유와 경계 출혈을 확인한다. 베벨 하이라이트가 베이크에서 최소 2–3 텍셀로 표현되는지 목표 텍셀 밀도에서 계산한다. 색맵과 법선/거칠기맵의 색 공간을 구분한다.

## 3. 관문 — 소품마다 표 한 줄씩 증거를 남긴다 (`references/qa-template.md`)

| 관문 | 방법 | FAIL 조건 |
|---|---|---|
| Q0 소유·출처 | 소유 파일, 참고 URL·라이선스, 직접 제작/외부 조달 구분 | Story 소유물 무단 변경, 출처 불명·참조 사이트 파일 반입 |
| Q1 비례·실루엣 | 치수표 + 단색 정면·측면·3/4 클로즈업. 실제 대상 특징 3개를 적어 식별 | 장비가 무특징 상자로만 읽힘, 주요 비례 오류, 접촉·관통 |
| Q2 엣지·단차 | 모델링 값과 측면/역광 캡처. 의도적 예외 외 보이는 모서리 조사 | 베벨 누락, 겹친 베벨, 평면 그림으로 만든 기능부, 노멀 아티팩트 |
| Q3 재질·UV | 동일 조명의 clay/재질 비교와 원본·베이크·압축 비교 | 얼룩이 형태를 가림, 반복/스미어/이음선, 해상도 원인 미분리 |
| Q4 실제 화면 | 목표 카메라·해상도에서 원본 크기 캡처. 주요 기능부·1–2px 엣지 하이라이트를 실제 픽셀로 확인 | 클로즈업에서만 좋아 보이고 최종 화면에서 읽히지 않음 |
| Q5 장면·성능 | 접지·가림·Story 충돌·파일 크기·메시/재질/텍스처 수 기록 | 침투/떠 있음, 다른 주연 가림, 예산 미확인인데 배포 합격 주장 |

Q1·Q2는 **clay에서 통과 후** 재질을 얹는다. Q2에서 적용 전후 object scale, 역방향/깨진 노멀, zero-area 면, nonmanifold 경계, 겹친 coplanar 면, 바닥 접촉, 예산 초과를 점검한다. 다만 열린 판재나 의도적 비접촉 구조는 예외 이유를 기록한다. high→low 노멀 베이크를 선택했다면 low-poly 삼각화가 bake/export 사이에서 같고 hard edge와 UV seam이 일치하는지 확인한다(Polycount Texture Baking). 자동 진단 PASS만으로 형태·음영 합격을 선언하지 않는다. Q4의 1–2px은 기존 서고 리뷰의 미적 목표이지 영상 전체의 정량 단독 판정이 아니다. 카메라가 8.5m/22.9°가 아니면 3.6mm/px을 그대로 쓰지 말고 수평/수직 투영을 다시 계산한다. 수치 검사와 육안 판정 모두 필요하다. FAIL은 수정 후 같은 각도·조명으로 재촬영한다. 관문별 `PASS / CONDITIONAL / FAIL / 확인 안 함`, 촬영 조건, 실제 치수·화소·자산 수, 판단한 사람/환경을 `verification/<작업>/README.md`에 쓴다. 확인 안 한 항목을 PASS로 합치지 않는다.

초기 빌더의 박스형 PC/CRT/ECG 기기는 Q1·Q2 재검수 대상이다. 이 물체가 담긴 빛 시험 렌더는 **빛의 진단 자료**이며 소품 품질 합격 자료가 아니다. 새 키트를 채택할 때는 별도 D와 소유 범위 조율을 거친다.
