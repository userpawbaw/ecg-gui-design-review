## 0. 이번 검토의 범위와 근거

이 문서는 사용자가 보낸 피드백, 브랜치의 [외부 AI용 브리프](https://github.com/userpawbaw/ecg-gui-design-review/blob/claude/r1-autopilot-recommended/docs/uiux_system/handoffs/SCENARIO_BRIEF_EXTERNAL_AI_2026-10-01.md), [기존 공간 시나리오](https://github.com/userpawbaw/ecg-gui-design-review/blob/claude/r1-autopilot-recommended/docs/uiux_system/rounds/R1/SPACE-R1-ARCHIVE.md), 실제 저장된 장면 캡처를 대조한 결과다. 첨부 영상 파일은 이번 대화에서 확인할 수 없어 사용자가 설명한 17–22초, 25초 장면을 직접 프레임 분석한 것으로 주장하지 않는다. 설명된 시차와 글자 효과는 이미 저장소의 REF-003 White Desert 분석과 일치한다.

브랜치에 구현된 것은 역광 지구→인체 외곽선→심장→2.5초 파형 스윕이다. 지구와 인체의 연결, 중간 삼각형 형태, 마네킹 질감, 빈 화면이 문제로 기록되어 있다. 파형의 0 dB 입력, 그리드, R 동기, 네온 잔광, 지우는 쪽 페이드, 박동마다 4분의 1 출력 교차는 구현 기록과 캡처가 있고 사용자가 거의 만족한다고 밝혔다. 최근에는 서가·사다리·블라인드 빛·앉은 고리 인체로 공간을 채우는 시험 장면과 인체 v3 정지 렌더가 추가됐다. **정지 렌더의 존재는 스크롤 속 품질이나 목표 PC 성능 검증이 아니다.**

**Story 상태 정정:** [통합 계획](https://github.com/userpawbaw/ecg-gui-design-review/blob/claude/r1-autopilot-recommended/docs/uiux_system/rounds/R1/PLAN-R1-INTRO-STORY-V2.md)의 P5는 전원 간섭·기저선 변동·근육 잡음 **세 장면을 재구성하는 단계**다. 현재 Story 화면의 저품질 행성·정지 파형·기법 코드·기존 배치는 폐기 대상으로 이해한다. 원인 전체 3D 장면 → 왼쪽 원인/심장과 오른쪽 실제 파형의 이분할 → 처리 전환 → 다음 원인으로 이동이 계획 문법이다. 이 문서의 A/B Story 표는 그 계획과 경쟁하는 **새 제작안**이며, 현재 Story의 화면·소품·카메라를 재활용하거나 그 품질을 전제로 삼지 않는다. 도입부의 검증된 파형 재생 엔진과 데이터 계약만 재사용 후보로 둔다.

피드백의 핵심은 “더 화려한 행성”보다 **무엇을 시연하는지 즉시 알림 → 저장된 박동과 파형의 정확한 연결 → 잡음의 원인을 화면 속에서 발견 → 같은 기록이 처리 전후 어떻게 달라지는지 보여 줌**이다. 글자는 데이터 옆의 작은 설명이 아니라 화면 구도와 움직임을 이끄는 층이어야 한다. 3D 인체는 수단이지 필수 목적이 아니다.

| 피드백이 가리킨 장면 | 사용자가 중요하게 본 것 | 결과물에서 보여야 할 판별 장면 |
|---|---|---|
| 첫 제목 | 처음 보는 관람객이 한눈에 주제를 안다 | `심전도 잡음 제거`가 첫 1초부터 충분한 크기로 읽힘 |
| 지구→인체 | 화면의 이유와 형태의 완성도 | 어떤 3D 물체든 다음 장면을 여는 인과가 보이고, 중간 모양/실루엣이 어색하지 않음 |
| 심장→파형 | 스크롤이 멈춰도 살아 있는 정확한 박동 | 심장 또는 박동 상징과 R 피크가 동일 프레임, 재생은 독립 시계 |
| 입력→출력 | 예쁜 빛보다 신호 정직성과 전환 임팩트 | 낮은 명도의 주황 입력과 청록 출력이 같은 좌표에서 알파 교차, 축·격자 유지 |
| 큰 문구 | 글자가 공간·시선의 일부 | 무엇을 먼저 읽는지 위치·크기·등장 순서·머무름 시간이 설계됨 |
| 전원/기저선/근육 | 잡음 종류를 기법 설명 없이 알아차림 | 콘센트·전선, 느린 호흡, 손 쥠을 각각 저장된 입력 파형과 나란히 볼 수 있음 |
| 방법·성능 | 초반에 의미 모를 코드나 거짓 순위가 없음 | 방법 선택은 Lab에 두고, 수치는 저장 근거가 있을 때만 표시 |

사용자가 좋아한 파형 장면은 바꾸기 위한 대상이 아니라 **새 도입부가 반드시 도달해야 할 품질 기준**이다. 두 안에서 오브젝트의 재질과 무대는 바꾸지만 그 장면의 0 dB 입력, R 동기, 네온 헤드, 국소 페이드, 그리드와 4박동 교차는 재사용하도록 설계했다.

Story는 별도 품질 기준이 필요하다. 세 잡음 각각에서 (1) 원인의 위치와 작동을 글 없이 알아볼 수 있고, (2) 카메라가 원인을 찾아간 뒤 읽기 가능한 이분할 구도로 멈추며, (3) 저장 입력 파형이 멈춘 이미지가 아니고, (4) 3D 원인·심장·R 피크가 정확히 동기화되며, (5) 다음 장면으로 이동할 때 공간·원인·상태가 이어져야 한다. 현재 화면이 이 조건을 충족했다고 주장하지 않는다.

## 1. 원래 시나리오의 구체성 평가

원래 피드백은 장면의 순서, 카메라 방향, 인체/심장의 위치, 한 박동과 R 피크의 시간 동기, 2.5초 창, 노이즈 0 dB, 교차 전환, 전원선·콘센트·60 Hz 물결·모니터 4칸, 호흡·주먹의 데이터 연동까지 지정한다. **아이디어 수준보다 훨씬 구체적인 제작 브리프**다. 다만 화면 좌표와 글자의 크기·등장 시점, 스크롤 정지 때 독립적으로 사는 요소, 장면 이음새, 실패 시 대체안, 실제 데이터와 설명 연출의 경계는 열려 있다. 저장소의 후속 브리프는 이 빈칸을 장면 표와 수치 계약으로 보완했다. 아래 제안은 그 브리프의 형식을 기준으로 한다.

### 바꿀 수 없는 계약

- 파형 꼭짓점은 저장된 S038 250 Hz 표본에서만 그린다. 도입부 0 dB 백색 잡음 입력과 저장된 Residual U-Net 출력; Story 세 잡음은 각각 −5 dB 저장 장면. 수치가 필요한 곳은 저장값만.
- 그래프의 시간 `s`와 진폭 `mV`, 작은 칸 `0.04 s × 0.1 mV`, 큰 칸 `0.2 s × 0.5 mV`는 파형과 같은 좌표계에 둔다. 원근 연출은 그래프 바깥 장식에만 적용한다.
- 심장 또는 박동 상징을 쓰면 실제 R 표본 인덱스 하나를 공유한다. 스크롤 정지 중에도 재생 시계는 계속 간다. 스크롤은 장면과 출력 혼합 목표만 바꾼다.
- 전원·호흡·주먹은 합성 잡음을 이해시키는 **설명용 연출**이며 실제 측정 장치/인체 반응처럼 제시하지 않는다. 60 Hz 물결의 느린 이동은 주파수 자체가 아니라 위치를 알려 주는 상징이다.
- “기법별 1등이 바뀐다”는 메시지는 쓰지 않는다. 기존 브리프에 따르면 세 잡음의 −5 dB 저장 결과에서 모두 딥러닝이 1등이다. 방법 비교는 실험실에서 관람객이 선택하게 둔다.

## 3. 시나리오 A — **기록이 열리는 인쇄실**

### 콘셉트와 화면 언어

와우 지점은 지구나 인체 변형 대신, 화면을 꽉 채운 거대한 **접힌 심전도 기록지**가 스크롤에 맞춰 펼쳐지면서 그 안쪽에 원인 무대가 드러나는 순간이다. 서고처럼 “보관”을 말하지 않고, **저장된 한 기록을 읽는 행위**를 인쇄·재단·투과광의 물성으로 보여 준다. EXT-REF-02의 물리적 접힘, EXT-REF-01의 고정 그래프, EXT-REF-03의 층 시차를 결합한다. 완성형 첫 화면의 제목은 왼쪽 상단에 `심전도 잡음 제거`; 한 줄 보조 문구 `같은 기록의 입력과 처리 결과`. 가운데는 우측 아래에서 화면을 가로지르는 접힌 아이보리 종이의 큰 면, 오른쪽 뒤에는 얕은 금속 트레이와 둥근 투과광. 사람 얼굴이나 지구는 없다.

### A의 접합·제작 판단

접힘은 WebGL의 장식 종이 mesh에서만. 그래프가 나타나는 순간에는 DOM/Canvas 정면 화면으로 마스크를 넘겨 **물리 눈금이 기울거나 접히지 않게** 한다. 종이 굽힘은 12–16개 관절의 스킨 또는 정점 셰이더로 만들고, 실제 인쇄 문자는 DOM으로 분리한다. 그림자는 베이크하고 접히는 끝부분에만 동적 접촉 그림자를 둔다. 인체 종이 절개는 2.5D 레이어라 플라스틱 불쾌감을 피할 수 있다. 에셋은 자체 제작하거나 CC0 소스만 확인해 사용한다. 실패 위험은 종이 접힘이 ‘또 다른 장식’으로 보이는 것과, 실제 파형을 종이에 직접 인쇄한 듯 보여 평면 그래프 계약을 흐리는 것. 정지 목업에서 **파형 전·후와 축은 항상 별도 정면 무대**임을 먼저 검사한다.

## 4. 시나리오 B — **한 박동을 통과하는 관측실** (과감한 안)

### 콘셉트와 화면 언어

한 화면을 채운 수백 개의 밝은 표본점이 흩어진 별처럼 보이다가 카메라가 빠지면 **실제 2.5초 ECG의 정확한 꼭짓점**으로 읽히는 것이 첫 wow다. 이후 관람자는 신호의 ‘안’으로 들어가는 대신, **같은 표본 창 주위를 도는 세 개의 원인 관측창**을 지난다. EXT-REF-01의 한 그래프 유지와 EXT-REF-03의 서사층, EXT-REF-06의 Z축 후보에서 출발하되, Z축 후보의 실제 동작은 미확인이라 우리의 새 설계로 표시한다. 지구·사람·서고·종이 접힘은 쓰지 않는다. 공간은 검은 극장보다 **암회색 광학 관측실**: 수평 광로, 렌즈 프레임, 작은 금속 나사·유리 반사·먼지, 전원/호흡/손의 선명한 측면 실루엣이 화면 가장자리를 채운다.

1920×1080: 첫 표본점은 화면 중심 x=960/y=560, 2.5초 뷰가 완성되면 그래프 x=510–1810/y=370–740, 좌측 제목 x=96/y=90. 근경 점들은 엄밀한 샘플 위치를 3D 원근으로 그린 ‘장식 렌더’임을 하단에 표시하고, 수치 읽기는 2D 평면으로 정착한 다음에만 허용. 색은 차콜/크림 타이포/낮은 밝기의 앰버 입력/청록 출력. 렌즈 원형 마스크가 큰 프레임과 작은 표시를 만들지만, 숫자는 유리 반사 위에 놓지 않는다.

### B의 접합·제작 판단

표본점 근경→평면 파형의 연속성은 강한 wow 후보지만 **데이터 변형처럼 보일 위험**이 가장 크다. 시작 근경은 `샘플에서 유도한 공간 연출`임을 표기하고, 수치·시간을 읽게 하는 순간에는 2D로 완전히 정착시킨다. 그래프는 현재 Canvas 2D를 재사용, 광학창만 Three.js. 심장 표식/천/손은 동일 `sampleIndex`에서 구동한다. 마우스 시차는 광학창 외곽 최대 8px, 120ms 정도 감쇠; 그래프·글자는 0px. 실측 60 Hz처럼 보이는 파장/주파수 연출은 피한다. 렌즈/유리 반사는 별도 저해상도 패스로 제한하고, 패스 과부하 시 정적 반사 텍스처로 내린다.

## 5. 비교·타당성·추천 순서

|---|---|---|---|
| 첫 화면의 주제 인지 | 지구 장면에서 지연, 서고안은 기록 의미가 뒤에 읽힘 | 제목과 기록 물성 즉시 연결 | 제목과 표본점의 과학적 인상 즉시 연결 |

**우선 검토 추천: A.** 사용자가 지적한 따뜻하고 꽉 찬 질감, 사람 모델 품질 문제, 첫 제목의 명료함을 한꺼번에 해결할 가능성이 높다. 다만 기존 서고와 소재가 가까워 보여 **접힌 기록 물체가 공간을 여는 순간**을 정지 구도와 짧은 움직임 시험으로 구분해 확인해야 한다. B는 더 새로운 인상이 강하지만, 표본점을 3D로 보여 주는 순간의 과학적 오독과 유리 후처리의 성능 위험이 크다. 두 안 모두 **도입부 파형 무대의 검증된 표현**은 보존하지만, **Story 세 장면은 새 장면으로 제작**하는 제안이다. 현재 승인된 서고·사다리·고리 인체·확대/축소 왕복을 A/B가 바꾸는 부분은 장점으로 자동 판정하지 않으며, 최종 선택 전에 별도로 비교할 설계 변경이다.

### 구현 전 확인 순서와 판정

1. **구도 보드**: 첫 화면, 전환 정점, 실제 그래프 정착, 전원 간섭 원인 발견, 호흡, 쥠, Lab 연결의 7장. 사용자 피드백 후 목업 이미지 제작.
2. **도입부 10초 움직임 시험**: A의 접힘 또는 B의 점→2D 정착만 먼저. 1920×1080에서 60 fps 목표, 스크롤 역방향과 정지/재생을 확인. 실제 목표 PC 성능은 별도.
3. **Story 장면별 새 제작**: 전원→기저선→근육을 각각 원인 발견, 이분할, 저장 입력 재생, 처리, 퇴장까지 구현·캡처한다. 기존 Story의 저품질 화면을 임시 완성본으로 세지 않는다.
4. **데이터 계약**: 동일 샘플 인덱스·R 프레임, 그리드 s/mV, alpha 교차 전후 표본·축 일치, Story 3종 실제 저장값, 루프 접합. 틀리면 연출 제거.
5. **읽기/접근성**: 제목 2초 이상 읽기, 장면 정지 구간, reduced motion에서는 원인 소품과 정면 파형을 단계 컷으로, 키보드/자동 진행에서도 원인→입력→출력을 놓치지 않게.
6. **KEEP/TUNE/REJECT**: 한눈에 ECG 잡음 제거임을 알 수 있는가, 원인과 파형이 같은 장면에서 읽히는가, 빛/소품이 데이터를 가리지 않는가, 실제 스크롤·되감기에서 연결이 유지되는가.

### 원래 브리프와의 구체성 대조

| 브리프가 요구한 항목 | 이 문서 |
|---|---|
| 새 레퍼런스 8–12개, 확인 수준 | 10개, 3개 직접/제작자 핵심 + 7개 목록 수준을 구분. 목록 후보의 초 단위 영상 분석은 미완료라고 명시 |
| 효과 카드 3–5개 | 4개, 관찰/입력/번안/검증 지점 |
| 새 시나리오 2개, 하나 과감 | A와 B, 기존 지구·서고 카메라 동선 반복 없음 |
| 첫 화면·파형·3잡음·Lab까지 장면별 | 각 안 6+5+5+5+5행, 진행률·초·카메라·화면·글자·데이터·위험 포함 |
| 시각 양식·전환·노하우·비용 | 각 안의 물성/빛/접합/성능 위험, 마지막 비교와 판정 순서 |
| 사용자 피드백을 반영한 목업 | **지금 제작하지 않음.** 시나리오 검토와 최종 피드백 뒤 제작 |

**판정:** 장면 묘사의 구체성은 원래 피드백 및 저장소 브리프 수준을 충족한다. 레퍼런스 채굴의 증거 밀도는 아직 부분 충족이다. 목록 수준 7개의 실제 시각·초 단위 동작을 확인하지 못했으므로 이를 wow 효과의 입증 근거로 승격하지 않았다. 목업 전 선택할 레퍼런스 2–3개는 녹화/프레임 확인이 필요하다.
