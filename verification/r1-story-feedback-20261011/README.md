## 2. 브라우저 테스트

- `browser-tests/story-noise.spec.ts` PASS (5.3 min, SwiftShader).
  - 휠 25회에도 장면 유지.
  - 자동 1회 뒤 끝에서 버튼이 나타남. 휠을 되돌리면 사라지고, 앞으로 하면 다시 나타남.
  - 겹쳐 보기 중에는 휠을 무시함. "다음 장면 →"을 누르면 기저선 변동으로 넘어감.
- 이번에 고친 테스트 문제:
  - 휠 이벤트를 25 ms 간격으로 보내면 소프트웨어 렌더에서 시간 초과가 남 → 한 번에 보내도록 바꿈.
  - 교차가 0.98까지 차는 데 4프레임쯤 걸림 → 대기 시간을 60 s로 늘림.
- 첫 실행에서 낡은 빌드 때문에 첫 장면 버튼이 "처음으로"로 보였다. 다시 빌드한 뒤 "다음 장면 →"으로 확인했다.

## 4. 측정하지 못한 것

- S-10의 "가슴 앞선 변위 ≥ 6 px, 윤곽 대비 ≥ 3:1": 단순 경계 대비 지표는 창의 밝은 가장자리에 왜곡되어 무효였다. 윤곽선의 빛 번짐 때문에 오히려 낮은 값이 나왔다. 몸 마스크로 다시 측정해야 한다.
- 근육·전원 장면의 약한 숨(×0.3)은 값으로만 확인했다. 화면에서 "보일 듯 말 듯"인지는 사용자 확인이 필요하다.
- 실물 멀티탭 사진과 나란히 놓은 비교 시트는 만들지 않았다. CEE 7/3 규격 수치(오목부 깊이 17.5 mm, 핀 4.8 mm·19 mm 간격)로 대신했다.
- 계획 대조표의 "사인 빛 점이 선을 타고 컴퓨터로 거슬러 오름"은 보류했다(다음 라운드).
