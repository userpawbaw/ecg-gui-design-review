# ECG GUI 수정 워크플로우 v1.0 — 피드백에서 검증·복구까지

2026-09-13 · **정식 운영 지침**. 적용 대상: ECG Signal Studio v2.2.1 이후의 GUI 개선 작업.

[20번 논의 초안](20_ui_refinement_workflow.md)을 기존 설계·실제 코드와 대조해 발전시킨 문서다. 작업 절차를 확정한 것이며, 아래 예시의 GUI 변경이나 새 실험을 이미 수행·승인했다는 뜻은 아니다. 초안 원문은 보존한다.

## 1. 바로 사용하는 방법

사용자는 **현재 화면 + 표시한 위치 + 불편한 점/원하는 결과**만 전달해도 된다. 움직임 문제라면 재현 순서 또는 짧은 영상을 더한다. 버전·상태·영향 범위·검증 항목은 AI가 확보할 수 있는 자료로 채운다. 긴 양식 작성이 수정 요청의 진입 조건이 되지 않게 한다.

기본 순서: **기준 상태 확인 → 문제·영향 분류 → 수정 범위 확정 → 구현 → 필요한 검증 → 전후 비교·기록 → 잔여 계획 점검**.

한 번의 변경은 하나의 사용자 문제와 되돌릴 수 있는 수정 묶음으로 한다. 같은 원인인 2~3개 조정은 함께 처리할 수 있다. 별개의 미관·재생·데이터 변경은 분리한다. 이미 요청한 수정에 대한 재승인을 반복하지 않는다.

## 4. 변경 종류와 검증 깊이

분류는 가장 영향이 큰 항목을 따른다. 아래 노력 수준은 운영 시작점이며 성능 보장이 아니다. 현재 사용자가 선택한 모델·수준을 AI가 임의 변경하지 않는다.

| 분류 | 예시 | 진행 방식 | 필요한 증거 |
|---|---|---|---|
| U1 국소 외형 | 한 버튼 굵기, 제한된 여백, 의미가 같은 문구 | 바로 수정; Low 후보 | 관련 배치/상태 확인, 빌드가 필요한 배포면 빌드. 의미 없는 신규 단위 테스트는 생략 |
| U2 공유 배치·상태 | 패널 폭, 전역 폰트, Dialog, hover/Pin, 여러 화면 공통 토큰 | 영향 지도 후 수정; Medium 후보 | 영향을 받는 크기/상태, 포커스·선택 유지, 필요한 행동 테스트 및 렌더 |
| U3 데이터 표현·재생 | 축 환산, Difference 부호·gain, Sweep/Scroll, async scene swap | 수식/상태 계약 먼저; Medium~High 후보 | 알려진 입력의 수치 검증, 상태/경계 회귀, 영상·trace 또는 실제 브라우저 |
| U4 정보 구조·연구 근거 | 탭 통합, 새 Loss 비교 화면, 지표/Reference 의미 변경, 모델 출력 재생성 | 목표·자료·화면 수명 설계; High 후보 | 새 계약·근거·진입/복귀·변경된 전체 흐름. 구현 승인이 없으면 구체안까지 작성 |

“M04가 M_FE와 같아 보임”은 먼저 U3/연구 진단으로 분류한다. 잘 보이게 하려고 한 방법만 확대·정규화하거나 threshold를 임의 변경하지 않는다. 출처·해시·동일 조건·실제 수치부터 확인한다.

## 5. 한 사이클의 실행 절차

| 단계 | AI가 수행하는 일 | 종료 기준·기록 |
|---|---|---|
| F0 복구·기준선 | 다른 실행/원격 변경 확인, 마지막 검증 상태와 실제 소스 확인 | 기준 SHA·변경분·현재 요청 확인. 손상만 복구하고 정상 실험 반복 안 함 |
| F1 접수·재현 | 화면/요소/증상/목표를 매칭, 기존 상태를 복원하거나 재현 제약 기록 | UI-ID와 변경 계약. 표시 위치가 명확하면 추가 질문 없이 진행 |
| F2 영향·설계 | U1–U4, 공유 영역, 보존 조건, 필요한 검증 선택 | 수정 항목과 기대 결과 명시. 설계 판단이 필요한 경우 대안·선택 이유 기록 |
| F3 구현 | 최소한의 일관된 수정, 데이터/명세 부작용 확인 | 리뷰 가능한 diff. dist만 편집하지 않고 소스에서 재생성 |
| F4 검증 | 관련 수치·상태·렌더·환경 항목 실행 | 명령·종료 결과·소스/데이터 버전·증거 경로와 PASS/NV 등 기록 |
| F5 전후 비교 | 동일 과업·상태에서 목표 달성/보존/새 문제 평가 | 전후 자료 및 예외 설명. 자동화 PASS와 사용자 수용은 따로 기록 |
| F6 종료·재개 준비 | PLAN/WORK_STATE/WORKLOG 갱신, 커밋·원격 확인, 잔여 계획 점검 | 완료/남은 단계/다음 행동 보고. 승인된 잔여 작업이 실행 가능하면 이어서 진행 |

작은 수정은 F1–F3를 하나의 짧은 업데이트로 묶는다. 내부 사고 과정 대신 **확인한 사실·결정·검증 결과**를 로그로 남긴다. 매 단계마다 확인 버튼을 요구하지 않는다.

## 6. 변경 계약과 피드백 형식

사용자용 최소 요청:

```text
현재 화면 첨부. ① 방법 패널이 넓어 파형 비교가 답답해.
패널을 조금 줄이고 그 공간을 파형에 줘.
방법 설명은 계속 읽을 수 있어야 하고, 다른 탭 배치는 유지해줘.
```

AI가 보완하는 항목은 [복사용 템플릿](templates/ui_change_request.md)에 있다.

- **관찰과 제안 구분:** “설명이 두 줄 잘림”은 관찰, “폭 20% 축소”는 해결 후보다. 후보가 글자 잘림을 악화시키면 이유와 더 적합한 범위를 제안한다.
- **위치 식별:** 전체 화면의 번호 + 요소 이름 + 필요 시 확대본. pixel 좌표는 해당 캡처에서만 유효하다. 내부 파일/DOM ID를 사용자가 알아야 할 필요는 없다.
- **증거 종류:** 정렬/잘림은 캡처, Sweep/hover/요청 경합은 재현 순서·영상, 수치 이상은 조건·버전·로그/출력.
- **보존 조건:** 입력/Reference, record·noise·SNR, 시간/단위/축, selected/preview/pinned 의미, 근거 범위. 해당 변경과 관련된 것만 적는다.
- **수용 기준:** “예쁘게”를 확인 가능한 결과로 바꾼다. 예: 가장 긴 방법명이 잘리지 않고, 파형 실제 내부 폭이 늘며, 동일 표본·mV 범위를 유지한다.
- **변경 제외:** 사용자 지정 제외와 프로젝트 불변 조건을 기록한다. 필수 연관 수정은 설명하고 수행하되 승인되지 않은 새 기능을 끼워 넣지 않는다.

## 7. ECG 화면에서 항상 보존할 계약

1. Noisy/선택 출력/Pin/Reference는 같은 source sample과 시간 매핑으로 비교한다. 방법별 독립 autoscale이나 보기 좋은 시간 이동을 하지 않는다.
2. hover/focus는 임시 점선 후보, 클릭은 선택, Pin은 지속 비교다. hover만으로 selected 지표·pinned 방법을 바꾸지 않는다. 터치는 선택/Pin으로 접근한다.
3. Pause는 현재 Sweep 모양 정지, 구간 고정은 연속 sample interval 비교다. 모드 전환·큰 창 진입/복귀의 상태 보존 규칙을 검사한다.
4. Difference는 **Output−Reference**다. Input−Output 제거 성분과 구분한다. ×1/3/5는 표시 확대이며 원 데이터/지표를 변경하지 않는다.
5. 각 행 y축은 실제 mV, 좌상단 `[mV]`, 5개 수치 눈금이다. 범위 ±A, Difference gain G라면 해당 Difference 축은 ±A/G다. 예: A=2, G=5 → 0.4, 0.2, 0, −0.2, −0.4 mV.
6. Reference는 현재 파이프라인의 FE 기준 신호다. 원 MITDB raw를 완전 무잡음 ground truth라고 바꿔 부르지 않는다. D1 실제 ECG와 합성 noise preset, 실제 NSTDB 잡음을 혼동하지 않는다.
7. Local 고정 구간/현재 600초 Session/별도 Experiment 집계를 분리한다. LIVE는 실제 장치 증거가 있을 때만 표시한다.
8. 새 조건 로딩은 요청 상태와 마지막 유효 장면을 구분한다. 새 라벨+이전 파형을 섞거나 누락 출력을 다른 방법으로 대체하지 않는다.
9. Sweep 페이드는 지우기 경계에만 적용한다. waveform morph·긴 잔상·순위 연출로 성능 해석을 바꾸지 않는다.
10. 전시의 핵심은 같은 조건에서 차이를 이해하는 것이다. 파형 가독성을 지표 카드·설명·장식보다 우선하고, 첫 체험의 주요 선택은 하나로 안내한다.

이 계약도 사용자 요청으로 발전시킬 수 있으나, 무엇이 달라지고 과학적 해석이 유지되는지 명시적으로 검토한다.

## 8. 전후 비교와 필요한 검증만 고르는 법

### 8.1 정적 배치 비교

소스 commit/build, 데이터 manifest/scene, record·noise·SNR, 선택/Pin, viewport CSS 크기, OS/browser 배율, DPR, 표시 길이·mV 범위·Reference opacity·Difference gain을 맞춘다. 가능한 경우 동일 sample interval로 구간 고정한다. Sweep 정지 모양 자체가 대상이면 동일 head/phase를 맞춘다. 정지 비교를 위해 데이터를 다른 구간으로 바꾸지 않는다.

1366×768와 1920×1080은 기본 비교 크기다. 공유 레이아웃/폰트/Canvas 변경이면 둘 다 확인하고, 국소 문구 변경이면 영향을 받는 크기를 우선한다. 동일 환경에서 before/after를 비교하고, 다른 환경의 캡처만 있으면 차이 원인을 확정하지 않는다. whole-page 캡처로 요소가 존재함을 확인하는 것과 발표자가 viewport 안에서 읽고 조작할 수 있음을 구분한다.

파형 면적은 카드 바깥 크기와 실제 plot 내부를 나누어 측정한다. 큰 창·2행/Pin 3행·Difference 조합에서 축/라벨/transport 접근성을 확인한다. 도면의 280px 같은 목표 수치를 현재 측정값으로 베끼지 않는다.

### 8.2 동적/상태 검증

움직이는 프레임끼리의 pixel 차이는 회귀 근거가 아니다. 같은 이벤트 순서를 실행해 video/trace, sample index와 transport 시간, 요청/표시 scene 일치, 로그를 함께 본다. 재생 중 export는 Pause를 유발하므로 문제 영상을 먼저 확보한다. test-only 시계 제어를 쓰면 실제 wall-clock 검증과 구분한다.

일반 CSS 수정에 98조건 재추론을 하지 않는다. 파형 엔진/데이터 계약 변경이면 관련 경계·수치 테스트를 추가하고, 실제 데이터 변경이 필요한 경우에만 별도 생성 단계를 수행한다. 재생 속도 2× 테스트를 10분 실제 soak로 기록하지 않는다.

### 8.3 현재 실행 도구와 한계

준비된 v2 개발 환경에서는 `prototype/v2`에서 `npm test`, `npm run build`, `npm run qa`/`npm run qa:headed`가 각기 단위 검사·빌드·PC 브라우저 검사 역할을 한다. 실행 ZIP의 qa 폴더 명령은 [17번](17_v2_team_handoff.md)을 따른다. 실행 전에 package.json과 실제 테스트 범위를 확인한다.

현재 Work의 브라우저 접근 차단 이력 때문에 native 렌더 결과는 NV다. 도구나 다른 경로로 차단을 우회하지 않는다. 허용된 환경이 제공되면 직접 검수하고, 그렇지 않으면 PC runner 결과 또는 사용자 캡처를 활용한다. 사용자가 모든 항목을 수동 점검하게 하지 않도록 실패·변경된 항목 중심으로 증거를 요청한다.

기존 runner에는 주요 큰 창/hover/포커스/다운로드/두 모드 Difference/선택적 600초 종료 검사가 있다. **폰트 로딩, 실제 축 숫자 시각 판독, 모든 오류 경합, 전체 10분 무끊김/프레임 속도는 기존 테스트만으로 보장되지 않는다.** 필요 변경 시 해당 증거를 보강한다. 이번 문서 작업에서 runner를 확장하거나 실행한 것은 아니다.

## 9. 모델·노력 수준과 전체 리뷰 운용

처음에는 §4 분류에 맞는 수준을 후보로 삼는다. 높은 추론을 사용 중이라는 이유로 요청 외 재설계를 늘리거나, 낮은 추론이라는 이유로 완료 기준을 줄이지 않는다. 어떤 모델이든 같은 변경 계약과 검증 기준을 적용한다. AI는 현재 설정으로 진행할 수 있는 일을 계속하고, 자동 전환 능력이 있다고 주장하지 않는다.

전체 설계 리뷰의 trigger:

- 정보 구조·기본 시연 흐름·Reference/지표 의미가 바뀐다.
- 전역 타이포그래피·공유 토큰·여러 화면 공통 레이아웃을 바꾼다.
- 같은 문제가 두 번의 수정 뒤에도 재발하거나 서로 반대되는 수정이 반복된다.
- 국소 수정으로 다른 영역의 가독성/조작성이 악화된다.
- 전시 배포 후보를 확정한다. 변경 범위와 열린 게이트에 집중한다.

단순 국소 수정 3건이 쌓이면 영향 목록만 짧게 확인한다. 이 숫자는 운영상의 초기 점검 간격이며 무조건 High 모델 전체 재검사를 뜻하지 않는다.

효율은 **수용 가능한 결과 한 건당 총 소요**로 본다. 변경 로그에 실제 선택한 모델/수준(확인 가능할 때), 첫 통과 여부, 재작업 횟수, 도구/사용자 검수 시간을 간단히 남긴다. 이미 발생한 다음 3~5건을 관찰해 기준을 조정한다. 비교 실험 때문에 같은 수정을 여러 모델로 중복 실행하지 않는다. 사용량 표시가 없으면 추정 토큰/절감률을 발명하지 않는다.

2026-09-13 공식 자료 확인: [OpenAI model guidance](https://developers.openai.com/api/docs/guides/latest-model)는 API의 reasoning 설정·캐시 유지 방식과 필요한 범위의 테스트를 설명한다. 이것으로 ChatGPT Work의 모델 전환 비용 공식이나 최적 노력 수준을 도출할 수 없다. **본 문서의 Low/Medium/High 배분은 프로젝트 운영 가설**이다. 이번 문서에서 노력 수준별 성능 A/B 실험은 하지 않았다.

## 10. 외부 시각 편집기를 사용할 때

기본 경로는 현재 앱 캡처에 표시하고 동일 저장소를 수정하는 방식이다. 별도 유료 서비스나 새 프레임워크가 필수는 아니다. 특정 제품의 현재 기능을 확인하지 않고 지원된다고 가정하지 않는다.

도입한다면 다음 조건을 모두 확인한다.

1. 시작 commit과 실제 수정할 컴포넌트/토큰을 지정한다.
2. 편집 결과를 브랜치 또는 제한된 diff로 가져올 수 있어야 한다. 가져오기 전 데이터/엔진/패키지 변경을 검토한다.
3. main이 달라졌다면 양쪽 변경을 비교하고 사용자 변경을 보존한다. export로 프로젝트 전체를 덮어쓰지 않는다.
4. 원 저장소에서 빌드하고 같은 입력/상태로 전후 검증한다. 편집기 preview만으로 완료하지 않는다.
5. 라이선스·폰트·에셋·외부 네트워크 의존을 실제 배포 범위에서 확인한다. 오프라인 시연 조건을 유지한다.

Canvas 내부 파형/축을 DOM 클릭 편집으로 개별 선택할 수 있다고 가정하지 않는다. 해당 영역은 renderer와 수치 계약을 수정한다. 코드 round-trip이 불가능한 도구의 출력은 시안 자료로만 사용한다. 기존 React/Canvas를 교체하거나 Electron/Tauri 포장을 추가하는 것은 별도 요구가 있을 때 판단한다.

## 11. 기록·완료·자동 재개

`WORKLOG.md`에 UI-ID, 목표, 기준 SHA, 변경 범위, 보존 조건, 실제 검사·판정, 증거 경로, 다음 단계를 기록한다. 상세 UI 이슈가 아니라면 ID를 만들기 위한 별도 행정 작업은 필요 없다. 현재 유효한 설계 결정은 본 문서 또는 해당 기능 명세에 짧게 반영하고 과거 결정은 이력으로 남긴다.

증거 폴더에는 필요한 파일만 둔다: before/after 캡처, 짧은 동작 영상 또는 trace, review JSON, manifest/환경 정보, 결과 요약. 모든 조합의 영상이나 전체 데이터 복제는 피한다. Git에 적합한 문서는 저장소에, 큰 증거 파일은 지속 저장된 경로·해시로 연결한다. 실행되지 않은 테스트 결과 파일을 템플릿으로 채워 PASS로 두지 않는다.

완료는 세 축으로 기록한다.

| 축 | 가능한 상태 |
|---|---|
| 구현 | 미시작 / 진행 / 완료 / blocked |
| 검증 | PASS / CONDITIONAL / FAIL / NOT VERIFIED; 구조·동작·근거·환경별 범위 명시 |
| 사용자 수용 | 명시적 승인 요청 시 대기 / 사용자 수용 / 사용자가 별도 승인 게이트를 요청하지 않음 |

자동검사 통과를 “사용자 승인 완료”라고 쓰지 않는다. 명시적 승인 게이트가 없는 평범한 수정은 검증 후 완료 보고하고 다음 승인된 작업을 진행한다. 실제 렌더를 못 본 U2 배치 수정은 구현 완료·시각 NV로 보고한다.

6시간 예약은 [복구 정책](../WORK_RESUME_POLICY.md)을 적용한다. 정상 실행이 있으면 no-op, 전체 완료면 no-op, 중단이면 실제 산출물 검증 후 필요한 단계만 복구해 남은 승인 작업을 계속한다. 차단/결정 대기는 상태만 보고한다. 새 수정 요청이나 자료가 오면 현재 과업과 재개 조건을 갱신한다.

채팅 종료 예시:

```text
UI-xxx / 방법 패널 배치 수정: 구현 완료.
검사: 관련 동작 PASS, 1080p·768p 렌더 NOT VERIFIED(실행 환경 대기).
기준/체크포인트: <실제 commit 및 증거>.
남은 단계: 변경 화면의 PC 렌더 → 필요한 보정 → 팀 문서 갱신.
이번 요청: 조건부 완료. 전체 GUI/AFE 검수 완료는 아님.
```

## 13. 이번 문서 작업의 판정과 다음 적용

20번 11절의 과제는 원칙 통합·상태 분류·요청 양식·보존 조건·전체 리뷰 trigger·로그 위치·시각 편집기 동기화 절차로 구체화했다. 모델/노력 수준의 실제 비용·성공률 검증은 현재 근거가 없으므로 가설과 관찰 절차로 남겼다. 이것은 워크플로우 완성을 막는 필수 실험이 아니다.

기존 소스에서 확인한 CSS/Canvas 글꼴 분리, export의 Pause, 테스트 증거 범위를 반영했다. 문서·소스 대조와 사례별 절차 검토가 이번 검증이다. **사용량 절감 실측, 새 GUI 렌더, 사용자 연구, 알고리즘 수정은 수행하지 않았다.**

다음 UI 요청부터 이 문서와 템플릿을 적용한다. 남아 있는 R4 실제 브라우저/전시 환경 검수와 R5 최종 인계는 기존 계획대로 유지한다. 폰트 변경, SWT 재튜닝, Loss 화면/탭 통합은 이후 사용자의 지시로 별도 진행한다.
