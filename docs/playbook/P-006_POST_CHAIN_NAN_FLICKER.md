# P-006. 화면 전체가 한 장씩 검게(또는 하얗게) 깜빡일 때 — NaN을 먼저 의심하고 셰이더 밑을 정의역으로 고정한다

| | |
|---|---|
| 상태 | 유효 |
| 언제 읽나 | 후처리(블룸·톤 매핑) 체인이 있는 장면에서 화면 전체가 순간적으로 검거나 하얗게 깜빡일 때, 새 셰이더에 fresnel·`pow`를 쓸 때, 특정 PC에서만 나는 깜빡임 보고를 받았을 때 |
| 도달 수준 | 사용자 GPU에서 46–49 s 깜빡임이 사라짐(사용자 확인 2026-10-15) `[대화]`. 증거 F-042, `verification/r1-story-feedback-20261011/README.md` §8 |
| 근거 여정 | J-003 T1–T3 |
| 강제 장치 | 수동 — 셰이더 정의역 검사기는 아직 없다. 셰이더 리뷰 `docs/uiux_system/11_CHECKLISTS.md` §12에서 본다 |
| 갱신 | 2026-10-15 |

## 권장 방법
1. 녹화를 프레임마다 평균 밝기로 잰다. 앞뒤와 동떨어진 한 장(예: 5–26 대 45–85)이 있으면 후처리 전파를 의심한다.
2. 셰이더에서 `pow(x,k)`, `sqrt(x)`, `log(x)`, `acos(x)`를 모두 찾는다(`grep -n "pow(\|sqrt(\|log(\|acos(" src -r`). 밑이 `1.-dot(..)`, `1.-abs(dot(..))`처럼 반올림으로 범위를 넘을 수 있으면 `max(0.,…)` 또는 `clamp(x,-1.,1.)`로 막는다.
3. 장면 하나만 고치지 말고 같은 계산을 쓰는 모든 셰이더를 같이 고친다(이번에는 6곳).
4. 소프트웨어 렌더에서 재현되지 않으면 고친 빌드를 사용자 GPU에서 확인받는다. 확인 전까지 "해결"이라고 쓰지 않는다.

## 도달한 품질
수정 뒤 사용자 PC에서 깜빡임이 사라졌다 `[대화]`. 화면 모양은 바뀌지 않았다(정상 범위의 값은 그대로).

## 가지 말 길
- **검은 프레임을 녹화 누락·근평면 단면·MSAA 탓으로 돌리고 넘어가기** — 누락은 앞 장 반복, 단면은 부분 공백이라 "전체가 한 장 검음"을 설명하지 못했다(J-003 T1).
- **후처리에 `isnan` 정리 통과를 덧대기** — 드라이버 최적화가 검사를 지울 수 있어 믿을 수 없다. 원인 셰이더를 고친다(J-003 T3).

## 틀린 길이라는 신호
- 깜빡임이 특정 시각·카메라 각에서만 나고, 그때 화면 전체가 한 번에 바뀐다(J-003 T1).
- 내 환경에서는 재현되지 않고 사용자 PC에서만 난다(J-003 T2).

## 타협하면 안 되는 지점
- 재현 없이 고친 것은 사용자 GPU 확인 전까지 "후보 수정"이다. 당시에도 그렇게 적었고, 확인 뒤에야 상태를 바꿨다(J-003 T2).

## 적용 범위와 재검토 조건
- 범위: three.js 후처리 체인(HalfFloat 대상 + 블룸) 위의 커스텀 셰이더.
- 다시 열 조건: 밑을 모두 막았는데도 깜빡이면 깊이 텍스처 해석(MSAA·`samples`)이나 0으로 나누기(`/w`, `normalize(0)`)를 다음으로 본다.

## 남은 한계
- 셰이더 정의역을 자동으로 찾는 검사기가 없다. `normalize(vec3(0))` 같은 다른 NaN 원인은 이번에 훑지 않았다.
