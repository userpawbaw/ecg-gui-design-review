# 질환 탭 축 확대 애니메이션 끊김 — 측정과 수정 (D-199, 2026-11-25)

사용자 영상 `2026_11_25_16_28.mp4`: 「재생은 괜찮은데, 축이 확대되는 애니메이션이 좀 끊긴다. 한 15프레임밖에 안 나오는 것 같아」.

## 측정(headless Chromium, 1920 × 1032, dpr 1, `vite build` + `serve-v2`)
- `draw_ms.cjs <url> pvc <CPU 감속>`: 투어 단계별 rAF 간격 · 그래프 한 번 그리기 시간(`__labStats`).
- `zoom_profile.cjs`: 단계 하나의 CPU 프로파일(PH=in · run). `before.txt` · `after1*.txt`의 「확대 프레임」 줄은 data-span 변화로 센 값이라 신뢰하지 않는다(그리기 시간 표가 기준).
- `grab.cjs`: 확대 중 같은 구간 값에서 그래프 캔버스를 그 프레임 그대로 저장 → `zoom_old_vs_new.png`(왼쪽 `?zoomsnap=0` 이전 방식, 오른쪽 새 방식).

| CPU 4배 감속 | 그리기 평균(in · move · out) | rAF 간격 평균(in · move · out) |
|---|---|---|
| 수정 전(`draw_ms_after1.txt`) | 54 · 59 · 69 ms | 34 · 50 · 36 ms |
| 캔버스 크기 재할당만 없앰 | 47 · 62 · 67 ms(변화 없음) | — |
| 처음 · 끝 장면만 그리고 늘여 섞기(`draw_ms_after3.txt`) | 17 · 12.5 · 15.5 ms | 31 · 36 · 30 ms |
| 같은 것, 감속 없음(`draw_ms_after3_x1.txt`) | 2.7 · 1.7 · 2.5 ms | 17.1 · 16.9 · 17.9 ms(≈ 60 fps) |

수정 전 그리기의 대부분은 파형 층 합성(composeRow)이었다(감속 4배에서 프레임당 31–44 ms; 격자 다시 그리기는 1 ms 미만). 확대 중에는 구간이 매 프레임 바뀌어 행마다 잔광 · 번짐 · 사라짐 층을 처음부터 다시 긋고, 구간이 좁을수록 잔광 창(나이 3τ)이 화면 전체로 넓어져 더 무거웠다.
초점 밖 흐림(A2)을 꺼도 차이가 없었다(`draw_ms_after3_nodof.txt`). 배경 서고는 재생 중(투어 멈춤 포함) 이미 그리지 않는다.
headless는 캔버스를 CPU로 그리므로 절대값은 실제 노트북(GPU 캔버스)과 다르다 — 상대 비교만.
- `ui_recap_banner.cjs`: 저장된 옵션 recap true 상태에서 시작 → 질환 4번 전환 중 「준비 중」 띠 0회, 투어 끝 숫자 표식 0개, 저장 recap false(한 번 끔).
