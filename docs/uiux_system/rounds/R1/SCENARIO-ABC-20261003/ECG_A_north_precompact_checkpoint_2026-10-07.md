구현 기준 커밋: `44b11426da93a05b00cb8cb19a2834f9e7e46ab4`, 작업 branch `codex/abc-light-design-20261004`. 이번 시작 시 원격 branch 동일, main `cfef4300e241134a7b4caf1d781766a4931a99db` 확인. [커밋]

## 3. 확정·미완·보류를 분리

- **KEEP:** 기존 서고 빛·소품(D068), 사다리 오르기/등→측면→심장과 혼합 입력, 검정 몸·심실형 심장, Story 의자 자세. VDB 구름 형태와 지역 지형 디테일.
- **승인된 시험:** 지형 높이1.5×. 근접 늘어짐이 크면1×로 복귀 가능.
- **TUNE:** 원형 지구/수평선의 조명·반사·대기, global/parent/broad/near 경계, 이동 중 texture/LOD popping·alias, 구름→서고 가림 템포.
- **미구현:** 웹 지역 장면에서 실제 VDB 외곽·3D 통과·지형 receiver 그림자. 현재 웹 구름은 native 안쪽 렌더 **한 장**의 가림 bake다. native 양감과 웹 구현 완료를 혼동하지 않는다.
- **보류:** A-P3 처리·출력/의자 인계, A-P4 PLI/BW/EMG Story, B/C 후속 제작. 각 파트의 설계·피드백 기록을 유지한다.

## 4. 검증 증거와 한계

기존 완료 기록: [북반구 인계 검토](ECG_A_north_handoff_review_2026-10-07.md), `verification/a-north-handoff-20261007/`의 native-vdb-manifest / browser-manifest / native-captures / archive-comparison. [캡처] [런타임] [테스트]

- native 실제 VDB+1.5× 지형3장, RTX3070 OptiX48samples·1280×720, 원본/출력 hash 확인.
- 실제 IAB 웹9개 고정 구도, region ready/오류0/pending0. ShaderPass 복제 uniform 수정 후 실제 p.319 가림 재확인.
- 직전 구현 검증: build64modules / records200 / Python syntax / diff PASS. 이번 문서 정리는 기록 검사만 다시 수행하며 렌더·build를 반복하지 않는다.
- 서고 baseline 비교는 viewport가 달라 **동일 pixel NOT VERIFIED**. 연속 스크롤·정역 영상·목표 PC·600초·GPU 비용도 이번 후보에서는 미검증. 준비표시/무오류는 시각 품질 PASS가 아니다.
- 시작 시 기존 `verification/a-terrain-lod-20261007/native-captures/ridge.png`와 `ridge.json`의 미커밋 변경 확인. 작성자·생성 시점은 확인되지 않았으며, 이번 커밋에 포함하거나 덮어쓰지 않는다. 이전 LOD manifest와의 재정합도 이번 요청 범위 밖이다.

## 5. 지금 받을 피드백 범위

| 화면 | 피드백할 대상 | 별도로 남겨둘 것 |
|---|---|---|
| 원형 지구 p0 | 전체 미감, 대륙/극지·밤 불빛·빛 방향 | 실제 ice DEM은 아직 없음 |
| 수평선 .10 / 북유럽 .18 | 푸른 대기광, 반사, 확대 시 지도 뭉개짐·패치 느낌 | 물리 대기 완전재현 아님 |
| 지역 .235 / 상세 .265 / 능선 .294 | 필요 detail, 1.5× 높이, 지도·기하 인계, 카메라 구도 | 정지 캡처만으로 움직임 품질 확정 금지 |
| 가림 .319 / 서고 .55 | 가림의 밝기·템포와 기존 공간 연결 | 현재 한 장 bake라 완성 구름 외곽 품질 평가와 구분 |

다음 사용자 반응은 이 후보의 **중간 파트 피드백**으로 기록한다. 미완 live-cloud를 포함한 후보 검토를 자동으로 전체 완성 제작 피드백2로 세지 않는다. 전체 제작 피드백2는 구름·빛·연속 인계까지 갖춘 후보와 범위를 명시하고 진행한다.

## 6. 재개 순서·최소 읽기 묶음

1. 최신 사용자 피드백 → 이 문서 → WORK_STATE의 scenario_a_production / 북반구 인계 review.
2. 피드백을 화면별 KEEP/TUNE/REJECT로 분리하고 해당 F/D/O 기록에 반영. 새 구현 갈림길이면 제작 전 D 작성.
3. 원형→궤도→지역의 경계/노출/움직임 보완. 구름은 승인 VDB density/광학 cache와 연속 경로 bake를 비교하고 선택 근거 기록.
4. 실제 구름 외곽/통과·receiver와 같은 서고 인계 → 연속 왕복·성능 검증 → 완성 후보 사용자 피드백2.
5. 두 차례 완성 제작 후 실패 조건이면 D080의 구름 없는 전이와 AI 생성 영상 두 후보 비교. 현재 영상 생성/채택 완료 증거 없음.
6. A-P2 판정 뒤 A-P3 → A-P4, B/C는 별도 후속 순서.

새 요소 탐색·제작 시 작업 색인 → 전 장면 제작 조사 기준 → 해당 scene 명세/에셋 registry를 추가로 읽는다. 모든 역사 문서를 매번 읽을 필요는 없다. 현재 내부 시안 이용 정책(D084)은 유지하고 출품 전환 시 대체·권리 확인을 재검토한다.
