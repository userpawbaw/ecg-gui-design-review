## 코드와 대조하여 바뀐 판단

1. 초기 .1025에는 earthDetail=ss(.045,.10,p)이 이미 1이다. macro/region 고해상도 자료가 globe 위에 섞인다. 반면 parent.set(ss(.135,.19,p),...)의 광역 mesh는 .135 이전에 숨겨진다. 따라서 **초기 경계를 새 3D 지역 등장만으로 설명할 수 없다**. globe source 접합도 별도로 고쳐야 한다.
2. .1348 역시 정착값 기준 parent 시작보다 앞이다. D123 detailratio 보충은 parent shader에만 들어가므로 이 초기 구간을 해결하지 못한다.
3. .1584는 parent geometry와 평균색 인계가 진행 중이다. 영상에서 이 구간의 변화는 작은 사각 패치만이 아니라 화면 전체 연무/대비 변화다. depth/normal을 이용하는 aerial pass와 표면 인계의 상호작용이 유력한 검토 대상이다. **대기 패스가 확정 원인이라고 선언하지 않는다**.
4. 현재 p≥.18에서만 handoffCamera로 바꾸므로, 영상의 .1584 변화는 .18 카메라 branch 자체로 설명되지 않는다. wheel 중 프레임별 TAA/누적 상태나 depth는 영상에 없어 미확정이다.
5. orbital 경로의 구름은 높이장 proxy이다. 구름이 걷히고 진짜 Takram volume가 붙은 결과라고 해석하지 않는다.

## 다음 수정 순서와 통과 기준

### S1a 초기 지도 source 접합
같은 p .1025/.125/.1348, 같은 camera/sun/gain/DEM에서 cloud OFF, aerial ON/OFF, macro/region 개별 OFF 대조. globe와 parent의 동일 좌표 source·feather·linear 색·저주파 명도 정합부터 확인한다. source 경계만 지우려고 전체 지도를 더 흐리게 만들지 않는다.
통과: 초기 고해상도 유지, 노르웨이/바다/외곽에서 사각형 또는 얼룩 경계가 새로 보이지 않음. 기존 gain.8와 변경 후보를 고정 구도에서 비교; 사용자 긍정 후반 화면 유지.

### S1b .135–.18 광학 인계
p .132/.135/.14/.15/.1584/.165/.18에서 render albedo, actual deformed normal, linear depth, aerial output을 따로 저장한다. 정착과 이동 중 모두 확인한다. .135–.17 정·역 이동을 촘촘히 기록해 갑자기 veil이 바뀌는 지점을 찾는다.
통과: 새 surface가 depth를 대체해도 화면 전체 연무/대비가 튀지 않고, 앞뒤 이동에서 반복 가능한 연속 변화. 고정 캡처만으로 motion 통과 판정 금지.

### 후속 유지
S1a/S1b가 통과한 뒤 구름 광학/동일 footprint 근접 volume 인계→통과 가림→서고 KEEP 연결. 그림자 튜닝 보류, 구름 제작 실패 2/2와 fallback 선택지, A 우선/Story·B·C 후속 유지. 이 검토에서는 shader/runtime 코드를 바꾸거나 현재 후보를 채택하지 않았다.
