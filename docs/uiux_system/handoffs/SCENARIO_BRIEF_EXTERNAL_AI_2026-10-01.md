# 외부 AI용 시나리오 브리프 — ECG 잡음 제거 전시 도입부·Story

작성 2026-10-01 · 발행: R1 구현 세션(`claude/r1-autopilot-recommended`) · 용도: 다른 AI에게 **현재 진행 상황을 보여 주고, 새로운 레퍼런스에 기반한 새 시나리오를 같은 구체성으로 받기** 위한 문서. 이 파일만으로도 이해되게 썼고, §9의 시스템 문서를 함께 주면 우리 레퍼런스 탐색·기록 방식을 그대로 따를 수 있다.

**핵심 요청**: 지금 흐름(지구에서 내려와 사람 → 심장 → 파형)을 다듬거나 변형하는 것이 아니다. **새 레퍼런스를 먼저 찾고, 그 레퍼런스의 연출 문법에서 출발한 새 시나리오**를 원한다.

---

## 1. 프로젝트 한 줄

심전도(ECG)에 섞인 잡음을 여러 방법(고전 신호처리 + 딥러닝)으로 제거한 **저장된 실험 결과**를 전시장에서 보여 주는 웹 전시물. 관람객은 전문가가 아니다. 스크롤(또는 자동 진행)로 이야기를 따라가며 "잡음이 무엇이고 어디서 오며, 처리하면 어떻게 깨끗해지는가"를 본다. 화면은 데스크톱 16 : 9 전시 화면, 웹(three.js WebGL + Canvas 2D + DOM).

## 2. 바꿀 수 없는 조건 (모든 시나리오에 적용)

1. **파형은 저장값만**: 화면의 심전도 꼭짓점은 실제 저장 표본(250 Hz)이다. 시간·진폭을 변형하지 않는다. 발광·색·흐림은 스타일일 뿐. 가짜 실시간 파형, 장식용 곡선을 데이터처럼 보이게 하는 것 금지.
2. **수치는 저장값**: 성능 수치(SNR, 상관계수)를 지어내거나 애니메이션 중에 임의 숫자를 보여 주지 않는다.
3. **단위·눈금**: 파형에는 물리 눈금(시간 s, 진폭 mV)이 같은 층에서 함께 움직인다. 지금 격자: 작은 칸 0.04 s × 0.1 mV, 큰 칸 0.2 s × 0.5 mV.
4. **동기화**: 3D 심장의 박동 순간 = 파형의 R 피크가 그려지는 프레임(오차 0 프레임). 이미 구현·자동 검사됨.
5. **합성 표기**: 잡음은 합성으로 섞은 것이다. 숨·주먹 같은 원인 연출은 "설명용 연출"로 작게 표기한다.
6. **레퍼런스 사이트의 코드·에셋 복사 금지**. 에셋은 CC0/공공/CC BY(출처 표기)만.
7. **사람 모델에 눈·입·얼굴 세부 없음**(사용자가 불쾌하다고 명시). 실사 피부도 피한다(불쾌한 골짜기).

## 3. 사용할 수 있는 데이터 사실

| 항목 | 값 |
|---|---|
| 기록 | MIT-BIH 계열 한 사람(S038), 약 100 bpm, 10 s 장면, 250 Hz. R–R 간격 0.53–0.66 s(실제 간격 그대로, 이소성 박동 포함) |
| 도입부 장면 | 백색 잡음 0 dB 입력 → 최상위 저장 출력(Residual U-Net). 표시값 `SNR 0 dB → 12.44 dB · cc 0.971` |
| Story 잡음 3종(모두 −5 dB) | 전원 간섭(60 Hz), 기저선 변동(합성, 저주파 출렁임), 근육 잡음(합성, 폭발형) |
| 기저선 변동 시간 구조 | 1 s 평활 극값 1.1↓ 2.5↑ 4.6↓ 6.0↑ 7.6↓ 9.1↑ s → 주기 약 3–3.5 s(10 s에 숨 약 3번)로 쓸 수 있음 |
| 근육 잡음 시간 구조 | 0.5–1 s 폭발이 10 s에 5–6번, 켜짐 약 50 %. 주먹 연동 시 문턱 + 최소 유지 0.3 s 필요 |
| 전원 간섭 | 60 Hz — 화면 60 fps에서 실제 속도로 움직이면 멈춘 듯 보여 물결은 상징 속도로 |
| 결과 | −5 dB에서 세 잡음 모두 딥러닝이 1등 → 방법 이름 비교는 전시에서 뺐다(사용자 결정) |

## 5. 다음으로 계획된 흐름 (참고 — **구체성의 수준만 참고**, 지구 하강·사람 확대 구조를 반복하지 말 것)

**도입부 v2 (계획)**: 궤도 → 한반도 야간 불빛으로 하강 → 구름 통과(장면 이음새 가림) → 도시 불빛이 줄지어 심전도 격자 바닥으로 바뀜 → 격자 위 사람이 스캔되듯 등장 → 가슴 → 심장 → 파형 무대. 확대 구간만 고해상도 조각을 겹침(Powers of Ten 방식).

**Story 공통 문법(사용자 결정)**: 원인 막(화면 전체 3D, 카메라가 원인을 찾아감) → 이분할 막(사람·원인은 왼쪽 45 %, 오른쪽 55 %가 어두워지며 도입부와 같은 파형 무대, 몸 안 심장 박동과 R 동기) → 처리 막(화면 속 컴퓨터 모니터의 "박동마다 한 겹" 4칸이 박동마다 차며 파형이 깨끗해짐 — 컴퓨터가 잡음을 만들고 지우는 역설은 의도) → 나가기. 확대·축소 왕복은 유지하고 장면마다 다른 카메라 서명으로 보는 맛을 낸다.

예시 — 전원 간섭 장면 표(일부):

| s | 시간 | 카메라 | 보이는 것 |
|---|---|---|---|
| 0–.08 | 0–3 s | 심장 극근경에서 뒤로 빠짐 | 오른쪽 파형 막이 걷힘 |
| .08–.18 | 3–7 s | 빠지면서 왼쪽 50° 궤도, 중경 정지 | 몸 뒤에 가려 있던 책상·컴퓨터·모니터가 시차로 드러남 |
| .18–.26 | 7–10 s | 초점이 전원선으로, 선을 따라 바닥까지 낮게 추적 | 선이 콘센트로 |
| .26–.34 | 10–13 s | 콘센트 극근경 | 말풍선 보드가 튀어 오르고 교류 사인이 그려짐 |
| .34–.46 | 13–17 s | 크레인 업, 45° 원경 | 동심원 물결 3회가 사람에게 닿을 때마다 몸이 떨림 |
| .46–.52 | 17–19 s | 세 번째 물결이 가슴에 닿는 박동 순간 휩 줌 | 상반신, 왼쪽 45 % |
| .52–.85 | 19–32 s | 정지 | 이분할 → 잡음 입력 → 모니터 4칸 ↔ 깨끗한 출력 |

기저선 변동 = 옆모습 궤도 + 숨에 맞춰 오르내리는 카메라, 근육 잡음 = 주먹 전경 + 흐린 가슴 배경의 얕은 초점 접사.

## 6. 사용자가 이미 기각하거나 문제 삼은 것 (반복 금지)

- 감성적 제목, 의미 없는 행성 장식, 정지 이미지 파형.
- 기법 이름(M04 등)·"잡음이 바뀌면 1등이 바뀝니다" 같은 결론 먼저 주는 문구, 기법 설명으로 템포가 늘어지는 전개.
- 눈·입이 있는 사람, 플라스틱 마네킹, 어두운 화면에 사람만 덩그러니 있는 구성.
- 왕복(확대·축소)을 줄이는 방향 — 사용자는 왕복을 "원인을 애니메이션처럼 보여 주는 장치"로 원한다.
- 모니터 안에만 작게 파형을 보여 주는 구성.

## 7. 요청 — 새 레퍼런스 기반 새 시나리오

### 7.1 진행 순서

1. **레퍼런스 탐색 먼저** (우리 탐색 규약 `13_REFERENCE_GROUNDED_CREATIVE_MINING.md`, 조달처 목록 `17_REFERENCE_SOURCE_REGISTRY.md`를 받았다면 그대로 따른다):
   - Awwwards·FWA·CSS Design Awards·Godly 수상작, 과학·의료 시각화, 데이터 스토리텔링, 3D 스크롤 연출 등에서 **이미 분석한 REF-001–010(목록 §9 README)과 겹치지 않는** 후보 8–12개.
   - 각 후보: 이름, URL, **정확히 어디를 몇 초쯤 보면 되는지**, 그 장면의 연출 문법 한 줄, 우리 주제(심장·잡음·처리)로 옮길 수 있는 이유. 확인하지 못한 것은 "미확인", 지어내지 말 것.
2. 후보 중 3–5개를 골라 **연출 메커니즘을 분석**한다 — 받았다면 효과 카드 형식(`21_REFERENCE_EFFECT_RECORDS.md`: 지각 / 입력 모델 / 판별 근거 / 구현 메커니즘 / 파라미터 / 타임라인 / ECG 번안)으로. 번호는 `EXT-REF-01…`처럼 임시 번호를 쓴다(우리 저장소 번호와 겹치지 않게).
3. 그 레퍼런스들에서 출발한 **새 시나리오 2개**(하나는 과감하게)를 쓴다.

### 7.2 재사용해도 되는 것

- **지금 구현된 파형 표현**(§4 p .73–1): 2.5 s 네온 스윕·잔광·지우는 쪽 페이드, 심전도 용지 격자, 박동마다 4분의 1씩 깨끗해지는 교차, 큰 한글 + 작은 고정폭 두 층 라벨, R 주석, 심장 박동 ↔ R 피크 동기, 첫 R에 심장에서 날아가는 빛 고리. 그대로 쓰거나 새 레퍼런스에 맞게 바꿔도 된다(바꾸면 이유).
- 지금 애니메이션 기법(스크롤 진행률 → 카메라, 박동 시계, 층 시차, 글자 뒤섞임 등)과 우리 구현 경로(`25_EFFECT_PRODUCTION_PIPELINE.md`: 3D는 three.js 바닐라 모듈 + GSAP + Lenis, 장식 층과 데이터 층 분리).
- 3D 심장·사람은 써도 되고 안 써도 된다. 쓴다면 §2-7 조건.

### 7.3 형식 (각 시나리오)

1. **콘셉트 한 문단**: 와우 지점, 주제(심장·잡음·처리)에 맞는 이유, 출발한 레퍼런스 ID.
2. **장면 표**(첫 화면 → 파형 무대, 잡음 3종 각각, 실험실 진입): 열 = 진행률 구간 / 대략 시간(초) / 카메라·화면 움직임(위치·이동·렌즈·속도) / 보이는 것 / 글자(내용·크기·위치·등장 방식) / 데이터 연결(어느 저장값에 맞추는지) / 근거 레퍼런스 / 계약 위험. 장면당 최소 5행, "멋지게 등장" 같은 문장 금지 — 무엇이 몇 초에 어디서 어떻게.
3. **시각 양식**: 공간·인물·심장(쓴다면)의 재질·조명·후처리 수준. "꽉 찬" 화면을 무엇으로 만드는지.
4. **전환 목록**: 장면 사이 이음새.
5. **구현 노하우와 비용**: 에셋(라이선스), 셰이더·후처리, 어려운 부분, 성능 위험.
6. **지금 흐름과 비교**: 더 나은 점 / 잃는 점.

### 7.4 기준

- 데이터 사실(§3)과 조건(§2)을 어기는 연출은 "계약 위험" 칸에 적고 대안을 함께.
- 근거 태그(받았다면 `10_RECORD_KEEPING.md`): 직접 확인한 것과 추론을 구분.
- 레퍼런스 사이트의 코드·에셋은 가져오지 않는다 — 수치·구조·짧은 인용만.
- 한국어로.
