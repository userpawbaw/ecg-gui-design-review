# J-003. 서고 그림자 — 광량 조정에서 가림 거리·아랫면 재질을 분리한 선택까지

| | |
|---|---|
| 기간 | 2026-10-16 ~ 2026-10-18 |
| 도착 | P-006 |
| 기록 | D-084, D-085, D-141, F-046, F-047, `verification/r1-archive-b3-selected-20261018/README.md` |

## 출발점

광량을 조정한 r8에도 사다리의 선명한 그림자와 먼 가림의 자유로운 흐린 그림자가 함께 부족했다. 선반 아랫면도 밝았다. 이 여정은 B0 이후의 기록을 연결하며 r7/r8·V1 카메라 전체의 최종 채택을 대신하지 않는다.

## 흐름 한눈에

T1 가림 거리·점토 시험대 → T2 같은 해 + 천창·잎 → T3 16개 변형과 아랫면 비교 → T4 사용자 선택을 분리 프리셋으로 기록.

## T1. 가림 거리와 채움빛을 점토 시험대로 분리

| | |
|---|---|
| 날짜 | 2026-10-16 |
| 종류 | 시도 |
| 계기 | r8의 먼 사다리 그림자와 밝은 선반 아랫면을 광량만으로 설명하기 어려움 |
| 가설 | 해 하나와 가림 거리 차이를 쓰면 선명한 경계·부드러운 무늬를 함께 만들 수 있음 |
| 판정 | 부분 채택 |
| 다음 | T2 |
| 기록 | F-046, F-047, `verification/r1-archive-b1-clay-bench-20261016/README.md` |

### 한 것
쌍별 가림 거리·반그림자를 재고 회색 점토 장면에서 광원과 칸 깊이를 비교했다.

### 결과
기존 기록 `[런타임]`: 가까운 가림 0.2~0.5 px와 먼 창틀 10~12 px가 함께 나왔다. 깊은 칸은 그늘을 키우지만 빗각 창빛을 막았고, 아랫면 밝기는 남았다(F-047).

### 왜 다음으로
거리 원리는 실제 서고에 적용하되, 칸 깊이와 아랫면은 별도 문제로 남겨야 했다.

## T2. Story와 같은 해, 뒤쪽 천창과 화면 밖 잎

| | |
|---|---|
| 날짜 | 2026-10-17 |
| 종류 | 시도 |
| 계기 | T1의 원리를 실제 서고에 넣고 같은 방의 Story 해 방향을 유지해야 함 |
| 가설 | 높은 천창의 가까운 경계와 그 위 먼 잎이 한 해 아래서 두 경계 폭을 만듦 |
| 판정 | 부분 채택 |
| 다음 | T3 |
| 기록 | D-084, `verification/r1-archive-b2-light-structure-20261017/README.md` |

### 한 것
해 방향 (−0.42,0.40,−0.81)을 유지했다. 첫 오른쪽 벽 창은 책장에 빛이 닿지 않아 뒤쪽 천창·뚜껑·잎으로 시험을 수정했다.

### 결과
기존 측정: 잎 반그림자 15 px, 해 경계 선명 비율 62 %, plain_range 약 45(D-084). 사용자 선택은 B2 방향이었으나 잎 덩어리와 흩어진 빛 조각은 추가 비교 대상이었다.

### 왜 다음으로
빛 세기보다 잎 형태와 사다리의 받는 면까지 거리를 바꾸는 비교가 필요했다.

## T3. 16개 변형과 아랫면 재질 시험

| | |
|---|---|
| 날짜 | 2026-10-17 |
| 종류 | 비교 |
| 계기 | 사용자가 잎 형태, (a)/(b), 사다리 위치 두 안·회전 두 안을 결과로 고르기를 원함 |
| 가설 | 가지·뾰족한 잎과 벽에 가까운 사다리가 흐린 무늬와 선명한 사다리 그림자를 분리함 |
| 판정 | 부분 채택 |
| 다음 | T4 |
| 기록 | D-085, `verification/r1-archive-b2-variants-20261017/README.md` |

### 선택지와 기준
(a) 웅덩이 하나 / (b) 조각 유지, L1 해치 뒤 / L2 벽 레일, 30° / 45°를 두 V1 높이에서 비교했다. 아랫면은 원래 재질·×0.35·4 cm 앞턱을 따로 비교했다.

### 한 것
그림자 거리와 톤을 같은 1280×720 조건에서 재고 아랫면의 광원별 기여를 추적했다.

### 결과
L2는 2.0~2.4 px, L1은 6~7 px다. ×0.35는 **(a), L1**에서 아랫면/윗면 비 0.60 → 0.27을 얻었고 앞턱은 밝은 띠를 더했다(D-085). L2가 해치로 이어지지 않는 연출 문제는 남았다.

### 왜 다음으로
사용자가 형태·사다리·아랫면을 선택해야 조합을 고정할 수 있었다. 개별 시험의 숫자를 새 조합의 결과로 옮겨 적어서는 안 됐다.

## T4. 선택은 반영하고 조합 재현은 원본 접근 뒤로 구분

| | |
|---|---|
| 날짜 | 2026-10-18 |
| 종류 | 비교 |
| 계기 | 사용자 `[대화]` “(b) 조각 유지”, 이어 “권장안들로.” |
| 가설 | 선택된 (b)·L2·×0.35를 기존 30°에서 검증하면 r8·D-084를 보존하면서 다음 결과를 판단할 수 있음 |
| 판정 | 부분 채택 |
| 다음 | T5 |
| 기록 | D-141, `verification/r1-archive-b3-selected-20261018/README.md` |

### 선택지와 기준
명시적 권장 L2와 ×0.35를 반영하고 권장값이 없는 각도는 기존 30°를 유지했다. 기존 기본값 덮어쓰기 대신 독립 실행 프리셋을 택했다.

### 한 것
고정 레시피와 환경변수 격리·원본 누락 관문을 구현하고, Python 3.11.17/bpy 4.5.3 패키지를 설치했다. 기존 JPG 두 장도 재측정했다.

### 결과
실행 레시피 검사는 PASS. Poly Haven API 프록시 403으로 원본 16종 복구와 조합 렌더는 BLOCKED다. 사용자 선택을 완료된 시각 결과로 바꾸지 않았다. 같은 조합의 아랫면 전후 비교, 사람·해치 조율, 웹 이식은 확인 안 함(D-141).

### 왜 다음으로
사용자가 원본 품질과 다른 공급처의 실제 검토를 요청하고 접속을 개방했다. 기존 장면 재현과 신규 재질 채택을 구분해 독립 비교로 이어갔다(D-142).

## T5. 공급처 교체 대신 원본·맵 규약·가공을 분리한 재질 시험

| | |
|---|---|
| 날짜 | 2026-10-18 |
| 종류 | 비교 |
| 계기 | 사용자가 저품질 텍스처 원인·대체 조달처의 실제 검토를 요청하고 외부 접속을 개방·재게시함 |
| 가설 | 깨끗한 단색 기준과 실제 2K 후보를 같은 시험대에 두면 원본 얼룩과 가공 손실을 구분할 수 있음 |
| 판정 | 부분 채택 |
| 다음 | 끝 |
| 기록 | D-142, F-107, `verification/r1-archive-material-review-20261018/README.md` |

### 선택지와 기준
공급처 전체 교체와 항목별 검수, 사이트 미리보기와 실제 원본, 기존 서고 교체와 독립 벤치를 비교했다. 사용자 승인된 자체 키트 주력·낮은 대비 표면 목표가 기준이다.

### 한 것
CC0 8팩을 받고 자체 베벨 시험대에서 최종 22장을 렌더했다. PH .15 혼합과 자체 재질을 포함하고 맵 해상도/압축을 따로 측정했다. CGBookcase의 DirectX normal 누락 두 장은 G 반전 후 재렌더했다.

### 결과
PH 도장 벽과 ambientCG 석고의 얼룩은 2K 원본에도 있었다. PH ash의 미세 결은 균일해 PH 전체 저품질 판정은 기각했다. 실제 서고 적용·웹·B3 조합 렌더는 확인 안 함이다. 사용자 미감 확인 전 권장 카드는 잠정으로 둔다(F-107, `verification/r1-archive-material-review-20261018/README.md`).

사용자 후속 `[대화]`: PH ash **원본**이 가장 괜찮고 자체 paint도 나쁘지 않다고 평가했다. 원래 기기 품질은 별도 출처 감사로 확인했다(F-108, `verification/r1-original-branch-assets-20261018/README.md`). 실제 장면 적용 승인은 아직 없다.

### 왜 여기까지
자체 도장면과 약한 목재 결이 현재 목표의 우선 후보다. 최종 화면에서의 타일 크기·빛·베이크 확인이 남아 독립 벤치를 최종 채택으로 바꾸지 않는다.

## 도착점

P-006은 이번에 분리해 검증한 거리·재질·선택 기록 방법을 정리한다. 상태는 잠정이다. 외부 접속은 복구됐고 T5 재질 비교를 완료했다. T4의 조합 렌더 결과는 별도로 이어 기록하고, L2 연출 변경은 사용자 확인을 거친다.
