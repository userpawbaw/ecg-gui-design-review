# IDEA-R1-NOISE — 잡음별 장면(도입부 다음) 공동 구상 보드

형식: `20` Step 5A (D-039) · 시작 2026-09-29 · 계기 F-028 · branch `claude/r1-autopilot-recommended`
상태: **잡음 −5 dB 고정·기법 표시 제외(D-040, §5).** 흐름 분석만 기록 — 착수는 도입부(IDEA-R1-INTRO) 구현 완료 후.** 스택 점검·선택지 라운드는 그때 한다(사용자 요청).

## 0. 사용자가 정한 흐름 (2026-09-29 `[대화]`)

> "기법별 차이를 강조하는 것은 포기하고 앞에서 내가 수정했던 wow 포인트의 임팩트를 유지시켜서 기법 비교 패널까지 끌어오는 것에 집중하자." · "이 잡음이 바뀐다는 부분에 집중하자는 거야."

잡음 3단계(전원 간섭 → 기저선 변동 → 근육 잡음)를 같은 문법으로 반복한다. 전원 간섭의 시간 흐름:

| # | 스크롤 | 보이는 것 |
|---|---|---|
| P1 | 도입부 끝(혼합 잡음 → 깨끗) 이후 | 파형 fade out, 심장이 화면 중앙으로 돌아와 강조 |
| P2 | 계속 | 도입부 확대와 **대비되게** 사람 윤곽까지 축소 |
| P3 | 함께 | 상태 표시기(잡음 3단계)가 구석에 부드럽게 등장, "전원 간섭"이 소나처럼 강조 — "이제 잡음별로 본다"를 UI 하나로 |
| P4 | 계속 | 사람 옆에 전자기기 하나 + 선 + 꽂힌 콘센트(자세할 필요 없음, 글자 없이 원인 전달) |
| P5 | 조금 더 | 콘센트에 작은 AC 아이콘 |
| P6 | 계속 | 전자기기 중심으로 **물결처럼 퍼지는** 60 Hz 간섭(소나보다 물결 느낌) |
| P7 | 계속 | 다시 사람 → 심장 확대, 전원 간섭을 받은 잡음 입력이 박동에 맞춰 재생(도입부의 반복) |
| ~~P8~~ | ~~깨끗해지기 직전부터~~ (D-040으로 제외) | 옆에 작게 **"최선 기법: (풀어 쓴 이름)"** — 코드(M04) 대신 |
| P9 | 계속 | 필터를 통과해 깨끗한 파형으로 교차(도입부와 같은 디테일) |
| → | | 기저선 변동, 근육 잡음도 같은 문법. 관람자가 "어, 최선 기법이 다르네?"를 스스로 알아채게 |

제목 "잡음이 바뀌면 1등이 바뀝니다"는 결론만 먼저 주므로 이 흐름에서는 쓰지 않는다. 기법 설명형 전개("여러 디지털 처리 방식을 비교했습니다 → 모든 면에서 최선의 방법이 존재할까요?")는 사용자가 검토 후 **템포 때문에 기각**했다(§4).

## 1. 흐름 분석 (AI, 짧게)

| # | 관찰 | 판단 |
|---|---|---|
| A1 | 도입부의 확대(지구 → 사람 → 심장)를 **역방향으로 한 번 더** 쓰는 구조 | 좋음 — 카메라 경로를 진행률 함수로 만들면 같은 경로를 재사용·역재생할 수 있다. 3회 반복에서 지루하지 않게 2·3회차는 축소/확대 구간을 짧게 하는 것을 이후 검토 |
| A2 | 원인을 **글자 없이 오브젝트로** 보여 준다(전자기기·콘센트·AC) | 좋음 — 기저선 변동(호흡·몸 움직임), 근육 잡음(근육 긴장·움직임)도 같은 방식의 "원인 오브젝트"가 필요. 무엇으로 할지는 이후 라운드 |
| A3 | **데이터 사실: 1등이 달라지는 구간은 15–20 dB뿐** | 저장값(D0 S038, 참조 필요 oracle B01 제외, extension 포함): 전원 간섭 15·20 dB → **M04 Adaptive SWT**, 기저선 변동 10–25 dB → **M_FE 공통 Front-end**, 근육 잡음 15·20 dB → **M06L6 Residual U-Net · L6**. 10 dB 이하에서는 M06L6/M08이 대부분 1등 `[코드]` |
| A4 | **긴장: 이 SNR에서는 잡음이 얇다** (F-026) | 전원 간섭 15 dB 잡음 p2p 0.111 mV, 신호 p2p 1.78 mV — 60 Hz 떨림이 선 두께 수준. "잡음 입력 → 깨끗"의 대비가 도입부(−5 dB)보다 약하다. 해결 후보(이후 검토): 잡음 구간만 시간 확대 렌즈(G-02), 물리 눈금을 둔 확대 띠(F-026 방식), 또는 SNR 표기와 함께 받아들이기. 저장값을 부풀리지 않는다 |
| A5 | 잡음 주파수 | 저장 전원 간섭 잡음의 스펙트럼 최대 60 Hz `[코드]` — 국내 전원과 같아 "60 Hz" 표기 가능. 단 화면 60 fps에서 60 Hz를 그대로 움직이면 멈춘 듯 보이므로(스트로보), 물결(P6)은 **상징 속도**로 움직이고 숫자는 라벨로 전달 |
| A6 | 기법 이름 | M04의 정식 이름은 "Adaptive SWT" — SWT는 **Stationary** Wavelet Transform(정상 웨이블릿 변환). 사용자 원문의 "Static"은 표기 시 바로잡는다. 기저선 변동 1등 M_FE는 "추가 잡음 제거기 없이 공통 전처리(대역 필터)만"이라는 뜻이라, 풀어 쓸 때 오해가 없게 문구를 따로 정한다 |
| A7 | 상태 표시기 | 자동 진행 구현의 조건 경로(소나)를 재사용 가능. 사용자 평가: 소나는 잘 동작 |
| A8 | 도입부와 문법 통일 | 도입부 라벨 "M08 출력"도 같은 형식("최선 기법: Wavelet U-Net")으로 맞출지 도입부 라운드 2에서 함께 정한다 |

## 5. 사용자 결정 — −5 dB 고정 (2026-09-29, D-040)

> "잡음은 무조건 -5dB가 좋아 보이는데. … 차라리 기법 얘기는 expo 시연 결과물에서 지우는 한이 있더라도 -5dB로 고정하자. 만약 모두 딥러닝이 우위라면 아예 기법 얘기를 빼도 괜찮아." `[대화]`

| 잡음 | 장면 | 1등(oracle 제외) | 고전 기법 최고 |
|---|---|---|---|
| 전원 간섭 | d0-pli--5, S038 | M06L6 Residual U-Net · L6, 34.1 dB | M04 Adaptive SWT 28.8 |
| 기저선 변동 | d0-bw_synth--5, S038 (extension) | M06L6, 28.2 | M_FE·M04 23.1 |
| 근육 잡음 | d0-ma_synth--5, S038 | M08 Wavelet U-Net, 19.2 | M05 Sameni EKF 17.5 |
| (혼합, 도입부) | d0-mixed--5, S022 | M08, 19.7 | M05 11.2 |

→ 모두 딥러닝이 1등 → A3·A4·A6·P8은 이 결정으로 대체. 깨끗한 파형에는 "잡음 제거 출력(저장값)" 수준의 작은 표기만 남긴다.
**해결(D-041)**: 사용자 결정으로 S038 통일 — 도입부는 `d0-awgn--5`. 이전 기록: 잡음별 장면은 모두 S038(약 100 bpm)인데 도입부 권장 장면은 S022(약 74 bpm, 혼합 잡음은 S022에만 있음). 도입부와 이후 장면에서 같은 사람의 심장 박동 속도가 달라진다. 도입부를 S038의 −5 dB 장면(예: 전극 움직임 잡음 em_synth, 1등 M09 CNN + Transformer / extension M06L6)으로 바꿀지 도입부 라운드 2에서 정한다.

## 2. 자동 진행 구현에 대한 지적 (F-028)

- 조건 경로(소나)는 움직이는데 **정작 파형은 멈춘 이미지**.
- 제목 "잡음이 바뀌면 1등이 바뀝니다"는 처음 보는 관람자·평가자가 이해할 수 없다 — 의문과 해소 없이 결과만 준다.
- 오른쪽 기법 표시(M04, M_FE …)는 관람자가 알 수 없는 코드.

## 3. 이후 단계 (도입부 구현 완료 후)

1. 이 보드로 라운드 1: 원인 오브젝트(3종), 물결 표현, 축소/확대 반복 길이, A4 해결 방식, 기법 이름 문구 선택지.
2. 스택 점검(도입부 엔진 재사용 범위, 카메라 경로 역재생, 물결 셰이더).
3. 사용자가 이어서 줄 뒤 화면(격자·막대·Lab 진입) 피드백.
