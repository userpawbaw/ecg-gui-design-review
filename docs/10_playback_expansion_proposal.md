# 연속 재생·대형 비교창 수정 제안

작성: 2026-09-10. 상태: 사용자 승인 대기. 이 문서는 수정 제안이며 GUI 코드·데이터·모델은 아직 변경하지 않았다. 기존 S0–S5 결과 위에 추가하는 R 단계다.

후속 검토: [Expo·GUI 기획서 v2](11_expo_gui_plan_v2.md)가 모션·조작·기술 스택의 최신 제안이다. 이 v1은 비교 기록으로 보존한다. v2도 구현 전 검토본이다.

## 1. 요청의 해석과 추천 결정

목표는 실제 시간에 따라 변하는 ECG를 충분히 큰 화면에서 입력과 선택 방법으로 비교하는 것이다. 첨부 발표 그림의 넓은 축, 반투명 회색 reference, 선명한 처리 신호를 반영한다. 모든 방법을 작은 격자로 펼치지 않는다.

추천 조합: **정지 / Sweep / Scroll + 최소 600초 연속 데이터 + 화면 대부분을 쓰는 대형 비교창 + 기본 두 행 및 hover 점선**. 세 번째 비교 방법은 선택적으로 고정한다. 기법 설명 확장은 사용자가 요청한 후속 논의로 남긴다.

사용자 추가 정정 반영: 요청은 재학습이 아니라 **모든 잡음 조건에서 각 기법을 통과시킨 10분 출력 파형 재생성**이다. 재학습은 이번 범위에서 제외한다. '모든 조합'은 현재 제공하는 잡음 7종(혼합 포함) × SNR 7단계 × D0/D1 = 98조건으로 해석한다. 잡음 7종의 임의 부분집합·모든 혼합 비율까지 무한 확장한다는 뜻으로 해석하지 않는다. 각 조건마다 입력·reference·지원하는 각 방법 출력이 모두 있어야 한다.

## 2. 확인한 현재 상태

- prototype/app.js의 setPlaying/tick은 10초 고정 파형 위 커서만 움직이며 재생을 시작하면 시간을 0으로 되돌린다. 진짜 Sweep/Scroll은 없다.
- 원본 demo/mockup_expo.html의 drawAll은 Sweep에서 같은 짧은 파형 위에 지우는 띠를 옮긴다. Scroll은 짧은 합성 배열의 표시 구간을 이동하다 되돌린다. 모션의 참고 자료이며 긴 실측 데이터 재생 엔진으로 그대로 옮기지 않는다.
- scripts/build_demo_bank.py는 20초 처리 후 양쪽 5초 guard를 제외한 중앙 10초를 저장한다. 현재 98개 장면은 연속 10분 기록이 아니다.
- 원본 고정 SHA 5eb27946087faca3c6e70b3925e2ba132b2ee680의 Git tree에서 MITDB 원자료, NSTDB 자료, D0/D1 모델 체크포인트 존재를 확인했다. 111.hea는 360Hz, 650000표본으로 약 30.09분이며 현재 분할의 TEST 기록이다. 바이너리 다운로드·체크포인트 로딩·600초 추론은 아직 수행하지 않았다.
- ecgdn/methods/dl_wrapper.py에는 학습 window/hop·입력 정규화·FE 설정을 따르는 임의 길이 프레이밍 및 overlap-add 구현이 있다. 재학습 없이 긴 입력에 추론할 수 있는 경로가 있으나 실제 호환성 검사는 필요하다.
- 원본 NSTDB 잡음의 TEST 분할은 마지막 25%다. ECG 길이와 잡음 TEST 가용 길이는 별개이며 10분 잡음이 확보됐다고 간주하지 않는다.

## 3. 공통 재생 계약

표시 방식(displayMode: sweep/scroll)과 재생 여부(isPlaying)를 분리한다. 사용자에게 정지·Sweep·Scroll을 제공하되 정지는 현재 장면을 동결하며, 처음으로 이동하는 동작은 별도다.

| 기능 | 제안 동작 |
|---|---|
| Sweep | 작성 헤드가 왼쪽→오른쪽으로 새 표본을 그린다. 끝에 도달하면 왼쪽부터 다음 시간대 표본으로 덮어쓴다. 아직 덮지 않은 지난 주기 파형은 남고, 헤드 앞 지우는 간격은 모든 파형 및 reference에 동일하게 적용한다 |
| Scroll | 최신 표본은 오른쪽에 들어오고 기존 표본은 왼쪽으로 이동한다. 커서만 이동시키지 않는다 |
| 정지/재개 | 현재 기록 시각·표시 위치 유지. 재개하면 그 지점부터 진행한다. 초기화는 별도 처음으로 버튼 |
| 모드 전환 | 같은 세션·방법·재생 시각 유지. 레이아웃에 맞춰 표시 구간을 재구성하며 필요시 이미 읽은 과거 표본을 사용한다 |
| 표시 길이 | 기본 5초, 선택 2.5/5/10초. 데이터 전체 길이 600초와 별개다. 기존 국소 확대 기능은 유지 |
| 속도 | 기본 1×, 선택 0.5/1/2×. 표시 시간은 표본 수와 fs, 경과 시간으로 결정한다 |
| 전체 위치 | 00:00–10:00 탐색 막대와 현재 시각. 탐색 시 정지한 뒤 선택 위치를 정확히 보여준다 |
| 종료 | 기본은 마지막에서 정지. 반복 재생은 명시적 옵션이며 경계에서 이전·다음 끝점을 연결하지 않는다 |
| 조건 변경 | noise/SNR/record 변경은 정지→같은 시각의 새 조건 준비→표시. 이전 조건 출력을 새 결과처럼 남기지 않는다 |
| 방법 변경 | 같은 입력·시각 유지. 캐시가 준비됐다면 재생을 계속하며 바꾼다. 로딩이 필요하면 공통 재생을 정지하고 준비 상태를 표시한다 |
| 숨김/복귀 | 탭 숨김 시 정지하여 갑자기 시간을 건너뛰지 않는다. 열린 대형창과 기본 화면은 하나의 재생 상태를 공유한다 |

Sweep의 래핑 화면은 왼쪽의 새 주기와 오른쪽의 지난 주기가 함께 존재한다. 전체 x축을 하나의 연속 절대시각으로 잘못 표기하지 않는다. 상대 위치 눈금·작성 헤드의 기록 시각을 표시하고, 정지 시 각 위치의 실제 표본 시각을 조회한다. 연속 구간 지표는 마지막으로 도달한 시각 기준으로 계산하며 이 래핑 화면 전체를 연속 구간으로 간주하지 않는다. 첫 주기의 아직 읽지 않은 영역은 빈칸으로 둔다. 지우는 간격은 초기값 0.2초로 제안하며 2.5/5/10초 창에서 검수한다.

## 4. 대형 비교창

기본 제안은 앱 내부 modal dialog이며 브라우저 영역 약 96% 폭·94% 높이를 사용한다. 별도 OS 팝업을 전제로 하지 않으며, 전체화면 버튼을 제공한다. 사용자 표현의 '새 창'을 대형 앱 창으로 해석했으므로 승인 시 이 차이를 명시한다. 여러 모니터에 분리하는 OS 창이 필요하면 별도 요구로 바꾼다.

- 진입: 파형 패널의 명확한 '크게 비교' 버튼. 기존 파형 클릭은 구간 선택 동작을 유지한다.
- 상단: record/잡음/SNR/REPLAY, 선택 방법, 닫기·전체화면. 출처 상세는 요청 시 연다.
- 중앙: 첫 행 Noisy + 회색 Reference, 둘째 행 선택 방법 출력 + 동일 Reference. 좌우 분할보다 **위아래 두 행이 전체 폭을 사용하는 구조**를 기본으로 한다.
- 우측: 약 220px의 접을 수 있는 Method Explorer. 충분히 넓은 화면에서는 파형 영역에 폭의 80% 안팎을 배정한다. 좁은 창에서는 선택기를 상단으로 옮겨 플롯 폭을 확보한다.
- 하단: 정지/Sweep/Scroll, 표시 길이, 속도, 진폭 범위, 전체 10분 위치. 설명·수치가 파형 높이를 잠식하지 않게 한다.
- 1920×1080 목표에서는 각 파형 높이 약 280–330 CSS px를 초기 설계 목표로 삼는다. 실제 가독성 확인 후 조정한다. 3행이면 높이가 줄어듦을 사용자가 선택한다.
- 범례: Reference는 회색 반투명 실선으로 뒤에, 입력/처리 결과는 더 선명한 실선으로 앞에, hover 후보는 점선으로 구분한다. 회색 투명도 초기값 약 0.45–0.6이며 배경과 겹침 검수 후 확정한다.
- 모든 행에 동일 시간 매핑·mV 스케일·지우는 간격을 쓴다. 자동 진폭 맞춤은 비교 중 행마다 하지 않는다. 화면 밖 진폭은 잘림 상태와 수동 범위 맞춤으로 안내한다.
- Reference를 기준으로 출력을 임의 정렬·진폭 보정하지 않는다. 저장 데이터의 실제 정렬과 물리 단위를 보존한다.
- D1 범례는 'Reference · 원기록에 공통 FE 적용'으로 설명한다. 완전히 무잡음인 환자 clean을 확보했다고 표시하지 않는다. D0 합성 clean은 구분한다.
- 닫으면 방법·시각·진폭·재생 상태가 기본 화면에 이어진다. Escape와 닫기 버튼, 키보드 focus 순환·진입 버튼으로 복귀를 검수한다.

### 비교 방식의 추천

**기본: 두 행 + hover 점선.** 방법 목록 hover/focus가 둘째 행에 후보 출력을 겹치고, 선택 방법의 실선·고정 지표는 그대로 둔다. 벗어나면 점선만 사라진다. 클릭하면 그 방법이 선택된다. 재생 중에도 모든 선이 같은 시간대로 움직인다. 목록에 없는 출력은 생성해 보이지 않는다.

**선택: 비교 방법 고정 버튼으로 세 번째 행 추가.** 기본 화면의 comparison 방법을 세 번째 행으로 표시하며 모든 행의 축을 공유한다. 이 상태에서는 hover 후보도 셋째 행의 임시 미리보기로 사용해 셋째 행을 추가로 늘리지 않는다. 별도 '비교 방법으로 고정' 동작 전까지 고정 비교 방법과 지표를 바꾸지 않는다. 같은 방법을 중복 선택하면 중복 행을 숨기거나 명확히 안내한다.

이 절충안은 사용자가 요청한 두 대안 중 첫 번째를 기본값으로 선택하고 두 번째를 선택 기능으로 둔다. 구현 범위를 줄이려면 첫 번째만으로도 핵심 요구가 충족된다.

## 5. 10분 데이터 생성과 배포

완료 목표는 짧은 클립 60회 반복이 아닌 **연속 원기록의 최소 600초**다. 모든 방법은 같은 clean/reference·noisy 입력·표본 인덱스를 공유한다.

1. 코드 SHA, 원자료 해시, split/lead/시작 표본, checkpoint 해시 및 FE/window/hop/정규화 규약을 확인한다. TEST111 등 시작 후보를 성능에 맞춰 사후 선별하지 않고 명시적 규칙으로 정한다.
2. ECG 600초와 필요한 양끝 실제 문맥을 준비한다. D0는 600초를 생성하며 D1은 연속 원기록을 자른다. 250Hz 기준 본 구간은 150000표본이다.
3. 동일 레코드·잡음 종류에서 SNR만 바뀌면 같은 잡음 실현을 배율만 바꿔 쓴다. 전 구간 목표 SNR의 정규화 기준을 기록한다. 짧은 창마다 잡음 세기를 재정규화해 연속성을 바꾸지 않는다.
4. 기존 합성 잡음 조건은 긴 잡음을 결정론적으로 생성한다. 실제 NSTDB를 쓰는 조건은 허용 TEST 길이를 확인한다. 부족하면 train 구간을 섞거나 무표시 반복하지 않는다. 사용자가 이해할 수 있는 별도 구성/반복 표기 또는 독립 합성 조건으로 분리하며 이를 '미사용 연속 10분 잡음'으로 주장하지 않는다.
5. 기존 체크포인트와 고전 방법으로 사전 추론한다. 재학습은 수행하지 않는다. 체크포인트가 호환되지 않거나 없어 생성할 수 없는 방법은 원인을 보고하고 해당 출력의 완료 판정을 보류한다. 임의 대체 모델을 쓰지 않는다.
6. 긴 입력 FE 및 DL overlap-add 처리를 검증한다. 전송용 chunk 경계마다 필터를 초기화하지 않는다. 처리 분할이 필요하면 문맥·겹침을 포함하고 접합부를 수치로 확인한다.
7. 먼저 D1 대표 한 조건으로 전체 600초 생성·재생을 검증한 뒤 D1 전체 격자, D0 전체 격자로 확대한다. 최종 목표는 기존 98조건의 선택 범위를 유지한 600초 자료이며 대표 한 조건 완료를 전체 완료로 보고하지 않는다. 실제 생성 시간·크기는 첫 실행 후 보고한다.
8. M00는 입력 재사용. 실제 계산 가능한 기존 방법을 유지하고 M07/M10 추가는 체크포인트 호환성·별도 검증 후 다룬다. 이번 요구만으로 미지원 출력을 만들어 넣지 않는다.

600초 ×250Hz ×int16은 파형 한 개 약 0.3MB다. 13개 저장 배열 ×98조건이면 약 382.2MB, base64로 약 509.6MB이며 JSON 등 부가는 별도다. 이는 계산상 크기이지 실측 압축 크기가 아니다. 따라서 장시간 버전은 거대한 단일 HTML 대신 **앱+manifest+조건별 데이터 청크+로컬 실행 도구**를 ZIP으로 제공하는 방향을 추천한다. 현재 10초 단일 HTML은 간편 검토본으로 유지한다. 최종 실행에 인터넷이나 Python 모델 추론은 필요하지 않게 하고, 정적 로컬 실행기의 런타임 요구와 설치 절차는 패키지에 명시한다. 첫 설치·Playwright 브라우저 설치와 행사 중 오프라인 실행은 구별한다.

지표는 새 600초 세션 전체, 현재 연속 표시 구간, 기존 EXP-A/EXP-G 집계 근거를 구분한다. 10초 지표를 600초 성능으로 재사용하지 않는다. 재생 중 국소 지표는 과도하게 깜박이지 않도록 제한된 주기로 갱신하고 정지 시 정확한 선택 범위로 계산한다.

## 6. 브라우저 자동 검수

이번 환경 확인에서 제어 가능한 브라우저는 cloud Chrome(cdp) 하나다. 사용자 PC 브라우저가 연결됐다는 증거는 없다. 앞선 file/localhost 정책 차단은 해제 확인이 없으므로 우회하거나 반복 시도하지 않았다. browser skill 연결 확인만 했으며 실제 새 렌더링은 수행하지 않았다.

추천: 승인 후 프로젝트에 **사용자 PC용 Playwright 실행 패키지**를 만든다. 준비 후 명령 한 번 또는 Windows 실행 파일로 별도 브라우저 창을 띄워 자동 조작하고, screenshots/영상/trace/HTML·JSON 보고서/콘솔 오류를 ZIP으로 모은다. 기존 사용자의 개인 브라우저 창에 임의 연결하는 방식은 아니다. 결과 ZIP을 이 대화로 전달받으면 이미지와 로그를 검토하고 수정한다. 직접 PC 실행·자동 회수는 현재 연결 기능으로 보장하지 않는다.

| 검수 | 예정 증거와 통과 기준 |
|---|---|
| 실제 렌더링 | 1920×1080, 1366×768, 좁은 폭에서 기본·대형창 캡처. 버튼/범례 접근·겹침 검토 |
| 재생 | 실제 브라우저의 여러 Sweep 래핑·Scroll·정지/재개·모드 전환 영상. 새 인덱스와 선 위치가 함께 변하는지 확인 |
| 장시간 | 1× 실제 경과 10분 soak와 별도 가상시계 경계 테스트. 후자를 실제 10분 성능 증거로 대체하지 않음 |
| 비교 | hover 진입/이탈, 클릭 고정, 세 번째 행, 기본/대형창의 동일 표본·진폭·시각 |
| 예외 | 데이터 청크 로딩·실패·끝·재시도. 이전 조건 출력 오표시 금지 |
| 네이티브 UI | dialog focus·Escape 복귀, 실제 다운로드 이벤트와 파일 내용, 전체화면 지원/거절 처리 |
| 성능 | 프레임 간격·긴 작업·메모리 지원 범위·측정 PC 환경 기록. 데이터 시각과 프레임 수를 혼동하지 않음 |
| 오프라인 | localhost 앱 자료는 허용한 상태에서 외부 요청 차단 후 실행. 실제 OS 네트워크 분리 여부는 별도 표기 |

Playwright screenshot을 만들었다고 미적 품질을 자동 통과시키지 않는다. 수집된 이미지는 별도 시각 검토한다. OS 125/150% 배율, 스크린리더 체감, 실제 AFE 품질은 viewport 에뮬레이션만으로 검증하지 않는다.

공식 근거: https://playwright.dev/docs/running-tests (headed 실행), https://playwright.dev/docs/trace-viewer (행동/화면 추적), https://learn.chatgpt.com/ko-KR/docs/browser (지원되는 앱 브라우저 연결과 실행 환경 구분). 2026-09-10 조회.

## 7. 승인 후 순서와 종료 조건

| 단계 | 작업 | 완료 증거 |
|---|---|---|
| R0 | 현재 요청·원본·제약 조사 및 이 제안 | 문서·PLAN·WORKLOG, 원격 커밋 확인. 승인 대기 |
| R1 | 공통 재생 엔진 및 대형창 | 기존 10초 실제 자료로 두 모드·hover·상태 공유 확인. 600초 완료 주장은 보류 |
| R2 | 600초 생성 경로와 자료 확보 | 한 조건 검증 후 기존 격자 확장, 출처 manifest·정렬·경계·새 지표 |
| R3 | 장시간 UI/배포 및 PC Playwright 패키지 | 캐시·탐색·종료·전체화면·원클릭 검수·결과 ZIP |
| R4 | 실제 브라우저 결과 검토·보완 | 캡처/trace/10분 재생 결과, 문제 수정·관련 회귀 검사 |
| R5 | 팀 가이드·검증표 갱신 | 요청별 완료/미검증, 커밋, 재개 지점 |

매 단계 종료 시 수행 내용·실제 검사·판정·남은 단계를 채팅에 기록한다. 현재 판정: 조사와 제안 작성 완료, 구현 및 브라우저 검수는 승인 후 진행. 기법 설명의 상세화는 이번 수정 이후 논의한다.
