# 26. 룩덱(Look-dev) 자체 피드백 루프 — 모델링·조명·효과의 디테일 품질을 올리는 반복 절차

상태: 2026-10-04 채택 제안(D-049). 대상: HIGH/MEDIUM 구역의 3D·셰이더·후처리 작업(`25_EFFECT_PRODUCTION_PIPELINE.md`의 S4 구현~G6 사이를 구체화한다). LOW/폴리시는 제외.

## 0. 왜 만드나

모델링·조명·효과 구현은 "처음 한 번 만들고 사용자 피드백으로 고치는" 방식에서 매번 같은 종류의 부족함(베이직 머티리얼처럼 뜨는 책, 접촉 그림자 없음, 선형 모션, 깨끗한 신호가 노이즈 위에 얹혀 보임)이 반복됐다. 사용자가 보기 전에 **AI가 스스로 부족한 점을 찾아 고치는 반복**을 절차로 고정한다. 이 문서는 `25`의 G6(최대 3회 AI 자체 수정)과 같은 상한을 쓴다.

## 1. 루프 한눈에

```
S0 기준판   : 레퍼런스 보드 + 분야별 표준 관행 시트(§4)에서 이번 라운드 합격선을 정한다
S1 에셋 조사 : 24 단계. explore → 후보 비교 → fetch --pin → registry 등록. 쓸 수 없는 에셋은 "품질 기준 레퍼런스"로만 쓴다
S2 구현     : 한 라운드에 한 묶음(예: 책 모델+재질)만 바꾼다
S3 표준 샷  : 고정 카메라 샷 세트(§3)를 같은 조건으로 캡처한다 (프레임 번호·시각·박동 위상 고정)
S4 자기 비평 : 샷을 보고 §2 루브릭의 항목별 점수(0–3)와 "무엇이 왜 부족한가"를 글로 적는다
S5 수정 목록 : 점수가 낮은 항목마다 원인 가설 → 고칠 방법 → 예상 효과를 적고 우선순위를 매긴다
S6 재구현   : 수정 목록의 상위 항목만 반영한다 → S3으로
종료        : 모든 필수 항목 ≥ 2 이고 성능 예산 통과, 또는 3라운드 소진. 소진 시 남은 항목은 사용자에게 "남은 부족함"으로 정직하게 보고
```

각 라운드는 `docs/uiux_system/rounds/<R>/LOOKDEV-<주제>.md`에 **전/후 캡처 경로, 점수표, 원인 가설, 수정 내용, 실제로 좋아졌는지(후 점수)** 를 남긴다. 좋아지지 않은 수정은 지우지 말고 "효과 없음"으로 표시한다(`10_RECORD_KEEPING.md`).

## 2. 루브릭 (항목별 0 나쁨 · 1 미흡 · 2 허용 · 3 우수)

| 코드 | 항목 | 우수의 기준 |
|---|---|---|
| M1 | 형태·비례 | 실물 레퍼런스와 겹쳐 놓았을 때 외곽·두께·모서리 라운딩이 어긋나지 않음. 완전한 직각·완전한 평면 없음 |
| M2 | 재질 반응 | 거칠기·금속감이 부위별로 다르고(천/박/종이/가장자리), 빛의 각도에 따라 하이라이트가 이동 |
| M3 | 디테일 계층 | 큰 형태 → 중간(조인트·밴드) → 미세(직조·섬유) 세 단계가 있고 가까이 가면 한 단계 더 나옴 |
| L1 | 키 라이트 | 하나의 의도된 주광이 부피를 만들고 명암 경계가 형태를 따라감. 균일 조명 금지 |
| L2 | 대비·키아로스쿠로 | 화면의 가장 밝은 곳과 어두운 곳이 이야기의 초점을 가리킴(주인공이 가장 밝은 3분의 1 안) |
| L3 | 접촉·그림자 | 접촉 그림자·AO·반사광이 있어 물체가 "놓여" 보임 |
| L4 | 색 온도 대비 | 주광/보조광/림의 색 온도가 다르고 한 장면 안에서 일관됨 |
| P1 | 후처리 균형 | 블룸·비네트·그레인·DOF가 보이되 "필터"로 읽히지 않음(끄고 켜서 비교) |
| A1 | 모션 문법 | 예비 동작·가속/감속·오버슈트·머무름이 있고 선형 보간이 없음 |
| A2 | 2차 운동 | 넘김·펄럭임·시차처럼 주 동작을 따라가는 지연된 움직임이 있음 |
| D1 | 데이터 충실 | 파형·수치가 데이터 계약을 따르고 장식이 데이터를 가리지 않음(깨끗한 신호를 노이즈 위에 겹쳐 그리는 식의 오해 금지) |
| D2 | 이해 가능성 | 처음 보는 사람이 "무엇이 무엇으로 바뀌는지" 설명 없이 읽음 |
| F1 | 성능 | 1080p 메인 ≤ 6 ms, 후처리 ≤ 3 ms(`__bench` 기준, `25` §5 잠정값) |
| F2 | 연속성 | 불연속 팝·순간이동·텍스처 깜빡임 없음(프레임 단위 확인) |

필수: M1 M2 L1 L2 L3 D1 D2 F1 F2. 해당 없는 항목은 N/A로 적는다.

## 3. 표준 샷 세트 (같은 조건으로 전·후 비교)

고정: 해상도 1280×720, 같은 시각·박동 위상(R 피크 직후 0.05 s, 피크 후 0.4 s 두 장). 책 단계의 표준 샷:

1. 서가에서 책 정면(닫힘) 2. 꺼내진 책 3/4 3. 표지 반쯤 열림 4. 표지 완전 열림 + 첫 장 5. 페이지 넘김 중간 6. 심전도 용지 정면 + 파형 7. 심장 팝업 클로즈업 8. 광원만 끈 비교 샷(조명 기여 확인) 9. 후처리 끈 비교 샷. 레퍼런스 비교(`hard cover` CC0 모델)가 있으면 같은 카메라로 나란히 둔다.

## 4. 분야별 표준 관행 시트 (요약 — 각 라운드 S0에서 이 줄을 근거로 합격선을 정한다)

**양장본 모델링** — 보드는 책 블록보다 커서 가장자리 턱이 생기고, 조인트(바깥 홈)와 힌지(안쪽)가 있으며, 책등은 둥글고, 헤드밴드/테일밴드·면지(pastedown+free)·리본·종이 마구리(페이지 라인)가 있다. 천 직조 노멀·박 엠보싱은 거칠기 맵으로 구분한다. 출처: BookPublish, iBookBinding, Hasier Goitia 책 튜토리얼.

**조명 일반** — 키(주광) 하나로 형태를 만들고, 필(보조광)은 낮게, 림은 윤곽만, 대비비는 이야기에 맞춰 크게(키아로스쿠로: 빛이 닿는 곳만 보이고 나머지는 어둠에 둔다). 접촉 그림자와 AO가 없으면 물체가 떠 보인다. 색 온도는 주광/보조광을 다르게 한다. 발광 물체는 블룸으로 번지고 그 빛이 주변 면에 반사광을 남겨야 한다.

**종이** — 섬유 노멀, 가장자리 AO와 누렇게 바램, 얇은 종이의 투과광(뒷면의 빛이 비침), 곡면에 따른 음영 변화. 두께는 시트 스택으로 만든다.

**페이지 넘김** — 평면을 원통 곡선으로 휘어 넘긴다(Bend). 시트마다 약간의 지연(stagger), 책등 쪽이 먼저 움직이고 바깥이 늦게 따라온다. 넘기는 동안 왼쪽 스택은 늘고 오른쪽 스택은 준다.

**파형 표시(프로젝트 계약)** — 이전 도입부 설계를 따른다: 어두운 ECG 격자 위, 입력 호박색 · 출력 민트, 쓸고 가는 헤드(네온 + 나이 기반 백열 잔광), 지우는 틈, 헤드 마커, 입력↔출력은 **단순 교차 페이드 + 초점 이동(defocus)**, 박동에 맞춘 단계적 섞임 + 플래시. 깨끗한 신호를 노이즈 위에 반투명으로 겹쳐 그리지 않는다.

**심장** — 등가면(marching cubes) 메시 + 젖은 클리어코트, 박동 변형은 수축 방향을 따라 부분적으로. 층 쌓기 공예풍은 장식용일 때만.

**맥동 FX** — 박동은 파면(wavefront)으로 퍼진다. 입자는 파면이 지날 때 변위·밝기 변화를 받고, 엔벨로프는 연속(어택/감쇠)이어야 순간이동이 없다.

**후처리** — 블룸(임계값보다 부드러운 무릎), 비네트, 필름 그레인(정적 패턴 아님), 톤매핑(ACES/AgX) 후 색 보정, 초점 주인공만 DOF. 한 효과씩 꺼 보며 기여를 확인한다.

## 5. 에셋 조사 단계(S1) 규칙

`24_ASSET_RESEARCH_STAGE.md`를 따른다. 추가 규칙: (1) 후보를 최소 3개 보고 **미리보기 이미지를 직접 본 뒤** 고른다. (2) 쓸 수 없는 형태(예: 닫힌 단일 셸이라 열리지 않는 책 메시)는 버리지 말고 **품질 기준 레퍼런스**로 등록한다. (3) 레지스트리 `used_by`에 사용처와 "reference only" 여부를 적는다. (4) 생성형 3D 서비스는 라이선스·재현성 때문에 기본 제외한다.

## 6. 외부 스킬·플러그인 (2026-10-04 조사)

claude.ai 플러그인 카탈로그에서 3D 렌더·조명·셰이더 룩덱에 해당하는 항목은 없었다(Render, Simplio3D, Unity, biorender, Meshy 등은 용도·라이선스·키 요구 때문에 부적합). 따라서 이 문서와 `.claude/skills/lookdev-loop/SKILL.md`를 **프로젝트 로컬 전문가 관행 스킬**로 둔다. 분야 시트(§4)는 라운드마다 근거를 추가하며 확장한다. 외부 스킬은 자문일 뿐 데이터 계약을 넘지 못한다(AGENTS.md).

## 7. 검증 방법과 한계

각 라운드의 점수는 **AI 자기 평가**이며 사용자 시각 확인을 대체하지 않는다. 캡처는 내장 브라우저(스로틀된 rAF)와 고정 프레임 렌더로 얻으므로 실사용 GPU의 실시간 질감은 보증하지 않는다. 루프가 끝나면 사용자가 보는 것은 "마지막 라운드 결과 + 남은 부족함 목록"이다.
