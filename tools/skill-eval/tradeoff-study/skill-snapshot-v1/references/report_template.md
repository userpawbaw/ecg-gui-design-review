# 트레이드오프 보고 양식

채팅 보고와 D 기록 초안이 같은 순서를 쓴다. 표준(MEDIUM) 이상은 전 항목, 가벼움(LOW)은 0번 세 줄만.

```
## 0. 요약
- 권장: <후보 이름> — <한 문장>
- 얻는 것: <성능·비용 이득, 수치와 태그>
- 잃는 것: <손해> → <무료/싸다/실손, 근거가 된 여유 칸>
- 뒤집히는 조건: <민감도 결과>

## 1. 목표 기능
| 기능 | 필수/좋음/없어도 됨 | 근거(사용자 인용·기록) |

## 2. 제약
- 하드: …
- 소프트(예산): …
- 동시 부하 지도: <가장 무거운 겹침 구간>
- 이전 검증: <F/D/O/R 번호와 결론>

## 3. 여유 지도
| 축 | 값 | 태그 |
(공간 · 밝기 · 시간 · 주의 · 정밀도 · 변화 빈도 · 범위)

## 4. 기준과 문턱값
| 종류 | 기준 | 문턱값 |

## 5. 후보
| 후보 | 레버 | 한 줄 설명 |
(현상 유지와 사용자 제안을 반드시 포함)

## 6. 평가
| 후보 | 하드 필터 | 지배 여부 | 잃는 것 → 여유 칸 | 판정(무료/싸다/실손) | 성능 이득 | 비용 |

## 7. 권장 조합과 남는 손해

## 8. 민감도
- <가정/수치> 가 <값> 이면 <후보>로 바뀜

## 9. 검증
- 한 것: …(결과, 태그, 환경)
- 미검증: …(어디서 확인해야 하나)

## 10. 가정과 질문
- 가정: …
- 질문(결론을 바꾸는 것만): …
```

마지막에 프로젝트 규칙의 단계 마감(확인한 것 · PASS/CONDITIONAL/FAIL · 미검증 조건 · 다음 행동)을 붙인다.
