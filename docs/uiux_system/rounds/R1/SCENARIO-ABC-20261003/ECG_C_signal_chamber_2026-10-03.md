## 1. 중심 아이디어와 레퍼런스의 역할

**처음부터 심전도 자체가 커다란 입체 조형으로 화면을 채운다.** 카메라가 옆으로 돌면 이 조형이 심장과 전극에서 나온 신호임을 알게 된다. 잡음이 낀 리본은 입자로 풀리고, 밝은 디지털 표본 배열을 통과하면서 정렬된 뒤 깨끗한 리본으로 다시 모인다. 같은 처리실 안에서 전원·호흡·근육의 원인을 차례로 관찰한다.

A의 지구 하강, B의 종이 틈 진입과 다른 **처리 과정 자체가 도입부의 공간**인 안이다. 의료 기구를 실제로 촬영한 것처럼 만들지 않고, 신호를 크게 확대해 보여 주는 설명 조형이다.

| 레퍼런스의 구체적 와우 | 확인 수준 | C에서 가져오는 것 | 독자 확장 |

‘입자 폭발 후 재결합’도 가능하지만 폭발만으로는 디지털 처리를 보여 주기 어렵다. **C는 그 사이에 배열·통과·출력 방향을 갖는 장면을 넣는다.** 입력·중간 배열·출력의 형상은 실제 필터 내부 연산을 시각화한 수학적 모형이 아니다. 긴 알고리즘 강의 대신 `디지털 처리` 한 줄로 연출의 의미를 잡는다.

**대안 검토:** 우주 폭발형은 주제 연결이 약해 중심안에서 제외. 반투명 프리즘에 신호를 넣어 층을 분리하는 안은 보조 아이디어로 보류. **표본 배열 처리실**은 파형·처리·3잡음 원인이 같은 구조로 이어져 이번 C의 기본 초안으로 제안한다. 사용자의 채택을 대신 결정한 것은 아니다.

## 2. 세계의 구조와 공통 구도

기준 화면 1920×1080, 기본 카메라 35–40mm 상당. 검고 푸른 공간 안에 **가로 약 6m의 얕은 원형 처리 무대**. 중앙 뒤에는 격자처럼 정렬된 가는 디지털 기둥 12열, 그 바깥에는 3개의 넓고 반투명한 링. 링은 장치의 설명 조형이며 MRI/검사 장비라고 표기하지 않는다. 파형은 화면 좌우를 흐르는 리본, 두께와 뒤로 밀린 잡음층이 있어 옆면이 보인다.

측정 대상은 왼쪽 관찰 자리, 컴퓨터/바닥 멀티탭/카트는 오른쪽 뒤에 처음부터 존재한다. 도입 원경에서는 흐리고 작게 보여 주다가 Story에서 같은 물체로 가까워진다. 인체는 저장소에서 승인된 **얼굴 없는 H5 고리+젖빛 면과 3전극**을 출발 재료로 한다. 전극은 양 쇄골 아래와 왼쪽 아랫배, 리드 묶음은 오른쪽 허리 옆. 고정 소품은 카메라가 바뀌어도 위치를 바꾸지 않는다.

색은 어두운 남청 배경, 조형 면의 코발트 반사, 신호의 낮은 명도 앰버/청록, 연결 경로의 파랑/보라, 원인 잡음의 빨강. 초기 혼합 입력은 기존 피드백의 **0dB 목표**를 반영한 데이터/조건을 사용하되 해당 입력의 실제 생성 조건을 확인한다. 임의의 모습에0dB 라벨을 붙이지 않는다. 밝은 면은 리본 전체가 아니라 곡면 모서리/새로 생기는 표본/처리 배열 일부에만 준다.

큰 제목 80–88px 2행, 장면 제목 60–72px, 보조 상태 16–20px. 글자는 객체의 한쪽 모서리를 따라 배치하지만 한글 획이 입자에 가려지지 않게 별도 화면 면에 둔다. 아래 수치와 진행률은 **우리 설계값**, 원본에서 측정한 값이 아니다.

## 3. 도입부 C0–C7 — 프레임·전환·인과

도입부 진행률 p는 0→1, t는 저장 신호의 연속 재생 시간이다. p는 카메라·형태 전환을 제어하고 t는 심장과 R 피크/입자 주기를 계속 제어한다. 관찰 위치에서는 2.5초 창으로 움직이는 입력/출력이 보인다. 과감한 변형 중에는 리본이 확대/뒤틀려도 되며, 도착하면 박동 대응을 다시 분명히 읽게 한다.

### C0 / p0–.10 — ‘심전도 잡음 제거’와 커다란 신호

**정확한 화면:** 왼쪽 x100–720,y180–430에 제목 `심전도 / 잡음 제거` 88px, 그 아래 `신호가 달라지는 순간을 살펴봅니다` 22px. 리본 중심은(1200,660), 바운딩 박스 x650–1950,y240–1030, 오른쪽 일부는 프레임 밖. 높은 R 모양의 면은 화면 오른쪽 위로 솟고 앰버 잡음 선 3–4겹이 그 뒤쪽을 감싼다. 뒤의 첫 링은 리본보다 어둡고 상단만 보인다. 바닥에는 리본의 흐린 반사, 아래 왼쪽 작은 스크롤 힌트.

**움직임:** 리본을 따라 새 표본이 흐르며 얇은 국소 잔광. 정지 중에도 미세하게 움직여 이미지로 보이지 않는다. 기본 자전은 하지 않고 포인터에 카메라 방향±2°부터 시험한다. 제목은 더 적게 움직인다.

**전환/의미:** 다른 사물을 거쳐 ECG임을 뒤늦게 밝히지 않는다. 처음부터 ‘파형을 처리하는 프로젝트’를 선언한다. 다음 화면에서는 이 신호의 출처를 발견한다.

### C1 / p.10–.23 — 옆으로 돌자 심장과 연결선이 드러난다

**정확한 화면:** 카메라가 리본 오른쪽에서 왼쪽 방향으로 약25° 돌아 앞·뒤 층을 분리한다. 리본의 큰 R 중심은(1230,540), 폭900/높이580으로 작아진다. 왼쪽 뒤(430,590)에 인체 실루엣 높이560, 가슴의 심장 높이100. 전극에서 카트까지 파란 선, 카트에서 처리실 방향 보라 선. 사람/심장이 리본 뒤에서 전경으로 갑자기 튀어나오지 않게 회전 중 먼저 실루엣을 노출한다.

**글자/전환:** C0 제목은 먼저 위로 나가고 `한 사람의 박동에서` 64px가 왼쪽 상단에 들어온다. 리본은 더 늦게 회전해 서로 다른 깊이와 도착 속도를 준다.

**인과:** 리본의 시작점이 측정 선에 연결돼 공간이 장식 전시가 아니라 기록을 확대해 보여 주는 장소로 읽힌다. 사람은 카메라가 발견한 같은 물체다.

### C2 / p.23–.36 — 심장과 잡음 입력을 같은 리듬으로

**정확한 화면:** 심장 중심(440,540), 높이380. 인체 윤곽은 왼쪽 화면 경계 뒤로 흐르고 3전극 중 가슴의 두 전극이 일부 보인다. 오른쪽 리본은 x850–1830,y360–780, 앞뒤 깊이 약150px로 보이되 이 관찰 위치에서는 R의 모양을 읽을 수 있다. 리본 뒤에 얇은 격자면, 제목 `잡음이 섞인 심전도` 68px는 x870,y180. 아래 작은 INPUT/확인된 조건만 표시.

**시간 동작:** 저장된 R 인덱스 이벤트가 심장 박동 envelope와 새 R 표본을 함께 만든다. 노란 선의 명도는 청록 출력과 같은 수준, 헤드만 짧게 밝다. sweep의 지움 쪽에는 국소 fadeout, 새 선에는 밝아졌다 정상 밝기로 복귀하는 잔광. 스크롤을 멈추면 이 장면의 재생은 계속된다.

**인과/도착:** 신호를 찢기 전, ‘그 심장과 이 입력’을 충분히 한눈에 연결한다. 전환 중 극단적 변형을 허용하기 위해 전후의 기준 장면을 분명히 둔다.

### C3 / p.36–.49 — 잡음 리본이 표본으로 풀린다

**정확한 화면:** 카메라가 오른쪽 리본 쪽으로 .6m 접근, 심장은 왼쪽 전경(210,600)에 절반만 남는다. 리본은 x480–1850,y250–900으로 커지고, 오른쪽 끝에서부터 작은 앰버 조각들이 깊이 방향으로 떠난다. 깨끗한 중심선이 먼저 보이는 해법 대신 **입력 전체가 표본 조형으로 해체**되는 안이다. 가장 가까운 10–20개의 조각은 사각 면/두께가 보이고 뒤쪽은 작은 빛점으로 가늘어진다.

**움직임/전환:** 원점 주변의 짧은 팽창 후 앞으로 마구 폭발하지 않고 중앙 뒤 처리 배열로 흐른다. 먼 조각은 빠르게, 큰 가까운 조각은 느리게 지나 카메라 깊이를 드러낸다. 화면 전체를 백색 flash로 가리지 않는다. 제목은 `기록을 디지털로 처리합니다` 60px로 교대.

**인과:** 입자화는 기록의 디지털 표본을 크게 보여 주는 은유. 실제 필터가 공간에서 샘플을 부수는 것으로 설명하지 않는다. p를 멈추면 해체된 정도는 고정되고 입자의 미세 운동/심장 주기는 유지된다.

### C4 / p.49–.65 — 밝은 배열을 통과하며 정렬된다

**정확한 화면:** 중앙 배열 입구(1120,540), 폭900/높이700. 카메라는 15° 비스듬하게, 가까운 기둥 2개가 화면 좌우를 가려 안으로 들어가는 느낌. 작은 조각은 12열의 가는 선 사이를 통과하며 좌→우의 규칙적 행으로 정돈된다. 배열 뒤(1690,570)에 청록 출력의 첫 묶음. 붉은/앰버 잡음층은 아래쪽(1100,930)으로 떨어져 어두워진다. 무대 오른쪽 뒤의 컴퓨터를 작은 연결선으로 배열에 붙여 처리의 주체를 남긴다.

**글자:** 화면 왼쪽 위 `디지털 처리` 68px, 밑에 긴 설명 없음. 실제 선택 데이터에서 검증된 처리 기법만 작은 한 줄로 넣을 수 있으며, 근거가 없으면 특정 기법/‘최선’ 표기는 생략한다.

**운동/인과:** 입구는 흐트러짐, 중간은 정렬, 출구는 결합이라는 3구역이 한 프레임에 보인다. 배열은 **단계 수/성능 점수/수학적 알고리즘 순서를 주장하지 않는 연출 장치**다. 속도에 따른 국소 발광으로 보는 맛을 만들고, 그 빛이 다음 리본의 선폭으로 이어진다.

### C5 / p.65–.81 — 출력 리본이 다시 모인다

**정확한 화면:** 카메라가 출구를 지나 왼쪽으로 살짝 돌면서 청록 출력 리본 x800–1810,y330–800, 심장(410,550) 높이360을 동시에 되찾는다. 흐트러진 앰버 조각은 왼쪽 뒤/아래로 빠지고 청록 조각은 R의 높이부터 중심선으로 붙는다. 남은 조각들이 기준선과 T 모양을 완성한다. 완성 직전 작은 격자가 리본 뒤에 다시 펼쳐진다.

**운동/인과:** 재결합을 한 번의 박동 발광에 맞춰 닫으면 ‘심장–기록–처리–출력’이 연결된다. 정지 스크롤에도 출력 재생은 계속. 출력이 임의로 너무 완벽한 직선이 되지 않게 실제 저장 결과에서 도착 형상을 만든다. 중간 입자 궤적은 실제 데이터 값이 아니다.

### C6 / p.81–.92 — 세 잡음 원인의 공간을 보여 준다

**정확한 화면:** 카메라가 1.5m 뒤로 나가 원형 무대 전경. 사람(720,590) 높이620, 오른쪽(1360,660) 컴퓨터/카트/바닥 멀티탭. 위쪽 큰 제목 `잡음은 어디에서 올까요?` 68px. 왼쪽 아래 작고 또렷한 상태 면에 `전원 간섭 / 기저선 변동 / 근육 잡음` 3행, 첫 행만 밝은 소나 고리.

**전환:** 출력 리본은 얇아져 무대 뒤를 감싸는 청록 띠로 남는다. 도입부의 물체를 모두 버린 새 페이지가 아니다. **원인 물체가 있는 같은 세계로 카메라가 돌아온다.**

### C7 / p.92–1 — 전원선으로 카메라가 향한다

**정확한 화면:** 컴퓨터가(1270,540) 폭560/높이480, 바닥 멀티탭(1120,900) 폭360. 전원선은 이 둘 사이, 보라 통신선은 책상 윗면을 지나 카트로. 인체는 왼쪽 뒤 높이360. 전원선과 심전도 케이블이 가까이 지나가는 구역을 보여 줄 수 있는 낮은 3⁄4 구도.

**운동/의미:** 카메라가 전원선 방향으로 돌아 멀티탭에 접근한다. 플러그 옆 작은 AC 보드가 다음 장면에서 나온다. 기존 Story의 저품질 행성/정지 파형을 재활용하지 않는다.

## 4. Story — 같은 처리실의 세 원인

각 장의 진행률은 독립 q0→1이다. 원인·입력·처리·출력의 의미를 공유하지만 **카메라와 원인 조형은 다르게** 만든다. 두세 번의 물결/호흡/쥠을 볼 수 있는 t 루프를 두고, 빠른 스크롤을 강제로 막지 않는다. 이전 구간의 도착 후 q를 다음 장으로 넘긴다.

근육 장면은 저장소 F-030의 이미 채택된 규칙을 따른다. 설명용 합성 잡음의 0.1초 RMS 포락선에 켜짐0.3mV/꺼짐0.15mV 문턱과 히스테리시스, 쥔 상태 최소0.3초, 0.25초 미만 간격 묶음, 쥐기0.12초/펴기0.25초를 적용한다. 이는 선택한 기존 입력에 대한 승인 규칙이며 다른 입력에 무조건 같은 문턱을 쓰지 않는다. 잡음 문턱을 넘는 표본에서 쥐기를 시작해 시점을 늦추지 않고, 작은 `합성 잡음 · 설명용 연출` 고지를 둔다. 잦은 쥠/폄이 떨림으로 읽히는지는 실제 손 애니메이션에서 다시 확인한다.

## 5. 도입부 이후의 독자 아이디어 — 중심 C와 별도 선택

| 아이디어 | 언제/어디 | 보는 맛과 ECG 의미 | 제작 시 비교할 선택지 |
|---|---|---|---|
| **잡음 공간 투사 확장** | CP1/CB1/CM1 | 원인 근처의 붉은 장이 파형의 뒤쪽 깊이 층을 흔들어 ‘그곳에서 잡음이 유입’ | 주변 장의 변위 vs 입자층 이동. 정확 비교에는 적용하지 않음 |
| **처리 배열을 타이포로 연결** | C4 | 입자 행이 한순간 `디지털 처리`의 획 방향으로 정렬됐다가 출력으로 흐름. 단어도 연출의 물체가 됨 | 전체 글자 입자화보다 가는 하이라이트 획만 연결하는 안. 읽기 시간을 검토 |
| **심장이 격자를 여는 박동** | C2/C5 | 심장 박동마다 격자의 가까운 면이 짧게 벌어져 깊이가 보이고 R이 도착하면 다시 정리 | 전체 격자 진동 vs R 근처 국소 면의 개폐. 파형까지 과하게 흔들 필요 없음 |
| **잔광이 처리 흔적이 된다** | CP2/출력 도착 | sweep에서 지워질 밝은 잔광이 뒤쪽 모니터 배열로 흘러가 처리 경로를 이어 줌 | 단순 잔광 유지/한 박동당 한 번의 연결. 이미 만족한 밝기를 보존하는 버전과 대조 |

새 아이디어는 위 목록에서 끝내지 않는다. 각 씬 제작 결과를 보고 **그 프레임의 빈 곳·약한 시선 연결·지루한 전환을 해결할 2–3개**를 제안하며, 사용자 반응을 해당 씬의 피드백 기록에 남긴다.

## 6. 기술 계획과 먼저 검증할 위험

1. **핵심 전환 예비 영상:** 입력 리본/배열/출력 target만 회색/단색으로 C3–C5 구현. 의미와 카메라를 먼저 시험. GPU 입자 20k는 시작값이고, 가까운 면 조각과 먼 점을 분리한다.
2. **물성:** 리본의 유광·반투명 잡음층·넓은 조명과 국소 bloom을 한 장면에서 조정. Lusion에 준하는 ‘밀도’는 개수보다 가림과 곡면 빛이 좌우한다. 무작정 입자 수를 늘리지 않는다.
3. **입력 통합:** 프로젝트의 한 Lenis→GSAP 진행률. 렌더는 Three.js, 입자는 GPU target 보간/texture 방식 중 시험 결과로 선택. 별도 스크롤 엔진을 중복 도입하지 않는다.
4. **단일 표본 시계:** 심장·리본·burst는 같은 재생 인덱스로 계산. 이벤트마다 독립 setTimeout으로 맞추지 않는다. 변형 중 보이는 가짜 R 형상을 실제 측정 표본이라고 기록하지 않는다.
5. **같은 공간:** 인체/3전극/카트/컴퓨터/멀티탭 고정 좌표, CP/CB/CM 카메라와 주제별 효과만 분리. 기존 Story 전면 수정 계획에 맞춰 새 장면을 구성한다.
6. **경계와 성능:** CM3에서 정확 비교 renderer로 인계 확인. 핵심 효과의 프레임 시간·발열/긴 재생·목표 PC 검증은 실제 구현 때 수행. 저성능이면 Intro/Story는 고품질 사전 렌더 경로도 검토하되 비교 데이터는 실시간 정확 렌더 유지.

가장 큰 위험은 **처리실이 멋진 공장처럼만 보이고 심전도 프로젝트가 잊히는 것**, 입자가 안개로 뭉개지는 것, 3원인에서 같은 처리 효과가 반복돼 지루해지는 것이다. 첫 제목/심장 연결/배열 방향/원인별 다른 구도로 대응한다. 이것들이 실제로 성공하는지는 목업과 전환 영상으로 판정해야 한다.

## 7. 신규 C의 구체성 자체 점검

기존에 수락된 사용자 피드백 분석/대조를 다시 평가하는 절이 아니다. **새로 쓴 C의 제작 명세가 충분한지**만 확인한다.

| 점검 항목 | C에 기록된 것 | 상태 |
|---|---|---|
| 한 씬의 결과 화면을 그릴 수 있는가 | 해상도, 좌표, 크기, 면/깊이, 색·빛, 글자 위계 | 문서 충족. 생성 이미지 검토 전 |
| 시작→중간→도착이 있는가 | C2 입력, C3 풀림, C4 배열, C5 출력. 인과 별도 작성 | 문서 충족. 연속 운동 검증 전 |
| 정지에도 살아 있는가 | p/t 분리, 저장 R와 심장, 단계별 loop 상태 | 명세 충족. 구현 전 |
| 실제 레퍼런스 와우와 독자 확대가 구별되는가 | §1 확인 수준/독자 확장 표, 마이닝 카드 | 충족. Igloo footer 직접 관찰은 미완료 |
| A/B와 다른 중심 그림인가 | 처리 공간 자체가 도입부, 지구/기록물 도입 없음 | 충족 |
| 정확 비교 경계가 명확한가 | CM3 renderer 인계 | 명세 충족. runtime 미검증 |

**현재 판정:** 신규 검토안. Q는 미구현, 개연성은 입력→처리→출력의 문서 연결까지 제안 가능. 결과물 품질의 KEEP을 선언하지 않는다. 이후 A/B/C 전체 피드백과 제작 순서를 정한 다음, **최종 피드백이 끝난 안의 목업**을 만든다.

**C의 우선 목업 프레임:** C0의 꽉 찬 리본/직접 제목 → C2 심장+입력 → **C4 배열 속 처리 공간** → C5 출력. 운동 판단용은 C3/C4/C5 전·중·후 영상. 지금은 생성하지 않는다.
