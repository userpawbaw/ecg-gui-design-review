## 1. 목표

레퍼런스 REF-002(leoparpeix.com 다락방 장면, `docs/uiux_system/references/REF-002_LEOPARPEIX.md`)처럼 다음 세 가지가 한 화면에 함께 있게 한다.

- **거리에 따라 감쇠하는 빛 웅덩이 하나**: 가운데·오른쪽이다. 사용자가 짚은 "부드러운 음영(파란 상자)"은 이 웅덩이 감쇠의 꼬리다.
- **그늘 경계 바로 옆의 선명한 직사광 강조**: 사용자가 짚은 "명암 대비 극대화(빨간 상자)"다.

지금은 Blender 정지 렌더 단계다. 웹(굽기·런타임)에는 아직 반영하지 않았다.

## 2. 현재 상태 (r6 조정판, 2026-10-10)

빌드(파스텔):
```
python scripts/blender/build_archive.py --intro2 --art r6 --dress --palette pastel --look h5 --preview DIR --samples 64
```
r6 기본값: 해치 밖 2.2 m의 작은 스폿 주광(5500, #fff0e2, 반지름 0.06 m, 방향 0.45/0.5/−0.74), 해 0.5°·세기 22(강조만), 하늘빛 0.5, 노출 0.15, AgX Punchy, 왼쪽 천장 구멍 닫음(그늘 구역), 벽·나무 재질 85 % 단색, 바닥 #a89075. 장면 구성은 해치 + 옆 사다리 + 오르는 사람 + `--dress` 소품(서랍장, 빈칸, 액자, 석고 조각, 눕힌 책)이다.

측정(파스텔 a1 / a2, `[런타임]`):

| 지표 | r6 조정판 | 레퍼런스 | 판정 |
|---|---|---|---|
| L* 5/25/50/75/95 | 4 15 24 42 77 / 4 15 24 53 78 | 2–4 15–18 25–33 52–62 81–97 | 근접 |
| 진한 색 deep% | 4.1 / 3.6 | 3.6 | 도달 |
| 방 단위 밝은 비율(≥ +1.5스톱) | 37 / 41 % | 48 % | 약간 부족 |
| 선명 경계 폭 σ* | 1.0 px (r6 첫판) | 0.8 px | 근접 |
| **plain_range**(무늬 없는 면의 빛 변화 폭) | **30 / 32** | 57–69 | **부족** — 조정에서 잃음 |
| pastel% | 18 / 20 | 22–25 | 약간 부족 |

남은 문제:
1. **plain_range 하락**(r6 첫판 52–57 → 30–32). 노출을 낮추면서 웅덩이 안의 서랍장·빈칸까지 어두워졌다.
2. **파스텔 비율이 레퍼런스 아래다.**
3. **갈색(archive) 팔레트는 이 노출에서 쓸 수 없다**(L*5 −10). 갈색을 고르면 노출을 따로 잡아야 한다.
4. **선명 경계의 대비(sharpC 12–13 대 20–22)**가 부족하다. 일부는 사람 고리 무늬가 만드는 경계이고, 레퍼런스에는 사람이 없다. 이 숫자를 쫓기 전에 사람을 가리고 다시 잰다.

## 3. 다음에 할 일 (사용자가 고르기 전 상태)

사용자에게 마지막으로 제시한 선택:
1. **그대로 확정(파스텔)**: 줄어든 변화 폭은 웹 굽기 뒤 화면에서 다시 확인한다.
2. **한 번 더 조정(AI 권장 후보)**: 그늘 깊이(L*5 ≈ 4)는 유지하고, 웅덩이 안 서랍장·빈칸의 빛만 되살려 plain_range를 50 이상으로 되찾는다. 방법 후보:
   - 주광 세기(`KEY_E`)를 올리고 노출은 유지한다.
   - 주광을 조금 더 좁히거나 가까이 두어 감쇠를 키운다(`KEY_D`, `KEY_DIR`).
   - 웅덩이 안 면의 반사율을 올린다(`TEX_KEEP`, 칸 뒷면 색).

색(파스텔/갈색)도 아직 정하지 않았다. **새 세션은 사용자에게 이 둘을 먼저 묻는다.** 확정되면 웹 굽기로 넘어간다(§7).

## 5. 측정 도구

- `python scripts/assets/frame-tone-stats.py FRAME [--box x0,y0,x1,y1] [--map edges.png]`: 명도 분포, 직사광, 파스텔, 진한 색, 경계 폭 지표(선명·번짐, 대비, plain_range). 합성 계단·경사로 하는 자체 검사는 `--selftest`.
- `python scripts/assets/light-structure-maps.py out.jpg "label|frame.png" …`: 사진 / 스톱 지도 / 방 단위 스톱 지도. 그늘 구역·웅덩이 배치를 볼 때 쓴다.
- `python scripts/assets/tone-sheet.py out.jpg "label|frame.png" …`: 수치가 붙은 2열 비교 시트.
- **레퍼런스 원본 프레임은 저장소에 없다**(에셋 복사 금지 규칙). 레퍼런스 수치는 F-038 ~ F-040과 각 verification README에 기록돼 있다. 레퍼런스를 다시 재야 하면 사용자에게 녹화나 프레임을 요청하고, 세션 임시 폴더에서만 쓴다. 시트에 넣을 때는 "analysis only, not an asset"으로 표시한다.
- 원본 3D 에셋은 받을 수 없다. 사이트는 배포 중지(402)이고, web.archive.org는 이 클라우드 출구를 TLS 단계에서 끊는다. 아카이브 목록에도 `.glb`·`.ktx2`가 없다(F-040 추가 절).

## 6. 함정 (이미 한 번씩 밟은 것)

- **O-010**: 백그라운드 렌더가 아직 읽을 스크립트를 수정하지 않는다. 편집 전에 `pgrep -af "^python scripts/blender/"`로 확인한다.
- **Cycles 확산 되튐 상한은 기본 4회**다. `BOUNCES`가 둘 다 맞춘다. 되튐을 12회로 늘려도 효과가 없었다(D-061).
- **천장판 두께 0.15 m**가 이 해 기울기에서 0.12 m를 스스로 가린다. 0.2 m보다 좁은 틈으로는 해가 들지 않는다(D-059).
- **해 원반을 키우면** 경계가 레퍼런스보다 흐려진다(2°에서 2.8 px). 부드러움은 원반이 아니라 넓은 광원·되튐·감쇠에서 온다(F-040).
- **구멍을 늘리면** 빛이 얼룩덜룩 흩어진다(r4 · r5). 레퍼런스는 웅덩이 하나다.
- **사다리나 오르는 사람을 옮기면** 가로대 접촉을 다시 맞춰야 한다(손 28·35 mm, 왼발 76 mm). r3에서 사다리와 사람은 같은 강체 변환(`LAD_M`)으로 함께 움직인다. 충돌 검사는 `reach=.09`로 한다. 기본값 0.2 m는 얇은 옆대에서 오탐을 낸다.
- 레퍼런스 사이트의 에셋·코드·이미지는 저장소에 넣지 않는다. 액자 그림은 직접 만든 색면 구성이다.

## 8. 기록 규칙

- 의미 있는 갈림길은 구현 전에 D를 남긴다(다음 번호는 커밋 시점의 마지막 D + 1). 해석이 바뀌면 F를 남긴다. 단계마다 PLAN.md·WORKLOG.md를 갱신하고, 커밋 전에 `npm run records:check`를 돌린다(`npm test`에 포함).
- 결론이 나면(사용자가 확정하면) 같은 커밋에서 플레이북 정리 대기의 "서고 빛" 행을 여정 J-003과 카드로 묶는다. 사슬은 r2 → r3(해치 하나) → r4(구멍 추가) → D-060(드레싱) → D-061(측정·바닥 조각) → F-040(해부) → r6(가까운 작은 주광)이다.
- 커밋 메시지 끝에 세션의 공동 작성자 줄을 붙인다. 모델 이름은 커밋·코드·문서에 넣지 않는다.
