## 0. 사용자가 정한 흐름 (2026-09-29 `[대화]`)

> "기법별 차이를 강조하는 것은 포기하고 앞에서 내가 수정했던 wow 포인트의 임팩트를 유지시켜서 기법 비교 패널까지 끌어오는 것에 집중하자." · "이 잡음이 바뀐다는 부분에 집중하자는 거야."

잡음 3단계(전원 간섭 → 기저선 변동 → 근육 잡음)를 같은 문법으로 반복한다. 전원 간섭의 시간 흐름:

| # | 스크롤 | 보이는 것 |
|---|---|---|
| P1 | 도입부 끝(혼합 잡음 → 깨끗) 이후 | 파형 fade out, 심장이 화면 중앙으로 돌아와 강조 |
| P2 | 계속 | 도입부 확대와 **대비되게** 사람 윤곽까지 축소 |
| P3 | 함께 | 상태 표시기(잡음 3단계)가 구석에 부드럽게 등장, "전원 간섭"이 소나처럼 강조 — "이제 잡음별로 본다"를 UI 하나로 |
| P4 | 계속 | 사람 옆에 전자기기 하나 + 선 + 꽂힌 콘센트(자세할 필요 없음, 글자 없이 원인 전달) |
| P5 | 조금 더 | 콘센트에 작은 AC 아이콘 |
| P6 | 계속 | 전자기기 중심으로 **물결처럼 퍼지는** 60 Hz 간섭(소나보다 물결 느낌) |
| P7 | 계속 | 다시 사람 → 심장 확대, 전원 간섭을 받은 잡음 입력이 박동에 맞춰 재생(도입부의 반복) |
| ~~P8~~ | ~~깨끗해지기 직전부터~~ (D-040으로 제외) | 옆에 작게 **"최선 기법: (풀어 쓴 이름)"** — 코드(M04) 대신 |
| P9 | 계속 | 필터를 통과해 깨끗한 파형으로 교차(도입부와 같은 디테일) |
| → | | 기저선 변동, 근육 잡음도 같은 문법. 관람자가 "어, 최선 기법이 다르네?"를 스스로 알아채게 |

제목 "잡음이 바뀌면 1등이 바뀝니다"는 결론만 먼저 주므로 이 흐름에서는 쓰지 않는다. 기법 설명형 전개("여러 디지털 처리 방식을 비교했습니다 → 모든 면에서 최선의 방법이 존재할까요?")는 사용자가 검토 후 **템포 때문에 기각**했다(§4).

## 1. 흐름 분석 (AI, 짧게)

| # | 관찰 | 판단 |

| A1 | 도입부의 확대(지구 → 사람 → 심장)를 **역방향으로 한 번 더** 쓰는 구조 | 좋음 — 카메라 경로를 진행률 함수로 만들면 같은 경로를 재사용·역재생할 수 있다. 3회 반복에서 지루하지 않게 2·3회차는 축소/확대 구간을 짧게 하는 것을 이후 검토 |

| A8 | 도입부와 문법 통일 | 도입부 라벨 "M08 출력"도 같은 형식("최선 기법: Wavelet U-Net")으로 맞출지 도입부 라운드 2에서 함께 정한다 |

## 5. 사용자 결정 — −5 dB 고정 (2026-09-29, D-040)

> "잡음은 무조건 -5dB가 좋아 보이는데. … 차라리 기법 얘기는 expo 시연 결과물에서 지우는 한이 있더라도 -5dB로 고정하자. 만약 모두 딥러닝이 우위라면 아예 기법 얘기를 빼도 괜찮아." `[대화]`

| 잡음 | 장면 | 1등(oracle 제외) | 고전 기법 최고 |
|---|---|---|---|
| 전원 간섭 | d0-pli--5, S038 | M06L6 Residual U-Net · L6, 34.1 dB | M04 Adaptive SWT 28.8 |
| 기저선 변동 | d0-bw_synth--5, S038 (extension) | M06L6, 28.2 | M_FE·M04 23.1 |
| 근육 잡음 | d0-ma_synth--5, S038 | M08 Wavelet U-Net, 19.2 | M05 Sameni EKF 17.5 |
| (혼합, 도입부) | d0-mixed--5, S022 | M08, 19.7 | M05 11.2 |

→ 모두 딥러닝이 1등 → A3·A4·A6·P8은 이 결정으로 대체. 깨끗한 파형에는 "잡음 제거 출력(저장값)" 수준의 작은 표기만 남긴다.
**해결(D-041)**: 사용자 결정으로 S038 통일 — 도입부는 `d0-awgn--5`. 이전 기록: 잡음별 장면은 모두 S038(약 100 bpm)인데 도입부 권장 장면은 S022(약 74 bpm, 혼합 잡음은 S022에만 있음). 도입부와 이후 장면에서 같은 사람의 심장 박동 속도가 달라진다. 도입부를 S038의 −5 dB 장면(예: 전극 움직임 잡음 em_synth, 1등 M09 CNN + Transformer / extension M06L6)으로 바꿀지 도입부 라운드 2에서 정한다.

- 오른쪽 기법 표시(M04, M_FE …)는 관람자가 알 수 없는 코드.

### 6.2 데이터 확인 (저장값, `public/archive.json`, S038 −5 dB, 잡음 = 입력 − 깨끗) `[코드]`

| 장면 | 잡음 p2p | 관찰 | 연출에 쓰는 법 |
|---|---|---|---|
| d0-pli--5 | 0.93 mV (신호 1.78) | 60 Hz | 물결은 상징 속도(A5 — 60 fps 스트로보) |
| d0-bw_synth--5 | 0.93 mV | 1 s 이동평균 극값: 1.1↓ 2.5↑ 4.6↓ 6.0↑ 7.6↓ 9.1↑ s → **주기 약 3–3.5 s(분당 17–20회)**, 10 s에 약 3번 숨 | 잡음 저주파 성분의 위상 = 들숨/날숨. 저장값에서 계산하므로 "가짜 호흡" 아님 |

### 6.3 AI 검토 — 좋은 점

- 원인을 **글자 없이 오브젝트와 몸의 동작으로** 보여 준다(A2를 구체화). 세 잡음이 각각 "밖(전원) → 몸 전체(숨) → 근육(주먹)"으로 원인이 점점 몸 안으로 들어오는 순서라 이야기 구조가 생긴다 `[추론]`.
- 모니터의 "박동마다 한 겹"은 도입부 T2 문법을 **화면 속 기계로 옮긴 것** — 잡음 제거를 "기계가 하는 일"로 보여 주고, 세 장면 모두 같은 장치로 깨끗해지는 반복 문법이 된다.
- 숨·주먹을 저장 잡음에 맞추는 것은 도입부의 "R 피크 = 박동" 동기화와 같은 원칙이라 일관된다.

## 7. 카메라 워크 검토 (2026-10-01)

사용자 `[대화]`: "카메라 워크에도 신경 좀 써줬으면 해. 이 부분이 3d 에셋의 가장 큰 장점이잖아? … 더 표현하기 적합한 시나리오, 더 보는 맛 있는 카메라 워킹에 관련해서 피드백을 받고 싶은 거야."

### 7.1 원칙 (AI 제안)

1. **동기 있는 이동** — 카메라는 무언가를 따라가거나 드러낼 때만 움직인다(전선을 따라감, 물결을 따라감). "오브젝트가 새로 나타남"보다 "카메라가 돌아서 원래 있던 것을 발견함"이 3D답다.
2. **장면마다 다른 카메라 서명** — 세 잡음이 같은 축소·확대를 반복하면 지루하다(S1). 전원 = 추적·크레인, 기저선 = 궤도·호흡 카메라, 근육 = 얕은 초점 접사·초점 이동.
3. **속도 대비** — 스크롤에 붙은 느린 이동 사이에 박동에 맞춘 짧고 빠른 이동(휩 줌)을 한두 번. 계속 느리면 졸리고 계속 빠르면 피곤하다.
4. **멈춤** — 파형을 읽어야 하는 구간에서는 카메라가 멈춘다(데이터 판독 우선). 빠른 이동은 파형이 그려지는 동안 금지.
5. **구도 크기 순환** — 원경 → 중경 → 근경 → 극근경을 섞는다. 지금 대본은 중경과 극근경 왕복이 대부분.

### 7.3 기저선 변동 — 카메라 서명: 궤도 + 호흡 카메라

- 정면에서는 가슴이 들썩이는 게 거의 안 보인다 → **옆모습(측면 중경)으로 천천히 궤도 이동**. 숨은 측면 실루엣에서 가장 잘 읽힌다 `[추론]`.
- 카메라 자체도 숨에 맞춰 아주 조금 오르내린다(호흡 카메라) — 관람자가 같이 숨 쉬는 느낌.
- 과감안: **가슴 실루엣 선이 그대로 파형의 기저선으로 이어진다** — 가슴이 오르면 기저선이 오른다(같은 저장 잡음 저주파 성분). 깨끗해지면 기저선이 평평해지며 가슴선과 분리.

### 7.4 근육 잡음 — 카메라 서명: 얕은 초점 접사

- 전경에 주먹(극근경), 배경에 흐린 가슴·심장. 잡음 폭발마다 **초점이 주먹 ↔ 가슴으로 이동**(rack focus) — 원인과 결과를 초점으로 연결.
- 주먹을 쥘 때 팔 근육 결이 빛나고, 같은 순간 파형에 잡음이 낀다(S4 최소 유지 0.3 s).
- 낮은 각도에서 올려다보면 힘준 주먹이 강조된다.

### 7.5 끝 — 요약 원경

세 원인(콘센트·숨·주먹)을 한 화면에 담는 높은 원경으로 한 번 빠진 뒤 모니터로 밀고 들어가 Lab 화면이 되는 match cut(S9).

### 7.6 구현 노하우

- 카메라 위치·시선을 각각 스플라인으로(CatmullRom), 스크롤 진행률 → 경로 매개변수(구간별 easing·멈춤 구간).
- 휩 줌 = 짧은 FOV·위치 변화 + 방향 흐림 후처리 0.15–0.25 s, 박동 시각에 발동(T2와 같은 시계).
- 초점 이동 = 피사계 심도 후처리(BokehPass 비용 확인, 낮은 해상도 흐림 대체 가능).
- 카메라 키 작성 도구: Theatre.js(시각 편집기) 검토 가치 — 새 라이브러리라 채택 시 D 기록(`23`).
- 데이터 계약: 카메라는 파형 꼭짓점을 바꾸지 않음. 파형 판독 구간은 정지. 3D 리본/모니터 속 파형도 물리 눈금 유지.

### 8.2 공통 문법 (세 장면)

1. **원인 막** — 화면 전체 3D, 카메라가 원인을 찾아가 보여 줌(장면마다 다른 카메라 서명).
2. **이분할 막** — 카메라가 사람을 화면 왼쪽 45 %에 두는 구도로 정착 → 오른쪽 55 %가 0.6 s에 걸쳐 어두워짐(왼→오 그라데이션 막) → 도입부와 같은 격자·라벨·sweep이 들어옴. 사람 몸 안 심장이 박동하고 R 피크가 같은 프레임에 그려짐(도입부 동기화 그대로).
3. **처리 막** — 컴퓨터 모니터에 "박동마다 한 겹" 4칸이 박동마다 채워지며(스크롤 목표 + 박동 해제, T2) 오른쪽 파형이 잡음 입력 → 저장 출력으로 교차. 마지막 칸이 차는 박동에 모니터 화면이 한 번 번쩍임.
4. **나가기** — 오른쪽 막이 걷히고 카메라가 다음 원인으로 출발.

데이터 계약: 오른쪽 파형 = 저장값, 물리 눈금(도입부 G3). 3D 연출(물결·숨·주먹)의 타이밍은 저장 잡음에서 계산(§6.2, F-030). "합성 잡음 · 설명용 연출" 고지.
