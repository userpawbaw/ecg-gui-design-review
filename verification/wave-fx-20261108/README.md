# 파형 그리기 연산량 측정 (D-161, 2026-11-08)

실시간 측정 탭에 실험실 파형 효과(D-073)를 옮기면서, 같은 효과를 얼마나 싸게 그릴 수 있는지 잰 기록.

## 조건
- `prototype/v2` 빌드를 `node scripts/serve-v2.cjs`(4173)로, Playwright Chromium headless, 1920 × 1080, `?bg=0`(3D 배경 끔: 파형 비용만 보려고), `labfx=2`(번짐 단계 고정).
- **소프트웨어 래스터**(`--disable-gpu`): 이 환경에는 GPU가 없다. 화소 채우기 비용이 CPU에 그대로 드러나는 보수적 조건이다. GPU가 있는 전시 PC에서는 이미지 붙이기 비용이 훨씬 작아 절대값이 다르다(미측정).
- 실시간 탭 자료: `mock-bridge.cjs` — **시험용 합성 심전도(측정값 아님)**, 250 Hz, 12 표본씩 48 ms, 입력 + 출력 3계열.
- 실험실: 저장 10 s 자료, 재생 시작 후 1.5 s 데움 → 6 s 측정. 실시간: 4 s 데움 → 10 s 측정. dpr 1은 3회 반복 중앙값, dpr 2는 1회.
- 지표: 초당 그리기 수, 그리기 함수의 스크립트 시간(ms/회), 브라우저 전체 프로세스 CPU %(모든 Chromium 프로세스 합, 100 % = 코어 1개), **프레임당 CPU = CPU % ÷ 초당 그리기**(그리기 수가 달라도 비교 가능한 값).
- `wave=`: `prev` 이전 그리기(실시간 D-157 · 실험실 D-073), `naive` 실시간 탭에 같은 효과를 실험실 원래 방식으로(기준선, 측정 전용), `live`/`all` 링 스트립.

## 읽기
- **실시간 탭**: 새 효과를 다 얹고도 프레임당 CPU가 이전 그리기 대비 +17 ~ 20 %(스윕 2.32 → 2.76, 스크롤 2.29 → 2.69, 중첩 2.02 → 2.43). 같은 효과를 실험실 원래 방식으로 그리면 +79 ~ 250 %(4.15 · 4.07 · 7.08)이고 초당 그리기가 29 · 30 · 16회로 떨어진다. 링 스트립은 그 기준선 대비 −34 % · −34 % · −66 %.
- **실험실 탭**: 같은 모양을 링 스트립으로 그리면 프레임당 CPU −37 % ~ −35 %(스윕 2.59 → 1.62, 크게 비교 4.74 → 3.29, 스크롤 2.62 → 1.72), 초당 그리기 25 → 34회, 18 → 28회.
- **dpr 2**(소프트웨어 래스터)에서는 모든 방식이 느리다(실험실 기존 그리기 10 fps). 실시간 링 스트립은 17.5 fps(이전 그리기 35 fps). 번짐 자동 낮춤(26 ms 넘게 이어지면 2 → 1 → 0)을 켠 상태(`labfx` 미지정)에서는 26.5 fps, 번짐 0단계로 내려간다.
- 그리기 스크립트 시간(ms/회)은 방식끼리 직접 비교하지 않는다: 링 스트립은 캔버스끼리 붙일 때 원본을 그 자리에서 래스터해 시간이 스크립트에 잡히고, 원래 방식은 래스터가 프레임 끝으로 미뤄져 스크립트 시간에 덜 잡힌다. 전체 CPU가 공정한 지표다.

## 최적화 단계별 기록
회차마다 기계 부하가 달라 같은 「이전 그리기」도 프레임당 CPU 2.00 ~ 2.32로 흔들린다. 그래서 단계 비교는 **같은 회차 안의 비율**로 적는다.

| 단계 | 바꾼 것 | 실험실 스윕: 링 ÷ 기존 | 실시간 스윕: 링 ÷ 이전 | 실시간 dpr 2 초당 그리기(링 / 이전) |
|---|---|---|---|---|
| 1 | 링 스트립 1차: 표본은 한 번만 긋기, 효과는 램프 · 스프라이트(행 크기 층에서 14번 붙이기) | ≈ 1.0(1회) — 비용은 꼭짓점이 아니라 **화소 채우기** | — | — |
| 2 | 선단 창만 층 처리(먼 구간은 링을 바로 붙임) + 번짐 3단 미리 합치기 + Reference 없는 칸 빈 링 생략 | 0.64 | 1.19 | 15.5 / 36.8 |
| 3 | 흰빛 창 1 s → 0.6 s, 선단 앞 빈칸을 링에서 미리 비움, 번짐 층 CSS ½ 해상도, 실시간 정적 층을 CSS 배경으로 | 0.63 | 1.19 | 17.5 / 35.4 |
| 3 + 자동 낮춤 | 실시간에도 실험실과 같은 번짐 단계 자동 낮춤(26 ms) | — | — | 26.5(번짐 0단계) |

단계 3은 dpr 1에서는 차이가 측정 오차 안이고, dpr 2(화소가 많은 화면)에서 효과가 있었다.
