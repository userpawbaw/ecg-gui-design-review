## 6. 효과 카드

### EFX-001-01 히어로 카드 영상: 인트로 1회 + 뒷부분 반복

**선정 이유**: wow 포인트(첫 장면), 재사용 메커니즘 — 실시간 3D 없이 고품질 제품 장면을 만드는 방법.
**지각**: 로딩 뒤 받침대 위 금속 카드가 빛을 받으며 드러나고, 이후 같은 장면이 자연스럽게 반복된다. 스크롤하면 영상이 조금 느리게 위로 밀린다(parallax).
**입력 모델**: 로드 + 시간(반복), 스크롤 위치(parallax).
**판별 근거**: 소스 — `.hero_video`는 mp4 `<video>`이며 `ended` 이벤트에서 `currentTime = duration × 211/340`으로 되감는다. parallax는 `scrub: true` 트윈 `[코드]`.
**구현 메커니즘**: 사전 렌더 영상 1개. 첫 재생은 처음부터, 끝나면 211번째 프레임(62 %)부터 다시 재생해 인트로 없이 반복한다. 로더는 `sessionStorage`로 세션당 1회만 보인다. iOS는 사용자 제스처를 기다렸다가 재생한다. `yPercent 0 → 10`(scrub true)로 parallax.
**파라미터**:
| 이름 | 값 | 출처 |
|---|---|---|
| 총 프레임 / 반복 시작 프레임 | 340 / 211 | `[코드]` |
| 시작 지연 | 0.7 s | `[코드]` |
| parallax | yPercent 0 → 10, scrub true | `[코드]` |
**타임라인**: 로드 → 0.7 s 지연 → 전체 재생 → 이후 62 %~100 % 구간 반복. 히어로가 화면 위로 나갈 때까지 parallax.
**에셋**: `MOTO_HERO_2.mp4` 4.53 MB, H.264(자체 S3 호스팅). 제품 렌더 영상 — 3D 툴에서 사전 렌더링한 것으로 추정 `[추론]`.
**성능 기법**: 실시간 3D 대신 영상이므로 GPU 부담이 거의 없다. 멈춤(stall) 감시 후 재시도.
**접근성·폴백**: reduced-motion 대응 없음 `[코드]`. muted + playsinline, iOS 제스처 대기.
**근거**: 영상·로더·되감기 로직 `[코드]`, 파일 크기 `[런타임]`, 제작 도구 `[추론]`.
**재현 요구사항**: Blender 등으로 ECG 오브젝트를 사전 렌더(또는 외부 영상 조달) + `<video>` 반복 제어 스크립트. 난이도 하(코드) / 중(영상 제작).
**수용 기준**: 첫 재생 후 이음매가 보이지 않게 반복된다. 반복 지점에서 프레임 점프가 1프레임 이하.
**ECG 번안**: Attract 첫 장면을 실시간 3D가 아닌 사전 렌더 영상으로 만들면 전시 PC 부담 없이 고품질을 낼 수 있다. 영상 속 파형은 canonical 데이터가 아니므로 "장식"으로만 쓰고, 측정 파형처럼 보이지 않게 한다(LOW zone 침범 위험).
**재현 상태**: `none`

### EFX-001-02 역광 지구: 느린 기본 회전 + 스크롤 위치 연동 회전·축소·페이드

**선정 이유**: 사용자 지목("wow 포인트인 스크롤시 지구 회전 효과", "스크롤 내릴 때마다 가속해서 돌다가"), wow 포인트.
**지각**: 화면 하단에 떠오른 지구가 느리게 돌고 있다. 스크롤하면 스크롤 속도에 비례해 빨리 돌며 작아지고, 헤드라인이 위로 빠지며 chip이 무작위 순서로 사라진다. 윗가장자리의 푸른 대기 rim이 점점 두드러진다.
**입력 모델**: 시간(기본 회전) + 스크롤 위치(회전·축소·페이드).
**판별 근거**: 녹화에서 회전 속도와 스크롤 속도의 상관 0.96 → 처음에는 "속도 적분"으로 추정했다 `[영상]`. 소스에서 `rotation.y`가 진행률에 선형 매핑되고 `scrub: 1`인 것을 확인해 **위치 연동으로 정정**했다(F-012) `[코드]`. 녹화만으로 판별하려면 되돌리기 반응을 봐야 한다(D-017 순서 7).
**구현 메커니즘**:
```
WebGPURenderer(forceWebGL) · PerspectiveCamera fov 25 · pos (0, .2, 5)
earthGroup = [globe (Sphere 64×64, MeshStandardNodeMaterial), atmosphere (같은 구, BackSide, ×1.04)]
earthGroup.position = (0, −1.32, 0), scale 1.3        // 화면 하단에 걸친 구도
DirectionalLight 강도 6, 위치 (0.26, 1.39, −3)          // 지구 뒤 위쪽 = 역광 (고정)
매 프레임: globe.rotation.y += dt × 0.025               // 기본 회전
ScrollTrigger(.earth, pin, 2.5 × 화면높이, scrub 1):
  earthGroup.rotation.y : base − π/1.4 → base − π/5   (ease none, 전 구간)
  earthGroup.scale      : 1.3 → 0.52                  (0.1–1.0, power2.out)
  uniforms.opacity      : 1 → 0                       (0.2–0.35, power2.out)
  .earth_header         : yPercent → −120             (0–1)
  .earth_point (chip)   : autoAlpha 0, y 24, stagger random 0.2 → 0.45에 display none
셰이더(TSL):
  fresnel = 1 − |dot(viewDir, normal)|
  sunOri  = dot(normal, sunDir)
  색 = mix(night × 0.95, 낮 PBR 출력, smoothstep(−0.25, 0.5, sunOri))
  대기색 = mix(twilight, day, smoothstep(−0.25, 0.75, sunOri))
  rim 마스크 = smoothstep(−0.5, 1, sunOri) × fresnel² × (normal.y 기반 reach 마스크)
  대기 구 알파 = remap(fresnel, .73→1, 1→0)³ × sunOri 마스크 × reach × opacity
  bump 텍스처 채널: b=구름(→ 흰색 합성), g=거칠기, r=지형 높이 → bumpMap
```
**파라미터**:
| 이름 | 값 | 출처 |
|---|---|---|
| 기본 회전 | 0.025 rad/s | `[코드]` |
| 스크롤 회전 범위 | −π/1.4 → −π/5 (약 1.35 rad) | `[코드]` |
| pin 길이 / scrub | 2.5 × 화면 높이 / 1 s | `[코드]` |
| 축소 | ×0.4 (1.3 → 0.52), 진행 0.1–1.0 | `[코드]` |
| 페이드 | opacity 1 → 0, 진행 0.2–0.35 | `[코드]` |
| 태양 | (0.26, 1.39, −3), 강도 6 | `[코드]` |
| 대기 | reach 0.635, 구 배율 1.04, 밤 세기 0.95 | `[코드]` |
| 재질 | roughness 0.25–0.35 | `[코드]` |
| 렌더 | ACES 톤매핑, 노출 1.16, pixelRatio ≤ 1(데스크톱)·≤ 1.5(모바일) | `[코드]` |
| 관측: 회전속도 ∝ 스크롤속도 | 상관 0.96, 지연 0 프레임 | `[영상]` |
**타임라인**: `.earth` 상단이 화면 상단에 닿으면 pin 시작. 2.5 화면 높이 동안 회전(선형)·축소(power2.out)·페이드(0.2–0.35). Lenis(duration 1.6) + scrub 1 s가 겹쳐 입력보다 부드럽게 늦게 따라온다.
**에셋**: day 텍스처 webp 315 KB, night(도시 불빛) webp 186 KB, 채널 묶음 bump(구름·거칠기·지형) webp 566 KB. 모두 등장방형으로 추정 `[추론]`.
**성능 기법**: pixelRatio 상한 1(데스크톱), 화면 밖(±400 px)이면 3프레임 중 1프레임만 렌더, 텍스처 로드 후 2프레임 워밍업, 텍스처 3장을 채널 묶음으로 줄임, 구 분할 64×64.
**접근성·폴백**: reduced-motion 대응 없음 `[코드]`. 모바일/Safari는 텍스처 샘플을 한 번으로 합침. WebGL 실패 시 폴백 없음.
**근거**: 파라미터 전부 `[코드]`, 속도 상관 `[영상]`, 녹화 기반 추정의 정정 기록은 F-011·F-012.
**재현 요구사항**: three.js(WebGL 또는 WebGPU+TSL), GSAP ScrollTrigger, Lenis. 지구 텍스처 3종(NASA Blue/Black Marble, public domain)을 받아 bump 채널 묶음을 직접 만든다. 난이도 중. spike의 정면 주광·큰 회전은 이 카드 기준으로 수정해야 한다.
**수용 기준**: (1) 정지 시 회전 0.025 rad/s ± 10 %. (2) 되돌리면 회전·크기가 거꾸로 복원된다. (3) 역광 구도: 정면은 밤 면, rim은 윗가장자리. (4) 1920×1080 target PC에서 60 fps.

**재현 요구사항**: DOM 위치를 매 프레임 읽어 WebGL 평면에 옮기는 동기화 층 + 텍스트 텍스처 캐시 + 호 변형 셰이더. 난이도 중~상.
**수용 기준**: 스크롤 중 DOM 위치와 WebGL 글자 위치가 1 px 이내로 일치하고, 중앙 확대가 연속적이다.
**ECG 번안**: 실험 수치(예: 방법별 SNR 개선량)를 이 방식으로 흐르게 하면 "데이터의 벽" 장면이 된다. 이때 숫자는 반드시 실제 결과값이고, 크기 변형은 강조 연출일 뿐 값의 크기를 뜻하지 않음을 명시한다(데이터 왜곡 위험 — `02_DATA_STORYTELLING` 대조 필요).
**재현 상태**: `none`

### EFX-001-07 컨시어지 이미지 패널 clip reveal

**선정 이유**: 장면 전환.
**지각**: 다음 섹션의 사진 패널이 아래에서 올라오면서, 패널 안의 사진은 반대로 내려와 제자리에 멈춘다. 창이 열리는 듯한 느낌이다.
**입력 모델**: 스크롤 위치.
**판별 근거**: 소스 — 바깥 패널 `yPercent 100 → 0`, 안쪽 이미지 `yPercent −100 → 0`, `scrub: 0.25` `[코드]`. 녹화 29–35 s `[영상]`.
**구현 메커니즘**: 바깥 요소는 `overflow: hidden` 마스크 역할을 하고, 바깥과 안쪽이 반대 방향으로 같은 거리만큼 이동하면 안쪽 이미지는 화면에서 정지해 보이고 마스크만 열린다(counter-translate reveal). 배경은 별도로 `yPercent ±10` parallax.
**파라미터**:
| 이름 | 값 | 출처 |
|---|---|---|
| 패널 / 이미지 | yPercent 100 → 0 / −100 → 0 | `[코드]` |
| scrub | 0.25 | `[코드]` |
| 구간 | `.concierge_bottom` top bottom → top top | `[코드]` |
**타임라인**: 섹션 하단 진입부터 상단 도달까지 선형(ease none).
**에셋**: 컨시어지 사진 webp(반응형 500~3200 px 7단계).
**성능 기법**: transform만 사용(레이아웃 재계산 없음), 반응형 이미지 srcset.
**접근성·폴백**: reduced-motion 대응 없음 `[코드]`.
**근거**: 수치 `[코드]`, 인상 `[영상]`.
**재현 요구사항**: GSAP ScrollTrigger만으로 가능. 난이도 하.
**수용 기준**: 되돌리면 정확히 역재생되고, 이미지 자체는 화면에 고정된 것처럼 보인다.
**ECG 번안**: 결과 요약 → 상세 비교 화면처럼 한 장면에서 다음 장면으로 "창을 여는" 전환에 쓸 수 있다.
**재현 상태**: `none`

### EFX-001-08 오른쪽 → 왼쪽 목록 타이포 전환 (끊김 사례)

**선정 이유**: 사용자 지목("37초 부근부터 나오는 오른쪽 타이포그래피 전환 효과는 이전 지구 파트나 카드 회전 파트처럼 부드럽진 않거든"), 품질 차이 비교 자료.
**지각**: 오른쪽 아래 대형 목록의 항목이 하나씩 작아져 사라지고, 왼쪽 위 작은 목록에 같은 항목이 하나씩 커지며 나타난다. 이동 경로가 없고 한 줄씩 계단처럼 바뀐다. 스크롤을 멈추면 모든 것이 정지한다.
**입력 모델**: 스크롤 위치(줄 단위, 짧은 구간).
**판별 근거**: 녹화 60 fps — 오른쪽 축소와 왼쪽 확대가 따로 일어나고 각 0.15~0.3 s, 정지 중 완전 정지 `[영상]`. 소스 — 줄마다 ScrollTrigger(`top 70%` → `bottom 70%`, `scrub: true`) `[코드]`.
**구현 메커니즘**:
```
각 줄 i: ScrollTrigger({trigger: 줄의 부모, start: "top 70%", end: "bottom 70%", scrub: true})
         오른쪽 줄 scale 1 → 0 (origin bottom right, power1.in)
         왼쪽  줄 scale 0 → 1 (origin top left,  power1.out)
```
끊겨 보이는 이유: (1) 트윈 구간이 줄 높이 하나(수십 px)라 보통 스크롤 속도에서 0.1~0.3 s 만에 끝남. (2) `scrub: true`라 지연 추종이 없음(지구·카드는 1 s). (3) 이동이 아니라 축소·확대가 따로 일어나 공간 연속성이 없음. (4) 기본 움직임 층이 없어 멈추면 완전 정지.
**파라미터**:
| 이름 | 값 | 출처 |
|---|---|---|
| 트리거 구간 | 줄 부모의 top 70% → bottom 70% | `[코드]` |
| scrub | true (지연 0) | `[코드]` |
| easing | 축소 power1.in / 확대 power1.out | `[코드]` |
| 관측 전환 시간 | 줄당 0.15–0.3 s | `[영상]` |
**타임라인**: 줄마다 독립. 줄 사이 겹침 없음.
**에셋**: 없음(DOM 텍스트). 배경은 지형 영상.
**성능 기법**: transform scale만 사용.
**접근성·폴백**: reduced-motion 대응 없음 `[코드]`.
**근거**: 끊김 관측 `[영상]`, 원인 `[코드]`, 해석 `[추론]`.
**재현 요구사항**: 재현이 아니라 **개선판**을 목표로 한다 — 트리거 구간을 여러 줄 높이로 늘려 겹치게(stagger), `scrub 0.8–1`, 또는 GSAP Flip으로 실제 이동 경로 + 배경 영상 계속 재생. 사전 준비: 로컬 글꼴 preload(측정 안정). 난이도 하~중.
**수용 기준**: 같은 스크롤 입력에서 한 줄의 전환이 0.5 s 이상에 걸쳐 연속적으로 보이고, 멈춰도 배경이 움직인다.
**ECG 번안**: 방법 목록 → 선택 목록 같은 UI 전환의 **반면교사**. 우리 구현은 FLIP 이동 + 지연 추종을 기본으로 한다.
**재현 상태**: `none`

## 10. 열린 질문

- Webflow 번들 JS와 CSS의 섹션별 레이아웃(sticky 높이, clip-path 등)은 읽지 않았다. 필요하면 `motoc333.webflow.shared.*.css`를 분석한다.
- 숫자 벽 열의 흐름이 CSS 애니메이션인지 순수 스크롤인지 확정하지 못했다(모듈 안에 스크롤 코드 없음). → D-017 규칙의 새 녹화(정지 구간 포함)로 판별.
- 실제 GPU에서의 fps, GPU 메모리 사용량은 측정하지 않았다(소프트웨어 렌더 환경). → 로컬 세션이나 target PC에서 측정.
- 히어로 영상의 제작 도구, 원통 사진의 출처는 확인하지 못했다.
- 카드 GLSL의 Spline 노드 부분(`nodeU0`~`nodeU23`)의 의미는 해석하지 않았다. Spline 재질을 직접 만들어 export해 보면 대응 관계를 알 수 있다.
