# 서고 재질이 저품질로 보인 이유와 대체 조달처 — 2026-10-18

분류: RESEARCH. 연결: F-106, 24번 §1.1, 10월 16일 검토안 §5. 근거·실제 이미지 메타데이터·접근 결과: `verification/r1-archive-material-forensics-20261018/README.md`(저장소 루트 기준).

## 1. 결론과 적용 범위

문제는 **낡고 거친 표면 선택 + 배포 해상도·압축 + 재질 표현·베이크**가 겹친 결과로 나눠 봐야 한다. Poly Haven 전체가 낮은 품질이라는 증거는 없다. 반대로 CC0·실사 스캔이라는 사실이 맑은 파스텔 서고에 맞는다는 증거도 아니다.

이번에 직접 검사한 것은 **현재 커밋된 기존 웹 archive.glb**와 현재 셰이더, 보존된 두 WaterBottle 변형이다. 웹 GLB는 최신 r8/B2 정지 렌더가 아니다. 최신 Blender 정지 렌더에 웹 압축·웹 셰이더를 원인으로 적용하지 않는다.

## 2. 원인별 증거와 남은 불확실성

| 원인 | 확인한 근거 | 해석 / 확인 안 함 |
|---|---|---|
| 표면 스타일 선택 | 포함 알베도 painted_plaster_wall, painted_wooden_table, vintage_wooden_drawer_01을 직접 열면 변색·긁힘·마모 무늬가 보임 | 깨끗한 낮은 대비 표면과 맞지 않는 입력이다. 최초 원본을 새로 받아 비교하지 않았으므로 모든 무늬가 최초 원본과 동일하다는 단정은 안 함 |
| 해상도·아틀라스 | archive.glb의 50장 중 49장 1024², ECG 종이 1장 512². ash/walnut의 이름은 2k지만 실제 1024² | 고밀도 UV 아틀라스를 한 장으로 줄이면 각 면의 유효 텍셀은 더 적다. 최종 각 면의 화면 texel/pixel 비율은 미측정 |
| 실제 가공 설정 | package-archive.py: glTF optimize + WebP + --texture-size 1024. 별도 lightmap은 q92 | 4K 원본만 새로 받아도 같은 가공 상한이면 결과는 다시 1K다. 현재 GLB의 실제 인코더 quality 값과 압축 전 손실량은 복원하지 못함 |
| 웹 재질 표현 | GLB에는 노멀/roughness-metallic 연결 재질이 각각 17개. archive.ts는 알베도 × 구운 빛, 채도/노출만 사용 | 실시간 노멀·거칠기·금속 반응은 원본 PBR 그대로 재현되지 않는다. 베이크에 이미 들어간 법선 음영까지 전부 없어진다는 뜻은 아님. 이 경로의 실제 인상 기여는 전후 렌더 미측정 |
| 베이크·UV | 과거 다락방 기록: 작은 책 UV 조각과 OIDN으로 얼룩; UV 점유 29→56 %, 재굽기로 보정. 현재는 책/소품 정점색, shell 2048 lightmap | 원본 재질과 별개로 생긴 얼룩 사례다. 그 과거 결함이 최신 B2에도 그대로 있다는 주장은 안 함 |
| 아트 디렉션·광량 | D-062에서 표면 결을 줄였고 현재 r6 코드도 벽/나무 15 %, 바닥 40 %만 남김 | 강한 결을 단색으로 누르는 임시 처리가 있었다. 전체 소품·모든 PBR 채널의 정리를 완료한 것은 아님 |

완전 베이크/unlit 표시 자체는 저품질의 증거가 아니다. 레퍼런스도 이 방식으로 높은 품질을 낸다. 중요한 것은 목표 장면에 맞는 입력 표면과 충분한 공간 해상도, 일관된 최종 색이다.

## 3. 과거 압축 비교의 해석 정정

9월 감사는 기본 WaterBottle 91 KB와 q90 683 KB 변형에서 반사 얼룩이 개선됐다고 기록했다. 현재 보존 파일은 정확히 **91,092 bytes / 683,088 bytes**, 이미지 4장씩이 **1024² / 2048²**다.

따라서 현재 파일을 근거로 “quality 90만 올렸더니 해결”이라고 할 수 없다. **해상도와 압축 조건이 함께 다르다.** 새 확인에서는 같은 원본·해상도·UV·카메라·조명을 고정하고 lossless/고품질/저품질만 바꿔야 한다. 기존 캡처 당시의 파일 동일성도 별도 미확인이다. 현재 fetch.mjs의 변형 명령은 1024 상한을 요구하지만, 실제 고품질 파일은 2048이므로 코드 설명만으로 생성 결과를 추정하지 않는다.

## 4. 다른 에셋을 어디서 구할 것인가

다음은 **조달 후보·용도 분석**이다. 이번 공식 사이트 접근 8건은 모두 프록시 CONNECT 403이었다. 현재 상품·가격·샘플 다운로드·약관을 직접 검증했다고 하지 않는다. 기존 저장소에서 실제 조사한 곳과 새 후보를 구분한다. 무료·유료 여부도 개별 상품과 현재 정책을 다시 확인해야 한다.

조달처를 늘리는 것이 결론은 아니다. 단순 서랍·책·액자·사다리·기하 조각은 **자체 베벨 키트가 우선**이다. 특수한 모델만 외부 후보와 제작 비용을 비교한다. 저대비 표면은 자체 재질 → ambientCG/CGBookcase의 깨끗한 후보 → 필요하면 제어 가능한 상용 재질 순으로 비교하는 것이 현재 목표에 맞는다. 구매·다운로드·채택 결정은 아직 하지 않았다.

Kenney·Quaternius는 기존 탐색처지만 로우폴리 팩을 받는 것만으로 이번 고급 서고의 베벨·미세 표면 목표가 해결되지는 않는다. Poly Haven을 다른 이름의 기본 팩으로 바꾸는 방식은 권하지 않는다.

## 5. 원인을 확정하는 다음 비교

아직 실행하지 않은 검증 계획이다. 같은 소품·카메라에서 다음을 따로 바꾼다.

1. 재질 선택: 현재 알베도 / 깨끗한 저대비 자체 재질. 원본의 먼지/마모 패턴과 빛 그림자를 분리한다.
2. 해상도: 동일 맵을 같은 무손실 조건의 1K/2K/4K로. 각 면의 화면 texel/pixel, UV 반복 크기를 확인한다.
3. 압축: 동일 해상도의 lossless/WebP 고품질/기존 가공. 베이크 lightmap과 색상·법선·roughness 데이터는 따로 비교한다.
4. 표현 경로: Blender diffuse bake와 웹 결과를 같은 카메라·톤 기준으로 비교. live PBR을 도입할지는 이 단계의 득실을 본 뒤 D 기록으로 정한다.

이번 분석만으로 renderer·압축·기본값을 바꾸지 않는다. Story 소유 소품과 r8/D-084 기준도 그대로다.
