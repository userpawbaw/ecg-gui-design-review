## 6. 효과 카드

### EFX-009-01 글자 뒤섞임(scramble) 등장 — HUD 라벨

**선정 이유**: 사용자 요청(글자 효과 연구) `[대화]`, 수상작의 대표 글자 효과.
**지각**: 라벨이 나타날 때 글자 자리마다 무작위 문자가 빠르게 바뀌다가 왼쪽부터 제 글자로 고정된다(사례 연구 서술 기반) `[추론]`.
**입력 모델**: 문턱 발동(장면 진입).
**판별 근거**: 사례 연구 "text scrambles: WebGL allows letter changes by adjusting SDF texture offsets" `[런타임]`.
**구현 메커니즘**:
```
DOM 판: 글자 칸마다 span, 진행률 k에 따라 i < k·N인 칸은 원래 글자, 나머지는 문자 집합에서 무작위(프레임마다 또는 40–60 ms마다 교체)
WebGL 판(원작): 글리프 atlas의 UV 오프셋만 바꿔 레이아웃 재계산 없음
고정폭 글꼴이면 글자 폭이 같아 뒤섞이는 동안 줄이 흔들리지 않는다
```
**파라미터**:
| 이름 | 값 | 출처 |
|---|---|---|
| 글꼴 | IBM Plex Mono(고정폭) | `[코드]` |
| 뒤섞임 시간·문자 집합 | 미확인 — 녹화 없음 | — |
**타임라인**: 미확인 — 녹화 없음.
**에셋**: 글꼴 SDF atlas.
**성능 기법**: 글자 변경을 텍스처 오프셋으로 — DOM 스타일 재계산 없음 `[런타임]`.
**접근성·폴백**: 미확인 — 녹화·코드 확인 안 함.
**근거**: `[런타임]`(사례 연구), `[코드]`(글꼴), `[추론]`(지각).
**재현 요구사항**: DOM span 방식이면 난이도 하. 한글은 조합형이라 "무작위 음절 → 제 음절" 또는 자모 단위 뒤섞임 중 선택 필요.
**수용 기준**: 뒤섞임 동안 줄 폭이 변하지 않는다(고정폭), 끝 상태는 원문과 같다, reduced-motion에서는 즉시 원문.
**ECG 번안**: 라벨 교체(입력 → 출력)나 수치 표시(0 dB, 250 Hz, cc 0.971)에 쓸 수 있다 — 숫자는 뒤섞임 동안 **가짜 값처럼 읽히지 않게** 짧게(0.3 s 이내) 하고 끝 값만 저장값. 파형 라벨의 "HUD 느낌"(고정폭, 작은 크기, 대문자 영문 보조)은 이 사례에서 가져온다.
**재현 상태**: `none`

### EFX-009-02 동심 링의 밝은 중심으로 접근

**선정 이유**: C 공간 접근/전환의 wow 후보 [대화].
**지각**: 반투명 얼음 공간에서 동심 링과 중앙 입자 조형으로 변화 [캡처].
**입력 모델**: 휠 입력 + 시간; 실제 정규화 p/감쇠는 미확인.
**판별 근거**: IG-01과 IG-06 단계 캡처, DOM body720px 일반 scroll아님 [런타임].
**구현 메커니즘**: Three.js와 custom shader 장면 [문헌]; 직접 본 캡처로 정확 camera경로/후처리 수치 확정하지 않음.
**파라미터**: canvas1280×720 [런타임]. 휠p/FOV/감쇠 미확인.
**타임라인**: 첫 얼음 공간→동심 링; 연속영상 없으므로 구간초/easing 미확인.
**에셋**: proceduralice [문헌], 모델/texture개별크기 미확인. entry16,546B, App3D403으로 미확보 [코드].
**성능 기법**: procedural shader, 정확DPR/framebudget 미확인.
**접근성·폴백**: 원본 미확인, 우리 정지프레임+짧은설명.
**근거**: https://www.igloo.inc/ [캡처][런타임], https://www.awwwards.com/igloo-inc-case-study.html [문헌].
**재현 요구사항**: Three.js ringmesh/camera/light, 단일scroll; 난이도상.
**수용 기준**: C에서 중앙목표·앞뒤깊이·ECG 연결을 읽음, 실제6–12프레임 필요.
**ECG 번안**: C의 디지털 배열 접근. 얼음/극지는 옮기지 않음, D-050 Intro변형 허용.
**재현 상태**: `none`.

### EFX-009-03 입자 목표 형상 전환 — 제작자 근거, 라이브 미관찰

**선정 이유**: 입력→디지털처리→출력의 중심 효과 후보 [대화].
**지각**: hover 모델에 따라 입자 형상이 재구성되고 속도연계 빛 [문헌]. footer live 미관찰; IG-07은 얼음집 복귀로 증거 제외.
**입력 모델**: hover 문턱 + 시뮬레이션시간 [문헌].
**판별 근거**: 제작자 Interactive Particles 설명. 직접 조작 판별 미완료.
**구현 메커니즘**: VDB모델을 browser용압축export, particle sim과 속도빛 [문헌]. 실제format/shader 미확인.
**파라미터**: 원본particlecount·초·VDBexport설정 미확인. 우리20k 시작값은 [추론]이지 원본값아님.
**타임라인**: hover modelchange; 원본easing 미확인. C의 풀림→배열→재결합은 독자타임라인.
**에셋**: VDB/압축browser형식 [문헌], 개별크기 미확인. 우리 저장입출력 targetbuffer, 원본자산복사없음.
**성능 기법**: 압축export [문헌]. 우리GPUtarget보간 후보, 성능시험전.
**접근성·폴백**: 원본미확인, 우리고품질사전렌더/단순전환, 비교renderer별도.
**근거**: https://www.awwwards.com/igloo-inc-case-study.html [문헌]. 선택구간live증거는 미확보.
**재현 요구사항**: Three.js Points/instance+GPUtargets, Houdini/Blender 선택, 난이도상.
**수용 기준**: 폭발만기억하지않고 입력→처리→출력방향을읽음. 원본같은수준verified는live및전구간검증후.
**ECG 번안**: C3–5, A-T5/B6 선택지. 비교화면표본을변형하지않음.
**재현 상태**: `none`.
