## 1. 현재 상태 (측정 `[런타임]` `[코드]`)

호버 가능한 요소: 도입부 `바로 실험실 →`(우상단 알약, 14 px) · 끝 단계 버튼 2개(`잡음마다 다를까요? →` 채움형, `직접 비교해 보기` 외곽선형, 60 px) · Story 잡음 칩 4개(56 px 알약, 오른쪽 위) · 왼쪽 경로 목록 항목(19 px, 1–3단계) · 하단 CTA 알약 · `바로 실험실` 알약.
- 위 요소 4곳을 자동 호버(`H-story`): **반응 영역 피크 0–1, 전체 피크는 평소(0.3–0.4) 수준** — 호버 효과가 없다. CSS에 `:hover` 규칙 자체가 없고 `cursor:pointer`만 있다.
- 이미 있는 것: **포인터 시차**(카메라가 ±2.5° 요, ±1.5° 피치로 포인터를 따라감, 감쇠 0.35; 도입부 글·파형 층 DOM 6 px/3 px 이동 `introStage.ts`), 칩 `aria-pressed` 상태 색, 칩의 sonar 링(첫 칩).
- 이징 언어: 도입부 라벨은 `cubic-bezier(.2,.75,.25,1)` 0.65–0.8 s(`intro.css`). 호버도 이 언어를 따르면 한 체계로 읽힌다.

## 4. 추천 조합과 근거 (한 줄씩)

- ★ **A2 + B1 + C1 (+ D1)**: 이미 쓰는 라벨 언어(A2)로 요소 반응을 통일하고, Oryzo가 보여 준 "장면 전체가 UI에 반응하는" 한 가지(B1)만 가져오고, 글 층(C1)으로 의미를 얹는다. 구현 규모가 한 번에 검증 가능하다.
- **과감 쪽**: A3 + B3(+ C1). 버튼은 "잡음 → 정리" 은유, 장면은 심박에 맞춰 반응 — 우리 데이터(R 피크·잡음/출력 색)로만 가능한, 레퍼런스에 없는 호버다. 비용·검증 부담이 크다.
- 피할 것: A1 단독(F-029 재발 위험), B2(의미 오해·구현량).

구현(`prototype/v2/src/story/hoverfx.css`, `hoverFx.ts`, `intro/IntroShell.tsx`, `intro/intro.css`):

- **B1**: 3D 장면 캔버스 바로 위·파형 무대와 글 아래의 검은 덮개(`.hd-dim`) opacity 0 → 0.62(0.6 s). 장면(지구·사람·심장)만 약 0.38배로 어두워지고 파형·격자·글은 유지. 이벤트 위임 한 벌로 root에 `data-hd`를 켜고 끈다(React 상태 없음).
