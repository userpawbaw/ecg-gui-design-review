## 6. 효과 카드

### EFX-006-01 막대 → 점: 한 줄씩 차례로 접히며 산점도로 이동 (object constancy)

**선정 이유**: 사용자 지목("같은 점이 사라지지 않고 모양만 바꿔 재배열"), wow, 장면 전환.
**지각**: SF(초록)·NY(파랑) 두 기둥의 가로줄들이 위에서부터 **대각선 물결처럼 차례로** 짧아지며 점으로 변해 오른쪽 산점도 자리로 간다. 초록이 먼저, 파랑이 나중에 움직인다. 모든 줄이 끝까지 한 대상으로 이어져 보이므로 "같은 집들"이라는 것을 설명 없이 안다. 되돌리면 정확히 거꾸로 돌아간다.
**입력 모델**: 스크롤 위치.
**판별 근거**: 소스 — 점마다 `start.scroll/end.scroll` 구간을 계산하고 `progress = (scroll − start)/(end − start)`로 위치를 정한다. 시간 트윈 없음 `[코드]`. 12장 캡처에서 중간 위치마다 같은 부분 상태가 재현됨 `[런타임]`.
**구현 메커니즘**: Canvas 2D. 점 하나 = 객체 하나(`ScatterPlotPointCanvas`). 의사코드:
```
for each point i (N = 250):
  span = plot.scrollEnd − plot.scrollStart
  half = span / 2                         // 코드상 이름은 quarterScroll
  [s, e] = target ? [start, end − half]   // 범주별로 앞 절반 / 뒤 절반
                  : [start + half, end]
  delay = (e − s) / 3 / N * i             // 전체의 1/3을 점 순서대로 나눈 지연
  s += delay; e += delay
  keyframe: (s → x0,y0,opacity 0) … (e → x1,y1,opacity 0.3), 선형 보간, clamp
per rAF: scroll = ZENO(scroll); for each point: pos = lerp(start,end,clamp(progress)); arc(r=2.5)
```
**파라미터**:
| 이름 | 값 | 출처 |
|---|---|---|
| 점 수 | 학습 250(SF/NY 두 범주) | `[코드]` |
| 범주 분리 | 범주마다 구간 절반씩 순서대로 | `[코드]` |
| 순차 지연 | 구간 길이의 1/3을 점 순서로 균등 분배 | `[코드]` |
| 보간 | 선형(easing 없음), clamp | `[코드]` |
| 불투명도 | 0 → 0.3 | `[코드]` |
| 점 | 반지름 2.5 px, 범주색 | `[코드]` |
| 평활 | ZENO 0.85/프레임(EFX-006-05) | `[코드]` |
**타임라인**: `#add-nuance` 섹션 동안(약 1,200–1,400 px 스크롤). 곡선은 선형이지만 **ZENO 평활 + 점별 지연**이 합쳐져 화면에서는 부드러운 물결로 보인다.
**에셋**: 없음(자료 JS 261 KB — 7개 속성 × 492 행).
**성능 기법**: 변화가 있을 때만 다시 그림(`rr`), 구간 밖 점은 계산 생략(시작 전·끝 뒤 상태 고정).
**접근성·폴백**: reduced-motion 처리 없음 `[코드]`. 스크롤 위치 함수라 스크롤을 멈추면 멈춘다.
**근거**: `[코드]`, `[런타임]`, `[대화]`.
**재현 요구사항**: Canvas 2D(또는 WebGL 점) + 점별 키프레임 계산 + 공용 평활 스크롤 값. 패키지 불필요(GSAP ScrollTrigger scrub로도 가능). 난이도 하–중.
**수용 기준**: (1) 구간 12장에서 모든 점이 매 장 존재(사라지는 점 0개). (2) 범주 A가 구간 앞 절반에, B가 뒤 절반에 이동. (3) 같은 스크롤 위치를 앞·뒤로 지나도 같은 장면(되돌림 일치, 픽셀 차 < 1 %). (4) 1920에서 스크롤 1 px당 점 이동이 3 px 이하(끊김 방지, F-021과 같은 기준).
**ECG 번안**: **파형은 재배열하지 않는다**(LOW 구역). 재배열 대상은 방법·조건·장면을 나타내는 **표시 객체**: 예) 11개 방법 × 7 SNR 장면 점들이 "잡음 종류별 1위" 배열 → "EXP-A 평균 순위" 막대 → "지표별 순위" 행렬로 모양을 바꾸며 이어짐(S1→S2→S3). 점 하나 = 저장된 한 장면·한 방법으로 대응시켜야 의미가 생긴다.
**재현 상태**: `none`

### EFX-006-02 막대 묶음 회전 → 짧아짐 → 빗방울처럼 떨어져 히스토그램으로 쌓임

**선정 이유**: 사용자 지목(같은 점의 재배열), wow, 장면 전환.
**지각**: 가로줄 묶음이 통째로 기울어(−90° → 0°) 세로 방향이 되고, 각 줄이 짧게 줄어든 뒤 하나씩 떨어져 바닥의 칸(고도 구간)에 쌓인다. 파랑(NY)이 먼저 쏟아지고 초록(SF)이 뒤따른다. 모인 모양이 그대로 히스토그램이 된다.
**입력 모델**: 스크롤 위치.
**판별 근거**: `ElevationToHistogramView` — rotate/shrink/fall 세 구간을 섹션 높이의 비율로 정의, 모든 값이 `d3.scale.linear().clamp(true)`의 스크롤 함수 `[코드]`. 12장 캡처에서 회전 중간 장면(약 45°) 확인 `[런타임]`.
**구현 메커니즘**: Canvas 2D(`#rotating-canvas`). 막대 = `ElevationRainDrop` 객체. 구간(섹션 높이 H 기준):
```
rotate: [0.01H, 0.07H]          캔버스 회전 −90° → 0°
shrink: [0.04H, 0.13H]          막대 높이 full → padding/4, 지연 = 고도가 낮을수록 늦게 (shrinkFactor = 1 − 정규화 고도)
fall:   [0.14H, 0.58H]          각 막대 낙하 시간 = fall 구간/6, 시작 지연 = 그룹 내 순서 × (구간 − 낙하시간)/350
                                 SF는 순서 + 167 → NY가 먼저 떨어짐
y(scroll) = 구간별 선형 [y0 → y1(위로 모임) → 유지 → 바닥], clamp
```
**파라미터**:
| 이름 | 값 | 출처 |
|---|---|---|
| 회전 | −90° → 0°, 섹션 1–7 % | `[코드]` |
| 축소 | 높이 full → padding/4, 섹션 약 4–13 % | `[코드]` |
| 낙하 | 섹션 약 14–58 %, 막대당 구간의 1/6 | `[코드]` |
| 낙하 순서 | 그룹 내 순서, 두 번째 그룹 +167 오프셋 | `[코드]` |
| 막대 폭 | 5 px, 불투명도 0.3 | `[코드]` |
**타임라인**: `#elevation-to-histogram` 섹션 1,315 px + 다음 섹션 일부. 세 단계가 약간 겹쳐(축소가 회전 끝 3 % 전에 시작) 끊김 없이 이어진다.
**에셋**: 없음.
**성능 기법**: 막대 250개를 한 캔버스에 매 변화 시 다시 그림.
**접근성·폴백**: 처리 없음 `[코드]`.
**근거**: `[코드]`, `[런타임]`.
**재현 요구사항**: Canvas 2D, 구간별 선형 키프레임 유틸(`makeAttributeFn`과 같은 `domain[] → range[]` clamp 함수). 난이도 중.
**수용 기준**: (1) 회전 중간(섹션 4 %)에서 묶음 각도 −45° ± 5°. (2) 낙하 구간 12장에서 매 장 떨어지는 중인 막대가 있고 순서가 그룹 순서와 일치. (3) 끝 상태가 정적 히스토그램과 픽셀 일치.
**ECG 번안**: 한 장면의 방법 점들이 "잡음 종류" 칸으로 떨어져 **조건별 1위 분포**가 되는 전환(S1). 파형 행은 그대로 두고, 파형 옆 표시층에서만.
**재현 상태**: `none`

### EFX-006-03 같은 점들이 산점도 행렬로 퍼짐 (source → target 연쇄)

### EFX-006-04 학습 점 → 시험 점이 나무 경로를 흘러 칸에 쌓이며 정확도가 떨어지는 반전

**선정 이유**: 사용자 지목(Step 1에서 AI가 제시한 "반전"을 사용자가 확인), wow, 이야기 결말.
**지각**: 학습 점들이 나무 가지를 따라 흘러내려 아래 두 칸에 쌓이고 정확도는 100 %. 이어서 **처음 보는 시험 점**을 같은 나무에 흘리면, 칸이 차는 동안 정확도 숫자가 도착할 때마다 바뀌며(헤드리스 캡처에서 78.6 %, 92.8 %, 88.4 %를 거쳐 최종 89.7 %) 100 %에 못 미치고, 틀린 점은 빈 원으로 남는다. 앞에서 쌓은 결론이 스스로 한계를 드러낸다.
**입력 모델**: 스크롤 위치.
**판별 근거**: `AnimatedClassifierView.updatePointPosition` — `progress = (scroll − start) × 4`, `path.getPointAtLength(progress)`; 점마다 시작 위치만 순서대로 밀림 `[코드]`. 12장 캡처에서 중간 정확도 수치가 스크롤 위치마다 다름 `[런타임]`.
**구현 메커니즘**: SVG. 점마다 자기 나무 경로(`path`, 뿌리 → 잎 → 칸)를 미리 만들고 원을 경로 위에 놓는다. 오분류 판정은 잎의 다수 범주와 비교해 미리 계산, 틀리면 `fill: none`. 결과 칸(`ClassifierResultsView`)은 도착한 점만 세어 정확도를 표시.
```
ballDuration = windowHeight / 4                        // 한 점이 경로를 다 가는 데 드는 스크롤 px
interval = (sectionSpan − ballDuration) / N            // 점 사이 시작 간격
start_i = sectionStart + i × interval
pos_i = path_i.getPointAtLength(clamp((scroll − start_i) × 4, 0, len))
학습 구간: [top − 0.3·vh, top + 1.2·vh], 시험 구간: [top, top + 1.5·vh]
```
**파라미터**:
| 이름 | 값 | 출처 |
|---|---|---|
| 점 수 | 학습 250, 시험 242 | `[코드]` |
| 경로 속도 | 스크롤 1 px당 경로 4 px | `[코드]` |
| 한 점 이동 | 창 높이/4(1080 → 270 px 스크롤) | `[코드]` |
| 구간 | 학습 1.5 vh, 시험 1.5 vh | `[코드]` |
| 최종 정확도 | 학습 100 %, 시험 약 89.7 % | `[런타임]`(헤드리스 캡처 읽음) |
| 오분류 표시 | 채움 없음(테두리만) | `[코드]` |
**타임라인**: `#classify-training-data`(1,858 px) → `#classify-test-data`(2,502 px). 수치는 도착 순서대로 갱신.
**에셋**: 없음.
**성능 기법**: 위치가 바뀐 점만 속성 갱신.
**접근성·폴백**: 처리 없음. 수치가 텍스트라 스크린리더로 읽을 수 있음 `[추론]`.
**근거**: `[코드]`, `[런타임]`, `[대화]`.
**재현 요구사항**: SVG 경로 + `getPointAtLength`(또는 GSAP MotionPath), 결과 집계. 난이도 중.
**수용 기준**: (1) 점마다 경로 이탈 0. (2) 표시 정확도 = 도착한 점 기준 실제 집계와 매 장 일치. (3) 되돌리면 점이 역행하고 수치도 되돌아감.
**ECG 번안**: Story 결말 후보 — "평균 1위"로 쌓은 결론에 **다른 조건의 실제 저장 장면**을 흘려 순위가 바뀌는 것을 보인다(S1·S3). 표시 수치는 archive.json 저장 지표에서만, 범위 문구 필수. "딥러닝이 틀렸다"로 읽히지 않게 방법 간 우열이 아니라 **조건 의존성**을 말한다. S5(학습 범위 밖)에는 수치 근거가 없으므로 이 연출로 수치를 만들지 않는다.
**재현 상태**: `none`

### EFX-006-05 ZENO 스크롤 평활 + 고정 그래픽 패널 (전역)

**선정 이유**: 재사용 메커니즘 — 이 사이트의 "완성도 높은 부드러움"의 바탕(사용자 평가 "애니메이션의 완성도도 높고" `[대화]`).
**지각**: 휠을 한 칸 굴려도 그래픽이 툭 뛰지 않고 짧게 따라와 멈춘다. 글은 흘러가고 그래픽은 제자리에 남아 무대처럼 보인다.
**입력 모델**: 스크롤 위치.
**판별 근거**: rAF마다 `ZENO(current, actual)`로 평활한 값을 모든 View에 배포 `[코드]`. 400 px 점프 후 화면 변화가 약 1.0 s에 0이 됨(헤드리스 — 프레임률이 낮아 실제보다 느림) `[런타임]`.
**구현 메커니즘**:
```
next = actual + (current − actual) × 0.85     // 프레임마다 남은 거리의 15 %만 따라감
if |next − actual| < 0.05: next = actual
Dispatcher.trigger("scroll", next)            // 모든 그래픽이 같은 값을 받음
StickyDivView: topFn() ≤ scroll < bottomFn() 동안 패널 fixed
```
**파라미터**:
| 이름 | 값 | 출처 |
|---|---|---|
| 추종 계수 | 0.85 / 프레임(= 프레임당 15 % 따라감) | `[코드]` |
| 붙는 문턱 | 0.05 px | `[코드]` |
| 95 % 수렴 | 60 fps에서 약 18프레임 ≈ 0.31 s(계산), 헤드리스 측정 약 1.0 s | `[코드]` `[런타임]` |
| 리사이즈 디바운스 | 700 ms | `[코드]` |
**타임라인**: 전 구간.
**에셋**: 없음.
**성능 기법**: 값이 바뀔 때만 이벤트, View별 `rr` 플래그로 다시 그리기 최소화.
**접근성·폴백**: 네이티브 스크롤 유지(스크롤바·키보드 정상). 평활은 그래픽에만 적용.
**근거**: `[코드]`, `[런타임]`.
**재현 요구사항**: 우리 스택에서는 Lenis 하나(RCP-01)가 같은 역할. 단 ZENO는 **프레임 의존**(0.85/프레임) — 우리는 RCP-08 `1 − exp(−k·dt)`로 바꿔 프레임률과 무관하게 한다(k ≈ 9.8/s가 60 fps의 0.85와 같음). 난이도 하.
**수용 기준**: 400 px 점프 후 0.3 ± 0.05 s에 남은 거리 5 % 이하(30·60·144 fps에서 같게).
**ECG 번안**: Story 전체의 시간축. v2.2.1 재생 시간과는 분리(스크롤 평활이 파형 재생 시간을 바꾸지 않음).
**재현 상태**: `none` (Lenis 쪽은 여러 spike에서 `verified` 수준 사용 중)

## 10. 열린 질문
