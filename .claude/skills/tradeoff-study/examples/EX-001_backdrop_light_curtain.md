# EX-001. 서고 배경을 "빛 커튼만 잘 보이게" 가볍게 — 실시간 탭 + 실험실 탭 (2026-11-11)

이 스킬을 처음 적용한 사례. 사용자 요청: 「빛 커튼만 잘 보이는 수준이고, 그래서 파형 창 바깥의 빛커튼만 잘 보이게 하는 수준이면 충분해. 이 제약에 적합한 최적화 트릭이 있을까?」 `[대화]`

## 0. 요약
- 권장: **실시간 탭 = 실행 중 굽기(A안) + 굽는 방은 반 해상도·블러**, **실험실 탭 = 패널 아래 안 그리기 + 방 반 해상도·블러 + 커튼 없는 구간 정지**. 빛 커튼 계산은 지금 품질 유지.
- 얻는 것: 실시간 탭 배경의 매 프레임 비용 ≈ 사각형 하나 `[추정]`. 실험실 스크롤 중 방 그리기 픽셀 약 1/4, 안개·합성은 패널이 덮는 62–74 %만큼 감소 `[계산]`.
- 잃는 것: 옆 이동 6 cm 시차, 방의 세부(빛 안 받는 곳), 실시간 탭 먼지 → 모두 `무료`(커튼 70 % 아래 + 사용자가 필요 없다고 함).
- 뒤집히는 조건: 빛 커튼 가장자리(책장이 빛을 자르는 줄무늬)가 반 해상도 방 깊이로 흐려지면 커튼 쪽 깊이만 원래 해상도 유지.

## 1. 목표 기능
| 기능 | 등급 | 근거 |
|---|---|---|
| 스크롤에 따라 빛 커튼이 달라 보인다(실험실, 파형 창 위 빈 공간) | 필수 | 「스크롤 맨 위쪽에서 파형 창 위에 빈 공간이 보일 때 빛 커튼이 스크롤에 따라 달라지는 그정도만 잘 보이면 돼」 |
| 파형 창 바깥 빈 공간에 비치는 빛 커튼 | 좋음 | 「좀 더 하면 파형 창 바깥의 빈 공간에 비치는 빛커튼까지」 |
| 빛 받는 곳의 공간감 | 좋음 | 「보이는 공간이랑 빛만 제대로」 |
| 빛 안 받는 공간의 세부 | 없어도 됨 | 「빛이 확실하게 비치는 곳이 아니면 배경이니까 좀 뭉갠 다음 블러처리해도 되고」 |
| 스크롤 끝(어두운 바닥) | 없어도 됨 | 「어두운 공간이라 잘 보이지도 않더라」 |
| 마우스 좌우 시점 변화 | 좋음 | D-074 「약하게 좌우로」 |
| 공중 먼지 반짝임 | 언급 없음 → 실시간 탭에서는 없어도 됨으로 가정 | — |

## 2. 제약
- 하드: 파형 렌더 우선(실험실 재생 중 배경 정지, D-074 이후 유지), 실험실 배경 경로·구간 확정값(`seg .61,.88`, D-169), 빛줄기 깜빡임 금지(D-169 평활 안개).
- 동시 부하 지도: **실시간 탭이 유일한 3중 겹침**(브리지 처리 + 실시간 파형 + 배경). 실험실은 재생 중 배경이 멈춰 겹치지 않는다 `[코드]` `labBackdrop.ts` tick(): `if(paused||playing) return`. 실시간 탭에서는 `playing`이 실험실 상태라 false → 먼지·안개가 초당 24번, 마우스 이동 시 방 전체를 MSAA 4배로 초당 30번 다시 그린다 `[코드]`.
- 이전 검증: 깊이 시차 = 가는 물체 끊김(F-022, 셰이더 반복 읽기로 완화) + 스크롤 중 경계 자글거림(F-023, 추정 깊이). 시점 섞기 = 이중상, 기각(F-019). 제자리 회전은 여백 이동이 실제 렌더와 오차 4.6/255(F-019). 사용자 기억("다락방 모서리 비틀림")은 F-022/F-023과 일치.

## 7. 권장 조합과 남는 손해
- **실시간 탭: A′.** 페이지가 스크롤되지 않아 카메라가 한 자리이므로 굽는 것은 정확히 한 장. ±3° 회전은 원근 변환으로 정확(F-019). 먼지는 끔(F-020: 굽기와 실시간 양쪽에 두지 않음).
- **실험실 탭: C1 + C2 + C5.** 필수 기능(빛 커튼)이 사는 안개 계산은 그대로 두고, 그 밖을 줄인다. C3는 나란히 비교에서 구분 안 될 때만 추가.
- 남는 손해: 실시간 탭 옆 이동 시차·먼지, 실험실 빛 안 받는 방 세부. 모두 사용자가 필요 없다고 했거나 커튼 아래.
- 탈락: V(A가 같은 결과를 파일 없이), D(시차가 안 보이는 곳에서 결함만), C4(필수 기능을 건드림), S1(A′가 같은 비용에 마우스 반응까지).

## 8. 민감도
- 실시간 탭이 스크롤되게 레이아웃이 바뀌면 → 한 장이 아니라 스크롤 위치별 다시 굽기 + 교차 페이드(A′ 유지, 비용은 스크롤 때만).
- 대상 PC에서 처음 굽기가 0.3 s를 넘으면 → 굽기를 여러 프레임에 나누거나(L2) 빌드 때 이미지로(V의 정지 이미지판).
- C2의 반 해상도 깊이로 커튼 줄무늬가 흐려지면 → 안개용 깊이만 원래 해상도.
- 사용자가 마우스 시점 변화도 필요 없다고 하면 → S1(가장 단순).

## 9. 검증
- 한 것: 패널 덮개 비율·스크롤 범위 측정 `[측정]`(Playwright, 1920 × 1080, 이 환경). 코드 경로 확인 `[코드]`.
- 미검증: 각 후보의 실제 프레임 시간(이 환경은 소프트웨어 렌더 저전력 모드라 절대값 무의미 → 사용자 PC), 연결된 실시간 화면의 덮개 비율, 커튼 줄무늬 나란히 비교.

## 10. 가정과 질문
- 가정: 실시간 탭 먼지는 없어도 됨(사용자 언급 없음).
- 질문: 없음 — 남은 빈칸은 측정으로 메운다.

## 사후 정정 (2026-11-11 저녁, D-174 · R-026)
- 3절의 「실시간 스크롤 0 px」는 **브리지 없음 화면**에서 잰 값이었다. 사용자 화면(1920 × 1032, 브리지 연결, 파형 4줄)에서는 스크롤된다. 그 전제로 7절 「한 장 굽기 + 자리가 바뀌면 200 ms 뒤 다시 굽기」를 만들었고, 사용자 화면에서 계단식 스크롤이 되었다.
- 고친 것: 스크롤 동안은 실험실과 같은 실시간 경로(반 해상도), 멈추면 굽기. 60 fps 프레임 캡처로 확인.
- 이 사례가 가르치는 것: 여유 지도 값은 **사용자가 실제로 보는 상태(화면 크기 · 데이터 · 연결)**에서 재고, 빈 상태 ~ 가득 찬 상태의 범위로 적는다. 움직임에 관한 결론은 프레임 단위로 확인한다.
