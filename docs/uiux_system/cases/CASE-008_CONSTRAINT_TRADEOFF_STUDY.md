# CASE-008. "1번이냐 3번이냐"에서 "무엇을 잃어도 되나"로 — 제약 기반 트레이드오프 탐색 스킬이 생긴 과정

관련 기록: D-171, R-025, D-170, F-019, F-020, F-022, F-023. 산출물: `.claude/skills/tradeoff-study/`, `third_party/skills/`.

## 배경

실시간 측정 탭은 브리지 처리, 실시간 파형, 서고 배경(3D 실시간 렌더)이 동시에 도는 유일한 화면이다. 실험실 탭은 파형을 재생하는 동안 배경을 멈추지만, 실시간 탭에는 그 조건이 걸리지 않았다(`labBackdrop.ts` tick). 사용자는 배경 비용을 줄일 방법을 물었고, AI는 사전 렌더 후보 셋 중 두 개(1번 색 + 깊이 시차, 3번 다시점 섞기)를 놓고 "어느 쪽으로 할지" 물었다.

## 논의 흐름

1. **AI의 첫 응답 — 두 안 중 고르기.** 1번은 연속적이라 추천, 3번은 찍은 시점에서만 정확하다고 설명하고 선택을 요청했다 `[대화]`.
2. **사용자의 반론 — 기억된 결함과 제약 재정리.** 「1번은 이전에 다락방 예시로 검증했을 때 물체 모서리에 비틀림이 생기던 걸로 기억해서 좀 걱정되는데... 1번 3번 외에 다른 개선 방식이나 다시 검증해볼 트레이드오프가 있나?」 `[대화]` 사용자는 경로 고정, 수평 이동만, 실시간 처리 중엔 배경이 잘 안 보인다는 점, 실시간 탭만 넓게 찍은 영상으로 가로 이동하는 안, 그리고 「leoparpeix는 베이크해서 쓰는데, 우리는 실시간 렌더만 가능해?」를 제시했다.
3. **AI의 재분석.** 기록을 대조해 사용자 기억이 F-022 · F-023과 맞음을 확인했다. 3번은 F-019에서 이미 이중상으로 기각된 방식이었다. 마우스 효과를 회전(이미지로 정확)과 옆 이동(시차, 이미지로 불가)으로 나눴다. 사용자 안을 "파일 없이 실행 중에 한 장 굽기"로 바꾼 A안을 제안했다 — 1번 · 3번 둘 다를 지배한다.
4. **사용자의 두 번째 재정의 — 필요한 기능을 좁힘.** 「빛 커튼만 잘 보이는 수준이고, 그래서 파형 창 바깥의 빛커튼만 잘 보이게 하는 수준이면 충분해」 · 「공간은 빛이 확실하게 비치는 곳이 아니면 배경이니까 좀 뭉갠다음 블러처리해도 되고」 `[대화]`. 이것이 "여유"의 직접 근거가 됐다.
5. **사용자의 일반화 요구.** 「제약사항과 현재의 환경에서 굳이 필요하지 않은 최적화 여지 부분을 같이 분석한 후 … 손해가 … 중요하지 않아 품질-성능 … 이 모두 최선인 이 과정은 어떤 작업에서나 필수적일 것 같아 … 매번 규칙적으로 하도록 만들고 싶어」 `[대화]`. 업계 용어 조사, 기존 스킬 조사, 개선 스킬 + 원본 제공을 요청했다.
6. **AI의 조사.** 다섯 전통(시스템 공학 trade study, ATAM, 가치 공학, 근사 컴퓨팅 · 지각 기반 렌더링, DSE · 파레토)이 이 과정의 한 부분씩을 다루고, "손해가 안 보이는 곳을 표로 만드는" 단계에는 따로 이름이 없음을 확인했다. 공개 스킬 다섯 개를 비교해 모두 "후보가 주어진다고 가정"한다는 공통 한계를 찾았다.
7. **스킬화와 첫 적용.** 여유 지도 · 레버 카탈로그 · 손해-여유 대응 · 측정 · 고정 보고를 담은 `tradeoff-study`를 만들고, 바로 이 배경 문제에 적용했다(EX-001). 측정 중 실시간 탭 페이지가 스크롤되지 않는다(0 px)는 사실이 나와, 굽는 것이 정확히 한 장으로 정해졌다.

8. **첫 적용의 반례(같은 날 저녁).** EX-001의 여유 지도에서 「실시간 탭 스크롤 0 px」는 브리지가 없는 빈 화면에서 잰 값이었다. 사용자 화면(브리지 연결, 파형 4줄)에서는 스크롤이 생겼고, 그 전제로 만든 「굽기 + 200 ms 뒤 다시 굽기」가 계단식 스크롤을 만들었다. 사용자: 「스크롤할 때 뚝뚝 끊기는 느낌 … 내가 원하는 바가 전혀 아니야」 `[대화]`. AI는 60 fps 가짜 시계 프레임 캡처로 이전(휠마다 한 프레임만 이동) · 이후(매 프레임 연속)를 재고 D-174로 고쳤다. 측정 조건을 사용자 화면과 맞추라는 규칙을 R-026으로 남겼다.

## 재사용 가능한 AI 사용 패턴

1. **AI가 "A냐 B냐"를 묻는 순간이 후보를 넓힐 순간이다.** 두 안을 고르게 하기 전에 기능 · 여유 · 레버를 돌린다(R-025).
2. **사용자의 기억된 결함은 기록과 대조해 사실로 만든다.** 이번에는 F-022 · F-023과 맞았다.
3. **"충분하다"는 사용자 발화는 가장 강한 최적화 근거다.** 그대로 인용해 여유 지도에 넣는다.
4. **측정 한 번이 설계를 바꾼다.** 스크롤 범위 0 px 측정이 "영상 · 여러 장"을 "한 장"으로 바꿨다.

## AI가 기여한 것

- 기록 대조(F-019 · F-020 · F-022 · F-023)와 코드 확인으로 무거운 이유(실시간 탭에 정지 조건 없음)를 특정했다.
- 회전/이동 분해, 실행 중 굽기 A안, 여유 지도 측정(덮개 비율 · 스크롤 범위).
- 문헌 · 기존 스킬 조사와 공통 한계 정리, 스킬 설계.

## 사용자가 기여한 것

- AI의 두 안 제시에 반론하고 과거 결함을 기억해 냈다.
- 제약(경로 고정 · 수평만 · 실시간 중 배경 안 보임)과 필요 기능(빛 커튼만)을 직접 좁혔다.
- 굽기라는 다른 축을 질문으로 열었다(leoparpeix).
- 이 과정을 모든 작업의 상시 절차로 일반화하자고 제안했다.
