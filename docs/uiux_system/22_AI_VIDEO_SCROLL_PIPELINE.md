## 5. 검토 결과 — 보완·추가·수정할 점

### 5.1 보완 (발상은 유지, 방법을 강화)
1. **구도는 프롬프트가 아니라 키프레임으로 고정한다.** 글만으로는 매번 다른 구도가 나와 반복 비용이 커진다. 첫/끝 프레임 이미지(우리 Blender·three 블록아웃 렌더)를 조건으로 주고, 가능하면 회색 블록아웃 카메라 이동 영상을 video-to-video 가이드로 준다. 입고 QA가 첫/끝 프레임 일치를 SSIM으로 검사한다.
2. **"가감속"은 두 층이다.** 스크롤 관성(Lenis)은 손의 입력을 부드럽게 할 뿐, 영상 자체가 느렸다 빨라지면 같은 스크롤에 화면이 다르게 움직인다. 입고 QA가 광류로 속도 곡선을 재고 remap 표를 만들어 "같은 스크롤 = 같은 화면 이동"으로 맞춘다(시험 CV 0.605 → 0.11). 단 느린 구간에서 생긴 중복 프레임은 remap으로 없어지지 않으므로 브리프에서 일정 속도를 요구한다.
3. **정지했을 때 영상은 멈춘다.** 레퍼런스의 wow는 대개 멈췄을 때도 살아 있다(REF-003 소나). 시간 층(먼지·빛·grain·DOM 반복)을 따로 두거나 같은 장면의 짧은 무한 반복 클립을 추가로 요청한다.

### 5.2 기대치 조정 — 마우스 시선
REF-002의 "고개를 돌리면 새로운 부분이 보이는" 느낌은 **실시간 3D라서** 가능했다(가려진 면이 드러남). 평면 영상에서는 가려진 부분이 없으므로 다음 조합이 한계다: ① overscan 여백 안에서 화면 이동(구현), ② 추정 깊이 맵으로 가까운 것을 더 움직이는 2.5D 시차(코드 구현, 깊이 추정은 미시험 — Depth Anything V2 같은 오프라인 추정 필요, 경계에서 번짐), ③ 영상 위 DOM·3D 전경 레이어를 따로 움직이기(구현). "고개 돌림"이 핵심인 장면은 V0에서 실시간 3D로 보낸다.

### 5.3 추가
4. **V0 적합성 판정**(§2) — 모든 구간을 영상으로 만들지 않는다.
5. **입고 QA 자동화 + 사람 확인 분리** — 자동 검사는 컷·깜빡임·속도·해상도만 본다. AI 특유의 형태 녹아내림·가짜 글자는 12장 시트로 사람이 본다. 피드백 문장이 자동 생성되어 도구에 바로 넣을 수 있다.
6. **피드백 반복 상한** — 3회 안에 PASS/TUNE가 안 되면 대안 경로로 전환. 무한 재생성이 가장 큰 숨은 비용이다.
7. **출처·약관 기록** — 도구·요금제·약관(상업/비상업, 소유권)·프롬프트·입력 이미지를 registry 출처에 남긴다. 비영리 학술 전시라도 도구 약관이 전시 사용을 막을 수 있다.
8. **메모리·용량 설계** — 프레임 시퀀스는 압축 12–13 MB(720p 240장)로 가볍지만, 전부 디코딩하면 약 885 MB(4K ≈ 3.5 GB)다. 디코딩 창 방식으로 해결(F-018). 대안인 all-intra 영상 + `currentTime`/WebCodecs는 미시험.
9. **해상도 계획** — 생성 도구 출력은 흔히 720p–1080p다. 4K 전시 화면이면 업스케일을 V4에서 선명도로 검사한다.
10. **클립 연결 규칙** — 여러 클립이면 앞 클립의 끝 키프레임 = 다음 클립의 첫 키프레임.

### 5.4 수정
11. **"AI가 레퍼런스를 참조하게"는 "레퍼런스 원칙을 글로, 구도는 우리 키프레임으로"로 바꾼다.** 레퍼런스 영상·캡처를 생성 입력으로 넣으면 파생물이 되고, 저장소 규칙(레퍼런스 에셋 복사 금지)과도 충돌한다.
12. **"부드러움" 판정은 헤드리스 캡처로 끝낼 수 없다.** 프레임 캡처는 위치를 보여 줄 뿐 체감 속도를 보여 주지 않는다 — V7에 실제 브라우저(가능하면 전시 PC) 확인을 필수로 둔다.

**판단**: 고정 경로 + 유기적 사실감 구간의 **첫 시안**은 AI 영상이 가장 싸다 `[추론]`. 정확한 구도·반복 수정·상호작용이 필요할수록 Blender/실시간 3D가 싸진다. 가장 유리한 조합은 **Blender 블록아웃(구도·카메라) → AI 영상(질감·빛) → 이 플레이어(디테일)**다. 실제 생성 도구의 비용·품질은 아직 측정하지 않았다 — 사용자 시험으로 확인한다.

## 8. 사용자 시험 절차

1. 구간을 정하면 AI가 V0 판정과 브리프(`templates/AI_VIDEO_BRIEF.md` + JSON)를 만든다.
2. 영상을 생성해 저장소 밖(또는 `assets/source/`)에 올린다.
3. `python3 tools/video-qa/check_video.py <영상> --brief tools/video-qa/briefs/VB-NNN.json --out <폴더> --first <첫 키프레임> --last <끝 키프레임>` → `feedback.md`와 `sheet.jpg` 확인, 필요하면 재생성(최대 3회).
4. `cd prototype/spikes/video-scrub && python3 scripts/import_clip.py <영상> <이름> --brief <json>` → `npm run build && npm run preview` → `http://127.0.0.1:4193/?clip=<이름>` (옵션 `remap`, `blend`, `depth`, `fx`, `kiosk`, `hud`).
5. `node scripts/qa.mjs` + 실제 브라우저에서 스크롤·마우스 체감 확인.

## 9. 미검증

실제 AI 영상, 실제 깊이 추정 맵, all-intra 영상 방식, 4K 업스케일, 실제 GPU·전시 PC 체감, 모바일·터치, reduced-motion 실기기.
