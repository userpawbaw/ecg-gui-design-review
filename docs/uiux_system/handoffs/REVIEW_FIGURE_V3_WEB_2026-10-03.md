### 2.3 제안 — 매뉴얼 6단계 순서로 다시 잡는 빛 라운드 (D 결정 필요)
1. **Pattern pass**(볼륨 끔, 회색): 창을 기능별로 나눔 — **hero 창 1개**(사다리 위 사람·심장 쪽으로 대각선, 살 간격 넓게 8–12 cm · 일부 살 틀어짐/한 칸 빠짐), **support 창 2–3개**(지금 방식, 간격 불규칙), **나머지는 블라인드 내림(어둠 = dark anchor)**. organic breakup 1종(창가 화분·종이 상자·커튼 한 장) 추가. 해 각 크기 1.2° → 0.5–0.6°(실제 해 ≈ 0.53°).
2. **Receiver pass**: hero 갈래가 **사다리 옆대·사람 어깨·서가 선반 앞턱**처럼 깊이가 다른 수광면 2개 이상을 지나게(매뉴얼 §19). 서가 끝면 막대는 hero가 아니면 블라인드로 줄임.
3. **Key pass**: `SUN_TO`를 hero 창 → 사람 방향으로 다시 잡고, 하늘 채움 최소.
4. **Atmosphere**: 방 전체 안개 `uHaze`는 0에 가깝게, 색은 중립(회색), 갈래 구간만 국소 밀도(매뉴얼 §7 local density). 정지 렌더의 균일 부피 안개도 제거하고 국소 부피로 → 정지 렌더를 다시 기준으로 쓸 수 있게.
5. **GI & shadow**: 굽기 그대로(Cycles bounce). 굽기 해상도는 hero 수광면(사다리·바닥 갈래 구역)에 texel을 더 주도록 UV 비중 조정.
6. **Post**: 블룸 문턱을 hero 하이라이트만 넘게, 레이마칭에 **양방향(깊이 인지) 블러 또는 시간 누적**, 먼지는 크기·밝기 분포를 치우치게(대부분 거의 안 보이고 5–10 %만 반짝).
검증: 매뉴얼 §11.1 디버그 세트를 웹(`?debug=clay|shadow|volume|receiver`)과 정지 렌더(`--debug`)에 추가하고, §17 루브릭 7문항을 판정 표로.

이 라운드는 서고 빛·블라인드·카메라를 바꾸므로 **계획 채팅 결정 + 정지 렌더 첫 시안 → 사용자 확인 → 위임** 순서(D-047).

### 5.3 받아들이지 않음 — 과하거나 목적에 맞지 않음
| 가이드 | 이유 |
|---|---|
| §17 심장 오브젝트에 bevel·layered shell·recess | 심장은 HRA 해부 데이터(CC BY) — 형태를 바꾸면 출처의 의미가 흐려짐. 심장은 햇빛을 받는 물체가 아니라 **스스로 빛나는 주인공**이고 밝기 변화는 저장된 박동 시점에서 온다 |
| §15 Unreal 루틴, Lumen·Local Fog Volume | 이 프로젝트의 렌더 경로가 아님 |
| §8 material ID·roughness 변화, §13 LOD 정책 | 굽기(난반사만) + 웹 무반사 경로에서는 효과가 거의 없음. hero 수광면 2–3개만 예외로 검토 |
| §11 식물·천 위주 organic breakup | 기록 서고 맥락에 큰 잎 그림자는 어색 — **종이 상자 하나·말린 용지·커튼 한 장** 수준만 |
| 비율 휴리스틱(70/20/10, 10–20 %) | 가이드 자신도 절대 규격 아님이라 명시 — 판정은 clay 렌더 비교로만 |
| 매뉴얼 §16 AI 재조명(IC-Light)·Blender MCP | 우리는 이미 스크립트로 Blender를 돌리고, 2D 재조명 이미지는 3D 가림과 맞는다는 보장이 없음(매뉴얼 자신의 경고). 탐색용으로도 이번 라운드엔 불필요 |

### 5.4 빛 라운드 제안에 반영한 변경(§2.3 갱신)
1. Pattern pass에 **aperture 깊이**(창틀·창턱)와 **보이지 않는 BLK_ 차광체**(굽기·웹 공통) 추가.
2. Receiver pass 판정: hero 갈래가 **깊이가 다른 수광면 2개 이상**(사다리 옆대 + 서가 앞턱 또는 바닥)을 지나고, **사람 영역에서는 심장이 햇빛보다 밝다**.
3. 승인 관문 = clay gate(A–D) 통과 후에만 부피·블룸.
4. 이름 규칙 APR_/BLK_/RCV_/NEG_/VOL_ 도입.
5. 파형 무대 보호 규칙(갈래·블룸이 파형 영역을 지나지 않음)을 검증 항목에.
6. 전환을 occlusion reveal로 바꾸는 안은 **사용자 결정 후보**(P3와 묶음).
