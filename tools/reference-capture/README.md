# 레퍼런스 사이트 촬영 규칙 (순서 합의됨 · 2026-09-25, D-017)

목적: 레퍼런스 사이트의 연출이 **스크롤할 때**와 **멈췄을 때** 어떻게 다른지, 스크롤 위치와 속도 중 무엇에 반응하는지를 녹화만으로 측정할 수 있게 한다.
배경: `docs/uiux_system/handoffs/EFFECT_PRODUCTION_PIPELINE_AUDIT_2026-09-25.md` §14–15.

## 1. 녹화 설정

| 항목 | 권장 | 이유 |
|---|---|---|
| 프레임률 | **60 fps 고정(CFR)** | 첫 녹화는 프레임 24.5 %가 중복되어, 미세한 끊김이 사이트 탓인지 녹화 탓인지 구분할 수 없었음 |
| 해상도 | 1920×1080, 브라우저 배율 100 % | 측정 기준 통일 |
| 화면 | 브라우저 **전체화면(F11)**. 다른 창·알림 끄기 | 탭·작업표시줄 제거 |
| 도구 | OBS Studio(무료, 워터마크 없음, CFR 설정 가능) 권장 | 기존 녹화 도구 워터마크가 오른쪽 아래 문구를 가림 |
| 소리 | 필요 없음 | — |

OBS 참고 설정: 출력 → 녹화 형식 mp4 또는 mkv, 비디오 → FPS 60, 인코더는 하드웨어(NVENC/QuickSync) + 품질 높음.

## 2. 입력 표시 HUD

`scroll-hud.js`를 레퍼런스 페이지의 DevTools 콘솔(F12 → Console)에 붙여 넣는다. 사이트가 허용하면 `bookmarklet.txt`의 한 줄을 북마크로 저장해 클릭해도 된다. 왼쪽 아래에 다음이 표시된다.

- `WHEEL ■ ▼ 100 #12` — 휠 입력 순간(120 ms 동안 표시)과 방향, 크기, 누적 횟수
- `KEY` — 키 입력(↓, PageDown, Space 등)
- `scrollY`, `velocity` — 실제 스크롤 위치와 속도(관성 스크롤 사이트에서는 입력이 끝난 뒤에도 값이 이어짐 → 관성 확인 가능)
- 진행 막대 — 페이지 전체 중 현재 위치

읽기 전용 스크립트다(이벤트를 듣기만 하고 사이트 동작을 바꾸지 않음). 새로고침하면 사라진다. 이 HUD가 휠 입력과 관성 스크롤을 구분해 보여 주므로, 키 입력 표시 프로그램보다 정확하다.

## 3. 파트별 촬영 순서

새 화면(파트)이 나올 때마다 다음 순서를 반복한다. **순서는 지키고, 시간은 대략이면 된다**(사용자 합의: 정지 1~2초, 휠 간격 0.5초 안팎도 가능). 정확한 시각은 HUD의 `t`와 `WHEEL` 표시로 사후 측정하므로 초 단위를 맞출 필요가 없다.

1. **정지 (약 1~3초)** — 아무 입력 없이 기본 움직임(idle)을 본다
2. **휠 1칸 × 3회, 약 0.5~1초 간격** — 입력 한 번에 대한 반응과 감쇠(얼마나 부드럽게 멈추는지)를 본다
3. **연속 스크롤 (약 2초)** — 일정한 속도로 굴린다
4. **정지 (약 1~3초)** — 빠른 상태에서 느린 상태로 넘어가는 전환을 본다
5. **빠르게 휙 1회** — 속도에 비례하는지 본다
6. **정지 (약 1~2초)**
7. **위로 조금 되돌리기** — 되돌리면 연출도 거꾸로 가는지(scrub), 한 번 실행되면 끝인지(문턱 발동) 본다

전환 효과(파트와 파트 사이)는 **아주 천천히 휠 1칸씩** 넘겨서, 전환 중간 단계가 여러 프레임에 담기게 한다.

hover, 클릭 반응이 있는 요소는 스크롤 녹화와 **분리된 짧은 녹화**로 따로 찍는다.

## 4. 함께 주면 좋은 것

- 사이트 URL, 녹화 날짜, 브라우저 종류와 버전
- 궁금한 파트의 녹화 시각(예: "37초 오른쪽 타이포")

## 5. 분석 산출 형식

영상 하나마다 **화면별 · 전환 효과별**로 나눠 기록한다(사용자 요청). 각 항목은 다음을 포함한다.
관찰 → 정량 측정(가능한 경우) → 입력 반응 유형(위치 / 속도 / 문턱 / 시간) → 구현 추정 → 필요 에셋·기술 → ECG 번안 메모.
