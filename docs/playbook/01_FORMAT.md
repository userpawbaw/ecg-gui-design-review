# 경험 플레이북 — 기록 형식, 검사, 기록 시점

설계 근거는 `00_DESIGN_RULES.md`(DR-1 ~ DR-12)에 있다. 이 문서는 쓰는 법이다. 검사기는 `scripts/check-playbook.cjs`(`npm run playbook:check`)이고 `npm test`에 들어 있다.

## 1. 두 층과 읽는 순서

```
작업 시작 → README 색인(언제 읽나) → 권장 카드 P-nnn → (왜?) 여정 J-nnn의 노드 Tn → (세부) F/D/O/R·verification
```

| 층 | 파일 | 질문 | 문체 |
|---|---|---|---|
| 권장 카드 | `docs/playbook/P-nnn_<slug>.md` | "이 작업을 하려면 무엇을, 어디까지?" | 짧은 명령형. 한 장 |
| 여정 | `docs/playbook/journeys/J-nnn_<slug>.md` | "어떻게 여기까지 왔나?" | 시간순 서사. 노드 사슬 |
| 운영 기록 | `docs/uiux_system/records/*.md`, `verification/` | "그때 정확히 무엇을 봤나?" | 기존 규약(`10_RECORD_KEEPING.md`) |

카드 하나는 여러 여정의 노드를 인용할 수 있다. 여정 하나도 여러 카드에 도착할 수 있다.

## 2. 권장 카드 P 양식

```markdown
# P-001. <작업 상황> — <권장 방법 한 줄>

| | |
|---|---|
| 상태 | 유효 / 잠정 / 대체됨 → P-nnn |
| 언제 읽나 | 이 카드를 펼쳐야 하는 작업 상황(동사로) |
| 도달 수준 | 이 방법으로 실제 도달한 품질 — 증거 경로 또는 근거 태그 |
| 근거 여정 | J-001 T6, T10–T12 |
| 강제 장치 | 검사기·스크립트·skill 경로, 또는 `수동 — 사유` |
| 갱신 | 2026-10-09 |

## 권장 방법
## 도달한 품질
## 가지 말 길
## 틀린 길이라는 신호
## 타협하면 안 되는 지점
## 적용 범위와 재검토 조건
## 남은 한계
```

| 절 | 필수 | 쓰는 법 |
|---|---|---|
| 권장 방법 | 항상 | 순서 있는 단계. 실제 명령·스크립트·수치가 하나 이상 들어간다(검사) |
| 도달한 품질 | 항상 | 무엇을 기준으로 "됐다"고 봤나. 누가 확인했나(사용자/AI). 증거 경로 |
| 가지 말 길 | 근거 여정에 `기각` 노드가 있으면 | 항목마다 `(J-nnn Tn)` 인용. "왜 실패"와 "이럴 때는 다시 열 수 있다" |
| 틀린 길이라는 신호 | 항상 | 결론보다 먼저 보이는 증상. 항목마다 `(J-nnn Tn)` 인용 |
| 타협하면 안 되는 지점 | 근거 여정에 `타협` 노드가 있으면 | 당시 멈춘 수준 → 그 뒤 실제 도달한 수준. 항목마다 인용 |
| 적용 범위와 재검토 조건 | 항상 | 이 카드가 맞지 않는 상황, 권장안을 다시 열 조건 |
| 남은 한계 | 선택 | 아직 풀지 못한 문제(패턴의 "풀지 못한 힘") |

조건부 절에 쓸 내용이 없으면 **절을 빼거나** `해당 없음 — <8자 이상 사유>` 한 줄만 쓴다. 빈칸을 그럴듯한 일반론으로 채우지 않는다.

상태:
- `유효`: 사용자가 결과를 확인했다.
- `잠정`: AI 검증만 했거나 사용자 확인 대기다. 도달 수준에 확인 대기라고 쓴다.
- `대체됨 → P-nnn`: 지우지 않는다. 새 카드의 근거 여정에 대체 사유 노드가 있어야 한다.

## 3. 여정 J 양식

```markdown
# J-001. <주제> — <출발> 에서 <도착> 까지

| | |
|---|---|
| 기간 | 2026-09-29 ~ 2026-10-08 |
| 도착 | P-001, P-002 |
| 기록 | D-045, D-048, … (이 여정이 꿰는 운영 기록) |

## 출발점
## 흐름 한눈에
## T1. <시도 이름>
## T2. …
## 도착점
## 여정에서 얻은 것
```

### 노드 `## Tn. <시도 이름>`

```markdown
## T3. 달걀 머리 — 얼굴 정점을 타원체로 투영

| | |
|---|---|
| 날짜 | 2026-10-01 |
| 종류 | 시도 / 비교 |
| 계기 | 이 시도를 부른 불만·요구 (앞 노드 또는 사용자 발화) |
| 가설 | 이렇게 하면 풀릴 것이라고 본 것 |
| 판정 | 채택 / 부분 채택 / 기각 / 타협 / 대체됨 |
| 다음 | T4 (여러 개면 쉼표) / 끝 |
| 기록 | F/D/O/R/REF ID, 커밋, verification 경로 — 없으면 `기록 없음 — 사유` |

### 한 것
### 결과
### 왜 다음으로
```

- `### 선택지와 기준`: 종류가 `비교`면 필수. 무엇을 어떤 기준으로 비교했나.
- `### 왜 다음으로`: `다음`이 `끝`이 아니면 필수. 이 결과가 왜 다음 시도를 불렀나. 연결성의 핵심이다.
- `### 결과`: 근거 태그 또는 기록 ID·경로가 하나 이상 필요하다.

판정:
| 판정 | 뜻 | 검사 |
|---|---|---|
| 채택 | 이 방법이 도착점의 일부다 | — |
| 부분 채택 | 일부만 남았다 | — |
| 기각 | 버렸다 | 어떤 카드의 `가지 말 길`이 인용하거나(`신호` 절 인용은 인정하지 않음), 노드에 `교훈 없음 — 사유` |
| 타협 | 기준에 못 미친 채 받아들였다(뒤에서 넘어선 경우 포함) | 어떤 카드의 `타협하면 안 되는 지점`이 인용하거나, `교훈 없음 — 사유` |
| 대체됨 | 한때 채택했으나 뒤 노드가 대신했다 | `다음`이 대체한 노드를 가리킨다 |

### 기록 원칙
- 노드는 짧게 쓴다(3–10줄). 세부 수치·이미지는 운영 기록과 `verification/`을 가리킨다(DR-12).
- 당시 생각을 기록 없이 복원하면 `[재구성]`을 붙인다. 사용자가 나중에 회고한 이유가 당시 기록과 다르면 둘 다 쓴다(`기록된 근거` / `사용자 회고`).
- 사용자 발화를 인용할 때는 원문만 따옴표에 넣는다.

## 4. 검사기 — 빠진 것과 억지로 채운 것

`scripts/check-playbook.cjs`. 자체 테스트 `tests/playbook.test.cjs`: 정상 표본 2(LF·CRLF), 누락 변형 10, 억지 변형 6. 각 변형이 기대한 이유로 실패하는지 확인한다.

### 빠진 것 (누락)
| 검사 | 실패 예 |
|---|---|
| 카드·여정 머리표 필드가 모두 있고 비어 있지 않다 | `강제 장치`가 없다 |
| 카드 필수 절(권장 방법, 도달한 품질, 틀린 길이라는 신호, 적용 범위와 재검토 조건)이 있다 | |
| 조건부 절: 근거 여정에 `기각` → `가지 말 길`, `타협` → `타협하면 안 되는 지점` | 실패한 시도가 있는데 카드가 말하지 않는다 |
| 여정의 `기각`·`타협` 노드는 어떤 카드가 인용하거나 `교훈 없음 — 사유`가 있다 | 실패가 어떤 권장에도 반영되지 않고 묻힌다 |
| 노드 필드 7개, `결과`·`한 것` 절, `다음`이 끝이 아니면 `왜 다음으로`, `비교`면 `선택지와 기준` | 사슬이 끊긴다 |
| `다음`이 실제 노드를 가리키고, T1이 아닌 모든 노드가 어떤 노드의 `다음`에 있다 | 고아 노드 |
| `근거 여정`·`도착`·`기록`의 ID(P/J/T/F/D/O/R/REF/CASE)와 경로가 실제로 있다 | 없는 D-099 |
| 카드 ↔ 여정 양방향: 여정의 `도착`에 있는 카드는 그 여정을 근거로 든다 | |
| `도달 수준`에 존재하는 경로 또는 근거 태그 | "잘 됨" |
| `강제 장치`의 경로가 있거나 `수동 — 사유` | |
| `상태`가 허용값, `대체됨 → P-nnn`은 실제 카드 | |
| README 색인이 모든 P·J를 나열하고 없는 파일을 나열하지 않는다 | |

### 억지로 채운 것 (padding)
| 검사 | 실패 예 |
|---|---|
| 절 내용이 placeholder 하나뿐(`TODO`, `TBD`, `N/A`, `-`, `없음`, `미정`, `추후`, `…`) | `## 남은 한계` + `없음` |
| `해당 없음`은 `해당 없음 — <8자 이상 사유>` 형식만 | `해당 없음` |
| `가지 말 길`·`틀린 길이라는 신호`·`타협하면 안 되는 지점`의 항목마다 `(J-nnn Tn)` 인용 — 경험에 근거 없는 일반론 차단 | "- 리그는 신중하게 고른다" |
| 막연한 항목: `적절히`·`신중히`·`꼼꼼히`·`충분히`·`잘 확인`·`주의 깊게`·`가능하면`이 들어가고 숫자·경로·코드·ID가 없는 항목 | "- 결과를 꼼꼼히 확인한다" |
| 같은 문장(공백·문장부호 무시 20자 이상)이 한 파일의 두 절에, 또는 두 카드에 반복 | 복사해 채운 절 |
| `권장 방법`에 실행 가능한 단서(코드 표기, 경로, 숫자)가 하나도 없음 | "좋은 리그를 쓴다" |
| 노드 `결과`에 근거 태그·ID·경로가 없음 | 근거 없는 서사 |

### 자동으로 못 보는 것 — 사람 점검
1. 권장 방법을 처음 보는 사람이 그대로 따라 해서 `도달 수준`에 갈 수 있나?
2. `틀린 길이라는 신호`가 실제로 **결론보다 먼저** 보이는 증상인가? 결과를 다시 쓴 것이 아닌가?
3. 여정의 `계기`를 이어 읽으면 왜 주제가 바뀌었는지(예: 머리 모양 → 리그) 납득되나?
4. 사용자 판단과 AI 판단이 섞여 있지 않나(누가 결정했는지)?
5. `타협` 판정이 빠진 노드는 없나? 당시 "충분하다"고 받아들였다가 뒤에서 넘어선 것은 모두 `타협`이다.

## 5. 기록 시점 (AGENTS.md 규칙과 같음)

| 순간 | 할 일 |
|---|---|
| 작업 시작 | README 색인의 `언제 읽나`를 훑고 맞는 카드를 먼저 읽는다. 카드와 다른 길로 가려면 카드의 `재검토 조건`에 해당하는지 먼저 적는다 |
| 개선 작업이 결론에 닿음(사용자가 결과를 받아들임, 또는 한 방식을 버리고 다른 방식으로 정함) | **같은 커밋에서** 여정에 노드를 추가하고 카드를 만들거나 고친다. 사용자 확인 전이면 카드 상태 `잠정` |
| 시도를 버림 | 여정 노드 `기각`, 카드 `가지 말 길` |
| 기준에 못 미친 채 넘어감 | 노드 `타협`, 카드 `타협하면 안 되는 지점` |
| 권장안이 뒤집힘 | 옛 카드 `대체됨 → P-nnn`, 새 카드, 여정에 대체 노드 |
| 커밋 전 | `npm run playbook:check` (`npm test`에 포함) |

작은 수치 조정은 기록하지 않는다. "다음 사람이 같은 작업을 할 때 다른 길로 가게 만드는가?"에 그렇다면 기록한다.
