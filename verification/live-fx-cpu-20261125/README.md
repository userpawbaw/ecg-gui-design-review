# 실시간 탭 효과별 CPU — 측정 (F-112, 2026-11-25)

사용자: 「프레임이 끊길 때 각종 효과들이 한번씩 재생되는게 있더라? 특히 격자무늬가 나아가는 효과 … 실시간으로 연산해서 새로 그리는 것 같은데 맞아? … 미리 만들어놓고 저장한 다음 오버레이하는 방식으로 하는게 맞지 않아?」

환경: 이 스크립트 · headless Chromium · 재생 브리지(`npm run bridge:replay`, M_FE · M04(hop 32) · M05S, D-198 패치)를 `taskset -c 0,1`로 같은 코어 2개에 묶음(노트북 경쟁 흉내). **이 환경은 GPU가 없어 화면 합성 · WebGL을 CPU(SwiftShader)로 한다** — 합성 비용은 GPU 노트북보다 크게 나온다. 비율 · 상대 비교로만 읽는다.

| 파일 | 내용 |
|---|---|
| `cpu_2cores.txt` | 설정별 브라우저 · 브리지 CPU, 브리지 RTF(루프) · 밀림, 그리기 횟수 · JS 시간 |
| `cpu_2cores_noheart.txt` | 3D 심장을 끈 상태에서 같은 비교 + 그림 한 장당 브라우저 CPU |
| `proc.txt` · `css.txt` · `bg.txt` · `bisect.txt` · `heart.txt` | chrome 프로세스 종류별 CPU, CSS 효과 · 배경 · 화면 구역 · 심장 하나씩 끄기 |
| `trace_top*.txt` | 3 s 추적 상위 이벤트(WebGL · ReadPixels · 합성) |
| `baseline.txt` | 비교 기준: 빈 rAF, 화면 크기 캔버스 하나 매 프레임 = gpu-process 14 % |
| `mutations.txt` | 2 s 동안 DOM 변화(매 프레임 변화 없음) |

요점(숫자는 위 파일):
1. 효과는 이미 대부분 미리 만들어 둔다: 용지 격자(캔버스 CSS 배경으로 한 번), 빛기둥용 밝은 격자 이미지, 잔광 램프, 선단 빛점 스프라이트, 선 · 번짐(링 캔버스에 새 표본만). 매 프레임 하는 일은 이것들을 화면 위치에 맞춰 **붙이는 합성**이다 — 스크롤은 모든 것이 매 프레임 움직여 칸 전체를 다시 합성한다.
2. 「끊길 때 효과가 한 번씩」: `glowLive` — 데이터가 0.3 s 넘게 안 오면 빛기둥 · 흰빛 · 빛점을 0.3 s에 걸쳐 끄고, 오면 바로 켠다. 화면 버퍼(D-197) 덕에 파형은 계속 흐르는데 효과만 꺼졌다 켜진다.
3. 3D 심장(심박 배지): 박동마다 0.7 s WebGL 렌더(시간의 약 85 %) — 끄면 gpu-process 106 → 73 %, 파형 캔버스까지 숨기면 페이지 전체 27 %.
4. 파형(심장 끔, 분리 · 스크롤, 칸 4개): 그림 한 장당 브라우저 CPU 36 ms(그중 JS 8.6 ms). 「최신 구간 강조」 끔 30 ms, 번짐 0 33 ms — 효과 몫은 약 10–18 %, 나머지는 칸 4개를 매 프레임 다시 합성 · 래스터하는 기본 비용. 중첩 55 ms.
