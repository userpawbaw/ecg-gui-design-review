# 딥러닝 기법 경량화 (D-201, 2026-11-25)

사용자: 「딥러닝 방식은 노트북에서 너무 무거운 것 같다. 조금 경량화 가능해?」

| 파일 | 내용 |
|---|---|
| `dl_infer.py` · `dl_infer.txt` | 추론 한 번(창 1024): 그대로 / TorchScript 고정(freeze + optimize_for_inference), torch 스레드 1 · 2 — CPU · 벽시계, 고정 출력 차이 |
| `hop64.py` · `hop64.txt` | 추론 간격 16 · 32 · 64의 계산량과 참값 RMSE(합성 심전도 + 혼합 잡음 0 dB, 40 s) |
| `bridge_cpu.txt` | 같은 재생(M_FE · M08 · M09)에서 브리지 프로세스 CPU 30 s |

요점:
- 스레드 1개: 추론 벽시계 시간은 비슷(M08 8.1 vs 8.5 ms)한데 CPU는 30–50 % 적다(8.1 vs 16.3 ms) — 2개는 스레드 맞춤에 CPU를 쓴다.
- 고정: 출력 차이 0, CPU 10–30 % 감소(M08 8.1 → 5.9 ms).
- 간격 32: 계산 절반, RMSE 같음(+64 ms). 64: 계산 1/4, RMSE 같거나 낮음(+192 ms).
- 브리지 CPU: 이전(16 · 스레드 2 · 고정 없음) 90 % → 새 기본(32 · 1 · 고정) 35 % → 가벼운 계산(64) 28 % (코어 1개 = 100 %). 남은 몫은 재생 신호 만들기 · 전처리 · 발행.
- 합성 신호 측정 — 실측 아님. 노트북 절대값은 다르다.
