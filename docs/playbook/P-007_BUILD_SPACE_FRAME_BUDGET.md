# P-007. 장면의 공간·세트·빛을 새로 만들 때 — 바닥 좌표가 아니라 카메라 프레임마다 예산을 정하고, 회색 블록아웃을 웹 톤으로 재서 현재안과 나란히 놓은 뒤에 짓는다

| | |
|---|---|
| 상태 | 잠정 |
| 언제 읽나 | 장면의 방·세트·소품 묶음을 새로 짓거나 크게 바꿀 때, 굽기(Blender bake) 전에 빛·구멍 위치를 정할 때, "허전하다·밋밋하다·테마가 안 느껴진다" 지적을 받았을 때, 새 안을 현재 채택안과 비교해 보일 때 |
| 도달 수준 | A안(구운 서고 + 구운 소품 세트)이 사용자 채택("A안이 훨씬 낫네", 2026-10-17) `[대화]`. 이 카드의 사전 검토 순서는 C안 실패를 진단해 만든 제안이다. 적용해 검증한 적은 아직 없어 사용자 확인 대기다. 증거 F-043, `verification/r1-story-feedback-20261011/README.md` §13 |
| 근거 여정 | J-004 T1–T4 |
| 강제 장치 | `scripts/qa/frame-budget.py` (예산 만들기·판정·나란히 시트), `scripts/qa/frame-capture.cjs` (웹 톤 캡처), 예산 `scripts/qa/budgets/story-noise-A.json` |
| 갱신 | 2026-10-17 (검사기 제작·진행 테스트 C2 3라운드 반영) |

## 권장 방법
1. **프레임 목록.** 장면별 핵심 프레임을 뽑는다. 이야기 장면 예: pli 5·7·8.5·11·16 s, bw 6 s, ma 6 s. 카메라 경로 전체는 0.25 s 간격으로 뽑는다(`window.__noise.probe(0,0)` 순회, 2026-10-17 `campath.json` 방식). 새 공간이 모든 시점을 감싸는지도 이 목록으로 본다.
2. **프레임 예산.** 현재 채택안(지금은 A안)을 `node scripts/qa/frame-capture.cjs --out A`로 찍는다. 이어서 `python3 scripts/qa/frame-budget.py derive --dir A --out scripts/qa/budgets/<장면>.json`으로 예산을 만든다. 하한은 A × 0.8, 깊은 어둠·볕 면적은 A 주변 범위다(하한만 두면 새카만 화면과 하얗게 탄 화면이 통과한다, J-004 T5). 이야기 장면 pli 7 s 기준은 다음과 같다.
   - 깊은 어둠(L<0.06) ≥ 25 %, L* 25 백분위 ≤ 4.
   - 볕 면적 lit% ≥ 5, 결정적 경계 crisp20‰ ≥ 9.
   - 흐린 그림자 soft_area% ≥ 6, 질감 밀도 edge ≥ 17.
   레퍼런스(REF-002)를 잴 수 있으면 같이 적는다.
3. **주제·빛 계획표 (짓기 전, 한 장).** 프레임마다 다음을 적는다.
   - 주제 물체: 이 프로젝트에서는 기록 보관소의 책·기록 상자·카드 서랍·심전도 종이 두루마리. 몇 개가 보여야 하는지 적는다.
   - 밝은 면 / 어두운 면: 수직면(벽·책장)을 포함해 화면의 어디가 밝고 어디가 어두운지.
   - 흐린 그림자: 화면 밖 고보가 떨어질 면.
   - 빛기둥: 시야를 가로지르는지.

   구멍 위치는 이 표에서 거슬러 정한다(바닥 좌표만으로 정하지 않는다).
4. **회색 블록아웃을 웹 톤으로.** 상자와 판으로만 공간과 빛을 만든다. `BAKE_SCALE=0.25`로 저해상도 굽기를 해서 웹에 올리고, 웹 캡처(`?msaa=0`)로 잰다. Blender 미리보기에서 노출을 따로 올려 판단하지 않는다.
5. **나란히 비교.** `python3 scripts/qa/frame-budget.py check --budget … --dir CAND --baseline A --sheet s.jpg --report r.md`로 판정한다. 통과하지 못하면 세부 소품과 본굽기로 가지 않고 구조(빛이 닿는 면, 깊이 층, 주제 물체)를 바꾼다. 한 라운드(빠른 굽기 약 200 s + 캡처 약 100 s)는 약 6분이다.
6. **3라운드에서 멈춘다.** 라운드를 거듭해도 같은 지표가 움직이지 않으면 공간 구조가 상한을 정한 것으로 보고 사용자에게 넘긴다. C2는 결정적 경계·질감 밀도·흐린 그림자가 A의 약 60 %에서 멈췄다(J-004 T5).
7. **의도된 예외.** 예산과 다르게 가려는 프레임(예: C안 pli 11 s의 사각 볕 40 %)은 사용자 승인을 받아 예외로 적는다. 승인 없이 기준을 낮추지 않는다.
8. **사용자에게는 5의 시트와 표를 함께 보인다.** "직전보다 나아졌다"는 진행 확인일 뿐 보고 근거가 아니다.

## 도달한 품질
A안이 채택됐다(사용자 확인). 2026-10-17 진행 테스트에서 검사기는 A를 49/49로 통과시키고 C1을 14/49로 걸렀다 `[런타임]`. C2 3라운드는 21–26/49에서 수렴하지 않았다(`verification/r1-story-feedback-20261011/README.md` §14). 순서를 따른 결과가 사용자 확인을 받은 적은 아직 없다. C안을 이 순서로 거꾸로 재 보면, pli 7 s에서 2의 하한 여섯 개를 모두 넘지 못했다. 같은 프레임의 A안은 여섯 개를 모두 넘는다(F-043 표) `[런타임]`. 블록아웃 단계였다면 본굽기 30분과 미리보기 9회를 쓰기 전에 걸렸을 것이다 `[추정]`.

## 가지 말 길
- **구운 방 위에 웹 국소 빛(램프 스폿·화면 발광)을 더해 볼거리 만들기** — 접촉 경화 그림자와 화면 밖 고보의 흐린 그림자가 나오지 않았고, 사용자가 "원하는 불빛이 아니야"라고 했다(J-004 T1). 실제 조명 기구가 장면의 주제일 때만 다시 연다.
- **기존 공간의 주제·밀도를 버리고 공간을 처음부터 다시 짓기** — 같은 평균 밝기에서 깊은 어둠·볕 면적·결정적 경계·질감 밀도가 모두 절반 안팎으로 떨어졌다(J-004 T4). 대체할 주제 물체 밀도 계획(3)이 예산(2)을 넘을 때만 다시 연다.
- **닫힌 방이 어둡다고 하늘빛·채움 창으로 그늘 전체를 올리기** — 어둠의 층위가 사라져 회색이 됐다. pli 8.5 s에서 깊은 어둠이 30 %에서 3.5 %로 떨어졌다(J-004 T4).

## 틀린 길이라는 신호
- 예산 판정에서 깊은 어둠·볕 면적이 "통과"인데 화면이 새카맣거나 볕이 화면 절반을 덮는다. 하한만 둔 예산이다(J-004 T5).
- 라운드마다 바꿔도 같은 지표(결정적 경계·질감 밀도)가 그대로다. 밝기·노출 조정이 아니라 공간 구조를 다시 볼 때다(J-004 T5).
- 미리보기를 고를 때 비교 대상이 직전의 내 렌더뿐이다(J-004 T4).
- Blender 미리보기에서 노출을 따로 올려야 보인다. 웹 톤에서는 회색이거나 검다(J-004 T4).
- 볕이 바닥·러그·책상 같은 수평면에만 떨어지고, 화면의 큰 면적인 벽·책장에는 하늘빛만 닿는다(J-004 T4).
- 화면의 4분의 1 이상이 민무늬 벽·천장이다(J-004 T4).
- 사용자의 첫 반응이 빛이 아니라 "웹 빛이 원하는 불빛이 아니다"처럼 빛의 종류를 문제 삼는다(J-004 T1).

## 적용 범위와 재검토 조건
- 맞는 범위: 굽는 공간·세트·소품 묶음, 그리고 그 빛 설계. 화면 UI·파형 레이아웃에는 쓰지 않는다.
- 다시 열 조건:
  - 이 순서를 한 번 적용해 사용자가 결과를 확인하면 `유효`로 올리고 예산 수치를 고친다.
  - 예산 하한이 사용자 판단과 어긋나면(지표는 넘었는데 "허전하다") 측정 항목을 바꾼다.
  - 프레임 예산 검사기를 만들면 `강제 장치`를 그 경로로 바꾼다.

## 남은 한계
- 빠른 굽기(`BAKE_SCALE=0.5`, 32샘플) 값이 본굽기 값을 얼마나 예측하는지 확인하지 않았다.
- 예산은 A안 한 장면 기준이다. 다른 장면은 그 장면의 채택안으로 다시 만든다.
- 주제 물체 수를 세는 자동 수단이 없다(레이캐스트 ID 버퍼 방식은 미구현).
- 웹에 덧붙인 모형(멀티탭·의자·인물)은 구운 볕을 받지 않아 볕 속에서 붙여 넣은 듯 보인다.
