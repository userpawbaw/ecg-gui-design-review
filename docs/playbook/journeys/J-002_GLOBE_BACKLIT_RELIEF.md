# J-002. 역광 지구 — 기록해 둔 bump 채널을 빼먹은 재현에서 극지방 요철까지

| | |
|---|---|
| 기간 | 2026-09-25 ~ 2026-10-09 (v2 같은 날) |
| 도착 | P-005 |
| 기록 | REF-001, D-041, `docs/uiux_system/rounds/R1/REVIEW-R1-WEB-20261008.md`, `verification/r1-globe-relief-20261009/README.md` |

## 출발점

도입부 첫 장면은 Moto Card(REF-001)의 역광 지구를 우리 식으로 재현한 것이다. 효과 카드 EFX-001-02는 2026-09-25에 원본 셰이더가 쓰는 텍스처 세 장을 이미 적어 두었다.
- day(낮), night(도시 불빛).
- bump 채널 묶음: R 지형 높이, G 거칠기, B 구름.

재현 요구사항에도 "bump 채널 묶음을 직접 만든다"가 있었다.

이 여정의 줄기: **기록해 둔 채널 하나를 구현 때 빼먹었다.** 그 빈자리를 빛 세기 조정으로 메우려 했다. 원인을 알고 나서도 다른 결정 뒤로 미뤘다.

## 흐름 한눈에

```
T1 day·night·구름만으로 재현(bump 누락) ──(사용자: 레퍼런스에 못 미침)──▶ T2 원인을 알고도 테마 결정 뒤로 미룸
   ──(8일 뒤 같은 지적: 극지방 요철 약함)──▶ T3 bump + 평평한 가장자리 빛 ──(극지 띠가 어두워지고 자글거림)──▶ T4 무늬에 곱하는 역광 + 3텍셀 미분 + 구름 그림자
   ──(사용자: 요철 거의 안 보임, 구름 과다, 불빛 부족)──▶ T5 같은 자리 나란히 놓고 데이터부터: 1월 지도·GEBCO 고도·8k 불빛·해 높이 ── 끝
```

| 가설 | 원본 셰이더의 색·회전·대기 가장자리 값을 옮기면 같은 인상이 난다 |
| 판정 | 타협 |
| 다음 | T2 |

### 한 것
`globe.ts`에 낮·밤·구름 텍스처, 대기 가장자리(fresnel²), 회전을 넣었다(커밋 4d7cba9). 효과 카드의 bumpMap 줄은 옮기지 않았다 `[코드]`.

### 결과
사용자 `[대화]`(2026-10-01): "지구 퀄리티는 레퍼런스인 moto-card 사이트에 못 미치는 느낌이야. moto-card의 지구는 남극이 튀어나온 느낌이라던가 각 대륙이 어떤 느낌인지 잘 표시되어 있었는데." 화면 대부분이 야간면이었고 입체가 없었다(IDEA-R1-INTRO §7.2 Q4).

### 왜 다음으로
AI는 같은 날 원인을 코드에서 찾았다. "REF-001은 지형 높이·거칠기 채널 bump를 쓰는데 우리 `globe.ts`는 bump 없이 day·night·구름만 씀" `[코드]`.

### 결과
테마는 같은 날 사용자 정정으로 "어두운 공간 + 서고"가 되었고 지구 표현은 바뀌지 않았다. 그런데도 Q4는 2026-10-08 검토 때까지 다시 열리지 않았다. 2026-10-08 도입부 검토에서 사용자가 같은 문제를 다시 짚었다 `[대화]`: "극지방(역광이 비치는 부분)의 요철·부피감에 따른 그림자 느낌이 약함"(REVIEW-R1-WEB I-1).

### 왜 다음으로
미룬 이유(테마 변경)가 사라졌는데도 미룸 표시가 남아 있었다. 사용자의 두 번째 지적으로 다시 열었다.

## T3. bump를 넣고 평평한 가장자리 빛은 그대로

| | |
|---|---|
| 날짜 | 2026-10-09 |
| 종류 | 시도 |
| 계기 | REVIEW-R1-WEB I-1 |
| 가설 | 구름과 낮 지도 밝기로 높이를 만들어 표면 방향을 굽히면 역광 띠 안에 요철이 생긴다 |
| 판정 | 기각 |
| 다음 | T4 |
| 기록 | `verification/r1-globe-relief-20261009/README.md` |

### 한 것
높이 = 구름 0.75 + 낮 지도 밝기 0.25로 표면 방향을 굽혔다. 극지 가장자리에는 기존의 평평한 fresnel 빛을 그대로 더했다.

### 결과
극지 띠가 오히려 어두워지고 자글거렸다 `[캡처]`. 원인은 두 가지로 보았다 `[추론]`: 평평하게 더하는 빛이 요철 음영과 따로 놀았고, 가까운 텍셀로 잰 미분이 너무 촘촘했다. T4에서 둘을 함께 바꿨으므로 각각의 기여는 나눠 재지 않았다.

### 왜 다음으로
요철만이 아니라 역광 띠의 빛 자체를 표면 무늬에 묶어야 했다.

## T4. 무늬에 곱하는 역광 + 3텍셀 미분 + 구름 그림자

| 판정 | 타협 (2026-10-09 처음에는 AI가 '채택'으로 기록했다. 같은 날 사용자 확인에서 기준 미달로 바뀌었다 → T5) |
| 다음 | T5 |

### 한 것
- 높이 미분은 3텍셀 간격으로 쟀다(uBump 6).
- 극지 빛을 `day*1.9+.06`에 요철 계수 `rf`(uRelief 4.5)를 곱한 값으로 바꿨다.
- 구름 그림자를 넣었다(uCloudShadow .5).
- 가장자리 선은 fresnel⁴로 얇게 했다(커밋 025a6e5).

### 결과
역광 띠 안에서 구름·얼음 무늬와 그림자가 보인다. Moto Card 프레임과 나란히 비교했다 `[캡처]`. 남은 차이도 있다.
- 밝은 극지 영역이 조금 좁다.
- 실제 지형 높이가 없다(산맥·빙상 가장자리).
- 사용자 Edge 확인 전이다.

### 왜 다음으로
사용자 로컬 확인 `[대화]`: "구름은 많이 늘었지만 극지방의 요철은 거의 보이지 않아. 좀 더 레퍼런스에 가깝게 수정해줘. 구름이 너무 많은 느낌이 있어서 줄여도 돼. 그리고, 어두운 부분 지구가 원본에 비해 도심 불빛이 너무 적게 나타나는 것 같아."
AI가 '남은 차이'로 적어 둔 두 가지(밝은 극지 영역이 좁다, 실제 지형 높이가 없다)가 바로 사용자 기준의 핵심이었다.

## T5. 레퍼런스 프레임과 같은 자리를 나란히 놓고 데이터부터 바꾸기 — 1월 지도, 실제 고도, 8k 불빛

| | |
|---|---|
| 날짜 | 2026-10-09 |
| 종류 | 비교 |
| 계기 | T4에 대한 사용자 지적 세 가지(요철, 구름 과다, 도시 불빛 부족) |
| 가설 | 차이는 셰이더 세기가 아니라 입력 데이터(어느 달의 지도, 높이 원천, 불빛 해상도)와 빛 방향에서 온다 |
| 판정 | 채택 |
| 다음 | 끝 |
| 기록 | REF-001, `verification/r1-globe-relief-20261009/globe_v2_before_after.jpg`, `scripts/assets/build-globe-textures.py`, `prototype/v2/src/story/intro/globe.ts` |

### 선택지와 기준
같은 장면(p .06, Moto Card 녹화 3 s 프레임과 같은 유럽 쪽)을 나란히 놓고 한 번에 하나씩 바꿨다. 기준은 세 가지였다. 극지 띠의 폭과 밝기, 띠 안의 요철, 밤 면 불빛의 밀도와 크기.
- 해 높이: 기본(.26, 1.39, −3) / 2.2 / 3.0 / 1.65 / **1.85** / 2.0. 3.0은 보이는 유럽 전체가 낮이 됐다. 1.85에서 띠 폭이 레퍼런스와 비슷했다.
- 불빛 곡선: `pow(γ)` 대 포화형 `1 − e^(−kL)`(k 5 / **6** / 9), 밝기만 곡선 + 따뜻한 색.
- 낮 지도: 7월 / **1월**.
- 화면 후광: 대기 껍질 두께(효과 거의 없음) / **지구 구간 bloom 축소**.

### 한 것
- `build-globe-textures.py`로 데이터를 바꿨다.
  - 밤: Black Marble 2016 13500 → 8192. 불빛만 남김(R − 0.55 B).
  - 높이: GEBCO_08 육지·빙상 고도.
  - 낮: Blue Marble 1월.
- 셰이더를 바꿨다.
  - 높이 = 고도 + 구름 0.35.
  - 구름을 줄였고, 밤 면 구름은 불빛을 가리기만 하게 했다.
  - 불빛은 포화형 곡선 + 따뜻한 색.
  - 해를 (.26, 1.85, −2.75)로 올렸다.
- 지구가 보이는 동안 bloom을 줄였다(세기 .55 → .25, 반경 .35 → .10).

### 결과
나란히 비교 `[캡처]`:
- 극지 띠가 눈·얼음으로 하얘지고 해안선에 요철 그림자가 생겼다.
- 밤 면은 유럽 해안선과 작은 불빛 점들로 읽힌다.
- 지구 위 회색 안개가 줄었다.

남은 차이:
- 레퍼런스 띠가 더 넓고 밝다.
- 불빛 점이 레퍼런스보다 조금 굵다(텍스처 3 km 해상도와 bloom).
- 사용자 Edge 확인 전이다.

결정적이었던 것은 **7월 → 1월**이었다. 레퍼런스 극지 띠가 하얀 이유는 빛이 아니라 계절(눈 덮인 북쪽 땅)이었다 `[추론]`(1월판으로 바꾼 직후 띠가 하얘진 것으로 확인 `[캡처]`).

## 도착점

- **P-005**(잠정) 레퍼런스 효과를 재현할 때 → 효과 카드의 텍스처·채널·패스를 대조표로 먼저 다 넣고, 그 다음에 세기를 조정한다.

## 여정에서 얻은 것

1. 효과 카드는 읽혔지만 구현 대조표로 쓰이지 않았다. 텍스처 장수는 같았다(카드: 낮·밤·bump 묶음, 우리: 낮·밤·구름). 그래서 장수가 아니라 **채널과 셰이더 입력**을 대조해야 bumpMap(지형 높이·거칠기) 누락이 드러난다(P-005).
2. 미룬 항목은 미룬 이유가 사라지는 순간 다시 열어야 한다. 이유 없이 남은 미룸이 원인 확인부터 수정까지 8일 동안 품질 격차를 남겼다(P-005).
3. 빠진 채널을 빛 세기·색으로 메우려는 조정은 오히려 결과를 평평하게 만들었다(T3)(P-005).
4. 효과 카드의 채널을 다 넣은 뒤에도 남는 차이는 **입력 데이터의 선택**(계절, 높이 원천, 해상도)에서 왔다(T5). 레퍼런스 프레임과 같은 지역·같은 구도로 놓고 하나씩 바꾸면 원인이 바로 갈린다(P-005).
5. AI가 결과 보고에 '남은 차이'로 적은 항목이 사용자의 첫 지적이 되었다(T4 → T5). 남은 차이가 레퍼런스의 대표 특징(여기서는 극지 띠)에 걸려 있으면 그것은 남은 차이가 아니라 미완성이다(P-005).
