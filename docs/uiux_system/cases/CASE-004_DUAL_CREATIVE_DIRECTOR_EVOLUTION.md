# CASE-004. Single Director에서 Dual Creative Director로 — 도구의 위치를 다시 묻다

작성: 2026-09-18. 상태: **설계 판단과 기록 보강; Dual Director 실행 시스템은 미구현·다음 승인 대기**.

Primary context: [handoff checkpoint](../handoffs/DUAL_CREATIVE_DIRECTOR_IMPLEMENTATION_2026-09-18.md).
기준 main: `08ffec3` (handoff); 앞선 generator 통합: `ee678f7` → `88a8c03`.
연결: F-001, D-001, R-001 → F-004, D-007, R-006 → F-006, D-009, R-008 → F-007, D-010, R-009. 기록 강화: D-011, R-010.

**번호 안내.** 대화와 실행 요청에는 CASE-003이라는 제안이 남아 있지만 최신 main의 CASE-003은 이미 Superdesign 최초 도입을 설명한다. primary handoff §0에 따라 이를 덮어쓰지 않고 CASE-004로 이어 쓴다. 당시 판단이 틀렸다는 이유로 과거를 삭제하지 않는다.

## 배경

사용자가 처음 필요로 한 것은 단순히 화면을 수정하기 편한 환경이 아니었다. ECG 전시 UI를 더 보고 싶게 만드는 제안과, 그 제안이 UX와 데이터 의미를 해치지 않는지 검증하는 조언이 필요했다. CASE-001에서는 이 요구를 Creative Art Director와 Validator로 분리했다. CASE-002에서는 텍스트 설명만으로 시각적 의도를 공유하기 어려운 문제를 실제 레퍼런스의 특정 장면으로 해결했다. CASE-003에서는 선택한 아이디어를 실제 화면으로 비교할 생성기의 빈칸을 Superdesign으로 채웠다.

이 세 단계는 같은 문제를 반복 해결한 것이 아니다. 각각 **발상의 부족 → 느낌을 공유하는 어려움 → 실제 시안 비교 비용**이라는 다른 병목에 대응했다. 그런데 마지막 도구 배치는 사용자가 기대한 독립적 발상 능력을 충분히 쓰지 못했다. 이것이 이번 반론의 출발점이다. [대화] (handoff §1–3) [추론]

## 논의 흐름 1 — 최초 문제와 AI의 직렬 해법

사용자는 생성기 부족을 다음과 같이 지적했다. [대화] (handoff §1.3에 Chat이 옮긴 발췌)

> "우리 시스템에 검증기용 플러그인이나 스킬은 많은데 생성기용은 부족한 느낌이 들어서"

AI는 기존 Reference Mining과 Art Director의 결론을 Superdesign에 넘기고, 상위 2~4개를 실제 draft로 만든 뒤 별도 Validator로 보내는 직렬 구조를 제안했다. 이는 같은 baseline에서 후보를 비교하고 생성기가 자기 결과를 승인하지 못하게 하는 유용한 해법이었다. D-009와 R-008은 당시의 이득과 위험을 기록한다.

하지만 여기에는 서로 다른 두 판단이 묶여 있었다. **역할과 승인권을 분리해야 한다**는 판단, 그리고 **하나의 도구에는 한 자리만 줘야 한다**는 판단이다. 앞의 원칙을 지키면서도 한 도구를 서로 다른 모드에서 쓸 수 있다는 가능성을 충분히 열어 두지 않았다. [추론: D-009/R-008과 handoff §3 비교]

## 논의 흐름 2 — 사용자는 Renderer가 아니라 또 하나의 Director를 기대했다

사용자는 다음처럼 기대와 실제 배치의 차이를 말했다. [대화] (handoff §2)

> "나는 superdesign이 자체적으로 아이디어를 발산시켜서 시안을 제조해보는 역할을 기대했거든."

> "현재 구축한 awwwards, godly 기반 레퍼런스 교차 creative director과 병렬로 존재해서 멀티 디렉터 구조로."

이는 시안 수를 더 늘려 달라는 요청이 아니었다. 기존 A는 이미 존재하는 사이트를 사용자에게 보여 주며 그 장면에서 어떤 원리를 ECG에 가져올지 설명한다. 사용자가 구상한 B는 자체 탐색 체계에서 프로젝트에 맞는 아이디어를 제안하고, 그중 유망한 방향을 실제 시안으로 제시한다. 즉 **A가 정한 답의 표현만 다양화하지 말고, 답을 찾는 출발점도 다양화하자**는 요구였다.

사용자는 비용도 함께 제어했다. 비싼 시안을 전부 만들기보다 아이디어를 먼저 평가해 1~2개만 생성하고 A의 여러 레퍼런스 변형과 비교하자고 제안했다. 긴 원문은 [대화 부록 §3–4](CASE-004_TRANSCRIPT_EXCERPTS.md)에 보존한다. 이 비용 제한은 AI가 뒤늦게 붙인 제약이 아니라 사용자 구상의 일부다.

## 논의 흐름 3 — AI의 판단 수정: 역할 분리와 도구 제한은 다르다

handoff §3은 당시 AI가 Superdesign의 codebase/design-system 이해, prompt/style 검색, direction discovery, branch generation 등을 재검토했다고 기록한다. 이 작업에서는 그 기록을 역사적 근거로 사용하며, 현재 서비스 기능을 새로 실측했다고 주장하지 않는다.

AI는 기존 직렬 경로를 폐기하는 대신 두 모드로 나눴다.

| 모드 | 받는 입력 | 맡는 일 | 승인권 |
|---|---|---|---|
| NATIVE_DIRECTOR | 공통 baseline·목표·제약과 자체 탐색 자료 | A와 독립적으로 새 방향 탐색 | 없음 |
| CONCRETIZER | 이미 선택된 A/B/Hybrid 방향 | 구체적인 시안 생성 | 없음 |

D-010은 이 확장을 기록한다. D-009의 bounded generator는 CONCRETIZER로 계속 유효하다. R-008의 자기 승인 금지는 유지하되, 한 도구에 반드시 한 자리만 주라는 범위는 R-009에서 수정한다. 처음부터 Dual을 설계한 것처럼 과거 기록을 고치지 않는다.

## 논의 흐름 4 — 병렬이라는 이름만으로 독립성이 생기지는 않는다

A의 아이디어를 B에게 먼저 보여 주면 B도 그 방향에 끌릴 수 있다. 따라서 AI가 구체화한 independent first pass는 공통 문제·코드·design system·hard constraints만 공유하고, 서로의 reference·아이디어·선정 결과·draft는 cross-review 전까지 공유하지 않는 방식이다. [대화] (handoff §5의 설계 요약)

설계 예산은 A 5~8 concepts, B 4~6 Direction Cards → cheap prefilter → 1~2 drafts다. 초기 필터는 데이터 의미 훼손, 프로젝트 무관성, 후보 중복, 낮은 정보 이득 대비 큰 비용을 본다. 낯설거나 의료 UI 관습에서 벗어났다는 이유만으로 제거하지 않는다. A와 B의 상보적 강점이 확인될 때만 Hybrid를 한 번 생성한다.

독립성을 지키려면 A/B 중복 비교도 두 first pass가 모두 끝난 뒤에 해야 한다. 한쪽이 탐색하는 동안 다른 쪽 후보를 미리 읽어 중복을 제거하면 독립성 조건을 스스로 깨게 된다. 이는 다음 실행 계약에서 확인할 구현 조건이다. [추론]

## 논의 흐름 5 — 동작 구상에서 activation과 기록의 문제로

구상된 routing은 HIGH의 중요한 신규 방향에서 Dual, MEDIUM에서는 A를 먼저 쓰고 B의 가치를 판단, LOW에서는 자동 Dual을 생략하는 것이다. 이를 반복 실행하려면 canonical 16번 문서, skill wrapper, 기존 Superdesign dual-mode routing, Master/AGENTS/handoff의 진입점이 필요하다는 논의로 이어졌다. [대화] (handoff §7–8, §12–13)

사용자는 동시에 이 논의가 매번 충분히 기록되는지 물었다. AI의 당시 답변은 기록이 일부 있지만 자동으로 빠짐없이 보존된다고 말할 수 없다는 것이었다. 이후 최신 main에는 CASE-003이 추가되었으므로, 그 이전 답변의 'Superdesign CASE가 없다'는 표현을 현재 상태로 복사하면 안 된다. 기준 시점의 차이도 기록의 일부다.

이번 사용자는 **기록 보강 → 검사·테스트 → PR·CI 성공 → 보고와 다음 단계 승인**을 명시했다. 따라서 실행 시스템 계획을 설명한 것과 구현한 것을 분리한다. D-011/R-010은 방법론 변화와 CASE 사이의 누락 방지 규칙을 기록한다.

## 구축된 시스템 — 이번 단계의 산출물과 다음 단계의 경계

이번 변경은 CASE-004와 발췌 부록, CASE-001의 발췌 부록, F-007/D-010/R-009 및 D-011/R-010, 기존 D/R의 CASE 연결, 기록 규약·체크리스트·checker와 회귀 검사를 추가한다. 별도 ledger는 만들지 않는다.

Dual Director의 `16_DUAL_CREATIVE_DIRECTOR.md`, skill, 실행 routing 및 시안 생성은 이번 산출물이 아니다. 위 논의의 설계안으로만 보존하며 다음 사용자 승인을 기다린다. 검증 결과는 WORKLOG와 해당 PR의 최신 head CI에서 확인한다. 기록 검사 PASS는 UI 품질이나 Director 다양성의 실험 증거가 아니다.

## 사용자가 기여한 것

- 실행 편의성과 창의적 역량 부족을 구별하고, 그 관점을 Superdesign 도입에도 다시 적용했다.
- AI가 만든 파이프라인을 그대로 받아들이지 않고 자신이 기대한 도구 역할과 비교했다.
- 독립 Director의 병렬 배치와 1~2개 시안으로 제한하는 비용 전략을 제안했다.
- 사용자 본인이 다시 읽을 논의 기록을 우선하고 실행 구현 전에 검증하도록 순서를 정했다.

## AI가 기여한 것

- 사용자 반론을 NATIVE_DIRECTOR/CONCRETIZER 구분, 독립 입력 경계, 예산, cross-review와 선택적 Hybrid로 구조화했다.
- 기존 결정의 유효한 부분과 수정해야 할 범위를 나눠 후속 F/D/R로 연결했다.
- 현재 작업에서는 CASE 번호 충돌과 원문 가용 범위를 확인하고 누락 검사를 구현했다.

## 재사용 가능한 AI 사용 패턴

도구의 도입 여부만 묻지 말고 **어느 입력을 받고 어느 단계에서 무엇을 결정하도록 배치했는지** 비교한다. 역할 분리의 목적은 승인권 충돌을 막는 것이며 도구의 유용한 능력을 하나로 제한하는 것과 같지 않다. 독립 탐색을 원하면 결과를 공유하는 시점을 설계하고, 비싼 산출물은 싼 아이디어 평가 뒤에 만든다. 판단을 수정할 때는 초기 답변과 사용자 반론도 함께 보존한다.

## 한계

전체 machine-export transcript는 없다. handoff가 Chat에서 옮긴 발췌와 기존 CASE의 요약을 사용했으며, 부록에 인용 출처와 원문 부재를 표시했다. 초기 AI 답변의 완전한 원문을 새로 만들지 않았다.

두 Director가 실제로 다양성·판단 속도·UI 품질을 높인다는 비교 실험이나 반사실은 없다. 독립성과 예산은 설계 가설이며 아직 실행·검증되지 않았다. 사용량·인기 신호가 더 넓은 reference 접근을 보장한다는 주장도 이 CASE의 근거로 삼지 않는다.
