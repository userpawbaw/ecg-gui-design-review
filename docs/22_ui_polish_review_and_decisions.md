## 2. 승인된 UI-01: 우상단 버튼 대비

캡처의 빈 흰색 버튼은 소스상 `크게 비교 ↗`이며 `data-open-large`로 식별된다.

검토 위치:
- `prototype/v2/src/main.tsx`: viewer-actions와 Button 사용.
- `prototype/v2/src/style.css`: 일반 button 배경과 문맥별 override.
- `prototype/v2/src/components/ui/button.tsx`: 공유 Button의 primary 배경/전경.

소스 검토상 원인: Tailwind 계층의 primary 전경색과, 계층 밖 전역 button의 흰 배경 선언이 충돌할 수 있다. 캡처 증상과 일치하는 원인 경로이며 실행 브라우저의 computed style로 재현한 결과는 아니다.

합의된 수정 방향: 기본 배경 `#067d72` + 흰 글자, hover `#05665e` + 흰 글자. 이 색상쌍의 계산 대비는 약 5.02:1과 6.84:1이다. 실제 적용/hover/focus/disabled 렌더 검증은 별도다. 공유 원인 영향 범위를 검토하여 검토 JSON 저장 등 같은 Button 사용처도 확인하되 임의 전면 테마 변경은 하지 않는다.

수용 기준: 정상/hover/focus에서 라벨이 읽히고, disabled가 off/선택 상태와 구별되며, 큰 창 열기와 닫은 뒤 포커스 복귀가 유지된다.

## 3. 승인된 UI-03/04: 표시 도구와 컨트롤

현재 `표시 설정`은 disabled 버튼이 아니라 기본적으로 닫힌 details다. 처음 보는 관람자에게 낮은 강조와 숨겨진 내용 때문에 누를 이유가 잘 드러나지 않는 것이 문제다.

합의: 모든 상세 옵션을 처음부터 펼치기보다는 작은 기본 도구 모음을 항상 보여준다. 차이 보기 버튼은 노출하되 차이 파형 자체는 기본 OFF로 유지한다. 기본 입력/출력의 큰 파형 면적을 보존한다.

| 위치 | 컨트롤 | 표현/상태 |
|---|---|---|
| 항상 보이는 기본 도구 | 표시 길이, ±mV 범위, 범위 맞춤 | 단위가 있는 입력/선택과 일반 실행 버튼 |
| 항상 보이는 기본 도구 | 차이 보기 | 눌림 상태가 명확한 토글 버튼; 라벨은 안정적으로 유지하고 켜짐/꺼짐을 별도 표시 |
| 차이 보기 ON일 때 | 표시 확대 | ×1/×3/×5 중 하나를 선택하는 인접 그룹 |
| 접히는 고급 도구 | 재생 속도, Reference 겹침 강도 | 라벨이 있는 선택 컨트롤 |
| 고급 도구/표현 그룹 | 경계 부드럽게 | 설명을 곁들인 ON/OFF 스위치 |
| 고급 도구/재생 그룹 | 끝에서 반복 | ON/OFF 스위치 |

스위치/버튼의 겉모양만 바꾸지 말고 실제 semantic control, 키보드, 포커스, checked/pressed/expanded 상태를 유지한다. native checkbox를 접근 가능하게 스타일링하는 방식도 가능하다. 즉시 ON/OFF에 스위치가 맞으며 `범위 맞춤`처럼 한 번 실행하는 동작은 일반 버튼을 유지한다. 모든 것을 같은 버튼으로 바꾸지 않는다.

보존할 동작: 차이 보기 중 Sweep/Scroll 동기, pause/replay 및 선택 상태 유지, Output−Reference 부호, gain과 실제 mV 축 환산, 동일 시간과 비교축. 관련 상태 회귀와 실제 기본/큰 창·차이/Pin 조합에서 잘림을 확인한다. 전체 98조건 재추론은 이 UI 수정의 검증이 아니다.

## 4. UI-02: UI인가 UX인가, 선단 발광 제안

UI·모션 디자인은 밝기/색/투명도/선의 마감을 설계한다. UX·상태 피드백은 새 표본 위치와 진행 방향을 알아보기 쉽게 한다. 따라서 복합 개선이다. 시각적 만족도도 목표가 될 수 있지만 이해 속도/피로/조작성의 개선은 실제 관찰 없이 확정하지 않는다.

초기 세 방향:
1. 새 파형의 짧은 선단 발광으로 위치를 안내한다.
2. 격자·0선·Reference·실제 출력의 위계를 정돈한다.
3. 버튼/제목의 짧고 안정적인 색 전환으로 조작 결과를 알려준다. 파형 사이의 morph는 하지 않는다.

다듬은 사용자 제안:
> Sweep 선과 바로 왼쪽의 새로 그려진 파형에 짧은 밝기 그라데이션을 적용한다. 선단에서 가장 밝고 왼쪽으로 멀어질수록 원래 파형 색으로 부드럽게 돌아온다. 원래 색과 가는 선의 형태를 유지하며 넓은 흰색 띠나 긴 잔상은 만들지 않는다.

비교 시안의 시작값이지 확정 사양은 아니다:
- 폭: plot 내부 너비의 2~3%, 대략 24~48 CSS px 범위에서 비교.
- 선단: 원래 색에 흰색 25~40% 정도를 혼합하는 안부터 비교; 완전한 흰색으로 방법 색을 없애지 않는다.
- 작은 halo는 선택적이다. 굵은 빛 번짐 때문에 작은 P/T와 Q/S 굴곡이 가려지면 제거한다.
- 입력/선택 출력/Pin에 같은 규칙을 적용하고 회색 Reference는 안정적으로 유지한다.
- 좌표/샘플/진폭/시간 매핑은 유지한다. 옛 주기 파형이 새 표본처럼 빛나지 않도록 wrap 전후를 검증한다.
- pause에서는 파형을 그대로 정지하고 장식 강조를 정리한다. 장식 fade-out 구현 시 별도 프레임 갱신이 필요할 수 있다.
- 기존 지우기 경계 fade와 새로운 생성부 밝기 효과를 구분한다. reduced-motion 선호를 확인하고 장식 효과와 사용자가 의도한 파형 재생을 분리한다.
- 현행 코드에는 reduced-motion에 따라 soft 상태를 조정하는 처리와 CSS transition 억제가 이미 있다. 새로 없는 기능처럼 재제안하지 않는다.

[21번](21_ui_refinement_workflow_final.md)의 기존 "fade는 지우기 경계" 계약을 구현 승인 없이 바꾸지 않는다. 생성부 효과를 나중에 구현한다면 해당 계약의 변경 이유/보존 조건을 먼저 명시한다.

## 6. UI UX Pro Max Skill 검토

사용자가 제공한 [외부 저장소](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)의 SKILL.md, UX 규칙, 검색 스크립트를 읽고 수동 검토에 참고했다. 설치/검색 스크립트 실행/계정 또는 Work의 영구 스킬 등록은 하지 않았다. 기존 React/TypeScript/Vite, Tailwind 4, 일부 shadcn 방식 Button 및 Canvas 구성을 기준으로 검토했다.

차용:
- 대비/포커스/선택 상태, 의미에 맞는 컨트롤, 간격과 아이콘의 일관성.
- 맥락에 맞는 모션과 사용자 reduced-motion 선호.
- 실제 대상 요소에 필요한 작은 검색만 수행하고 결과 적합성을 확인하는 방식.

발전/제외:
- 기본 우선순위 표의 Charts & Data LOW는 ECG 프로젝트에 부적합. 파형/시간/축/연구 의미는 최우선이다.
- 지속 애니메이션을 억제하는 일반 권고는 실제 ECG 재생을 없애는 근거가 아니다.
- 제품 분류만으로 전면 테마/글꼴/GSAP 의존성/새 페이지를 도입하지 않는다.
- 기존 21번 워크플로우를 최상위 프로젝트 규칙으로 유지한다. 매번 별도 디자인 시스템을 생성·덮어쓰지 않는다.
- 검색/패턴 자료는 누락 방지에 유용하지만 모델의 능력 자체를 교체하지 않는다. 품질/사용량/시간 절감 효과를 측정했다고 주장하지 않는다.

## 7. 상태·재개와 다음 단계
