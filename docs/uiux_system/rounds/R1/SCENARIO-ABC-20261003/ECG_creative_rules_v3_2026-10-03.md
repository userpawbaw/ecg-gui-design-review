# 도입부·Story 연출 및 결과 검토 규칙 v3

> 2026-10-04 보완: [첨부 빛/모델링 검토](ECG_light_modeling_review_2026-10-04.md)와 [후보별 조명 씬 명세](ECG_ABC_lighting_scene_spec_2026-10-04.md)를 함께 적용한다. 기존 본문은 보존하며, 새 장면·자세 제안은 실제 렌더 검증 및 사용자 선택 전이다.

2026-10-03 · 사용자 피드백으로 갱신 · 적용: A/B/C와 이후 파형·전환 아이디어

## 1. 구역마다 정확성 요구가 다르다

| 구역 | 우선하는 것 | 허용되는 표현 | 유지해야 할 것 |
|---|---|---|---|
| **도입부·Story** | 강한 인상, 공간감, ECG 디노이징의 의미 | 파형의 입자 분해/재결합, 3D 원근, 리본/볼륨, 순간 형태 변형, 깊이 분리, 설명용 공간 투사 | 심장/R 이벤트의 일관된 시계, 입력→디지털 처리→출력이라는 방향, 설명 연출을 실제 성능 근거처럼 쓰지 않음 |
| **Story에서 원인을 관찰하는 구간** | 전원/기저선/근육의 원인을 파형과 연결 | 전체 무대의 원근·카메라·빛, 간섭의 확대 강조, 순간 파형 변형 | 선택한 잡음의 특징을 알아볼 수 있는 도착 프레임; 호흡/손 쥠과 노이즈의 관련 시점 |
| **비교 패널·분석 화면** | 정확성과 비교 가능성 | 읽기를 돕는 제한된 강조 | 저장된 Input/Output/Reference/Difference, 단위/축/시간창, 동일 표본, 지표·출처; 실제 데이터 형태를 바꾸지 않음 |

v2의 `파티클 폭발 배제`, `파형 3D 투시 배제`, `형태 보간 전면 금지`는 도입부/Story에 대해 **폐기된 제한**이다. 기존 만족한 sweep/잔광/동기 역시 새 연출과 결합할 수 있다. 모든 씬을 분석 그래프처럼 만드는 제약은 적용하지 않는다.

과감한 연출의 끝에는 저장된 입력 또는 출력에서 출발한 알아볼 수 있는 신호가 돌아와야 한다. 그것을 3D로 보여 줄 수 있지만 숫자/정량 축을 붙여 정확한 판독 화면인 듯 만들지 않는다. 비교 패널에 들어갈 때는 장식적 변형·잔여 입자·공간 흔들림을 종료하고 저장 데이터에서 다시 정확히 그린다. 이전 3D 객체를 단순히 정면으로 돌렸다고 정확성 복원이 끝난 것으로 보지 않는다.

## 2. 레퍼런스에서 본 것과 새로 만든 것을 표시한다

씬 카드의 효과마다 다음 표시를 붙인다.

- **원본 관찰:** 이번 브라우저에서 캡처/조작해 실제로 본 화면. 프레임 파일과 보는 순서 포함.
- **원본 기술 확인:** 공개 소스 또는 제작자가 공개한 기술 설명. 버전·수치가 없으면 미확인으로 남김.
- **ECG 번안:** 원본에서 대상/재질/문구/의미를 바꾼 부분.
- **독자 확장:** 원본에는 확인되지 않은 카메라 경로, 형태 전환, 스토리. 향후 우리 목업/프리비즈가 시각적 기준이 됨.

예: Editorial New의 `CSS rotate(360×progress)`는 원본 기술 확인이다. B의 y축 입체 회전과 종이 틈으로 카메라가 들어가는 장면은 독자 확장이다. My Little Storybook은 이름과 달리 이번에 본 장면에서 실제 종이책/책장 넘김을 보여 주지 않았다. 이를 종이책 팝업의 근거로 쓰지 않는다.

## 3. 결과를 보고 새 아이디어를 내는 절차

`제작 → 동일 구도 캡처/영상 → 사용자 피드백 → 부족한 부분의 원인 → 신규 연출 2–3개 → 선택/보류 → 반영 → 재검증`을 씬마다 반복한다. 신규 아이디어는 다음 필드를 갖는다.

| 필드 | 예시 |
|---|---|
| 발생 위치 | B6의 청록 출력이 나타난 뒤 오른쪽 하단이 비어 보임 |
| 부족의 원인 | 입력과 출력 사이에 처리 사건이 없어 색 교체로만 읽힘 |
| 제안하는 사건 | 파형을 짧은 샘플 조각으로 나눠 디지털 배열판을 지나 재형성 |
| ECG 의미 | 입력을 처리하여 출력으로 만든다는 방향을 화면이 보여 줌 |
| 구도 영향 | 카메라는 고정, 중심 x=1280의 처리판만 깊이 20 cm 앞에 |
| 구현 출발 | 저장 표본을 texture/buffer로 공급, 입자 목표점 두 벌, p와 t 분리 |
| 반대안 | 폭발 후 전면 재집결, 또는 프리즘 통과; 한 안은 과감한 표현 |
| 피드백 | 사용자 원문/요지, 채택/수정/보류/기각, 수정된 씬 링크 |

레퍼런스가 없어도 ECG에 적합한 독자 아이디어는 제안한다. 그때 레퍼런스에서 확인한 것처럼 적지 않고 우리 목표 프레임을 기준으로 만든다.

## 4. 검증 게이트는 최소 기준이며 계속 갱신한다

정지 화면만으로 회전 속도, 가림, 재생 위상, 역스크롤, 입자의 튀는 움직임을 판정하지 않는다. 각 씬을 **정지 프레임 → 프리비즈 → 실제 구현 영상 → 실제 조작**의 서로 다른 수준에서 검토한다.

| 항목 | 핵심 질문 | 증거 |
|---|---|---|
| 구도/물성 | 어떤 면이 보이고 무엇이 먼저 읽히나? 저렴한 종이/플라스틱/평평한 지구로 보이나? | 시작/중간/도착 정지 프레임. 차용한 효과는 원본과 나란히 |
| 움직임/연결 | 중간에 형태가 망가지는가, 카메라가 물체를 뚫는가, 빈 스크롤이 생기나? | 효과 구간 6–12 프레임, 한 번의 연속 영상 |
| 의미 | 디지털 처리 사건과 ECG를 설명할 수 있나? 파티클만 기억하나? | 3초/15초 관찰 후 사용자의 설명, 제목 없는 전환 전후 비교 |
| 독립 재생 | 스크롤 정지 중 심장과 신호가 같은 시간에 살아 있나? | 정지 2–3박 영상, 원인별 시간 루프 |
| 조작 | 빠른/느린/역스크롤, 포인터, 경계 되돌림에서도 장면이 성립하나? | 실제 브라우저 조작 영상 |
| 비교 경계 | 설명 연출의 변형/입자가 비교 화면에 남지 않나? | 같은 샘플 인덱스의 패널 인계·왕복 캡처, 실제 배열값 확인 |
| 성능/접근 | 움직임이 끊기나, 정지 대안에서도 핵심 내용이 보이나? | 사용 환경과 실측을 적은 결과. 목표 PC 성능은 해당 PC에서 별도 확인 |

새 결함을 발견하면 `VAL-NEW-n`에 **실패 프레임 → 재현 입력 → 원인 가설 → 수정 → 영향 구간 → 추가할 검사**를 적는다. 한 번의 점수나 자동 PASS가 전시 품질을 확정하지 않는다. Q(품질), C(개연성), E(ECG 전달), D(비교 경계/시간 정합), M(실제 움직임) 각각 KEEP/TUNE/REJECT를 적고 전체 후보 채택과 구분한다.

## 5. 피드백 범위와 완료 기록

`A-*`, `B-*`, `C-*`, `SYS-*`, `MIN-*`, `VAL-*` ID를 유지한다. 파트에서 수락된 요소는 다음 수정의 유지 조건에 넣는다. 사용자 만족으로 닫힌 **피드백 분석/대조**는 다시 평가 과제로 열지 않는다. A의 발전 방향이나 B의 공간 아이디어가 긍정 평가되었다고 전체 구현 순위까지 확정하지 않는다.

원본 재현의 부족과 독자 확장의 부족도 구분한다. 전자는 레퍼런스의 에셋·빛·수치·카메라를 대조하고, 후자는 우리 씬 카드·목업·프리비즈와 ECG 인과를 대조한다. 모든 신규 스펙터클을 ‘원본과 동일해야 한다’는 게이트로 기각하지 않는다.
