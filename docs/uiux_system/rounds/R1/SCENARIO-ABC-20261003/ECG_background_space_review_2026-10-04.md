# ECG 배경 공간 보완 검토

2026-10-04 · BG-REVIEW-01 · 사용자 대화 발췌·첨부4장 / 현재 Three.js 구현 대조

## 1. 결론

추천은 **어두운 저밀도 입체 공간 + 선택된 모서리선 + 국소 수광면**이다. 공간의 존재는 상시 아주 낮게 남기고, 박동 스캔은 특정 장면의 선택 효과로 시험한다. 가구를 많이 넣기보다 **바닥과 벽의 만남, 가까운 가림 물체, 뒤 장비의 크기 차이**를 먼저 만든다.

현재의 허전함은 사물 개수뿐 아니라 사람·종이·파형이 어디에 서 있는지 알려 주는 공간 단서가 약한 데서 온다. 이번 이미지는 분위기 참고이며 **첨부3/4의 전신 원경·긴 종이·넓은 처리 상자는 채택하지 않는다.** B3/B5/B6와 C2/C4/C5의 기존 구도에 별도로 번안해야 한다. A 목업을 만드는 계획도 이 검토로 폐기하지 않는다.

이번 작업은 검토·설계 제안이다. 새 목업/제품 코드/성능 시험은 수행하지 않았다. 외부 대화의 제안을 기술 사실이나 확정 결정으로 간주하지 않았다.

## 3. 구현 타당성 — 어디가 쉬우며 어디가 어려운가

현재 확인한 코드: `prototype/v2/src/story/intro/introStage.ts`는 WebGLRenderer, ACES exposure, EffectComposer/bloom/OutputPass를 사용한다. `archive.ts`에는 별도 sun-depth와 ray-march shaft가 있다. 진행 브랜치는 `5d70777`까지 갱신됐으며 새 자세 자산/모델링 스크립트가 추가됐다. 위 렌더 진입 파일은 그 변경 목록에 없다. B/C의 생성 목업은 해당 장면의 런타임 구현이 있다는 증거가 아니다.

### 3.1 희미한 구조선: 구현 가능, 원시 wireframe보다 선택된 edges 추천

단순 박스·기둥·책상·모니터 프레임을 만들고 필요한 선만 남기는 방식이면 모델링 부담은 작다. 하지만 모든 삼각형 선을 켜면 대각선까지 나타나고, 많은 개별 가구/선 재질은 draw call과 선 겹침을 늘린다. **geometry가 단순하다는 것과 최종 화면이 싸게 렌더된다는 것은 다르다.**

`EdgesGeometry`는 인접 면 법선 사이의 각도 기준으로 모서리를 추출한다. 곡면/원형 다리는 무작정 추출하기보다 중요한 윤곽을 별도 작성하는 편이 제어하기 쉽다. 재질과 역할이 같은 정적 선은 묶고, 박동 반응 그룹/움직이는 물체만 따로 둔다. [Three.js EdgesGeometry](https://threejs.org/docs/pages/EdgesGeometry.html)

기본 `LineBasicMaterial.linewidth`는 WebGL에서 무시되고 선은 1픽셀이다. 먼 선이 끊기는 문제가 있으면 WebGL용 `Line2/LineSegments2 + LineMaterial`의 화면/세계 단위 폭을 시험한다. 이것도 자동으로 값싸다는 뜻은 아니므로 선택된 주요 선에만 적용한다. [LineBasicMaterial](https://threejs.org/docs/pages/LineBasicMaterial.html), [Line2](https://threejs.org/docs/pages/Line2.html)

### 3.2 빛을 받은 edge만 드러내는 방: 두 종류를 구별

- **실제 수광 공간:** 매우 어두운 불투명 PBR 면, 얇은 bevel/모서리, 제한된 key/rim으로 실루엣 일부를 읽는다. bake + 동적 국소광으로 시작한다. 모델·조명 설계 부담은 구조선보다 크지만 앞서 검토한 aperture/blocker/receiver 원칙을 잘 활용한다.
- **연출 구조선:** edge 선 재질에 밝기 마스크를 주어 광원이 닿는 것처럼 드러낸다. 조명 결과와 비슷하게 보일 수 있지만 실제 조명/그림자 해석과 구분해야 한다. `MeshBasicMaterial`은 광원의 영향을 받지 않으므로 여기에 light를 추가하는 것만으로 수광 동작이 생기지는 않는다. [MeshBasicMaterial](https://threejs.org/docs/pages/MeshBasicMaterial.html)

추천은 **실제 어두운 부피가 가림을 담당하고, 선택된 선/수광면이 읽힘을 담당하는 혼합 구조**다. 숨겨진 모든 선이 인체·종이 너머로 보여 X-ray 룸이 되는 상태는 피한다. 전면에서 보이지 않는 occluder라도 beauty depth에 참여할지 설계한다. 현재 sun-depth는 빛 가림용 별도 패스이므로 beauty 가림이 저절로 해결되는 것으로 보지 않는다.

### 3.3 투명선/가림/반사: 주된 구현 위험

희미한 선은 depth test를 유지하고 필요한 경우 depth write를 꺼 시험한다. 다만 선끼리는 부피를 가리지 못한다. behind edge까지 드러나면 어두운 불투명 면/깊이 전용 프록시를 둔다. 중첩 투명 물체의 정렬, 면과 선의 z-fighting, 화면 밖 이동 때 반짝임은 구도별 검사 대상이다. depthWrite=false나 renderOrder 한 값으로 모두 해결됐다고 판단하지 않는다. [Three.js Transparency](https://threejs.org/manual/pages/transparency.html)

첨부3/4의 풍부한 바닥 반사는 별도의 품질 비용이다. 첫 시험은 거친 어두운 바닥에 부드러운 수광 패치·contact shadow로 시작한다. 반사가 필요하면 정적/bake·단순 합성부터 비교한다. 이미지처럼 여러 신호가 길게 선명히 반사되는 것을 기본 요구로 만들지 않는다.

### 3.4 밝기10–20%: 출발값, opacity 규칙으로 고정하지 않음

제안된 비율은 ‘배경이 주연과 경쟁하지 않는다’는 목표로 유용하다. 그러나 `opacity=.1`이 인체 대비 화면 밝기10%를 뜻하지 않는다. 색·블렌딩·톤매핑·bloom·노출·뒤 배경이 함께 결정한다. 선들이 겹치면 예상보다 밝아질 수 있다. 선폭과 선 밀도도 밝기처럼 시선 점유에 영향을 준다. [Three.js Color Management](https://threejs.org/manual/pages/color-management.html)

동일 exposure/카메라에서 **배경 off / 낮음 / 중간**을 비교한다. 화면의 대표 배경선과 인체선 밝기를 대조하되 밝은 헤드 한 픽셀만 기준으로 삼지 않는다. 주연의 읽힘/시선 경쟁을 최종 기준으로 두고 10–20%를 절대 합격 수치로 만들지 않는다. 현재 bloom은 밝기 threshold 방식이므로 배경선이 bloom 문턱을 넘지 않는지도 실제 프레임으로 확인한다.

## 4. 박동 스캔을 발전시키는 방법

**가능하다. 다만 심장의 실제 빛이 물리적으로 방을 스캔한다는 구현과, 신호에 반응하는 설명 효과를 구별한다.** 첫 시험은 실제 동적 light/매번 새 shadow map 대신 선택된 edge의 shader mask로 구현하는 편을 추천한다. 분위기 참고의 은유이며 실제 생체 전자기파 전파/측정 장면으로 주장하지 않는다.

### 상태 설계

- R 이벤트는 심장/파형과 같은 표본 시계에서 받는다. 별도 타이머를 심장 박동처럼 재생하지 않는다.
- edge 꼭짓점의 world 위치와 스캔 원점의 거리(또는 특정 방향의 투영값)를 사용해 얇은 띠가 지나는 순간만 밝힌다. 벽 전체 opacity를 올리는 방식보다 표면 일부의 순차 등장으로 공간이 읽힌다.
- 300–500ms는 공간 반응의 **연출 목표**다. 파형 R 자체를 지연시키지 않는다. 가까운 desk edge→뒤 프레임→먼 장비의 지연은 배경에만 적용한다. 높은 박동수에서는 지속시간을 현재 RR의 일부로 제한해 반복이 겹쳐 상시 밝은 방이 되지 않게 한다. 초기 시험 `min(450ms, .45×RR)`는 제안값이다.
- p 정지/t 재생은 계속. world 원점은 카메라에 붙이지 않는다. 인체가 자리 이동하면 원점을 그 인체의 현재 측정 위치로 갱신한다. 역스크롤로 R 이벤트를 중복 발사하지 않도록 이벤트 ID/현재 t를 사용한다.
- 매 박동 모든 가구를 켜기보다 2–3개의 목적 있는 반응 그룹만 둔다. B3 첫 발견에서 시험하고, B5/C2의 읽는 자리에서는 더 낮게 또는 꺼진 버전과 비교한다.

**주요 위험:** 매 박동 장면 전체를 밝히면 ECG보다 스캔을 보게 된다. 인체의 고리·격자·구조선이 동시에 켜지면 놀이공원/레이더 장식처럼 보일 수 있다. 스캔이 켜지지 않아도 공간은 읽히게 하고, 효과 off와 낮은 상시 상태를 제공한다. 저동작 설정에서는 순환 스캔을 낮은 정적 상태로 대체하는 안을 시험한다.

## 5. 분위기만 번안한 후보별 배경 설계

구도 좌표는 최종 채택값이 아닌 다음 시험용 제안. 첨부 이미지의 원경/긴 종이/큰 processing box를 옮겨 놓지 않는다.

### B3: 종이 틈 안에 ‘기록을 측정하는 자리’

- 전경 종이 margin과 기존 인체 위치 유지. 사람 발 밑에는 낮은 blue-gray 바닥/벽 접선 1개를 둔다. 바닥 높이는 발 접지와 일치시킨다.
- 사람 뒤 오른쪽에 기존 측정 카트/모니터를 배치하고, 왼쪽 뒤에는 기둥·프레임 1개와 어두운 수광면만 둔다. 인체 높이의 1/3–1/2로 보이는 뒤 장비가 거리감을 만든다.
- 기존 blue-gray 선은 outline 중심, 카트 선은 일부만. 머리/심장 뒤로 긴 수평선을 관통시키지 않는다. 유리 프레임이 꼭 필요하지는 않으며 실제 glass transmission 없이 프레임만 먼저 시험한다.
- 카메라가 틈으로 들어오면 가까운 종이→사람→뒤 모니터의 이동량이 달라진다. 2D 그림을 배경에 붙여 같은 속도로 이동시키지 않는다.

### B5/B6: 배경 공간은 남고, 처리선은 전경 역할

벽의 접선은 제목 뒤를 비워두고 종이/파형 밖 암부에만 나타난다. desk/카트는 신호가 오는 출처로 한쪽에 남는다. 처리 grid는 채도가 있는 teal, 방의 선은 탈채도 blue-gray로 구별한다. B6의 이면 수광 효과와 방 전체 박동 스캔을 같은 순간 최대치로 겹치지 않는다. 처리 뒤 출력이 도착하면 배경 자극을 낮추는 안과 비교한다.

### C: 처리실에 구조를 추가하되 기존 링 과밀은 함께 줄인다

현재 C는 무대/링/기둥/반사가 이미 있으므로 가구를 더 넣는 방식부터 시작하지 않는다. 뒤의 저밀도 장비 프레임·어두운 벽면·바닥 접선으로 실체를 만들고, 대신 큰 장식 링과 바닥 반사를 낮춘다. C4 전경 기둥은 실제 어두운 가림 역할 유지. 밝은 셔터/출력과 배경 wire 색을 분리한다. ‘허전함’이 없어지는지와 표본 전환이 계속 주연인지 함께 본다.

### A: 서고의 실제 밀도를 활용

A는 서가·사다리·창의 구조가 이미 있다. 같은 wire 룸을 추가하면 서고의 의미와 겹친다. existing receiver/서가 앞턱/작은 기록함의 어둡고 밝은 영역을 먼저 조정하고, 먼 모서리만 선택적으로 읽게 한다. 후보들 모두를 한 ‘네온 방’으로 통일하지 않는다.

먼저 **무스캔 혼합 공간**을 목업/간단 clay에서 확인하고, 다음 스캔을 별도 짧은 모션으로 시험한다. 인체·파형·글자는 고정해 배경만 바꿔야 차이를 판단할 수 있다. 낮은 geometry/원시 wire/선폭 addon 각각의 비용은 실제 카메라/화면 크기에서 측정하며 FPS 향상을 현재 주장하지 않는다.

최종 게이트: 동일 p/t/frame에서 off/on 비교, 카메라 경로 6–12프레임, 정지 박동2–3회, 반사/bloom/배경선 분리, 빠른 입력/역방향/재진입, 정확 비교 화면에서 배경 연출 종료 또는 판독 방해 여부 확인. 이번 기술 근거 검토를 실제 구현 PASS로 처리하지 않는다.

현재 완료: 첨부 분위기 분석·기술 타당성·발전 제안·후보별 시험 계획. 보류: 구도 확정/새 목업/코드/성능/사용자 배경안 채택. A 목업 작업은 별도 대기하며, 이 제안의 채택 여부와 혼동하지 않는다.
