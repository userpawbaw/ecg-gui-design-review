# 경험 플레이북 — 작업 전에 먼저 보는 권장안과, 거기까지 온 시행착오

작업을 시작하기 전에 아래 **언제 읽나** 열에서 지금 하려는 일과 맞는 카드를 찾는다. 카드는 "무엇을, 어디까지"를 말한다. 카드의 `근거 여정`을 따라가면 "왜 그렇게 하는지"가 시행착오 순서대로 나온다.

- 설계 근거(조사한 방법론, 설계 규칙 DR-1 ~ DR-12, 사용자 기본 틀 검토): `00_DESIGN_RULES.md`
- 쓰는 법(양식, 검사 항목, 기록 시점): `01_FORMAT.md`
- 검사: `npm run playbook:check` (`npm test`에 포함)
- 세부 사실: 각 노드의 `기록`이 가리키는 F/D/O/R(`docs/uiux_system/records/`)과 `verification/`

## 정리 대기 — 운영 기록은 있으나 아직 여정으로 묶지 않은 것

아래는 F/D/O/R에 흩어져 있고 여정·카드로는 아직 정리하지 않은 시행착오다. 같은 종류의 작업을 다시 시작할 때, 또는 그 주제가 결론에 닿을 때 여정으로 묶는다. 빈 카드를 미리 만들지 않는다(01_FORMAT §2, 억지 기록 금지).
