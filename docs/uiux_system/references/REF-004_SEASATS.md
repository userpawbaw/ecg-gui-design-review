## 6. 효과 카드

### EFX-004-01 합성 셰이더로 만든 "홀로그램" 지구 — 글로·윤곽선·흰 표시층

**선정 이유**: wow 포인트("전략 홀로그램 지도를 보는 듯해 미래적인 느낌"), 품질 차이("3d 렌더링은 잘 된 반면").
**지각**: 청록 바다와 연녹 대륙의 지구가 가장자리에서 은은히 빛나고 얇은 밝은 윤곽선이 있다. 그 위에 흰 배·점선 원·점선 항적이 한 가지 흰색으로 또렷하게 얹혀, 사진 같은 지구가 아니라 **디자인된 작전 지도**처럼 보인다. 지구 뒤편으로 넘어간 표시는 가려진다.
**입력 모델**: 포인터(드래그 회전, EFX-004-05) + 시간(표시 요소 애니메이션). 렌더 구조 자체는 입력과 무관.
**판별 근거**: 소스 — 렌더 타깃 4장과 합성 셰이더(`GlobeCompositor`) `[코드]`. 녹화에서 표시 요소가 지구 뒤로 넘어가면 사라짐 `[영상]`.
**구현 메커니즘**:
```
r3f Canvas (frameloop never, GSAP ticker로 advance, 화면 근처일 때만)
 매 프레임 4개 장면을 각각 렌더 타깃에 그림 (카메라: fov 75, zoom 10 → 사실상 망원):
  1) glowRT  (1/2 해상도) : 구 scale 1.1, 셰이더 alpha = smoothstep(0,1,dot(view,normal))², 색 #CCF8BD
  2) globeRT (MSAA 8)    : icosahedron(1, 64) + MeshStandardMaterial
                            map = color_diffuse KTX2, displacementMap KTX2 × 0.014, normalMap webp
                            조명 = 카메라를 따라가는 directional 2개(0.5π, 그림자 1024) + hemisphere 1
                            → 회전이나 선택이 바뀔 때만 다시 그림(dirty flag)
  3) overlayRT            : 배·링·항적을 **빨강 채널 = 불투명도**로만 그림 + 초록(0x00FF00) 가림 구
  4) maskRT  (1/4 해상도) : 가림 구 마스크
 합성 평면(화면 전체, ShaderMaterial):
  globe = ACES(unpremultiply(globe) × 2.0)          // 지구만 톤매핑·노출 2배
  color = globe_premult + glow × (1 − globe.a)       // 글로는 지구 뒤에만
  edge  = 8방향 알파 경계 검출(1.5 px) → 윤곽선 #C7DBBE × 0.4
  boat  = overlay.r × (1 − overlay.g)                // 지구 뒤 표시는 초록 가림으로 제거
  color = mix(color, white, boat)                    // 표시층은 전부 흰색
```
표시 요소를 **색이 아니라 불투명도 한 채널**로 그린 뒤 합성에서 한 색으로 칠하기 때문에, 배·링·항적이 겹쳐도 번짐 없이 균일한 흰 "인쇄" 층이 된다. 이것이 홀로그램·지도 느낌의 핵심이다 `[추론]`.

| 변위 | displacementScale 0.014 | `[코드]` |

**접근성·폴백**: reduced-motion 처리 확인 못 함. 모바일은 지구 대신 카드 슬라이더(Swiper)가 주 탐색 수단 `[코드]`. WebGL 실패 폴백 미확인.
**근거**: `[코드]`(셰이더·설정 원문), `[영상]`, `[런타임]`(용량·캔버스), 느낌의 원인 `[추론]`.

**ECG 번안**: 실험 데이터가 어디서 왔는지(측정 장소·데이터셋 출처)나 모델·조건 공간을 "작전 지도"처럼 보여 줄 수 있다. 더 일반적으로는 **불투명도 채널 표시층 + 합성 단일색** 기법을 파형 오버레이(마커·구간 강조)에 써서, 여러 표시가 겹쳐도 파형 색을 오염시키지 않게 할 수 있다.

### EFX-004-02 시계 눈금처럼 도는 점선 링 (배 표시점)

**선정 이유**: 사용자 지목("시계의 시각 점 같은 원형 강조 표시기는 느리지만 꾸준히 돌며 세련된 느낌"), 재사용 메커니즘.
**지각**: 배마다 작은 흰 점(눈금)으로 이루어진 원이 두 겹 있다. 안쪽은 촘촘하고 바깥쪽은 성기다. 눈금이 실제로 도는 것이 아니라 **밝기 물결이 원을 따라 돌아서** 천천히 회전하는 듯 보이고, 두 원은 서로 반대 방향·다른 속도다. 배 자체는 물 위에서 살짝 흔들린다.
**입력 모델**: 시간.
**판별 근거**: 녹화에서 조작이 없어도 계속 돈다 `[영상]`. 소스 — 링 셰이더의 `sin(uTime·freq + aPhase)` 불투명도 물결 `[코드]`.
**구현 메커니즘**:
```
링 1개 = InstancedMesh(작은 상자 0.012 × 0.012 × 0.0024) N개를 원 위에 배치, 각자 원 접선 방향으로 회전
  안쪽: 반지름 0.14 × s,  N = round(28·√s),  aPhase = −각도,  freq = 0.3 × 2π/3 = 0.628 rad/s
  바깥: 반지름 0.21 × s,  N = round(16·√s),  aPhase = +각도,  freq = 2π/3   = 2.094 rad/s
  (s = ringsScale/100, 임무별 CMS 값)
정점 셰이더:
  sine  = sin(t·freq + aPhase);  sine2 = sin(t·freq·0.6 + aPhase + 0.54)
  pos.y += sine × 0.02;  pos.z += sine2 × 0.005            // 눈금이 살짝 들썩임
  opacity = 1 − clamp(((sine+1)/2)² − 0.2, 0, 0.6)          // 0.4 ~ 1.0 사이 밝기 물결
  opacity ×= mix(1, 0, highlighted)                          // hover되면 링이 사라짐
배: 정점 셰이더에서 sin/cos 흔들림(회전 ±0.02π, 높이 0.03, 속도 3 × 0.8–1.2 무작위)
출력은 빨강 채널 = 불투명도 → EFX-004-01 합성에서 흰색으로
```
**파라미터**:

    |Δ| < 0.01 rad면 종료

## 10. 열린 질문

- 지구본 실제 렌더를 라이브로 캡처하지 못했다(헤드리스 H.264 미지원 → 마운트 안 됨). → 로컬 세션(일반 Chrome) 또는 `capture-site.mjs`를 사용자 PC에서 실행.
- 팝오버 등장의 framer-motion 설정과 CSS transition 중 실제로 보이는 쪽(둘 다 0.3 s ease-out)을 구분하지 않았다.
- Lenis 설정값을 찾지 못했다.
- 스크롤 연속 이미지 끊김(EFX-004-06)의 원인은 추정이다. → D-017 규칙 녹화(HUD) + 프레임 번호 로그로 확인.
- 지구 텍스처의 제작 방법(위성 사진 재채색 추정)은 파일을 열어 보지 않아 추정이다.
- 필터의 500 ms 최소 대기가 의도된 연출인지(서버 요청 대비) 단순 로딩 보정인지 불명.
