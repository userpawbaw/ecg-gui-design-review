# J-003. 후처리 화면 깜빡임 — 재현되지 않는 검은 프레임에서 셰이더 정의역 고정까지

| | |
|---|---|
| 기간 | 2026-10-14 ~ 2026-10-15 |
| 도착 | P-006 |
| 기록 | F-042, `docs/uiux_system/rounds/R1/REVIEW-R1-STORY-20261011.md`, `verification/r1-story-feedback-20261011/README.md` |

## 출발점

Story 전원 장면(46–49 s)에서 구 껍질이 퍼지고 카메라가 크레인으로 오를 때 화면 전체가 검게 깜빡였다. 사용자 녹화에서만 보였고, 이 환경의 소프트웨어 렌더(SwiftShader)에서는 나오지 않았다.

## 흐름 한눈에

```
T1 녹화 누락·근평면 컷·MSAA를 먼저 의심 ──(증상과 안 맞음)──▶ T2 소프트웨어 렌더에서 재현 시도
   ──(재현 안 됨, 그래도 고쳐야 함)──▶ T3 모든 pow·fresnel 밑을 max(0.,…)로 고정 ── 끝(사용자 GPU에서 사라짐 확인)
```

## T1. 검은 프레임을 녹화·컷어웨이·MSAA 탓으로 의심

| | |
|---|---|
| 날짜 | 2026-10-14 |
| 종류 | 비교 |
| 계기 | 사용자 `[대화]`: "46초부터 49초까지를 보면 … 화면이 심하게 깜빡거리네 … 무조건 고쳐야 하는 문제야." |
| 가설 | 녹화 프로그램의 프레임 누락, F-041의 근평면 단면, 2026-10-12에 넣은 MSAA 4× 중 하나가 원인이다 |
| 판정 | 기각 |
| 다음 | T2 |
| 기록 | F-042 |

### 한 것
녹화 프레임마다 평균 밝기를 쟀다. 47.3–49 s에 약 10장이 홀로 검었다(5–26, 앞뒤 45–85) `[런타임]`.

### 선택지와 기준
"화면 전체가 한 장만 검다"를 설명하는지로 갈랐다. 프레임 누락은 앞 장을 반복할 뿐이다. 근평면 단면은 화면 일부만 비운다. MSAA는 남은 후보라 디버그 패널에 끄기 버튼을 두었다.

### 결과
셋 다 증상과 맞지 않거나 따로 확인할 수단만 남았다 `[런타임]`(F-042 "먼저 의심한 것과 배제 방법").

### 왜 다음으로
화면 전체를 한 번에 검게 만드는 것은 후처리 단계에서 퍼지는 값이다. 셰이더 쪽을 보려면 먼저 재현이 필요했다.

## T2. 소프트웨어 렌더에서 재현 시도

| | |
|---|---|
| 날짜 | 2026-10-14 |
| 종류 | 시도 |
| 계기 | T1에서 후처리 전파를 의심 |
| 가설 | 같은 시각·같은 카메라로 고정 렌더하면 검은 프레임이 나온다 |
| 판정 | 타협 |
| 다음 | T3 |
| 기록 | F-042 |

### 한 것
수정 전 빌드로 46–49 s를 시간 고정 렌더해 프레임 최저 밝기를 쟀다.

### 결과
최저 밝기 45, 검은 프레임 없음 `[런타임]`. SwiftShader는 음수 밑 `pow`를 NaN 없이 계산한다. 재현 없이 원인 후보를 고치고 사용자 GPU 확인을 기다리기로 했다.

### 왜 다음으로
재현할 수 없으니 코드에서 정의역을 벗어날 수 있는 계산을 찾아 모두 막는 쪽이 남았다.

## T3. 모든 pow·fresnel 밑을 0 이상으로 고정

| | |
|---|---|
| 날짜 | 2026-10-14 (사용자 확인 2026-10-15) |
| 종류 | 시도 |
| 계기 | T2 |
| 가설 | 껍질을 거의 수직으로 내려다볼 때 `1-|dot(n,v)|`가 반올림으로 음수가 되고, 일부 GPU에서 `pow`가 NaN을 내며, HalfFloat 블룸이 그 한 화소를 화면 전체로 번지게 한다 |
| 판정 | 채택 |
| 다음 | 끝 |
| 기록 | F-042, 커밋 3cfdf98 |

### 한 것
껍질, 몸, 심장 테두리, 지구, 장비, 산란 위상의 밑을 `max(0.,…)`로 막았다. 후처리에서 `isnan`으로 지우는 통과는 넣지 않았다. 드라이버 최적화가 그 검사를 없앨 수 있다.

### 결과
사용자 `[대화]`(2026-10-15): "깜박임 사라졌어."

## 도착점
P-006: 화면 전체가 한 장씩 검게 깜빡이면 NaN을 먼저 의심하고, 셰이더의 `pow`·`sqrt`·`log` 밑을 정의역으로 고정한다.

## 여정에서 얻은 것
- 증상의 범위(화면 전체·한 장)가 원인 단계를 가른다. 일부만 비면 기하, 전체가 비면 후처리 전파다.
- 소프트웨어 렌더의 "재현 안 됨"은 무죄 증거가 아니다. GPU마다 정의되지 않은 연산의 결과가 다르다.
