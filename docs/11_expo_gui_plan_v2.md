# ECG Signal Studio — Expo·GUI 개선 기획서 v2

작성: 2026-09-10. 상태: **설계 검토본 / 구현 전**.

이 문서는 [v1 수정 제안](10_playback_expansion_proposal.md)의 목적과 데이터 범위를 유지하면서 전시 동선, 모션, 조작 상태, 기술 구조를 개선한다. 충돌하는 세부 결정은 이 문서의 v2 제안으로 대체한다. 아래의 '채택 권고'는 기획상의 추천이며 사용자가 구현을 승인했다는 뜻은 아니다. 현재 실행 파일은 기존 S5 프로토타입이다.

## 1. 회의 결론과 유지할 강점

핵심 목표: **멀리서는 흘러가는 ECG가 눈에 들어오고, 가까이서는 같은 구간의 입력과 출력 차이를 직접 확인할 수 있어야 한다.**

사용자가 좋아한 현재 전체 인상, 선택 방법 설명, hover 미리보기를 유지한다. 기존 차분한 밝은 앱 배경과 어두운 파형 패널, 정렬과 여백을 발전시키며 일반적인 대시보드 템플릿으로 일괄 교체하지 않는다. 기법 해설 본문의 상세 확장은 이번 수정 후 논의한다.

| v1의 아쉬움 | v2 개선 | 기대 효과와 대가 |
|---|---|---|
| 재생 기능 중심이며 관람객이 무엇을 보아야 하는지 약함 | 60초 권장 체험 순서와 장면별 관찰 질문 | 발표를 돕지만 성능이 잘 나온 구간만 선별하지 않도록 구성 근거 필요 |
| Sweep의 지우는 경계가 갑작스러움 | 이전 파형의 지우는 경계에만 짧은 투명도 전환 | 부드러운 인상. P/T를 가리는 긴 잔상은 제한 |
| 세 가지 모드에 정지 의미가 섞임 | 재생/일시정지 버튼과 Sweep/Scroll 선택을 분리 | 정지·재개와 표시 방식이 예측 가능 |
| 움직이는 동안 방법을 바꾸면 박동 자체도 바뀜 | 현재 연속 구간을 고정해 같은 구간에서 비교 | 차이가 방법 때문인지 구분. 정지한 화면과 재생 화면의 상태 표시 필요 |
| 세 번째 행의 hover 역할이 바뀜 | 두 행/세 행 모두 hover는 선택 출력 행, 고정 비교 행은 유지 | 고정의 의미가 일관됨. 겹친 선 범례 필요 |
| 10분 중 어디를 보여줄지 발표자가 기억해야 함 | 조건·시각·방법을 저장한 발표 북마크 | 빠른 복귀. 북마크의 대표성 범위를 설명해야 함 |
| 순수 JS에 기능이 계속 추가됨 | React/TypeScript 기반 UI와 독립 파형 엔진의 단계적 전환 권고 | 상태·재사용 개선. 이관과 회귀 검수 비용 발생 |

## 2. 박람회 시연: 기능 목록을 짧은 경험으로 연결

10분 데이터는 관람객이 10분 동안 기다리라는 뜻이 아니다. 충분한 데이터 속에서 30–60초의 이해 가능한 경험을 제공한다. 아래 시간은 전시 리허설에서 조정할 기획 목표이며 연구로 확정된 체류시간이 아니다.

| 단계 | 관람객 경험 | 화면·발표자 조작 | 확인하려는 것 |
|---|---|---|---|
| 관심 유도, 약 5초 | 두 파형이 함께 흐르는 것을 본다 | 큰 비교창, Sweep, 1×, REPLAY 표기 | '잡음이 섞인 입력 / 처리 결과' 구분 |
| 직접 조작, 약 10–15초 | 잡음이나 SNR을 바꾼다 | 먼저 추천 3개 조건 제시, 전체 98조건은 펼쳐 선택 | 같은 입력 조건에서 무엇이 바뀌는가 |
| 차이 관찰, 약 15–20초 | 현재 구간 고정 후 방법을 hover/선택한다 | 두 행 + 회색 Reference, 필요시 2.5초 확대 | 작은 굴곡·진폭·남은 잡음 차이 |
| 근거 확인, 약 10–20초 | 관심 있는 지표·설명을 펼친다 | 선택 구간 수치, FE 기준선, 별도 전체 근거 | 한 장면 관찰과 전체 결과의 차이 |

추천 장면은 ① 혼합 잡음에서의 차이, ② FE만으로 상당 부분 제거되는 조건, ③ 입력이 비교적 깨끗해 추가 처리의 손해도 관찰할 수 있는 조건으로 구성한다. 기존 설명 문구를 새 600초 결과에 그대로 적용하지 않는다. 새 결과에서 뒷받침되는 표현만 사용하며 '항상 우수' 배지를 만들지 않는다.

관찰 안내는 한 줄로 제한한다. 예: '회색 기준선과 작은 굴곡이 얼마나 겹치는지 보세요.' 진단이나 검증되지 않은 자동 박동 판정 문구는 넣지 않는다.

### 화면을 더 늘릴 것인가?

이번 범위에는 실험실·전체 근거·계측의 기존 구조를 유지한다. 큰 비교창은 실험실의 집중 보기다. **시연/분석은 같은 화면의 정보 밀도 설정**으로 제공하고, 데이터를 따로 가진 새 앱이나 네 번째 작업 공간으로 만들지 않는다.

- 시연 보기: 두 큰 파형, 핵심 조건, 재생, 짧은 관찰 질문. 상세 지표·seed·checkpoint는 펼침 영역.
- 분석 보기: 비교 고정, 세부 구간, residual, 수치·출처를 추가 노출.
- 어느 보기든 REPLAY, record, 잡음, SNR, 시간·mV 단위와 Reference 의미는 접근 가능하게 유지.

## 3. Sweep의 부드러움: 신호가 아닌 지우는 경계에 적용

사용자 제안인 짧은 페이드는 **채택 권고**다. 빠른 전환으로 경계를 읽기 쉽게 하는 방향은 Fluent 모션 원칙과 맞는다[S1]. 다만 아래 수치와 ECG 적용 방식은 이 프로젝트의 초기 설계안이며 공식 표준값이 아니다.

### 3.1 초기 모션 규격

- 새 표본은 작성 헤드에서 원래 진폭·선명도로 바로 그린다.
- 헤드 앞에는 짧은 빈 간격을 두고, 그보다 앞의 **지난 주기 파형**은 지워지는 경계에 가까워지며 불투명도 1→0으로 변한다.
- 1× 기준 빈 간격은 데이터 시간 0.12초, 투명도 전환 구간은 0.08초를 초기값으로 한다. 전체 약 0.20초이며 v1의 지우는 폭 안에서 부드러운 경계를 만든다.
- 이 구간은 데이터 좌표에 고정한다. 따라서 0.5×에서는 전환이 약 160ms, 1×는 80ms, 2×는 40ms에 해당한다. 속도 변경에 따른 읽힘을 실제 영상으로 검수한다. 전시 기본은 1×다.
- 예: 폭 1500px에 5초를 그리면 빈 간격 약 36px + 전환 약 24px다. 해상도마다 고정 픽셀 폭을 억지로 적용하지 않는다.
- Reference·입력·선택 출력·hover·비교 출력에 **동일한 마스크**를 적용한다. 신호 종류마다 사라지는 속도가 달라지지 않는다.
- 그리드·축·범례는 마스크에 포함하지 않는다. 영역이 지워질 때 패널 전체가 깜박이지 않는다.
- 모서리 래핑 때 마스크를 좌우로 나눠 적용한다. 화면 오른쪽 끝과 왼쪽 시작을 선으로 잇지 않는다. 새 주기와 지난 주기 경계에도 선을 연결하지 않는다.
- 첫 주기의 아직 지나지 않은 영역에는 미래 파형을 미리 그리지 않는다.

### 3.2 사용하지 않을 효과

- 모든 과거 파형을 계속 흐리게 하는 긴 잔상: 위치에 따라 같은 P/T파의 가독성이 달라짐.
- 파형 glow/blur 및 두꺼운 발광: 작은 형태를 덮고 노이즈를 덜 보이게 함.
- 서로 다른 방법·SNR 출력 사이의 좌표 morph: 실제 존재하지 않는 중간 파형을 생성함.
- Sweep 진행 속도에 ease-in/out: 데이터 시간과 눈에 보이는 이동을 불일치시킴.

전송·재생은 일정 속도를 유지하고, 패널 출입 등 UI 이동에만 easing을 사용한다. 투명도는 표시 스타일이며 표본, 지표, 내보내기 데이터에는 적용하지 않는다.

## 4. 모션은 세 계층으로 정리

| 대상 | 초기값·동작 | 설계 이유 |
|---|---|---|
| 버튼 hover/선택 테두리 | 80–120ms, 배경·테두리 변화 | 눌러도 되는 대상과 선택 반응을 알려줌 |
| 방법 hover 대기 | 포인터 진입 후 120ms; 클릭은 즉시 | 목록을 가로지르는 움직임으로 수많은 미리보기가 바뀌지 않게 함 |
| 방법 설명 전환 | 글은 한 번에 교체, 강조 배경만 약 120ms | 겹친 두 설명이나 흔들리는 패널 높이 방지 |
| 대형창 열기/닫기 | 약 180–220ms 투명도 + 최대 6px 이동 | 공간 이동을 알리되 파형 확대/축소 왜곡은 피함 |
| 패널 접기 | 약 180ms, 끝에서 정확한 크기로 재렌더 | 전체 화면이 계속 다시 계산되지 않게 함 |
| 새 조건 반영 | 준비 후 표본·범례·지표를 같은 시점에 교체 | 이전 출력이 새 조건인 것처럼 보이는 순간 제거 |
| 수치 변화 | 제한 주기로 실제 값 교체, 숫자 카운트업 없음 | 실측·계산하지 않은 중간 수치 방지 |
| 데이터 이동 | 표본 시계와 선형 대응 | 부드러움 때문에 시간 의미를 바꾸지 않음 |

이벤트를 기다리는 시간과 애니메이션 시간을 구분한다. hover 120ms는 판단 대기 시간이지 점선을 120ms 동안 옛 방법과 혼합하라는 뜻이 아니다. 후보 점선은 원형 좌표로 나타나고 사라진다.

모션 축소 설정에서는 패널 이동·페이드·자동 관심 유도 재생을 끈다. 사용자가 명시적으로 시작한 Sweep/Scroll에는 항상 일시정지를 제공하고 정적 구간 검사로 대체할 수 있게 한다. 자동 움직임의 정지 수단과 비필수 상호작용 모션 축소는 별도 검수 항목이다[S7][S8].

## 5. 대형 비교창: 시선과 공간의 우선순위

기존 96%×94% 대형 modal + 선택적 전체화면을 유지한다. 별도 OS 팝업·다중 모니터 분리는 보류한다.

### 5.1 구성

1. 짧은 상단 행: '입력과 처리 결과 비교', REPLAY, 기록·조건, 닫기/전체화면.
2. 두 개의 전체 폭 파형: 위 입력 / 아래 선택 출력. 같은 시간축과 mV 범위.
3. 접을 수 있는 Method Explorer: 시연 보기에서는 짧은 이름·선택/미리보기 상태, 해설 펼침.
4. 항상 보이는 핵심 재생줄: 재생/일시정지, Sweep/Scroll, 구간 고정, 10분 탐색.
5. 추가 조작 펼침: 표시 길이·속도·진폭·Reference 강도·세 번째 비교·출처.

현재 선택 방법명은 짧은 ID와 읽을 수 있는 이름을 함께 둔다. 긴 원리 설명을 고정 높이 파형 영역에 넣지 않는다. 설명 펼침이 파형을 갑자기 압축하지 않게 옆 패널 안에서 스크롤한다.

### 5.2 크기와 선의 설계 목표

- 1920×1080, 100% zoom: 두 행 각각 280–330 CSS px를 초기 목표. 실제 plot 내부 높이는 축·라벨을 제외해 측정한다.
- 1366×768: 부가 설명을 접고 두 행 각각 약 180–220px 확보를 목표로 한다. 폭이 부족하면 목록을 상단 선택기로 바꾼다.
- 세 행의 높이가 각각 180px 미만이 되는 화면은 '3행은 스크롤하여 보기' 또는 2행 전환을 명시한다. 보이지 않는 행을 몰래 제거하거나 데이터 높이를 계속 줄이지 않는다.
- Reference는 중성 회색, 입력은 기존 따뜻한 색, 선택 출력은 기존 민트 계열, 고정 비교는 차분한 파랑, hover 후보는 황색 점선. 방법이 바뀌어도 색은 **행 역할**을 뜻한다.
- 실제 연결/오류 의미와 신호 색은 badge·문구·형태로 구분한다. 민트 파형 자체를 정상/성공 판정으로 쓰지 않는다.
- Reference 2–2.4px, 전면 신호 1.5–1.8px를 초기값으로 검토한다. 작은 굴곡을 덮으면 얇게 조정한다. 전면 신호가 같은 위치에 놓이면 회색 기준의 가장자리가 보이는 정도를 목표로 한다.
- Reference 불투명도는 0.55 초기값, 약하게/기본/강하게 3단계(0.35/0.55/0.75) 제안. 진폭은 변하지 않는다. 밝은 배경과 어두운 배경의 합성 후 대비를 각각 확인한다.
- 관련 제어 글자는 14–16px, 주요 값은 18–22px를 초기 목표로 한다. 글자만 키워 파형을 빼앗지 않도록 제어 수를 먼저 줄인다. 주요 클릭 영역은 시연 보기 44px 이상 목표.

수치는 검수 전 초기안이다. 실제 모니터·1m 거리의 읽힘, 100/125/150% OS 배율은 따로 확인해야 한다. 브라우저 viewport 크기를 바꾼 것만으로 OS 배율 검수를 대신하지 않는다.

### 5.3 배경과 효과

기존 밝은 앱 외곽/어두운 신호 패널을 유지한다. 유리 재질·배경 blur·카드별 glow를 추가하지 않는다. 큰 창의 배경 dim과 얕은 경계만으로 전후 관계를 만든다. 작은 계층은 테두리보다 정렬·여백으로 표현한다. 별도 테마 선택기는 이번 범위에서 보류한다.

## 6. '움직이는 감상'과 '같은 구간의 비교'를 연결

두 방법을 차례로 선택하는 동안 다른 박동으로 시간이 흐르면, 비교 결과가 처리 방법 때문인지 박동 변화 때문인지 읽기 어렵다. v2에서 **구간 고정**을 핵심 행동으로 승격한다.

- 일시정지: Sweep이면 지우는 마스크까지 그 장면 그대로 멈춘다. 재개는 같은 위치부터.
- 구간 고정: 현재 도달한 시각을 끝으로 하는 연속 2.5/5/10초 중 현재 표시 길이를 고정한다. Sweep의 좌우 주기를 잘라 붙여 연속 시계열로 읽을 수 있게 한다. 아직 데이터가 부족하면 실제 가용 구간만 사용하고 빈 부분을 채우지 않는다.
- 고정 상태에서 방법 hover/선택·SNR 변경을 해도 동일한 record와 표본 구간을 유지한다. 데이터 준비 전에는 변경 중임을 표시한다.
- '재생으로 돌아가기'는 고정 진입 시점부터 이어간다. 정적 검사 중 시간이 몰래 흐르지 않는다.
- 파형 클릭·숫자 입력으로 짧은 국소 구간을 고른다. 검증된 annotation 없이 '자동 한 박동'이라고 이름 붙이지 않는다.
- 상단에 '구간 고정 02:14.000–02:19.000'처럼 명시한다. Sweep 축의 좌우 위치와 실제 절대 시각을 혼동하지 않게 한다.

이는 정지 버튼을 눌렀을 때 갑자기 레이아웃을 재배열한다는 뜻이 아니다. '일시정지'와 '구간 고정'은 구별되는 명시적 행동이다.

### 6.1 hover·클릭·고정 비교의 일관성

- 미리보기는 포인터 hover 또는 키보드 focus로 열고, 선택 실선/선택 지표를 유지한다. 터치에는 클릭 선택과 비교 고정 버튼이 있으므로 hover가 필수 경로가 아니다.
- 두 행이든 세 행이든 **hover 점선은 선택 출력 행에 나타난다**. v1의 세 행 상태에서 후보를 세 번째 행에 표시하는 규칙을 대체한다.
- 세 번째 고정 비교 행은 미리보기로 바꾸지 않는다. 고정/미리보기 역할의 예측 가능성을 우선한다.
- 선택 또는 고정과 동일한 후보는 중복 점선을 그리지 않고 해당 행 라벨만 강조한다.
- 미리보기 중 다른 행·Reference를 과도하게 어둡게 하지 않는다. 선명도를 낮춰 방법이 좋아 보이게 하지 않는다.
- 목록에 포인터를 올리는 것만으로 전체 재생을 멈추지 않는다. 설명을 위해 멈추려면 '구간 고정'을 쓴다.
- 후보 출력이 준비되지 않았으면 짧은 '미리보기 준비 중' 상태만 표시한다. 선택 출력은 유지하고, 후보는 준비됐을 때만 표시한다. 포인터가 떠난 뒤 늦게 도착한 후보는 표시하지 않는다.

### 6.2 발표자가 덜 조작하도록

발표 북마크는 axis/record/잡음/SNR/시각/구간/방법/비교/진폭/모드를 저장한다. 준비된 구간으로 이동했음을 표시하며 생방송 또는 임의로 뽑은 대표 표본이라고 표현하지 않는다. '처음 설정으로'는 구간 고정과 별도 동작이다.

핵심 단축키는 제한한다. Space=재생/일시정지(텍스트 입력·다이얼로그 내 기본 키 동작을 방해하지 않는 문맥에서만), Escape=최상위 UI 닫기. 문자 한 글자 전역 단축키는 기본 제공하지 않는다. 나머지 기능은 버튼으로 접근한다.

## 8. 기술 스택: 역할을 구분한 선택

확인한 현재 구현: `prototype/index.html`, `style.css`, `app.js`, `core.js`의 HTML/CSS/일반 JavaScript + SVG. package.json에는 개발 검사용 jsdom만 있다. React, Tailwind CSS, shadcn/ui는 아직 사용하지 않는다.

HTML은 웹 UI의 기본 구조다. React는 구성요소·상태를 관리하고, Tailwind는 CSS 작성·생성을 돕고, shadcn/ui는 수정 가능한 UI 구성요소 소스를 제공한다. 서로 같은 층의 대체재가 아니며 함께 사용할 수 있다[S2][S3][S4].

| 도구 | 이 프로젝트에서 맡길 역할 | 맡기지 않을 역할·비용 |
|---|---|---|
| React | 실험실/대형창의 선택 상태, 공통 버튼·패널, 조건·출처 표시 | 매 프레임 모든 파형 표본을 React state로 갱신하지 않음; 이관 비용 |
| TypeScript | session·sample index·method·loading 상태 계약 | 실제 런타임 데이터 유효성 검사를 대신하지 않음 |
| Vite | 개발 실행과 JS/CSS 배포 빌드 | 모델 추론 서버·클라우드 호스팅 요구 아님[S5] |
| Tailwind CSS | 간격·색·반응형·focus 스타일을 프로젝트 토큰으로 통일 | 기본 테마를 그대로 적용해 외형을 바꾸지 않음; build 시 정적 CSS 생성[S3] |
| shadcn/ui 일부 | Button, Dialog, Tooltip, Toggle Group, Collapsible 등 필요한 구성요소 | 차트/대시보드 템플릿 통째 도입 금지; 수정한 소스의 유지·업데이트 책임[S4] |
| Canvas 2D | 가시 시간 창의 Sweep/Scroll·마스크·후보 선 | 전체 10분을 매 프레임 그리지 않음; 접근 가능한 DOM 설명/조작을 별도 제공 |
| SVG | 축·가이드·정지 구간의 정밀 표현, 필요시 정적 그림 | 같은 표본·좌표 규약을 공유하고 Canvas와 결과 비교 |
| CSS 모션 | 버튼·패널의 짧은 전환 | 파형 연산·실시간 시계·수치 보간을 맡기지 않음 |
| Playwright | 실제 브라우저 기능·화면·trace와 10분 재생 증거 | 스크린샷만으로 주관적 시각 품질·OS 배율을 자동 인증하지 않음 |

### 8.1 대안과 추천

| 안 | 장점 | 대가 | 적합한 상황 |
|---|---|---|---|
| A. 현재 JS/CSS를 모듈화해 확장 | 변경 범위 작음, 현재 동작 유지 용이 | 상태·반복 UI 관리 계속 직접 구현 | 행사 마감이 임박해 검수 시간이 짧음 |
| **B. React/TypeScript + Vite + Tailwind + 필요한 shadcn/ui + 독립 파형 엔진** | 화면 간 상태와 컴포넌트 계약 관리, 후속 확장·팀 설명에 유리 | build 도입, 스타일 이관, 기존 동작 회귀 검수 | 현재처럼 대형창·장시간 데이터·운영 기능을 함께 확장 |
| C. Electron/Tauri까지 함께 전환 | 설치형 프로그램으로 배포하는 경로 | OS 포장·업데이트·권한·추가 검수 범위 | 장치 접근·설치형 배포가 실제로 필요할 때 |

**v2는 B를 추천한다.** 이는 기존 UI 디자인의 '권장안 B'와는 별개의 기술 선택 표다. 도구가 화면을 자동으로 더 아름답게 만든다는 근거로 선택하지 않는다. 같은 상태를 공유하는 대형창, 반복되는 제어 요소, 장기 유지보수라는 현재 변경 범위가 이유다. 행사 일정이 촉박하면 A로도 같은 시각 목표를 달성할 수 있다.

도입은 단계적으로 한다. 기존 `independent/` 동결은 유지하고 S5 `prototype/`를 비교 기준으로 보존한다. 승인 후 새 구현 영역에서 동일 10초 데이터·동일 지표를 읽는 한 화면으로 먼저 동등성을 확인한다. 그 뒤 재생 엔진과 600초 자료를 연결한다. 데이터를 다시 만드는 작업과 기술 스택 이관으로 생긴 문제를 구분해 추적한다.

프레임워크 전환은 오프라인 실행과 양립한다. JS/CSS/폰트/구성요소 의존성을 build 산출물에 포함하고 localhost 정적 실행으로 제공한다. CDN·원격 폰트·행사 중 패키지 설치는 사용하지 않는다. 개발용 Node와 관람객용 실행 절차를 분리해 설명한다.

## 9. 파형 렌더링·상태·성능의 구현 계약

아래는 구현 방향이며 성능 측정 결과가 아니다.

- 하나의 재생 시계가 source sample index를 결정한다. requestAnimationFrame의 시간 정보를 사용하고 디스플레이 주사율을 데이터 샘플링률로 간주하지 않는다[S6]. 기본/대형창은 같은 시계를 구독한다.
- React는 선택·일시정지·모드 등 저빈도 상태를 관리하고, 렌더러는 ref/엔진 구독을 통해 가시 표본을 그린다. 엔진 연결/해제를 명시하며 재진입 시 두 개의 재생 루프가 생기지 않도록 한다[S2].
- Canvas의 정적 그리드와 동적 파형·마스크를 분리한다. 실제 devicePixelRatio에 맞추고 가시 범위만 그린다. Canvas 최적화 기법은 도입하되 성능 향상은 해당 PC에서 확인한다[S9].
- 화면보다 많은 표본이 몰리면 시간순 극값을 보존하는 표시 축약을 검토한다. 단순 매 N번째 표본만 그려 R peak를 잃지 않게 한다. 표본·지표·확대는 원래 자료를 쓴다.
- 한 조건의 현재/다음 데이터 chunk와 방법 목록의 미리보기 출력을 먼저 준비한다. 98조건 전체를 매번 메모리에 풀지 않는다. 취소·재시도·캐시 상한을 둔다.
- 외부 chunk의 session/condition/method/sample range/hash를 검사한다. 요청 ID를 연결해 늦게 도착한 옛 조건이 최신 선택을 덮지 못하게 한다.
- 정지/구간 고정/보이지 않는 뷰는 불필요한 프레임 루프를 중단한다. 마스크를 포함한 정지 장면은 결정론적으로 다시 그릴 수 있어야 한다.
- 디코딩이나 지표 계산이 주 스레드에서 실제로 조작을 막는 것이 확인되면 Web Worker로 분리한다. 처음부터 WebGL·OffscreenCanvas·대형 상태 라이브러리를 모두 도입하지 않는다.

60Hz 시험 환경에서는 가시 파형 갱신 60fps를 목표로 하며 입력 피드백 지연·긴 프레임·메모리를 함께 기록한다. 60fps를 보장한다고 표기하지 않는다. 디스플레이가 더 빠르거나 느려도 1×에서 1초 데이터는 1초로 진행해야 한다. 떨어지는 성능은 우선 장식 효과를 줄여 대응하며 데이터 표본을 몰래 생략하지 않는다.

## 10. 데이터 범위와 비교의 타당성 보완

v1의 **98조건 × 연속 600초 × 각 지원 방법 출력**, 재학습 제외를 유지한다. 누락 출력을 다른 방법의 결과로 대체하지 않는다. 실제 미지원 방법은 생성/호환성 확인 전 완료로 처리하지 않는다.

v2에서는 장시간 시연용 기본 D1 세션에 **잡음 종류가 바뀌어도 같은 record/lead/시작 구간을 사용**하는 안을 권고한다. v1은 기존 자료처럼 잡음별 record 변화가 허용됐지만, '잡음 종류가 차이를 만든다'는 시연에서는 ECG 형태도 함께 변하는 혼동이 있다. D0도 같은 기반 합성 파형을 조건 간 공유한다.

- TEST111은 길이와 현재 split을 확인한 시작 후보이며 확정된 대표성 판정이 아니다. 성능을 본 뒤 유리한 기록으로 바꾸지 않도록 선정 이유를 먼저 기록한다.
- 같은 잡음에서 SNR만 바꾸면 동일 잡음 실현의 크기만 바꾼다. 다른 종류의 잡음은 별개 실현임을 구분한다.
- 전시용 한 record의 10분 결과는 전체 TEST 집계의 대체가 아니다. 기존 집계 근거와 새 세션 수치를 명시적으로 분리한다.
- 같은 기반 reference는 모든 조건에서 같은 전처리 정의를 사용한다. noisy 조건에 맞춰 reference를 임의 변경하지 않는다.
- 실제 NSTDB 가용 TEST 잡음이 600초보다 짧으면 범위·재사용을 정직하게 표기하고 새 연속 원자료라고 주장하지 않는다. 현재 합성 잡음 7종 격자는 이 문제와 구분한다.
- 미리보기·선택 비교는 물리 진폭 그대로 한다. 최적 배율 alpha를 적용한 '보기 좋은 출력'을 기본 파형으로 만들지 않는다.

## 12. 우선순위와 수정된 실행 순서

필수: 공통 재생, 경계 페이드, 두 행 대형창, 안정적 hover, 구간 고정, 전 조건 600초 자료, 데이터/출처 정합, 자동 검수.

권고: React 기반 단계적 전환, 세 번째 비교 행, 발표 북마크, Reference 강도, 시연/분석 밀도.

선택: 발표자가 켜는 Attract·무인 초기화. 보류: 별도 OS 창·설치형 포장·음향·Blind A/B·대형 모션 라이브러리·질환 자동 판정·기법 해설 본문 확장.

| 단계 | v2 작업 | 종료 시 확인 |
|---|---|---|
| R0-v2 | 이번 검토·계획·근거 정리 | 설계안 완료, 구현 승인 여부 명확화 |
| R1a | 채택된 스택으로 동일 데이터 화면·핵심 상태 이관, 최소 PC 브라우저 검수 경로 준비 | 기존 지표·주요 동작 동등성; native 렌더 결과 전까지 NV |

## 13. 근거와 가정 구분

아래는 2026-09-10 조회한 공식 문서다. 모션 목적, 도구 역할, 브라우저 API 및 접근성 원칙을 뒷받침한다. 이 문서의 80ms 페이드·60초 체험·폰트·행 높이·스택 추천·북마크 구성은 **프로젝트 적용 제안**이며 출처가 특정 ECG GUI에 보장한 값이 아니다.

- [S1 Fluent 2 Motion](https://fluent2.microsoft.design/motion): 목적 있는 모션, 빠른 전환, 필요한 경우 일정 속도, 모션 축소.
- [S2 React — Synchronizing with Effects](https://react.dev/learn/synchronizing-with-effects): UI와 외부 시스템의 동기화 및 정리. 고빈도 파형 엔진 분리는 이 프로젝트 설계 판단.
- [S3 Tailwind CLI](https://tailwindcss.com/docs/installation/tailwind-cli): 소스의 클래스를 읽어 정적 CSS 생성.
- [S4 shadcn/ui Introduction](https://ui.shadcn.com/docs): 구성요소 소스를 받아 수정·조합하는 접근.
- [S5 Vite Building for Production](https://vite.dev/guide/build): 정적으로 제공할 수 있는 앱 bundle 생성.
- [S6 MDN requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame): 화면 갱신과 timestamp 기반 진행.
- [S7 WCAG 2.3.3](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html): 비필수 상호작용 모션 비활성화.
- [S8 WCAG 2.2.2](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html): 자동 움직임·갱신의 정지 제어.
- [S9 MDN Optimizing canvas](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Optimizing_canvas): 레이어 분리 등 그리기 최적화.

로컬 근거: prototype/index.html·style.css·app.js·core.js·package.json, v1 제안 및 그 안의 원본 고정 SHA. 현재 폰트 선언은 시스템 대체 경로이며 외부 폰트를 이미 포함했다는 뜻이 아니다.
